# 実装席の指示書テンプレート — NeNe Folio

設計席が背景席（Agent）へ渡す**指示書の型**。hide の運用変更（2026-09-24・Issue #100 の手 1〜手 3・記録 #106）を
「人の記憶」ではなく指示書の型で守るためのもの。運用の判断は [ADR 0034](adr/0034-agent-seats-by-job.md)。
ここに書いてあるのは**指示書に必ず入れる文言**で、席ごとに書き換えるのは `{…}` の穴だけである。

## 0. 席を立てる前に設計席が決めること

| 決めること | 選択肢 | 根拠 |
| --- | --- | --- |
| 仕事の種類 | probe（現物調査）／実装／差し戻し対応／下ごしらえ／機械作業 | 手 1・手 3-1 |
| `model` | 実装・差し戻し = `opus`／下ごしらえ・ペルソナ・棚卸し・撮影・checkout 準備 = `sonnet`／照合・差分の列挙 = `haiku` | 手 1・手 3-4。判断は設計席自身 |
| 大きさ | **S 級**（変更 1 命題・ファイル数が片手・フルゲート 1 回で終わる） | 手 3-3。M 級 1 本より S 級 3 本 |
| 席の寿命 | **この task の 1 仕事だけ** | 手 3-1 |
| 報告ファイル | `out/agents/<issue>-<仕事>/report.md`（git の管理外） | 手 3-2 |

🔴 **1 task を 1 席で走らせない。** probe → 実装 → 差し戻し対応は、それぞれ**新しい Agent** にする。
引き継ぎは報告ファイル（と mailbox があればそれ）で渡す。**SendMessage で同じ席を次の仕事に使い回すのは Opus では禁止。**
`fork` は親の全文脈を継ぐので背景席には使わない。差し戻しは「変更 1 命題 = 新しい席」。

## 1. 指示書の型（この順で、この文言を入れる）

```text
あなたは NeNe Folio の {仕事の種類} 席（{model}）。この席の仕事は {1 文で 1 命題} だけである。
終わったら報告ファイルを書いて止まる。次の仕事はこの席には来ない。

## 先に読むもの（範囲を限る）
- CLAUDE.md の §0〜§3（全文）
- {正典経路のファイル}: {行範囲 or 関数名}
- {前の席の報告ファイルのパス}（あれば。全文でよいのは 300 行以内のとき）
それ以外のファイルは、必要になった範囲だけ読む。ファイルの丸読み・ディレクトリ全体の cat はしない。

## 正典経路
{ARC / C / QLT の規則 ID と、編集してよいファイルの一覧}
上の一覧に無いファイルは編集しない。必要なら報告ファイルの「止めた理由」に書いて止まる。

## やること（S 級・変更 1 命題）
{手順 1〜n。各手順に「確かめ方」を 1 行}

## 道具出力を小さくする（必ず守る）
- テストは対象だけ実行する: `ctest --test-dir build -R {テスト名} --output-on-failure`。落ちたら失敗行だけを `tail -n 40` で読む。
- ビルドとフルゲートの出力はファイルへ落とす: `pwsh -NoProfile -File ./eng/check.ps1 > out/agents/{issue}-{仕事}/gate.log 2>&1`。
  読むのは `grep -n "error\|FAIL\|failed\|passed" out/agents/{issue}-{仕事}/gate.log` の結果だけ。
- ファイルは必要な範囲だけ読む（`sed -n '{a},{b}p'`／Read の offset・limit）。全文を読んでよいのは 200 行以内のファイルだけ。
- 同じ出力を 2 度読まない。読んだ結果は報告ファイルに要点だけ書く。

## 完了の定義
- {受け入れ条件 1〜3。数で言えるもの}
- `pwsh -NoProfile -File ./eng/check.ps1` が exit 0（結果はログのパスと `passed` の行で報告）
- Draft PR を出す（Ready にするのは設計席）

## 報告（最終報告は 30 行以内）
報告ファイル out/agents/{issue}-{仕事}/report.md に詳細（変えたファイルと理由・実行したコマンドと結果・止めた理由・残るリスク）を書く。
親（設計席）への最終メッセージは次の形だけで、30 行を超えない:
  Issue / 規則 ID:
  変更したファイルと振る舞い: {ファイル名と 1 行ずつ}
  実行した検証コマンドと結果: {コマンド → exit code と数字（テスト n/n・分岐 x%）}
  報告ファイル: out/agents/{issue}-{仕事}/report.md
  ログ: out/agents/{issue}-{仕事}/gate.log
  Draft PR: #{N} / HEAD {sha}
  Waivers: none | WVR-NNNN
  残るリスク: {1〜3 行}
本文・差分・テストの全文・ログの全文を最終メッセージに貼らない。

## やらないこと
- 一覧に無いファイルの編集、閾値・除外・重大度の変更（QLT-010）、`planned` を `active` と書くこと（ADR 0001）
- 別の Issue の修正を同じ枝に混ぜること
- 2 回目の差し戻しをこの席で受けること（新しい席が受ける）
```

## 2. 差し戻しの席の型（追加で入れる）

```text
この席の仕事は Draft PR #{N} への差し戻し 1 命題「{命題}」だけである。
- 読むもの: 前の席の報告ファイル {パス}、レビューの所見 {S-n の本文}、差分は `git diff main...HEAD -- {ファイル}` の該当ファイルだけ
- 再実行する検査は {1 集合}（フルゲートは最後に 1 回、ログはファイルへ）
- 命題の外は直さない。直したくなったら報告ファイルの「気づき」に書くだけ
```

## 3. 設計席の側で守ること

- 席を立てる**前に**指示書を書き切る。走らせてから SendMessage で足さない（足したくなったら新しい席）。
- 報告は 30 行の最終メッセージだけ読んで受理の判断を始め、詳細は報告ファイルを**必要な範囲だけ**読む。
- 枠の減りを疑ったら、手を増やす前に transcript の usage（cache_read / output / 最大文脈 / ターン数）を席ごとに集計する。
  数字で言えないうちは手を増やさない。
- Opus 5.5 は試行扱い（ADR 0034 決定 3-5）。実装席で 1 日走らせ、枠の減りを見てから決める。
- 起動した席は日報に「仕事・model・ターン数・報告ファイル」を 1 行で残す。
