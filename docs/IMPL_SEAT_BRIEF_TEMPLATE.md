# 委任する場合の指示書 — NeNe Folio

既定は対話席の単体実行。必要な読み取り専用の独立レビュー、またはhideが明示した分担を行う場合だけ使う。
判断の正本は [ADR 0043](adr/0043-current-instructions-and-single-agent.md)。ファイル名は既存リンクのため維持する。
項目は仕事に合わせて短く記載する。テンプレートの利用自体を委任の理由にしない。

## 委任前に決めること

- 委任の根拠: 独立レビューが必要な理由、またはhideのどの指定をどの範囲で適用するか。
- 目的・完了条件: 何を確認/変更し、どこまで終えたら報告するか。
- 権限と対象: 読み取り専用か、編集を許可するファイルはどれか。使うworktreeの絶対パス。
- 参照先: 対象Issue/PR、該当する正本・ADR、確認対象のコードや証跡。
- 検証: QLT-008 / QLT-012に従い、完成時にまとめる対象と検出する誤動作、再利用する既存結果と関係入力、未測定の条件を決める。
  途中診断が必要な理由と、統合時の必須CIを担当する席を明記する。
- 成果物・整理: 報告先、保持する証跡、一時物の終了時整理、ブランチ/commitの保持。

## 指示書の例

```text
NeNe Folioの {仕事} を担当する。
根拠と範囲: {必要な独立レビューの理由 / hideが指定した分担と適用範囲}
目的・完了条件: {具体的な到達点}
Issue / PR / 規則ID: {対象}
読むもの: {正本・ADR・コード・証跡の必要な範囲}
作業場所: D:/NeNeFolio/worktrees/{issue}-{名前}
権限: {読み取り専用 / 編集許可されたファイル一覧}
検証: {完成時の対象コマンドと検出する誤動作、再利用する証跡と関係入力、未測定の条件}
実行時点: {完成時 / 理由付きの最小途中診断}。統合時の必須CI担当: {席}
報告先: D:/NeNeFolio/agents/{issue}-{仕事}/report.md
保持・整理: {恒久成果物、一時物、整理を担当する席}

製品コードを変更する場合はAGENTS.mdの必読・正典経路・品質ゲートに従う。
読み取り専用のレビューでは変更や製品テストを行わず、所見の根拠となるファイル/行を示す。
編集する場合は絶対パスを使い、本体main・他の作業木・対象外ファイルへ書かない。
追加範囲が必要になったら理由を対話席へ伝える。対象外を独断で修正しない。
長いログはファイルへ保存し、結果・失敗箇所・残る不確実性を簡潔に報告する。
実行していない検査を成功扱いにしない。成功した対象検証はQLT-012の関係入力が不変なら繰り返さない。
対象commitまたは入力の識別、コマンド・結果・範囲・環境条件・証跡を残す。担当交代だけで再実行しない。
```

## 受理と完了

対話席は所見と実出力を確認して受理する。実装を委任した場合、検証とDraft PRの要否を最初に明記する。
PR本文は `.github/PULL_REQUEST_TEMPLATE.md` の欄名を維持し、統合は `tools/merge-pr.ps1` を使う。
head・タイトル・本文を確定してからReadyにし、最終headの必須CI成功を要求する。結果追記だけの本文編集でCIを再起動しない。
対象検証までの到達点と、統合・必要反映まで済んだ完了を区別する（[ADR0044](adr/0044-tests-at-completion-and-integration.md)）。
作業木と一時物は統合・必要反映・証跡収載後にワークフロー§2の確認をして整理する。ブランチとcommitは残す。

報告には対象、所見または変更点、実行コマンドと結果、証跡、未確認事項、残した一時物と理由を含める。
報告ファイルを書けなかった場合は、その事実と同じ要点を最終メッセージへ残す。
