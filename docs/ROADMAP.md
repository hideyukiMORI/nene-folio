## 今回の指定

hideは11月14日に次の3機能を希望し、今回は「まずロードマップと仕様を整理する」と指定した。

- お気に入りマークを付け、お気に入りを優先表示する。
- タグを作成し、Markdownに付けて管理・フィルターする。タグはMarkdown内のfront matterに保存する。
- fzf/Telescopeのようなファイル検索・live grep・プレビューへ、サイバーなアニメーションを取り入れる。
  最初の検索対象はFolio内の全ノート。

操作・保存・受け入れ条件の案は[ノート整理と検索の仕様案](plans/2026-11-14-note-discovery.md)へ集約する。
下の順序は主担当の推奨で、hideが実装順や公開版を確定したものではない。
11月10日の「次版はNibの開発が落ち着いてから」という判断に対し、今回許可された範囲は計画整理まで。

## 推奨する順序

| 段階 | 利用者に届くもの | 次へ進む条件 |
| --- | --- | --- |
| 1. お気に入り | 星の付け外し、優先表示、お気に入りだけの絞り込み | 元の並び順と本文を保ち、改名・移動・再起動後も指定が残る |
| 2. タグ | 作成・付与・解除・管理、front matterへの保存、タグの絞り込み | 既存メタデータ・本文・Undoを壊さず、単票/ZIPの持ち出しでもタグが残る |
| 3. 検索とプレビュー | 名前のあいまい検索、本文のlive grep、一致行のプレビュー、星・タグとの組合せ | 最新入力の結果だけを表示し、候補移動と確定操作を区別する |
| 4. 検索の演出 | 開閉・選択移動・処理表示のサイバーなアニメーション | 入力を待たせず、動きを減らす設定や高コントラストでも操作できる |

3と4は同じ検索機能の段階。演出は機能の設計時から考慮し、結果と操作が成立した段階で仕上げる。
お気に入りとタグは検索の絞り込みにも用いるため、先に保存と管理の意味を固める。

## Aboutと次版へ持ち越すもの

Aboutは「このアプリについて」の情報画面。過去の[11月10日引き継ぎ](handoffs/2026-11-10.md)には
「次版（About含む）」という検討案があり、表示項目・配置・受け入れ条件を確定した記録は見つかっていない。

今回の提案は、設定からアプリ名・版・著作権/ライセンス・第三者通知・公式リンクを確認できる面。
版は既存の単一ビルド入力を使う（FR-014 / [ADR0045](adr/0045-single-version-and-verified-release-bundle.md)）。
具体的な配置とリンクは実装のIssueで決める。アプリの自動更新機能を含めない。

通常exeへ反映済みの書体修正 #783 は、公開済み1.3.2のZIP/MSIX・Store版には未収載。
次版の範囲を決める際に収載を確認する。新3機能を全部そろえるまでこの修正の公開を待つ、という決定はしていない。

## MarkdownとMermaidの整理

10月31日の[拡張候補一覧](quality/2026-10-31-markdown-scope.md)は当時の記録。
その後に実装されたものを、新規予定として数え直さない。

| 分野 | 現在の対応 | 残る候補・今回の扱い |
| --- | --- | --- |
| Markdownの構文 | 見出し、強調、リスト/引用の入れ子、チェック表示、表、リンク、画像等 | 字下げコード、参照形式link/image、裸URL、脚注、定義リスト、数式、目次等は候補。実装順未定 |
| コードの色分け | C/C++、JS/TS、Python、JSON、Shell、PowerShell、SQLの基本字句色分け、言語ラベル | 対応言語や精度の拡張、言語選択UI、コピー操作は別候補。Markdown原文全体の編集時色分けとは別 |
| タグ用メタデータ | front matterの専用処理は未対応 | 今回のタグ機能に必要な読み書き・表示を段階2で設計。一般的なYAML編集機能まで採用したわけではない |
| Mermaid | flowchartとsequenceDiagram、主要形状、サブグラフ、注釈・分岐/反復等 | 既存2種の構文・配置の改善と、新しい図種の追加を分けて検討。クラス図・状態図・ER図・ガント等は未対応で優先順位未定 |

「mdのシンタックス強化」は、Markdown記法の対応追加とコードブロックの色分け改善を区別して扱う。
どちらも拡張候補だが、現時点で次版への確定収載や全CommonMark/GFM互換を約束していない。
Mermaidも全記法互換・Mermaid.jsと同じ見た目を目標として確定していない。
まず新3機能の計画を整え、構文や図種は実際に必要な例をもとに後続Issueへ分ける。
