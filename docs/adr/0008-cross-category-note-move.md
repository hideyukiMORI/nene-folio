# ADR 0008 — 別カテゴリへの移動は md の rename が先で、両方の index.json はそれに追随し、同名は拒む

- 状態: 受理
- 日付: 2026-09-10
- Issue: #15
- 影響する規則: ARC-002 / ARC-003 / ARC-004 / ARC-005 / ARC-007 / ARC-008 / ARC-009 / ARC-010 / ARC-011 / C-002 / C-003 / C-005 / C-006 / C-012 / CNF-002 / QLT-009 / QLT-013

## 文脈

ADR 0007（Issue #13）はノートの並び替えを同じカテゴリの中に限り、別カテゴリの上で離しても自分のカテゴリの端に寄せた。
SPECIFICATION 第 2 節は別カテゴリへの移動を「初版を使ってから判断」としており、施主が 2026-09-10 に初版を使って
「移したい」と判断した。

カテゴリ = ディレクトリ（FR-002）なので、別カテゴリへの移動は **md ファイルの移動**である。関わるものが 3 つ
（md ファイル・移動元の `index.json`・移動先の `index.json`）あり、1 回の原子的な置き換えでは揃えられない。
一方で FR-008 の照合規則（`index.json` に無い md は末尾に付け、`index.json` にあって無い md は落とす）があるので、
**md の場所さえ正しければ台帳は次回の起動で自己修復する**。この性質を順序の根拠にする。

既存の道具: `MoveFileExW` は同じボリューム内では rename で、`MOVEFILE_REPLACE_EXISTING` を付けなければ移動先に同名が
あると失敗する（NTFS は大文字小文字を区別しないので、大文字小文字だけ違う名前も失敗する）。`name_list` の重複判定は
バイト単位（大文字小文字を区別する）。C-012 は引数 4 を上限とする。

## 決定

**別カテゴリへの移動は md ファイルの rename を先に行い、成功したら索引をそれに合わせ、移動先・移動元の順で `index.json` を
書き戻す。移動先に同じ名前のノートがあれば移さない。台帳だけ書けなかったときは「移したが台帳は次回の起動で揃う」と
利用者に伝える。**

具体的には:

1. **ドロップ先の意味を広げる。** ノート行を掴んだとき、`drawer_layout_drop` はポインタのある塊（カテゴリ行と展開中のノート行。
   塊の境界は隣り合う塊の間の中ほど）のカテゴリを移動先とし、その中のノート行の中点で数える。折り畳んだカテゴリなら末尾
   （台帳のノート数）。自分のカテゴリなら ADR 0007 の決定 1 のまま。`drop_target.category` は**移動先**のカテゴリ番号になる
2. **意図は 1 本に統合する。** `folio_state_move_note(state, struct note_ref from, struct note_ref to)`。`note_ref` は
   カテゴリ番号とノート番号の組（完全型・単独ファイル）。引数 4 の上限（C-012）を守るための型で、同じカテゴリなら ADR 0007 の
   並び替え、違えば移動
3. **順序。** (a) 移動先の台帳に同じ名前があれば `FOLIO_STATE_NAME_TAKEN` で何もしない → (b) 新しい 2 つの台帳
   （`note_ledger_removed` / `note_ledger_inserted`）をメモリに作る（記憶不足ならここで止まる）→ (c) `persistence_port.move_note`
   で md を rename（失敗なら `FOLIO_STATE_STORE_FAILED`・何も変えない）→ (d) 索引と選択中の番号を新しい台帳に差し替える
   （md は既に移っているので、表示はファイルに従う）→ (e) 移動先の `index.json` → 移動元の `index.json` の順に書き戻す。
   どちらかが書けなければ `FOLIO_STATE_LEDGER_STALE`（「ノートは移しましたが、台帳（index.json）を書き戻せませんでした。
   次回の起動で揃います。」）。索引は (d) のまま
4. **ポート。** `move_note(adapter, from_category, note, to_category)`。adapters は `MoveFileExW(from, to, MOVEFILE_WRITE_THROUGH)`
   （`MOVEFILE_REPLACE_EXISTING` 無し）で移す。移動先に同名があれば `PERSISTENCE_UNWRITABLE`。コピーと削除の 2 段にはしない
5. **編集中でも移せる。** 本文は RichEdit が持ち、application は `note_ref` を付け替えるだけ（ADR 0007 の決定 7 と同じ）。
   右ペインの頭（番号・カテゴリ名・色）は親の再描画で追随する
6. **UI は変えない（最小）。** `drawer_window` は `drop_target` を `note_ref` に写して意図を出すだけ

## 強制

- モジュール境界は ARC-002 / ARC-003 が **active**。`note_ref` は 1 ファイル 1 型（CNF-002）
- 順序 (a)〜(e) は `tests/unit/state_tests.c` が偽物アダプタの呼び出し順で固定する（rename の前に台帳を書かない・失敗時に不変）
- ドロップ先の意味は `tests/unit/layout_tests.c` の境界のテストが正本
- 分岐 90% は QLT-009 が **active**。実機は `docs/quality/gate-proofs.md` 第 5-g 節（QLT-013）

## 結果

得る: ノートをカテゴリ間で動かせる。途中で落ちても md は移動元か移動先のどちらかに必ずあり、台帳は次回の起動で揃う。
同名の上書きは起きない。

失う・残る:

- 🔴 (e) が失敗した直後の `index.json` は md の場所と食い違う。表示はファイルに従っており、次回の起動で揃う。
  それまでに外部のツールが `index.json` を読むと古い
- 「何もしない」の原則（書けなければ状態を変えない）は、この意図に限り (c) の後では成り立たない。ファイルが主で台帳が従
- 大文字小文字だけ違う名前は台帳では別名だが OS では同名なので、(a) を通って (c) で失敗する。文言は「書き戻せなかった」になり、
  同名が理由だとは伝わらない。事故駆動で文言を分ける
- 別ボリュームへの移動は起きない（`data/` は 1 つのディレクトリ木）
- 移動の取り消し（Undo）は無い。戻すにはもう一度ドラッグする

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 台帳を先に書き、最後に md を移す | md の移動が失敗すると、表示が実体と食い違ったまま次回の起動まで残る。ファイルが主 |
| コピーしてから元を削除する | 同じボリューム内の rename は原子的で、コピー＋削除は途中で 2 つ残る。ADR 0004 の `MoveFileExW` の流儀のまま |
| 同名があれば上書きする | 利用者のノートを黙って消す。FR-015 / ARC-009 に反する |
| 同名があれば `名前 (2)` に改名する | 改名は別の機能。ノートの名前はファイル名そのもの（FR-003） |
| 移動先の台帳が書けなければ md を戻す（補償） | 戻す rename も失敗しうる。自己修復する照合（FR-008）があるので、補償の経路を増やさない |
| 折り畳んだカテゴリへは落とせない | 展開しないと移せないのは不便。末尾へ入れ、台帳のノート数を配置が持てば線の位置も決まる |
| `folio_state_move_note` を 5 引数にする | C-012 の上限 4 を超える。`note_ref` で 3 引数にする |
| 別の意図 `folio_state_transfer_note` を足す | 同じドロップから 2 種類の意図を UI が選ぶことになり、判断が UI に落ちる（ARC-011） |
