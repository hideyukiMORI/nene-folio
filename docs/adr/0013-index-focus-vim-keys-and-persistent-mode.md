# ADR 0013 — フォーカスは索引と本文の 2 区画、vim の鍵で選択を動かし、モードを保ったまま保存して次のノートを開く

- 状態: 受理
- 日付: 2026-09-10
- Issue: #24
- 影響する規則: ARC-004 / ARC-005 / ARC-011 / C-002 / C-005 / C-012 / C-014 / C-017 / QLT-009 / QLT-013

## 文脈

索引の操作はマウスだけで、鍵は主窓の Escape（閲覧中なら窓を閉じる・ADR 0006）・↑↓ / PgUp / PgDn（スクロール・ADR 0009）・
RichEdit の Ctrl+S だけ。ADR 0009 は「ドロワーはフォーカスを取らない」と決めた（編集中の Ctrl+S を RichEdit に残すため）。
別ノートを選ぶと編集中の本文は保存され**閲覧へ戻る**（ADR 0006 の決定 5・`folio_state_end_edit`）。

施主は 2026-09-10 に (a) 索引にフォーカスがあるときは vim の鍵で上下に選択が動き、右ペインが追随する、(b) フォーカスが移るときは
自動保存する、(c) 「保存後に閲覧へ戻すと索引の移動がスムーズでない」ので**モードは保ったまま**、(d) Escape は索引へ戻る鍵にする、
と求めた。誤保存の保険は FR-017（ADR 0012）で入った。

現行の Win32 のフォーカスは「主窓（索引側の鍵を受ける）」と「RichEdit（本文）」の 2 つしか無く、これがそのまま (a) の 2 区画になる。

## 決定

**フォーカスの区画は Win32 のフォーカスそのもの（主窓 = 索引・RichEdit = 本文）で、application は「どのノートが選ばれているか」と
「ペインのモード」を持つ。索引の鍵は選択を動かす意図になり、主窓が「編集中なら保存 → 選択 → 同じモードで開く」の順を 1 か所で行う。**

具体的には:

1. **区画。** 索引 = 主窓にフォーカス、本文 = RichEdit にフォーカス。クリックした側が取る（ドロワーのクリックは主窓へ `SetFocus`。
   ドロワー自身はフォーカスを取らない・ADR 0009）。起動時は主窓。閲覧の本文をクリックすれば RichEdit が取る
2. **索引の鍵（主窓の `WM_KEYDOWN` / `WM_CHAR`）。** `j` / `k` = 次／前の**ノート行**へ選択を動かす（カテゴリ行は飛ばす・折り畳んだ
   カテゴリの中は飛ばす・端で止まる）。`g` `g` = 最初のノート、`G` = 最後のノート。`h` = 選択中のノートのカテゴリを折り畳む、
   `l` = 展開する（既にそうなら何もしない・書き戻しは `expanded` の経路）。`Enter` = 本文へフォーカス。↑↓ / PgUp / PgDn は
   これまでどおりスクロール。`gg` の 2 打は UI が「直前の鍵が `g` だった」ことだけ覚え、他の鍵で忘れる。Escape は索引では何もしない
3. **本文の鍵。** RichEdit の `EN_MSGFILTER` で `Esc` を受け、編集中なら保存（`folio_state_store_note`・モードは変えない）して主窓へ
   `SetFocus`。Ctrl+S はこれまでどおり。**主窓の Escape で窓を閉じる動きは無くす**（閉じるのは Alt+F4 と閉じる操作だけ）
4. **モードの持続。** `pane_mode` はペインの状態として残る。ノートを切り替えるとき（鍵でもクリックでも）、主窓は
   (i) 編集中なら本文を取り出して `folio_state_store_note`（失敗なら理由 1 行で止まる・選択は動かない）、
   (ii) `folio_state_select_note`、(iii) 編集中なら新しい本文を RichEdit へ平文で流し（フォーカスは動かさない）、閲覧なら RTF を流す。
   ADR 0006 の決定 5（選択で閲覧へ戻る）はこれで置き換える。`folio_state_end_edit`（閲覧へ戻る）は「閲覧」の札と `WM_CLOSE` にだけ残る
5. **意図。** application に `folio_state_select_adjacent(state, direction)`（`enum folio_step` = NEXT / PREVIOUS / FIRST / LAST。
   展開中のカテゴリのノートだけを台帳の順に辿る。無ければ `NO_SUCH_NOTE`）と `folio_state_set_category_expanded(state, index, expanded)`
   （同じなら書かずに READY）を足す。UTF-16 を受けるのは `store_note` / `end_edit` の 2 本のまま（C-014 の例外を増やさない）
6. **見える位置へ寄せる。** 鍵で選択を動かしたあと、core の `drawer_layout_reveal(layout, category, note)` が「選択の行が頭の帯の下から
   下端までに収まる最小のスクロール量」を返し、application の `folio_state_reveal_selection(state, metrics)` がそれを要求量にする。
   クリックでは寄せない（ADR 0009 の却下案は鍵でだけ採る）
7. **ドロワー → 主窓。** ノート行のクリックは `folio_message_select_note`（`wParam` = カテゴリ・`lParam` = ノート・同期）で主窓へ渡し、
   主窓が 4 の順を行う。ドロワーは `folio_state_select_note` を直接呼ばない（保存の順を 1 か所にする）
8. **フォーカスの印。** 選択行の右端の角（カテゴリ色の四角）を、索引にフォーカスがあるときは塗り、本文にあるときは枠だけにする。
   主窓の `WM_SETFOCUS` / `WM_KILLFOCUS` でドロワーを描き直す。他の印は足さない（案2「堅」）

## 強制

- 判断（次のノート・寄せる量・同じなら書かない）が core / application にあることは `tests/unit`（`layout_tests.c` の `reveal`・`state_tests.c` の
  `select_adjacent` / `set_category_expanded`・保存 → 選択の順と失敗時の不変）が正本。鍵の解釈が UI の変換だけであることはレビュー事項（ARC-011）
- 分岐 90% は QLT-009 が **active**
- 実機は `docs/quality/gate-proofs.md`: 起動直後の `j` で最初のノートが開く／編集のまま `j` で保存されて次が編集で開き RichEdit にフォーカスが無い／
  `Esc` で索引へ戻り本文が保存されている／`gg` `G` `h` `l`／見えない位置のノートへ `G` で寄る／Escape で窓が閉じない／保存に失敗したら選択が動かない

## 結果

得る: マウス無しで索引を辿りながら読み書きできる。保存の順序が主窓の 1 か所に集まり、クリックと鍵で振る舞いが揃う。
フォーカスの区画に新しい状態を足さず、Win32 のフォーカスをそのまま使う。

失う・残る:

- 編集のまま `j` を連打すると、通ったノートは（本文が変わっていれば）すべて保存される。誤保存の逃げ道は FR-017 の履歴
- Escape で窓が閉じなくなる。慣れた人には変化
- `h` / `l` は選択中のノートのカテゴリにだけ効く。カテゴリ行そのものにカーソルは無い
- 高速な連打で保存が追いつかないとき、1 回ごとに同期で保存するので鍵が詰まる（体感は実機で見る）
- 本文に印は付けない。RichEdit のキャレットが唯一の手がかり
- `WM_CHAR` で文字を受けるので、IME が ON のときの `j` は未確定文字になり索引には届かない（英数へ切り替える。記録のみ）
- 実装で足した判断（2026-09-11・PR の前に記録）: `h` / `l` が「選択中のカテゴリ」を要るので、application に問い合わせ `folio_state_selection(state, note_ref *)`
  を 1 本足した（表示値 `pane_title_view.ordinal` を索引に使わない・ARC-011）。索引をクリックすると区画が索引へ移り Ctrl+S が RichEdit に
  届かなくなるので、**主窓の側でも Ctrl+S を受けて編集中なら保存する**（両区画で Ctrl+S が効く。ADR 0009 の決定 5 の理由はこれで役目を終えた）。
  ドロワーからの通知は `folio_message_select_note` 1 本になり、`edit_flush` / `selection_changed` は消えた。
  「編集」の札は `begin_edit` → 本文の流し込みの順なので、流し込みの確保に失敗したときだけ「モードは編集・RichEdit は読み取り専用」の中間状態が残りうる（理由 1 行は出る）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| application に `enum folio_focus` を持たせる | Win32 のフォーカスと二重になり、ずれたときにどちらが正か決まらない。区画は OS の状態で足りる |
| 保存後に閲覧へ戻す（ADR 0006 のまま） | 施主が「索引の移動がスムーズでない」と退けた。モードはペインの状態 |
| ドロワーがフォーカスを取り自分で鍵を受ける | ADR 0009 と同じ理由（編集中の Ctrl+S）。主窓が受ける |
| `j` / `k` でカテゴリ行にも止まる | 止まるたびに右ペインが変わらない行ができ、vim の `j` の手触りと違う。`h` / `l` で折り畳みは足りる |
| 選択の切り替えを非同期（`PostMessage`）にする | 保存の失敗で選択を止められない。同期で 1 か所 |
| クリックでも見える位置へ寄せる | 見えている行を押しているので寄せる理由が無い |
| `Esc` で編集を抜けて閲覧へ | 施主の (c) に反する。`Esc` はフォーカスだけを動かす |
