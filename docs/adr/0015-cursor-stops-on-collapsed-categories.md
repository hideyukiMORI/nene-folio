# ADR 0015 — 索引のカーソルは、ノート行と「見えるノート行を持たないカテゴリ行」に止まる

- 状態: 受理（ADR 0013 の決定 2「`j` / `k` はノート行だけを辿る」を置き換える）
- 日付: 2026-09-11
- Issue: #32
- 影響する規則: ARC-004 / ARC-005 / ARC-011 / C-002 / C-005 / C-012 / QLT-009 / QLT-013

## 文脈

ADR 0013 は `j` / `k` が**ノート行だけ**を辿り、カテゴリ行は飛ばすと決めた（「止まるたびに右ペインが変わらない行ができ、vim の `j` の
手触りと違う」）。施主が実機（main `ea17d45`）で使い、「カテゴリを閉じると `j` / `k` ではそのカテゴリにフォーカスできなくなる」と指摘した
（2026-09-11）。折り畳んだカテゴリは中にノート行が無いので飛ばされ、`l` で開き直す手段が鍵に無い。`h` で畳んだ直後だけは選択中のノートが
その中に残っているので `l` が効くが、別のノートへ動いた時点で届かなくなる。

application は「選択中のノート」（`selected` / `selected_category` / `selected_note`）を持ち、右ペインはそれに従う。ドロワーはカーソルの印を
選択行の右端の角（カテゴリ色の四角。索引に区画があれば塗り・本文なら枠）で描いている。

## 決定

**索引のカーソルは「ノート行」と「見えるノート行を持たないカテゴリ行（折り畳んでいる、またはノートが 0 本）」に止まる。
展開中でノートを持つカテゴリ行には止まらない。カーソルがカテゴリ行にあるあいだ、選択中のノートと右ペインは変わらない。**

具体的には:

1. **状態。** application に「カーソル」を足す: `enum folio_cursor_kind`（`FOLIO_CURSOR_NOTE` / `FOLIO_CURSOR_CATEGORY`）と、カテゴリ行のときの
   カテゴリ番号。`FOLIO_CURSOR_NOTE` のときのカーソルは選択中のノートそのもの（別の番号は持たない）。何も選んでいなければカーソルは無い
2. **辿り方。** `folio_state_select_adjacent` の歩みは「止まる行」の列を台帳の順に辿る: カテゴリごとに、見えるノート行があればそのノートを順に、
   無ければ（折り畳み・ノート 0 本）そのカテゴリ行を 1 つ。NEXT / PREVIOUS は端で止まり、FIRST / LAST は列の両端。ノートに止まれば
   `select_note`（右ペインが変わる・モードは保つ）、カテゴリ行に止まればカーソルだけを動かす（右ペインは変えない・保存も要らない）
3. **`h` / `l`。** カーソルがノートなら、そのノートのカテゴリに効く（ADR 0013 のまま）。`h` で畳むと**カーソルはそのカテゴリ行へ移る**
   （選択と右ペインはそのまま）。カーソルがカテゴリ行なら `l` で展開し、選択中のノートがその中にあればそのノートへ、無ければ最初のノートへ
   カーソルが移る（ノートが 0 本なら行に留まる）。`h` はカテゴリ行では何もしない（既に畳んでいるか空）
4. **`Enter`。** カーソルがカテゴリ行なら何もしない。ノートなら本文へ（ADR 0013 のまま）
5. **クリック。** ノート行のクリックは選択（カーソルはそのノート）。カテゴリ行のクリックはトグル（ADR 0004 のまま）で、カーソルは動かさない
6. **寄せる。** `folio_state_reveal_selection` は選択ではなくカーソルの行を見える位置へ寄せる（名前は `reveal_cursor` に改める）
7. **描画。** カーソルがカテゴリ行のとき、その行の右端に選択行と同じ角の四角（カテゴリ色・索引に区画があれば塗り・本文なら枠）を描く。
   折り畳みの `+` / `−` の印との重なりは、四角を `+` / `−` の左に置いて避ける。選択中のノートの面と角はそのまま（見えていれば）
8. **表示値。** `drawer_row` に `cursor`（bool）を足し、`drawer_layout_select` の代わりに `drawer_layout_mark(layout, selection, cursor)` で
   選択とカーソルの両方に印を付ける。UI は `row.selected` で面を、`row.cursor` で角を描く

## 強制

- 止まる行の列（折り畳み・空・展開の混在・端・未選択）と `h` / `l` の移り先は `tests/unit/state_tests.c` が正本。`drawer_layout_mark` は
  `tests/unit/layout_tests.c`。鍵の解釈が UI の変換だけであることはレビュー事項（ARC-011）
- 分岐 90% は QLT-009 が **active**
- 実機は `docs/quality/gate-proofs.md`: `h` で畳んだあと別のノートへ動き、`k` / `j` で畳んだカテゴリ行に止まり、`l` で開いて中のノートへ移ること／
  空のカテゴリに止まること／カテゴリ行に止まっているあいだ右ペインが変わらないこと／`G` で末尾が折り畳んだカテゴリならそこに止まること

## 結果

得る: 折り畳んだカテゴリも空のカテゴリも鍵で届き、`h` / `l` で開閉できる。展開中のカテゴリ行には止まらないので `j` の手触りは変わらない。

失う・残る:

- カーソルがカテゴリ行にあるとき、右ペインは「前に選んだノート」のまま。カーソルと右ペインがずれて見える瞬間がある（印で区別する）
- 展開中でノートを持つカテゴリ行には止まれない。畳むには中のノートに立って `h`
- `Escape` / `Enter` の意味はカテゴリ行では無い
- 実機は DPI 120 の合成入力でだけ見る

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| すべてのカテゴリ行に止まる | 展開中のカテゴリで右ペインが変わらない行が毎回挟まり、vim の `j` の手触りが崩れる（ADR 0013 の理由のまま） |
| `h` / `l` を「前後のカテゴリへ移る」に変える | 折り畳みの鍵が無くなる。施主の希望（`h` / `l` = 折り畳み）と違う |
| 折り畳んだカテゴリを `j` で通過するときに自動で展開する | 利用者の意図なしに台帳を書き戻す。折り畳みは利用者が決めたもの |
| カテゴリ行に止まったとき右ペインを空にする | 見ていた本文が消える。編集中なら保存の判断まで要る。右ペインは変えない |
| カーソルを UI の一時状態にする | `h` / `l` の対象と寄せる行が application の判断になるので、application が持つ（ARC-004） |
