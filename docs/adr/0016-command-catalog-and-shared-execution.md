# ADR 0016 — Ex・パレット・既存ショートカットは共通の操作へ変換し、一つの経路で実行する

- 状態: 受理
- 日付: 2026-09-12
- Issue: #37（全体計画 #36）
- 影響する規則: ARC-001 / ARC-003 / ARC-004 / ARC-005 / ARC-008 / ARC-010 / ARC-011 / C-002 / C-005 / C-014 / C-017 / QLT-009 / QLT-013

## 文脈

hide は INDEX の `:` による基本 Vim コマンドと、Ctrl+P から同じ操作を呼べるパレットを求めた。
既存の Ctrl+S は主窓と RichEdit の二つの入口から `store_body` を使い、`WM_CLOSE` は `leave_edit` を経て保存後に閉じる。
保存の正本は `folio_state` の UTF-16 検証・改行正規化・同一判定・履歴・原子的な書き戻しである。
新しい入口ごとに保存を書き直すこと、パレットを開いて RichEdit を流し直すことは、保存失敗時の保護と Undo を壊す。

## 決定

**core の閉じた操作 ID と一つの登録表を Ex 解析とパレットが共有し、主窓が操作 ID を一つの dispatcher で実行する。**

1. 初期の操作 ID は保存・未保存なら拒否する終了・保存して終了・未保存を破棄する終了・ヘルプ。
   Ex 別名は `w/write`、`q/quit`、`wq/x`、`q!`、`help`。先頭の `:` は省略可能、前後の ASCII 空白は除く。
   大文字小文字は区別し、余計な引数・未知語・空入力を成功と扱わない。UI は空入力の Enter を取消として扱ってよい。
   パレットは同じ登録表の操作 ID を列挙し、検索は表示名と Ex 別名を対象にする。未実装の操作は登録しない。
2. 登録表と解析は OS 非依存の core の純関数。安定した ID を表示文から分離し、初期登録表の日本語ラベルは #38 で同じ ID の翻訳表へ移す。
   application が本文比較と操作可否の意味を判断する。UI が HWND を操作する dispatcher は `folio_window` に一つだけ。
   Ctrl+S は保存、×と `WM_CLOSE` は保存して終了の ID へ変換する。閉じた操作 ID の分岐に default は書かない。
3. INDEX の `WM_CHAR` で `:`、主窓と RichEdit の `WM_CHAR` で Ctrl+P（0x10）を受ける。
   本文や入力欄の `:` は通常の文字。パレットと Ex 入力は主窓所有の一時的な UI 状態として、開き方・選択行・入力・戻り先 HWND を持つ。
   application にフォーカスの状態は追加しない（ADR 0013 の決定 1 を入力面まで拡張する）。
4. 入力面を開く／閉じるだけでは保存・モード変更・本文の流し直しをしない。元の Win32 フォーカスを覚え、
   Esc と成功した保存のあとに元の区画へ戻す。INDEX からの Ex は INDEX に戻る。
   Ctrl+P の再打鍵では二つ目の入力面を作らない。IME の変換中の Enter を操作実行として奪わない。
5. `:w` は選択があれば既存の保存の意図を使い、閲覧中は変更なしの成功。未選択なら既存の NOTHING_SELECTED。
   保存後の mode と RichEdit / Undo / キャレットを維持する。入出力・文字変換・確保の失敗は既存の `failure_box` に集約し、入力面と本文を保持する。
6. `:q` は閲覧中／未選択なら終了。編集中は正規化後の本文が保存済み本文と同じ場合だけ終了。
   新しい問い合わせ `folio_state_note_changed` は SAME / CHANGED の閉じた値を返す。変換と正規化は保存と共有し、
   問い合わせは mode・保存済み本文・履歴・ファイルを変更しない。別の dirty flag は持たない。
   CHANGED は追加の `FOLIO_STATE_UNSAVED_CHANGES` へ変換し、入力面に非モーダルで表示する。
   文言は `folio_state_failure_line` から得て第二の意味定義を作らない。未選択など操作の拒否も入力面内に表示する。
7. `:wq` / `:x` と× / Alt+F4 は既存の保存成功後だけ終了する。`:q!` は現在 RichEdit 上の未保存変更だけを破棄し、保存なしで終了する。
   既に自動保存したファイルや履歴は巻き戻さない。パレット表示は「終了」「保存して終了」「未保存変更を破棄して終了」を明確に分ける。
8. `:help` は同じパレットで登録表から現在サポートする操作と別名を表示する。別のヘルプ窓・コマンド集合を作らない。
   未知コマンドと操作の拒否は入力面内の状態表示で説明し、入力を保持する。入出力・文字変換・確保の失敗は既存の `failure_box` の経路。
9. 閉じるアイコンは右ペインの頭の右端。描画・当たり判定・caption 判定が同じ矩形関数を使う。
   札とパンくずの幅はその矩形を除いて計算し、最小 560×360（96 DPI）を維持する。設定アイコンは #38 の機能と同時に足す。
10. ADR 0006 / 0013 の UTF-16 公開入口の制限は、保存の `store_note` / `end_edit` に加え、
    本 ADR の読み取り専用の本文比較問い合わせ 1 本を許す。変換の実装は core の既存一経路のまま。
    ADR 0006 の破棄なしは明示的な `:q!` だけ置き換え、通常の×と本文 Esc の意味は維持する。
11. 終了が成功したら HWND へのフォーカス復帰を行わない。子からの同期実行通知中に主窓ごと破棄され得るため、
    通知の呼び出し後に子の状態や HWND を参照しない。保存して終了に失敗したら入力面と本文を保持する。

実装前のデザイン相談で足した判断（2026-09-12、PR 前）: 未保存拒否のモーダルは打鍵を妨げるため上記の入力面内表示を採用する。
Ex は下端全幅の26pxを初期寸法とし本文の矩形を動かさない。パレットは `min(460, 窓幅 - 64)`、上端76px
（窓高480px未満なら40px）、アイコン当たりは24×24px・右余白16px・間8pxを初期寸法とする（すべて96 DPI）。
実フォント・高 DPI・最小窓で収まらない場合は検証結果に基づき調整し、目視の成否を記録する。

実装レビューで足した判断（2026-09-12、PR 前）:

- 入力面を主窓の背景へ直接描くと、RichEdit・ドロワーの子窓に隠れ、候補クリックも本文へ届く。
  主窓所有の前面の子窓 `NeNeFolioCommandLayer` に入力と候補をまとめる。EDITはその子とし、
  描画はメモリDCで完成してから転送する（C-017）。本文と索引の位置・大きさ・内容を開閉時に変えない。
- 主窓・入力面は `WS_CLIPCHILDREN`、重なる兄弟のRichEdit・ドロワー・入力面は `WS_CLIPSIBLINGS`。
  [Win32の公式Clipping仕様](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#clipping)に従い、
  再描画が前面の入力面やEDITを塗りつぶす経路を作らない。実機での成否は未確認。
- 同じ主窓内で入力面外へフォーカスが移ったら、保存せず入力面を閉じ、新しいフォーカスを奪わない。
  `WM_KILLFOCUS`中には閉じず、内部通知をpostして実フォーカスを再確認する。別アプリへの移動では閉じない。
  Esc・保存成功の戻り先とは分け、面の状態を消す処理は共通にする。
- `:help`とEx内のCtrl+Pは同じ検索可能なパレットへ入力をクリアして切り替える。Help専用の状態や描画は持たない。
- Exは全幅で通常32px、拒否時だけ上へ24pxの状態行を追加する暫定値とした。Consolasの11論理pxと
  EDITの一行に上下の余白を取る判断であり、目視やフォント測定の結果ではない。最小窓・DPI・IME確認を残す。
  現在のパレットは5操作。#38以降で操作を増やす前に、使用可能高さから表示行数と移動範囲を決め直す。

## 強制

- ARC-002 / ARC-003 / ARC-007 / QLT-009 の既存 active ゲートは維持する。
- 操作解析・別名・不正入力・同じ登録表の列挙は `tests/unit/command_tests.c`。
- 本文比較・CRLF/LF・変更あり／なし・孤立サロゲート・問い合わせで保存と mode が変わらないことは `state_tests.c`。
- 問い合わせの新しい確保経路は `allocation_tests.c` に追加し、測定ビルドで失敗させる。
- dispatcher 一か所と HWND の ownership は planned の ARC-001 / ARC-004 / ARC-011 のレビュー事項。
  キー・IME・復帰先・Undo・閉じる・失敗時に窓が残ることは Win32 実機で別に記録する（QLT-013）。
  これらのレビュー事項を、この変更だけで active へ変更しない。

## 結果

入口が増えても保存と終了の意味は操作 ID で固定できる。パレットは本文を流し直さず開閉できる。
`:q` と×は異なる操作であることが利用者に見える。`:q!` は既存の自動保存を過去へ戻すものではない。
設定・行番号・検索・置換は別 Issue の実装時に登録する。Vim 全互換、シェル実行、任意コマンドのスクリプト実行は含めない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| Ex とパレットの各 handler に保存を書く | 同じ操作の第二経路ができ、失敗時の振る舞いがずれる |
| パレット開始時に編集を終了して閲覧へ戻す | hide の mode 持続と Undo 保持に反する |
| EM_GETMODIFY だけで `:q` の可否を判断する | 現在の保存は本文比較が正であり、保存や Undo 後の別フラグが二重の正本になる |
| `:q` も自動保存して終了する | 基本 Vim 操作としての `:q` と `:wq` の違いが消える |
| application に新しい focus enum を持つ | Win32 の実フォーカスとずれる第二の状態ができる |
| 未実装の number / search を候補に表示する | 動かない操作を表示することになる。各機能と同時に登録する |
| `:q!` の前に既存の archive_note を呼んで未保存本文の保険にする | archive_note が写すのはディスク上の本文で、RichEdit の未保存本文は保護できない。別の下書き保存契約が必要になる |
