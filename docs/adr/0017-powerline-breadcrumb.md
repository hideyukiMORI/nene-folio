# ADR 0017 — パンくずをPowerline風の連続した色面で描く

- 状態: 受理
- 日付: 2026-09-13
- Issue: #45（#37 / PR #44の上に積む表示変更）
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / ARC-011 / C-002 / C-012 / C-017 / QLT-013

## 文脈

hideがArtifactの画面案をおおむね了承し、パンくずをVimのPowerlineのようにしたいと希望した。
従来はカテゴリ色の番号・カテゴリ名・`/`・ノート名を別々に描く。ADR 0011は操作札と番号を確保し、
ノート名、次にカテゴリ名の末尾を省略する。リナの案は番号とカテゴリ名の色面を矢印でつなぎ、ノート名を本文地に続けるもの。

## 決定

1. 同じ `draw_breadcrumb` を置き換え、番号→カテゴリ名→ノート名を図形でつなぐ。ADR 0005と0011の
   `/`区切り表現だけを置き換える。選択・保存・フォーカス、右の操作、窓を掴む領域は変えない。
2. 帯44、左余白36、高さ24論理px。通常の内側余白8、矢じり10。割当幅が320論理px未満なら余白4、矢じり6。
   通常幅も最小幅も同じ描画経路を使う。
3. 操作札と×を先に確保し、同じ `breadcrumb_room` で名前の幅を割り当てる。ノート名を先に縮めて
   48論理pxを目安に残し、次にカテゴリ名を縮める。カテゴリ文字の幅が0ならその区画を省き、
   番号→ノートを同じ図形でつなぐ。描画は割当矩形でクリップする。
4. 番号の面は保存されたカテゴリ色。字は相対輝度からコントラスト比が高い白・黒を選ぶ。
   公開する `folio_palette_ink`（ui）がその一経路。[W3CのsRGB相対輝度式](https://www.w3.org/WAI/WCAG21/Understanding/relative-luminance.html)を使う。
   カテゴリ面はdark `#2C2026` / light `#E6DFDB`、字はdark `#D6CFCC` / light `#453A3D`。
   定数は `folio_palette` に置き、ノートには既存の本文地と現在タイトル文字色を使う。
   全体のUbuntuテーマは#38、同梱フォントは#42として扱う。
5. GDIの多角形で描き、専用文字・フォント・画像・外部ライブラリは追加しない。
   右ペインの背景・パンくず・操作札をメモリDCで完成して転送する（C-017）。選択したGDIオブジェクトを
   戻して解放し、既存の子窓クリッピングを維持する。

## 強制と確認

既存のコンパイラ、規約、依存・シンボル、分岐90%ゲートを維持する。配色・幅割当はUI内の描画判断。
通常dark/light、長い名前、未選択、最小窓、カテゴリ色変更、リサイズ、120/144 DPI、パレットとの重なりを確認する。
Chromeは画面案の証拠で、Win32実機（QLT-013）とは別。実機未確認ならDraftへその条件を記録する。

## 却下した選択肢

| 案 | 理由 |
| --- | --- |
| 狭い時だけ旧来の平文へ戻す | 同じパンくずに2つの描画経路を残す |
| 最小窓で操作札を1つに畳む | 見た目変更で既存の操作入口を減らす |
| 常に白字をカテゴリ色へ載せる | 明るいカテゴリ色で番号が読めなくなる |
| Powerlineの特殊グリフを使う | フォント依存と欠落表示を増やす |

## 結果

カテゴリの色とノートの所属が連続した帯になる。狭い時はカテゴリ名全文が見えないので、索引も手がかりになる。
実フォントでの成否は別途確認が必要。保存スキーマ・OSテーマ選択・実行時依存は変わらない。
