# ADR 0018 — 日本語GUIとキーを共通操作へ接続する

- 状態: 受理
- 日付: 2026-09-13
- Issue: #49（採用済み計画 #47）
- 規則: ARC-001 / ARC-004 / ARC-005 / ARC-011、C-002 / C-012 / C-017、QLT-009 / QLT-013

## 文脈と決定

hideが採用した日本語GUIの設計に従い、ADR0016の操作登録表とdispatcherを拡張する。保存・終了・本文比較の契約は維持する。

1. 44pxのペイン頭の下に36pxの操作行を置く。初期表示は「保存」「操作」「ヘルプ」。未実装の新規・検索等は機能と同時に追加する。
2. 「操作」は登録表から生成するWin32の日本語ポップアップメニュー。「保存」「ヘルプ」と既存モード札も同じdispatcherへ渡す。
   メニューの一時HMENUは表示関数が所有し、実行前に破棄する。戻り値0は取消、範囲検証した項目番号から登録表のIDへ変換する。
   色・余白はOS標準のメニューに従う。操作行とパレットは既存テーマで描画する。
3. 登録表へ「編集」と「保存して閲覧」を追加する。編集のEx名は`:startinsert`。閲覧はGUI専用でEx別名0個を許す。
   Vimの別の意味を持つ`:e`、`:view`をモード切替へ流用しない。「終了」は「保存済みなら終了」と表示する。
4. GUIヘルプ・F1・`:help`・`:h`・Ctrl+Pは同じパレット。日本語の使い方2行を上に置き、キー説明は既定で折り畳む。
   「キー操作を表示／閉じる」のクリックとTabで同じ説明を開閉する。展開は主窓所有の表示状態で、別のHelpモードは作らない。
5. パレットの高さを窓の利用可能高さに制限し、説明・状態行を先に確保して残りへ整数行の候補を描く。
   選択位置と先頭表示位置は主窓が所有する。描画・クリック・キー・ホイールは同じ候補矩形と表示行数を使い、範囲外を実行しない。
   最小560×360でも説明を省略しない。候補は上下の移動ボタン・ホイール・↑↓で全件へ到達する。
6. INDEXと閲覧本文の`:`は同じEx入力。Escで開く前のフォーカスへ戻り、開閉だけで本文を流し直さない。
   INDEX／閲覧本文の`i`、GUI編集、`:startinsert`は現在ノートの編集開始と本文フォーカス。
   既に編集中なら本文を再設定しない。初回はUTF-16の準備が成功してからmodeを変え、確保失敗でも閲覧を維持する。
   本文Escの保存→INDEX復帰・編集mode維持はADR0013のまま。
7. 編集本文の`:`・`i`は文字入力のまま。コマンド入力のIME未確定入力をF1／Tabでも奪わない。
   本文はnote_paneのsubclassでWM_IME_STARTCOMPOSITION／ENDCOMPOSITIONを記録し、読み取り問い合わせを親へ提供する。
   変換中の本文キー通知は既存の保存・終了キーも含めてRichEdit／IMEへ渡す。本文の所有者は増やさない。
   旧INDEXの`?`ヘルプは、実際に動く後方検索を追加する単位で同時に置き換える。
   → ADR 0023（#58）で後方検索へ移した。ヘルプはGUI「ヘルプ」・F1・`:h`・Ctrl+Pに残る。

## 強制と検証

操作登録・h/startinsert・GUI専用IDと別名0・未知語の拒否はcommand_tests。
Win32の描画・IME・フォーカス・Undoは実機で別記する。既存ゲート・依存・保存スキーマの変更はない。Waivers: none。

メニュー選択の契約は[TrackPopupMenuEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-trackpopupmenuex)のTPM_RETURNCMD／TPM_NONOTIFY、登録は[AppendMenuW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-appendmenuw)を使う。

## 2026-09-17 の補正（ADR 0026・決定本文は書き換えない）

「登録表の操作はパレットと『操作』メニューに必ず出る」を、core の閉じた述語 `folio_command_listed(command)` が真の操作に限る、へ改める。
語を要る Ex の文法（`FOLIO_COMMAND_SET`）は、パレットとメニューが引数を渡せないので偽。ほかの操作はすべて真で、
新しい操作を足すたびに閉じた switch が出すかどうかを決めさせる。理由と範囲は [ADR 0026](0026-line-numbers.md) の決定 8。

## 2026-09-22 の補正（#69・決定本文は書き換えない）

決定 5 の「最小 560×360 でも説明を省略しない」を、次のとおり補う。**実測**（`out/design/2026-09-22/palette-probe/`）で、
ヘルプが 16 行になった時点（#37〜#39）から最小寸法では説明と候補が同時には収まらなくなっていた。
箱の高さの不等式は `136 + 32r + 14h ≤ 箱`（96 DPI の基準値）で、最小窓の箱は 316 px、
候補 13 行とヘルプ 18 行を同時に出すには 804 px が要る。ヘルプは下から積むので候補の帯が先に 0 行になっていた。

1. **候補には下限 3 行を残す（`command_row_floor`）。** 残りの高さをヘルプに回す。
   最小寸法（560×360 と 150% の 840×540）では候補 3 行・説明 6 行、既定の 960×640 では候補 5 行・説明 18 行で今までどおり。
2. **説明は「省略しない」を「一度に全部は見えなくてよいが、辿れる」へ読み替える。** 入りきらない説明は `PgUp` / `PgDn` で
   1 枚ずつ送り、先頭と末尾で止まる（巡回しない）。最小寸法では 3 枚。文言は 1 行も削らない。
3. **何枚目かは札の右に ASCII の「n/m」だけで出す。** 数字と `/` しか使わないので、#74（単位 A・`ui_text` の表）が
   訳す文言は増えない。1 枚に収まるときは出さない。
4. 送り先は主窓が持つ一時的な UI 状態（決定 5 の「選択位置と先頭表示位置は主窓が所有する」と同じ扱い）で、
   入力面の開閉・Esc・面の切り替え・「キー操作」の開閉で先頭へ戻る。窓が広がって全部入るようになったときも先頭へ戻る。
5. **箱の高さの式は面ごとの行数を引数に取る 1 本**（`command_box_height(rows, help_rows)`）にし、
   面が出す行数は `command_surface_rows` / `command_help_rows` が答える。[ADR 0029](0029-settings-theme-language-split.md) の
   決定 9 の設定画面は、この 2 本に自分の行数を足すだけで同じ式と同じ配り方を使える。

区画別のヘルプ（開いたときのフォーカスの区画に関係する行だけを出す）は #74 の `ui_text` の表が固まってからの別単位とする。
