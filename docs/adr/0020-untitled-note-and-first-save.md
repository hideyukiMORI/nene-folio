# ADR 0020 — 無題の本文を保持し、初回保存だけ新しいmdを公開する

- 状態: 受理
- 日付: 2026-09-13
- Issue: #53
- 規則: ARC-001〜005/007〜011、C-001〜008/012/014/017、QLT-009/012/013

## 文脈

#47の採用計画に従い、先に本文を書いてから名前とカテゴリを指定できるようにする。
既存のfolio_stateは保存済みノートの選択boolを持ち、本文とキャレットはRichEditが所有する。
既存file_bytes_storeは置換保存なので初回作成の同名保護にはそのまま使えない。
name_listはUTF-8・区切り・末尾文字を検証するが、Windows予約デバイス名の検証は不足している。

## 決定

1. applicationの文書の種類をNONE / NAMED / UNTITLEDの閉じたenumで表す。既存のselected boolを置き換え、
   文書カテゴリと名前付きのノート番号は同じfolio_stateが所有する。無題に架空のファイル名・索引行を作らない。
   無題はEDITで、基準本文は空・改行はLF。未保存本文とUndo・選択範囲は既存RichEditだけが持つ。
2. 新規は現在カーソルのカテゴリ、カーソルが無ければ現在文書のカテゴリ、それも無ければ最初の既存カテゴリを選ぶ。
   カテゴリ0件なら理由を表示する。既存の編集中ノートは保存してから新規へ進む。
3. GUI・Ctrl+N・:enewは共通NEW操作、保存は既存SAVE操作。Exの解析は同じ登録表を使い、SAVEだけ任意の名前引数を許す。
   引数の日本語と途中の空白を保持する。名前付きに:w 名前は拒否する。新しい名前の検証型note_nameは.mdを一度だけ補完/除去し、
   name_listの正典検証を使う。ファイル名全体は既存の255 UTF-8バイト制限以内とする。
4. 予約名はname_listの唯一の検証に加える。拡張子前のCON/PRN/AUX/NUL/COM1〜9/LPT1〜9と上付き1〜3を大小文字非依存で拒否する。
   先頭ピリオドは既存どおり許す。末尾の空白やピリオドは削って成功にしない。
   ディスク上の大小文字・別名による衝突はアダプタの新規公開で最終的に判定し、上書きしない。
   最大長の葉を既存の深い配置でも扱えるよう、persistence_adapterのroot生成一か所で絶対パスをWin32拡張名前空間へ揃える。
   ドライブとUNCを区別し、既存の拡張パスは二重化しない。走査・本文・台帳・履歴が同じrootを使い、OS全体の設定は変えない。
   パス全体の既存上限1024 UTF-16単位は維持し、超える場合は失敗として扱う。
5. 保存名の面は日本語の名前・カテゴリ・拡張子説明・面内の失敗理由・保存・キャンセルを持つOSモーダルダイアログとする。
   背後の本文を保ち、親を無効にして同時の編集/切替を防ぐ。DialogBoxIndirectParamWの同期呼出し中だけ呼出元の処理を待機させる。
   継続する選択・終了などの意図を別の状態機械やフォーカス状態へ複製しない。成功時だけ同じ呼出元が再開し、取消/失敗なら戻る。
   HWND・名前欄の入力・IME compositionはUIが所有。本文は親RichEditの読み取りビューを呼出し中だけ借り、保存成功でも再設定しない。
6. 初回保存は正規化本文・RTF・挿入後台帳をすべて先に確保する。create_noteポートで一時ファイルに完書き/flush後、
   置換なしのMoveFileExWで新しいmdを公開する。既存write_noteと同じfile_bytesの書込本体を使い、作成/置換だけ閉じた方針enumで分ける。
   作成と通常保存で同じ固定長の一時名（対象の葉のハッシュと00〜ffの候補番号）を使う。名前に.tmpを追加すると最大長の葉が上限を超えるため。
   一時ファイルはCREATE_NEWで取得し、残存/使用中の候補は別番号で試す。256候補とも使えなければ拒否し、他の処理の一時ファイルを奪わない。
   ハッシュの衝突でも名前だけで同じファイルだとみなさず、CREATE_NEWで所有を確定する。公開前の失敗では無題・入力・台帳を変えない。
   初回の履歴は作らず、名前付きになった後は既存保存・履歴経路を使う。
   既にカテゴリ行を指すカーソルがある場合は初回保存で奪わず、無ければ保存したノートへ置く。
   キーでの移動先は保存前に写し、本文の再投入の要否は保存後の選択から比較する。同じ本文に名前が付くだけでUndoを消さない。
7. md公開後の台帳失敗では、メモリの本文・名前・索引を作成済みファイルへ一致させ、LEDGER_STALEで後続の終了/切替を止める。
   未保存の無題だと偽って同じファイルを再作成しない。未同期の索引はapplicationで一つのカテゴリ番号として保持し、
   次の保存/変更操作の前に台帳書込を再試行する。取消しや失敗で新規ファイルを削除しない。再起動は既存の走査照合が復旧する。
   永続化スキーマは版1のまま。既存のカテゴリ移動の履歴契約は変えない。
8. 無題の:qは空でも未保存として拒否。通常の×・Alt+F4・保存して閲覧・本文Esc・他ノートへ移る入口は共通保存を通す。
   取消は無題・本文・Undoを保持して後続処理を止め、失敗表示を増やさない。:q!は既存の明示破棄終了。
   索引の展開・並替えで文書を開き直す経路も無題を置き換える前に保護する。

## 却下した選択肢

- 新規時に空のmdを先に作る: 名前を決める前に本文を書けず、取消で不要ファイルが残る。
- UIの未保存フラグや第2本文コピー: 既存の本文比較・RichEdit所有と食い違う。
- 名前入力をEx欄だけで済ませる: GUIの利用者に保存先と取消を説明できない。
- 親を操作可能にした非同期フォームと継続意図キュー: 現在の同期Win32設計に不要な再入・状態を増やす。
- 存在確認後に置換保存: 確認後の競合で同名を上書きする。
- 作成後の台帳失敗を無視する/ファイルを消す: 保存結果が見えず、完成した本文を失う。

実機の名前入力・IME・取消・Undo・最小寸法・DPIは別に記録する。新規の実装前にこの判断を記した。
