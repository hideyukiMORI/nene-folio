# ADR 0021 — 別名保存は元を保存せず新しいmdを作る

- 状態: 受理
- 日付: 2026-09-13
- Issue: #55
- 規則: ARC-001/004/007/010/011、C-002/003/007/012/017、QLT-009/012/013

## 文脈

#47の採用計画は別名保存と改名を区別する。#53のstore_new/create_editedと名前入力面は、
既存ファイルを置換せずに現在の本文を新しいノートへ保存する正典経路になった。
Ctrl+SのWM_CHARではShift併用を区別できない。製品は修飾キーの状態を読み書きしない。

## 決定

1. 共通操作SAVE_ASを登録し、GUI「別名で保存」、Ctrl+Shift+S、:saveas 名前を結ぶ。
   :saveasだけの場合も同じ日本語の名前/既存カテゴリ入力面を開く。無題なら初回保存と同じ結果になる。
   :w 名前は引き続き名前付きの文書へは拒否し、共通dispatcherで操作の意味を区別する。
2. folio_state_store_newは「現在本文を新しいmdへ公開する」の一経路へ拡張し、NAMEDも受ける。
   EDITは借りたUTF-16を既存edited_textで正規化。VIEWは入力引数を使わず、application所有のMarkdown原文を複製する。
   表示用RTFから取り出した文字を保存せず、UIはVIEWの本文取得自体を行わない。modeは維持する。
3. 元の本文保存・履歴作成を先に呼ばない。create_editedで新しいmdだけを作り、その文書を開いた状態へ更新する。
   初回作成と同じ名前検証・台帳・部分失敗処理を使う。既存の台帳未同期があれば別の作成前に修復し、失敗なら進めない。
   公開前の取消/失敗は元の文書と未保存本文を保持。公開後の台帳失敗は新しい文書を保持し、再保存で台帳を修復する。
   閲覧中の:q・通常終了・保存も未同期を見逃さず、既存の保存/変更確認で同じ再試行・拒否を行う。
4. 名前入力面は現在文書がNAMEDなら「別名で保存」と元の保存内容を保つ説明を表示する。
   入力/カテゴリ/失敗/取消の所有者と同期モーダルはADR0020と同じ。本文の再設定はせず、編集のUndoを維持する。
5. 主窓がHACCELを所有し、TranslateMessageより前にCtrl+Shift+SをOSのTranslateAcceleratorWへ渡す。
   主窓・本文・コマンド入力の3入口だけを対象にし、各入力のcomposition中と他のモーダル/名前入力は対象外。
   WM_COMMANDのaccelerator通知を同じdispatcherへ戻し、元のWM_CHAR0x13を生成させない。
   Ctrl+Sや本文Ctrl＋hjklは既存経路を維持する。キー状態の読取・記録・合成入力は製品に増やさない。
6. 永続化スキーマと新しいmdの初回履歴なしという契約は変えない。元のmd/履歴の移動は改名の後続Issueで扱う。

## 却下した選択肢

- 元を保存してからコピー: 元ファイルと履歴を変えてしまい、hideが採用した意味と違う。
- 別名保存用の書込ポート・入力面・本文コピー: 初回作成と同じ意味の第2経路になる。
- 閲覧のRichEdit文字を保存: Markdownの記法を失う。
- WM_CHAR0x13でShiftを推測する/キー状態を読む: 正確な修飾条件とARC-007を守れない。

## 検証

元のwrite/archiveが呼ばれないこと、閲覧原文と改行の保持、取消・衝突・部分失敗・確保失敗を測る。
主窓のアクセラレータ・IME guard・本文とUndoは独立部品で測り、物理キーと目視は区別する。
この判断を実装前に記録した。Waivers: none。
