# ADR 0024 — 全ノートの絞り込みは遅延して載せた本文を core で判定し、配置は同じ drawer_layout に絞り込みを渡す

- 状態: 受理（設計リナ 2026-09-17。実装前に記録）
- 日付: 2026-09-17
- Issue: #40（FR-032。現在ノートの検索 FR-011 / ADR 0023 とは対象も語も別）
- 規則: ARC-001 / ARC-003 / ARC-004 / ARC-007 / ARC-009 / ARC-011、C-002 / C-003 / C-005 / C-012 / C-013 / C-014 / C-017、QLT-009 / QLT-013

## 文脈

採用済み計画（#47）はドロワー上部の日本語「すべてのノートを検索」と Ctrl+Shift+F で、全ノートの本文により索引を絞り込む。
Issue #40 は「純粋な一致判定は core、語と一致集合は application、ファイルはポートだけ。非一致になった現在 md を勝手に閉じない。
Esc で INDEX へ、空検索で元の全索引へ。初版は絞り込み中の並び替え／移動を禁止する。検索窓からの Ctrl+S も共通 command へ」と求める。
ドロワーの配置は core の `drawer_layout` が台帳から作り（ADR 0004 / 0009）、印は `drawer_layout_mark` が付ける（ADR 0015）。
ドロワー自身はフォーカスを取らない（ADR 0009）。入力面は元のフォーカスを覚えて Esc で戻す（ADR 0016）。

## 決定

1. **本文の読み込みは最初の絞り込みで遅延して行う。** application は「本文の写し」（カテゴリ番号・ノート番号 → `note_text`）を持ち、
   空でない語が初めて来たときにポートの `read_note` で全ノートを 1 回読む（起動時には読まない。Issue の「起動時に全 md を読む」は
   起動を遅くしない範囲でこの形に改める）。その後は保存成功（`store_note` / `end_edit`）・新規公開（`store_new`）・改名・移動で
   該当の写しだけを差し替える。読めないノートは写しを持たず**一致しない**扱いにし、理由は出さない（次の保存で写しが入る）。
   外部で変わった md は検知しない（既存の限界のまま）。
2. **判定は core の純関数 `index_filter`**（`index_filter.{c,h}` / `index_filter_outcome.h`）。入力は語（UTF-8）と各ノートの名前と本文（UTF-8）で、
   **ASCII の英字だけ大小を無視**する UTF-8 のバイト順序比較（多バイト列に ASCII は現れないので ADR 0023 と同じ意味になる）。
   **名前か本文のどちらかに部分一致**すれば一致。正規表現は #41 の範囲。空語は「絞り込みなし」。不正 UTF-8 の語は `MALFORMED` で前の語を保つ。
   出力は「見える (category, note) の集合」で、application が保持する（一致集合の所有者）。
3. **絞り込み中の配置は同じ `drawer_layout` が作る。** `drawer_layout_create` の入力を `struct drawer_source`（カテゴリ台帳・索引台帳の列・
   nullable の絞り込み）に束ね（C-012 の 4 引数を守る）、絞り込みがあれば **一致するノートを持つカテゴリだけ**を、その `expanded` に関わらず
   **展開して**並べ、一致しないノート行は置かない。行の `category` / `note` / `ordinal` / `color` は元の台帳の番号のままにし、
   クリック・選択・寄せる量が絞り込み無しと同じ経路で動くようにする。第 2 の配置関数は作らない。
4. **絞り込み中は台帳を書く操作を拒む。** 並び替え（`move_category` / `move_note`）・ドラッグ開始・`h` / `l` とクリックによる開閉
   （`expanded` の書き戻し）は閉じた値 `FOLIO_STATE_FILTERED`（「絞り込み中は並び替えと開閉ができません」）で何もしない。
   色の変更・新規・保存・別名保存・改名・削除以外の閲覧と編集は許す。改名と新規は写しと一致集合を更新して絞り込みを保つ。
5. **現在の文書は一致しなくても閉じない。** 右ペインとモードはそのまま。ドロワーには行が無いので面の印はどこにも付かない
   （`drawer_layout_mark` の既存の規則）。カーソルの行が消えたら application は**最初に見える行**へカーソルを移し、
   絞り込みの変更のたびにスクロール量を 0 にしてからカーソルを寄せる。
6. **検索窓は ADR 0016 の入力面だが常設。** ドロワーの頭 36px に「すべてのノートを検索」の欄を常に置く（主窓の子。ドロワーはフォーカスを取らない）。
   Ctrl+Shift+F（両モード・全区画。主窓の HACCEL、Ctrl+F と同じ `command_target` の抑止条件）で欄へフォーカス。
   欄の `EN_CHANGE`（composition 中は動かさない）で application の語を更新し、一致集合と配置を作り直す。
   **Esc と Enter は INDEX（主窓）へフォーカスを戻し、絞り込みは保つ。** 欄を空にすると絞り込み無しに戻る。
   欄の中の Ctrl+S は共通の SAVE へ渡す（欄は開いたまま作業する面なので、Ex とは違う）。`/` `?` `n` `N` `:` は欄では文字。
7. **語の所有。** application は「全ノート検索の語（1 つ・UTF-8）」を持ち、ノート内検索の語（ADR 0023）と同期しない。永続化しない。
   語を受ける UTF-16 の入口は C-014 の例外を 1 本増やす（7 本目: `set_index_filter`）。
8. 永続化スキーマ・依存・ゲートの変更なし。

## 却下した選択肢

- 起動時に全 md を読む: 使わない機能のために起動を遅くし、読めない md で起動を止める判断を迫る。
- UI がドロワーの行を隠す: 判断が UI へ移り、クリック位置・スクロール上限・寄せる量が 2 経路になる（ARC-011）。
- 一致だけを別のリストに出す: 索引の色・番号・カテゴリの文脈を失い、案2「堅」の 1 画面 2 ペインから外れる。
- 本文を UTF-16 に変換して `note_search` を流用する: 打鍵ごとに全本文を変換する。UTF-8 のバイト比較で同じ意味が出せる。
- 絞り込み中も並び替えを許す: 見えていない行の位置へ落ちる書き戻しが誤りやすい（Issue の初版の条件）。

## 検証

core: ASCII 大小・非 ASCII の区別・名前と本文・空語・不正 UTF-8・カテゴリの脱落と展開・番号と色の保持・確保失敗。
application: 遅延読み込みが 1 回だけ・保存／新規／改名／移動での差し替え・読めないノートの非一致・`FILTERED` の拒否・
現在文書の非一致で閉じない・カーソルの移動・スクロールの 0 化・語の独立。UI は独立 Win32 部品で Ctrl+Shift+F・EN_CHANGE・Esc／Enter の復帰・
composition 中の不干渉・欄の Ctrl+S・ドラッグ開始の拒否を測る。性能は 1000 ノート × 10KB の写しで 1 打鍵の判定時間を probe に記録する。
物理キー・IME 候補窓・高 DPI は実機で別記。Waivers: none。

## 2026-09-17 の補正（実装と独立レビューの後・決定本文は書き換えない）

受理した決定のうち、実装と読み取り専用レビューで分かった点をここに追記する。正典はこの節を含めた全文である。

1. **決定 4 の拒否は application の契約のまま、UI は絞り込み中に開閉の意図を送らない。**
   カテゴリ行のクリック（`drawer_window` の `act_on_row`）と索引の `h` / `l`（`folio_window` の `expand_cursor`）は、
   `folio_state_filtering` が真なら何もせずに戻る。`h` は絞り込み無しでは日常の移動なので、打鍵やクリックのたびに
   モーダルの失敗箱を出さない。ドラッグ開始を無音で拒むのと同じ扱いに揃える。`FOLIO_STATE_FILTERED` の値と文言は、
   UI を通らない入口（Ex・パレット・将来の入口）のために残す。
2. **絞り込み中に拒んだドラッグはクリックにもしない。** 押した位置からドラッグの閾値を超えて動いた操作は、
   離したときに押した行の選択へ落とさない（並び替えのつもりの操作が選択の変更になるのを防ぐ）。
3. **決定 1 の「改名で写しと一致集合を更新する」は、再開で完了した改名（`resume_rename`）にも適用する。**
   写しの付け替えと一致集合の作り直しは `adopt_rename` の 1 か所で行い、どの意図が再開を完了させても同じ結果にする。
4. **決定 5 のカーソルの移し先を 1 つの規則にする。** カーソルの行が見えなくなったとき、その行のカテゴリ行が
   「見えていてカーソルが止まれる行」（ADR 0015: 見えるノート行を持たないカテゴリ行）ならそこへ、そうでなければ
   最初に見える行へ移す。絞り込みを解いたときに、折り畳まれたカテゴリの中のノートから索引の先頭へ飛ばさないため。
   絞り込み中は一致を持つカテゴリが必ず展開されるので、従来どおり最初に見える行になる。
5. **決定 6 の欄でも「全区画」の操作は効く。** F1（ヘルプ）・Ctrl+P（パレット）・Ctrl+N（新規）は欄の中でも
   共通の操作へ渡す（`docs/KEY_BINDINGS.md` の「どこにいても」の表と一致させる）。
   欄の書体は DPI の変更で主窓の等幅書体を作り直すたびに付け直す（作り直しの所有者は `refresh_font` の 1 か所）。
6. **一致集合は台帳の順（カテゴリ番号・ノート番号の昇順）で作り、所属の判定は二分探索にする。**
   配置は描画・hit test・スクロールのたびに作り直されるので、線形走査のままだと全一致の 1000 ノートで 1 配置あたり
   約 2×10⁶ 回の比較になる。順序は `index_filter` の生成時の不変条件として core のテストで固定する。
7. **絞り込みの対象は保存済みの本文である。** 編集中でまだ保存していない内容は一致しない（写しは保存成功で差し替わる）。
   絞り込み中に別のノートへ切り替えると既存の経路で保存が走り、その時点で写しと一致集合が追随する。
8. 記録（この単位では変えない）:
   - `drawer_layout_drop` は表示行を数えて落とし先の番号を決めるので、絞り込み下の配置では台帳の番号と合わない。
     いまは UI と application の二重の拒否で到達しない。絞り込み中の並び替えを解禁するときは先にここを直す（ヘッダに注記する）。
   - 写しの付け替えが確保失敗で落ちたとき、旧名の写しが次の遅延読み込みまで残る。宛先が台帳に無いので誤一致はしない。
   - 頭の帯が 44px から 80px になったが、最小サイズ 560×360（ADR 0011）は据え置いた。96 DPI の最小サイズで索引に使える高さが
     ノート行 1 本ぶん減る。実機の目視で足りなければ ADR 0011 の補正として扱う。
