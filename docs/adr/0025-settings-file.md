# ADR 0025 — 設定は `data/settings.json` の版 1 を `number` だけで始め、キーを足すたびに版を上げる

- 状態: 受理（設計リナ 2026-09-17。実装前に記録）
- 日付: 2026-09-17
- Issue: #39（FR-021。設定画面・テーマ・言語は #38 の範囲で、この ADR は経路と版の規則だけを先に固定する）
- 規則: ARC-001 / ARC-003 / ARC-004 / ARC-007 / ARC-009 / ARC-010 / ARC-011、C-002 / C-003 / C-005 / C-012、QLT-009

## 文脈

Issue #39 は「`number` の値の所有者は application で、settings の経路を使う。設定の永続化を検証する」と求めるが、
その経路になる `data/settings.json`（計画 #36 の 4 節・Issue #38）はまだ無い。計画は版 1 の候補として
`theme` / `language` / `number` を挙げ、「最終スキーマと移行は #38 の ADR で固定する」としている。
#38 は設定画面・3 言語の全文言・配色を含む大きな単位で、#39 の前に丸ごと通すと行番号が長く待たされる。
一方、効果を持たないキー（`theme` / `language`）を先に受け付けて保存すると、手で `"theme":"dark"` と書いた利用者に
「受理されたのに何も起きない」状態を見せる。これは `planned` を `active` に見せる行為にあたる（ADR 0001）。

## 決定

1. **`data/settings.json` の版 1 は `{"version":1,"number":<bool>}` だけ。** 効果を実装したキーだけをスキーマに入れる。
   未知のキー・欠けたキー・重複したキー・型の違う値・未知の版は、既存の台帳の読み取りと同じ厳しさで拒む（黙って既定値にしない・ARC-009）。
2. **キーを足すときは必ず版を上げる。** 旧版からの移行は core の純関数（旧版の値 → 新版の値。足したキーは既定値）で行い、
   読み取りは「現在の版」と「移行できる旧版」だけを受ける。新しい版のファイルを古い exe が読んだら `UNSUPPORTED` で、**上書きしない**。
   #38 は `theme` / `language` を足して版 2 にする（その ADR がこの規則に従う）。
   **この単位では移行の関数を書かない**（版 1 しか無く、到達しない分岐になる）。版が 1 でなければ `UNSUPPORTED_VERSION`、で足りる。
   計画 #36 の 4 節が挙げた「版 1 の候補 = theme / language / number」はこの決定で置き換え、計画の文書に追記する。
3. **解析と直列化は core の `folio_settings`**（不完全型・`folio_settings.{c,h}` / `folio_settings_outcome.h`）。既存の `json_reader` / `json_writer` を使う。
   結果は閉じた値（`READY` / `MALFORMED` / `UNSUPPORTED_VERSION` / `OUT_OF_MEMORY`）。既定値（`number = false`）を作る関数もここに置く。
   キーの順序・空白・書き出しの整形は既存の台帳（`category_ledger`）の読み書きと同じ扱いにする。
4. **読み書きは既存の `persistence_port` に 2 つ足す**（`read_settings` / `write_settings`）。書き込みは台帳と同じ原子的な置き換え。
   adapter は台帳の読み書き（`file_bytes_read` → core の parse、`json_writer` → `store_document`）と同じ形で、新しい I/O の経路を作らない。
   「ファイルが無い」は既存の `PERSISTENCE_ABSENT` で区別し、**無いときだけ既定値**で始める。無いファイルを起動時に作らない（最初の変更で初めて書く）。
   `data/.nenefolio.lock`（ADR 0022）があるので同時に書く相手はいない。
5. **値の所有者は application（`folio_state`）。** 起動時に 1 回読み、変更の意図（`folio_state_set_number`）は
   **先に書いてから採用する**。書けなければ値を変えず、閉じた値の失敗を返す（表示と保存の食い違いを作らない）。同じ値なら書かない。
   設定は md・台帳・`.rename.json` と独立なので、この意図は未完了の改名の再開（`synchronize()`）を**通さない**。
6. **読めない設定ファイル（壊れている・未知の版）では、既定値で起動して理由を 1 回だけ見せ、そのセッションの設定の変更を拒む。**
   `folio_state_create` は READY のまま返し、合成ルート（`main.c`）が窓を作る前に application へ「設定の知らせ」を 1 回尋ねて、
   READY でなければ既存の 1 行の表示で見せてから起動を続ける（`main` は 1 回しか走らないので「見せたか」の真偽をどこにも持たない。
   `main.c` の「出してよいのは起動できなかった理由 1 行だけ」の注記もこの単位で改める）。
   拒否は閉じた値（`FOLIO_STATE_SETTINGS_UNREADABLE`）で、文言にファイルの場所を含める。人が直すか消すまで上書きしない
   （新しい版のファイルを古い exe が既定値で潰さないため。改名の `HALTED` と同じ考え方）。ノートの閲覧・編集・保存は妨げない。
7. 設定の値は md・台帳・`.rename.json` と独立で、台帳スキーマ版 1 は変えない。依存・ゲートの変更なし。

## 却下した選択肢

- 版 1 に `theme` / `language` も入れて値だけ往復させる: 効果の無いキーを受理することになる（ADR 0001）。#38 の設計前にその値域を固定することにもなる。
- 欠けたキーは既定値とし、版を上げずにキーを足す: 同じ版番号で受理するキーの集合が exe によって変わり、「未知のキーは拒む」と両立しない。
- 読めない設定でも変更を許して上書きする: 新しい版のファイルや、利用者が直そうとしていたファイルを黙って失わせる。
- 読めない設定では起動しない: 設定はノートの閲覧に不要で、`data/` が書けなくても閲覧のために起動を許す既存の方針（ADR 0022）と合わない。
- 書けない `data/`（ADR 0022 が閲覧のために起動を許す）ではセッションの中だけ値を採用する: 「保存された値」と「見えている値」の 2 状態になる。
  行番号は編集モードだけの表示で、書けない `data/` では編集した本文も保存できないので、切り替えられなくても失うものが小さい。可視の失敗 1 行で足りる。
- `number` をセッションだけの値にして永続化を #38 へ送る: Issue #39 の受け入れ条件（設定の永続化の検証）を満たさない。
- レジストリや `%APPDATA%`: `data/` を持ち運べば同じ見え方になる、という配置の前提を壊す。ARC-007 の読み取り箇所も増える。

## 検証

core: 版 1 の往復・既定値・未知／欠落／重複キー・型違い・未知の版・確保失敗。application: 無いファイルで既定値かつ書かない・
変更で 1 回書く・同じ値で書かない・書き込み失敗で値を変えない・読めない設定での起動と変更の拒否（上書きしないこと）。
実アダプタ probe: 原子的な置き換え・読み取り専用の `data/` での失敗・無いファイルの区別。Waivers: none。
