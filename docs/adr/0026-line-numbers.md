# ADR 0026 — 原文の行番号は core が論理行を数え、主窓が本文の左の空きに描く

- 状態: 受理（設計リナ 2026-09-17。実装前に記録。実測は `out/design/2026-09-17/number-probe/` の 39 項目）
- 日付: 2026-09-17
- Issue: #39（FR-021）。設定の永続化は ADR 0025
- 規則: ARC-001 / ARC-004 / ARC-005 / ARC-007 / ARC-010 / ARC-011、C-002 / C-003 / C-005 / C-012 / C-013 / C-014、QLT-009 / QLT-013

## 文脈

FR-021 は編集モードの本文の左に md 原文の**論理行**（改行区切り）の番号を出し、折り返しの継続行には重ねない。
本文には書き込まず、toggle で本文・Undo・選択を保つ。右ペインは `Msftedit.dll` の `RICHEDIT50W` 1 つで（`note_pane.c`）、
閲覧は RTF、編集は同じ HWND の平文である。矩形は主窓の `arrange()` だけが配り、ドロワーの右端と本文の左端のあいだに
36px（96 DPI・`base_pane_left`）の空きが既にある。実装前の実測で次が分かった。

- `EM_GETLINECOUNT` / `EM_LINEINDEX` / `EM_GETFIRSTVISIBLELINE` は**表示行**の単位。論理行の先頭は「位置 0 か直前が CR」で過不足なく判定できる。
- **行の高さは一定でない**（ASCII 25px・日本語 29px・fallback の字 33px。書体は単一でも）。y は表示行ごとに `EM_POSFROMCHAR` で得るしかない。
- RichEdit はスクロールを自分で描き切り、**スクロールでは `WM_PAINT` が来ない**。RichEdit の子窓は一緒にスクロールされる。
  したがって RichEdit の中（余白＋サブクラス描画、または子窓）に番号を置く方式は、打鍵では合いスクロールでずれる。
- `EN_VSCROLL` はキャレットの移動・PgUp / PgDn・`EM_LINESCROLL`・検索の `EM_SCROLLCARET` で来る。製品の本文はスクロールバーを持たない
  （`WS_VSCROLL` なし）のでつまみの経路は無い。合成した `WM_MOUSEWHEEL` では本文が動かず、実際のホイールで何が届くかは未確認。
  寸法・DPI の変更では `EN_*` が何も来ない。`EN_UPDATE` は一度も来ない。本文の増減は `EN_CHANGE` が唯一の合図。
- 表示中の平文（`note_pane_display_text`・CR 区切り・ADR 0023）は `EM_LINEINDEX` と同じ位置の系。1MB・1 万行で取り出し約 3ms、
  CR の位置表の作成約 1.3ms、表への二分探索 32ns、可視 17 行の位置と y の一巡 0.86ms。

## 決定

1. **番号は主窓が、本文の左の空きに自前で描く。** 新しい窓も RichEdit の余白の変更も作らない。主窓は `WS_CLIPCHILDREN` なので
   本文と互いに描き込まない。矩形は `arrange()` が、書体は主窓の等幅書体（`refresh_font` が所有）、色は `folio_palette` が持つ。
   描画はパンくずと同じメモリ DC の経路で、番号は右寄せ、本文の左端から 8px（96 DPI）手前で終える。帯の上下は本文の矩形と同じ
   （上の操作行の札とは y で分かれる。下端のコマンド面は上に重なってよい）。字間は足さず（`SetTextCharacterExtra` 0）、幅は同じ書体で数字を測って決める。
   **前提として `paint_pane` を更新矩形（`rcPaint`）に限って描くよう先に直す**（いまは毎回 client 全体のビットマップを作って右ペイン全域を写す。
   ↓キー 40 回で `EN_VSCROLL` が 25 回来るので、帯の無効化のたびに全域を描かない）。これは単独の修正として最初のコミットにする。
2. **論理行の数え上げは core の `line_index`**（不完全型・`line_index.{c,h}` / `line_index_outcome.h`、位置の答えは `line_mark.h`）。
   表示中の平文（借りるだけ）から CR の位置の昇順の表を作り、(a) 論理行の数、(b) 文字位置 → `{論理行番号（1 始まり）, その位置が論理行の先頭か}`（二分探索）、
   (c) 論理行番号 → 先頭の文字位置、(d) 番号の桁数（**最小 3 桁**）を答える。範囲外の位置と番号は閉じた値で拒む。
   末尾が CR で終わる本文の空の最終行も 1 行と数える。空の本文は 1 行。CRLF / LF の違いは表示中の平文では CR 1 つに揃っている（ADR 0023）。
3. **表の所有者は `note_pane`（本文の派生物の写し）。** `EN_CHANGE` で「古い」と印を付けるだけにし、**次に番号を描くときに**平文を取り出して作り直す
   （描画の合流が打鍵の連続をまとめる。タイマもスレッドも足さない・C-013）。スクロールでは作り直さない。
   「古い」の印は、本文を差し替える `note_pane_edit` / `note_pane_render` の**中**でも付ける（外の呼び出し元は 4 経路あり、呼び忘れを構造で防ぐ）。
   平文の取り出しは**番号専用のバッファ**で行い、保存と検索が借りる既存の 1 本（`taken`）を描画が無効化しないようにする。
   `note_pane` は「いま見えている論理行の先頭の列」を答える関数を 1 つ公開し（`note_pane_visible_rows(pane, rows, capacity, count)`。
   行の型は `gutter_row.h` の `{top, height, number}`、配列は主窓がスタックに 256 本持つ。あふれたら描けるぶんだけ描き、失敗にしない）、主窓はそれを描くだけにする。
   y は表示行ごとに `EM_LINEINDEX` → `EM_POSFROMCHAR` で得て（行高 × 番号で計算しない）、**`note_pane` が主窓の client 座標へ直して返す**（直すのはここ 1 か所）。
   選択とスクロール位置の正本は RichEdit のまま。桁数も表と一緒に作り直し、`arrange()` のたびに平文を取り出さない。
4. **描き直しの契機を 1 つの関数へ集める。** `EM_SETEVENTMASK` を `ENM_KEYEVENTS | ENM_SCROLL | ENM_CHANGE` に広げ（`ENM_KEYEVENTS` は消さない）、
   `EN_VSCROLL` と `EN_CHANGE`、既存のサブクラスに足す `WM_MOUSEWHEEL` の後処理、`arrange()`・DPI の変更・モードの切替・ノートの切替・`number` の変更が、
   同じ「番号の帯を無効化する」を呼ぶ。**すぐ描く（`UpdateWindow`）のはスクロールの契機だけ**で、`EN_CHANGE` は印と無効化だけにする
   （`EM_STREAMIN` の最中に本文へ問い合わせない。`EM_STREAMIN` が `EN_CHANGE` を出すかは実装の最初に probe で測る）。
   検索の選択（`EM_SCROLLCARET`）は `EN_VSCROLL` で拾える。本文の RichEdit に control id を与え、主窓の `WM_COMMAND` は送り手の HWND と id で
   振り分ける（#40 の絞り込みの欄の `EN_CHANGE` と同じ窓に届くため）。加速表は `lparam == 0` かつ `HIWORD == 1` に限る。
5. **出すのは「`number` が真・編集モード・文書がある」のときだけ。** 閲覧（RTF）では出さない（表示行が原文の行に対応しない）。
   無題の編集中も出す。判断は application の値（`number` と `pane_mode`）から UI が導き、UI に第 2 の真偽を持たない（ARC-004）。
6. **幅は桁数 × 等幅書体の数字の幅 ＋ 左右の余白で、既存の空き（36px）に収まるあいだ本文は動かない**（3〜4 桁 = 9999 行まで）。
   収まらなくなったときだけ `arrange()` が本文の左端を右へ送る。論理行の数は折り返しに依存しないので、本文の幅を変えても桁数は変わらず、
   「幅を変える → 折り返しが変わる → 幅が変わる」の振動は起きない。このとき、また `number` の切替で本文の矩形が変わるときは、
   変える前の「最初に見える論理行」を覚え、変えた後に (c) → `EM_EXLINEFROMCHAR` → `EM_LINESCROLL` で戻す（実測済みの手順）。
   本文・Undo・選択には触れない。折り返しの途中から見えていた場合にその論理行の先頭へ寄るのは許す。
7. **色は `folio_palette` に `gutter_text` を 1 つ足す。** ライト `#6B727C`（地 `#FFFFFF` に対し 4.86:1）、ダーク `#7C838D`（地 `#101214` に対し 4.91:1）。
   本文（`editor_text`）より薄く、頭の薄い文字（ライト 3.18:1・ダーク 2.31:1）より濃い。地は `pane` のまま。
   デザイン文書の `#7D716D` は暖色の案の値で、実装済みの寒色の配色（ADR 0005）では同じ比の寒色に置き換える。ClearType での見え方は実機で確かめる。
8. **操作は共通の登録表に 2 つ足す。** `FOLIO_COMMAND_SET`（Ex だけ・`:set` / `:se`）と `FOLIO_COMMAND_TOGGLE_NUMBER`
   （「行番号の表示を切り替える」。別名なし。パレット・「操作」メニュー）。
   引数の扱いは `takes_name()` の真偽を閉じた `enum folio_argument_kind`（`NONE` / `NAME` / `OPTION`。`folio_argument_kind.h`）へ一般化し、`OPTION` の語は core の
   `folio_command_parse_option(text, length, out)` が閉じた `enum folio_option`（`folio_option.h`）へ解く: `number` / `nu` → 表示、`nonumber` / `nonu` → 非表示、
   `number!` / `nu!` / `invnumber` / `invnu` → 切替。語は空白で切った 1 語の完全一致で、`folio_command_parse` は変えない（引数は既に 4 つ）。
   未知の語・語なし・余計な語は、未知のコマンドと同じ 1 行の可視の失敗で、入力を消さない（文言は増やさない）。
   3 つの入口はすべて application の同じ意図（`folio_state_set_number`・ADR 0025）へ渡る。設定画面からの変更は #38 が同じ意図へ結ぶ。
   **ADR 0016 決定 1 と ADR 0018 決定 2 の補正**: 「登録表の操作はパレットと『操作』メニューに必ず出る」を、core の閉じた述語
   `folio_command_listed(command)` が真のものに限る、へ改める。`SET` は語を要る Ex の文法で、パレットとメニューは引数を渡せないので偽。
   ほかの操作はすべて真。新しい操作を足すたびに閉じた switch が決めさせる。両 ADR に補正節を置いてここを指す。
   `:set` の文法はヘルプの説明（`command_shortcuts`）に 1 行足す。
9. 永続化は ADR 0025。md・台帳のスキーマと依存・ゲートの変更なし。

## 却下した選択肢

- RichEdit の余白（`EM_SETMARGINS` / `EM_SETRECT`）＋サブクラスで `WM_PAINT` の後に描く: スクロールで `WM_PAINT` が来ない（実測 0 回）。
- RichEdit の子窓に描く: RichEdit が子窓ごとスクロールする（実測で 75px 動いた）。
- 番号専用の子窓を主窓に足す: 書体・色・DPI・破棄の所有者が増える。主窓の自前描画で同じ結果になる。
- 行高 × 番号で y を計算する: 行高が一定でないので日本語の行から必ずずれる。
- 描くたびに平文を取り出して先頭から CR を数える: 1MB で毎回 4ms 以上。スクロールでは本文が変わらないので表を保てば足りる。
- TOM の `tomParagraph`: 同じ値を返すが 1 回 1ms 台で、`note_pane` が持つ経路（表示中の平文）を増やさないほうを選ぶ。
- `:set` を登録表の外の前段の文法にする: ADR 0016 / 0018 の補正は要らないが、Ex の入口が 2 つになり「操作の入口は 1 つ」が崩れる。
- 引数なしの「表示」「非表示」の 2 操作に `set number` などの空白入り別名を持たせる: 別名の照合が語単位でなくなり、`:set` の文法が表に埋もれる。
- 番号を本文へ書き込む・RTF で番号を流す: 本文を汚し、保存と Undo に混ざる。

## 検証

core: 空・1 行・空行・末尾の CR・長い行・位置 → 番号と先頭の判定（境界と範囲外）・番号 → 位置・桁数（9 / 10 / 999 / 1000 / 9999 / 10000）・
オプションの語の全別名と未知の語・確保失敗。application: `set_number` の 3 入口の合流・閲覧では出さない判断の材料・ADR 0025 の失敗。
UI は独立 Win32 部品 probe で、折り返しの継続行に番号が出ないこと、日本語の行の y、末尾の空行、スクロール（キー・`EM_LINESCROLL`・検索の選択）後の一致、`EM_STREAMIN` が `EN_CHANGE` を出すか、
入力・貼り付け・Undo 後の一致、toggle 前後の本文・`EM_CANUNDO`・選択の保持、5 桁で本文が動いたときの最初に見える論理行の復元、
閲覧で出ないこと、1 万行での 1 回の描き直しの時間を測る。
実機の目視（hide）: 実際のホイールでの追随、ちらつき、IME 変換中、高 DPI、両テーマの色、番号の字の大きさ（等幅 11px と本文 11pt の釣り合い）、
4 桁が空きに収まること、ヘルプが 1 行増えた最小寸法 560×360。Waivers: none。

## 2026-09-22 の補正（実装と独立レビューの後・決定本文は書き換えない）

受理した決定のうち、実装（`4a58fbf`）と読み取り専用レビューで分かった点をここに追記する。正典はこの節を含めた全文である。

1. **決定 6 の「収まらなくなったときだけ本文の左端を右へ送る」は、`WM_PAINT` の最後に気づいて次の回で配り直す。**
   帯の桁数は表と一緒に作り直され、表は「次に番号を描くとき」に作られる（決定 3）ので、幅の変化が分かる最初の瞬間は描画の最後である。
   描画の途中で窓を動かさないため、`paint_pane` の末尾（`check_pane_inset`）で「いま本文が置かれている左端」と「帯の有無と桁数から要る左端」を比べ、
   違えば `folio_message_gutter_resized` を **1 通だけ** post し、次の回の `rearrange_keeping_line` が配り直す。
   要る左端は `number`・モード・桁数だけから決まり、桁数は折り返しに依存しない（決定 6）ので、配り直した次の `WM_PAINT` では両者が一致して 2 通目は出ない。
   描く矩形が空でも毎回の `WM_PAINT` で確かめる（契機を 1 か所に保つ）。補正は `WM_PAINT` 1 回ぶん遅れる。これは受け入れる。
2. **最初に見える論理行を戻すのは、帯の幅の変化と `number` の切替の 2 つだけ。** どちらも `rearrange_keeping_line`（覚える → `arrange()` → 戻す）を通る。
   通常の `WM_SIZE` と DPI の変更は従来どおり `resize` → `arrange()` で、スクロール位置は RichEdit に任せる。
   本文の幅が変わると折り返しが変わり「最初に見える論理行」は定義が揺れるうえ、#39 の前から RichEdit 任せだった振る舞いを変えない。
3. **`:set` の表示名は登録表に「設定を変える（:set number）」として持つ。** `folio_command_listed` が偽なのでパレットと「操作」メニューには出ないが、
   登録表の行は表示名を空にしない（1 表 1 形）。利用者に見えるのはヘルプの 1 行（`command_shortcuts` の「Ex  :set number / :set nonumber / :set nu!」）だけである。
4. 設定を書けなかった失敗を台帳の `STORE_FAILED` と分けた理由は ADR 0025 の補正節に置く。
5. **決定 4 の「`EM_STREAMIN` の最中に本文へ問い合わせない」は、`EN_CHANGE` を抑えるだけでなく構造で守る。**
   `ENM_SCROLL` を足したので、流し込みの途中でスクロール位置が動いて `EN_VSCROLL` が届き、その同期描画（`UpdateWindow`）が
   途中の本文から表を作って「古い」の印を落とす経路がありうる（独立レビューの所見。実測は未了）。`note_pane` は `EM_STREAMIN` を挟むあいだ
   「流し込み中」の印を持ち、そのあいだは表を作らず（`refresh_lines` が偽）、番号も描かない。印は流し込みの後に落とし、「古い」の印は残す。
   `EM_STREAMIN` 中に `EN_VSCROLL` が来る回数は Win32 部品 probe に 1 項目足して測り、結果を確認記録に書く（0 回でも印は残す）。
6. **決定 6 の「最初に見える論理行を戻す」のは、`arrange()` の前後で本文の左端が実際に動いたときだけ。** 3〜4 桁では左端は動かないので戻さず、
   閲覧（帯が出ない）で `number` を切り替えても読んでいる位置は動かない。折り返しの途中から見えていた行の先頭へ寄るのは、矩形が動いたときに限る。
7. **番号は帯の矩形で切る。** `EM_POSFROMCHAR` が最初の表示行に負の y を返しうる（条件は未計測）ので、帯の外へはみ出す升目は帯でクリップして描き、
   上の操作行（パンくず・札・閉じる）に重ねない。升目の位置は行の実際の y のまま（本文と同じように切れる）。
   帯に掛からない更新矩形（閉じるボタンの hover など）では番号の一巡（`EM_LINEINDEX` / `EM_POSFROMCHAR`）を飛ばす。
   数字の幅は書体を作り直す `refresh_font` のときに 1 回測って持ち、毎回の `WM_PAINT` で測らない。
8. **桁数の落とし所は番号の列と揃える。** 表を作り直せなかった（確保失敗）ときは、古い表があればその桁数を答え、表が無いときだけ最小の 3 桁にする。
   番号が描けないのに帯の幅だけ縮んで本文が動く、を作らない。
9. **パレットの箱の高さは `folio_command_listed` が真の操作の数で決める。** 登録表の総数（`SET` を含む 13）で確保すると 1 行ぶん余る。
   数は core の `folio_command_listed_count()` が答え、テストで 12 に固定する。
10. 記録: 文脈節の行高（ASCII 25px・日本語 29px・fallback 33px）は実装前の probe の値で、実装後の確認記録の値（ASCII 20px・日本語 26px）とは
    本文の書体と大きさの条件が違う。どちらも「一定でない」の根拠であり、実装は行高で計算しない。`base_digit_fallback = 7` は測定に失敗したときだけの安全側の値で、実測は 6px。
    `adopt_settings` はポートが `LOADED` で `out` を触らなかった場合を `OUT_OF_MEMORY` として畳み、null を採用しない（ポートの契約違反への防御。テストの偽アダプタは常に触る）。
