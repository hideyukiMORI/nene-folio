## 文脈

仕様（FR-001〜FR-033）には、ノートを消す操作も、カテゴリを作る・消す・名前を変える操作も無い。現状（main `0a99ea5` の調査と `2343705` での批評）:

- **カテゴリが 0 件だとノートを作れない**（`folio_state_new_note` が `NO_SUCH_CATEGORY`）。アプリは `data/` もカテゴリのディレクトリも作らないので、
  新しい環境の利用者はエクスプローラでフォルダを作るしか始める手段が無い。外で作った／消したものは再起動の照合で拾える（FR-008）。
- カテゴリ行の右クリックは色の選択を直接開き、ノート行の右クリックは何もしない（FR-010）。ADR 0010 は「項目が増えたら（改名・削除）メニューにする判断が要る」と先送りした。
- `category_ledger` には `toggled` / `recolored` / `moved` しか無く、`note_ledger` にある `inserted` / `removed` / `renamed` が無い。
  `persistence_port`（16 本）にカテゴリのディレクトリを作る・消す・名前を変えるメンバーは無い。`note_corpus` に削除とカテゴリ名の付け替えが無い。
- カテゴリ名には専用の型が無い。名前入力面は種別に関わらず `note_name_create` を通し、末尾の `.md` を剥がす。台帳の `MALFORMED` は application で `LEDGER_MALFORMED` に写る。
- 起動した後に「文書なし」へ戻る経路は 1 つも無い。ノートのカーソルは選択そのもので、カテゴリ行に止まれるのは見えるノート行が無いときだけ（ADR 0015）。
- 履歴 `data/.history/<カテゴリ>/<ノート>/` は md が消えても残り、掃除する経路が無い。同じ名前のノートを作り直すと古い履歴がそのノートの履歴に見える（FR-033 の一覧に出る）。
  カテゴリ間の移動は履歴を連れて行かない（ADR 0012 決定 5）。改名だけが `data/.rename.json` を使って履歴ごと移す（ADR 0022・ノート 1 つ・同じカテゴリ内）。
- `RemoveDirectoryW` / `SHFileOperationW` / `IFileOperation` の使用は 0 件。shell32 は `eng/architecture.json` の `platformLibraries.adapters_win32` に
  **既にある**が CMake では結んでいない。ole32 は一覧に無い。
- コマンドの実行と失敗の分類は #168 で表引きになり（`command_runs[]` / `inline_outcomes[]`）、値を足しても関数の行数は伸びない。別名は 1 コマンド 2 つまで（`alias_limit`）。

hide の裁定（2026-10-06・4 点）:

1. 削除したノートの行き先は **OS のごみ箱**（履歴も一緒に）。確認の箱は出さない。
2. カテゴリの削除は **空のカテゴリだけ**。
3. ドロワーの右クリックは **メニューにする**（カテゴリ行・ノート行・空き）。同じ操作を「操作 ▾」・パレット・Ex にも置く。
4. 4 つとも進める。順は カテゴリ作成 → ノート削除 → カテゴリ削除 → カテゴリ改名。

## 決定

### 分け方と順序

1. **単位に分け、親 Issue は最後の単位で閉じる。順序は固定。** 1 つの単位は「変更 1 命題・フルゲート 1 回」（ADR 0034）に収め、層の境で割る。
   - **前提 P（#168・統合済み）**: コマンドの実行と失敗の分類の表引き。
   - **単位 A（FR-034）カテゴリの作成**: **A1** = core（`category_name`・`category_ledger_inserted`）・application の意図・port・adapter・単体・確保失敗・adapter の実物の probe。
     **A2** = コマンド・名前入力面の種別・文言。`data/` が無い環境で最初のカテゴリを作れる所まで。
   - **単位 M（FR-038）**: ドロワーの右クリックメニュー。この時点の項目は「色を変える…」「名前を変更…」（ノート）「新しいカテゴリ…」。後の単位が自分の項目を足す。
   - **単位 B（FR-035）ノートをごみ箱へ移す**: ADR 0040。**B1** = adapter と probe、**B2** = application と `note_corpus`、**B3** = コマンド・メニューの項目・文言。
   - **単位 C（FR-036）空のカテゴリの削除**: **C1** = core・adapter・application、**C2** = コマンド・メニューの項目・文言。
   - **単位 D（FR-037）カテゴリの改名**: 記録と復旧は **専用の ADR** で決め、割り方もそこで決める（決定 15）。
   依存は一方向: P → A → M → B → C → D。A を先に置くのは「入口が無い」穴を塞ぐから。M を B の前に置くのは、B が「ごみ箱へ移す」をメニューと同時に出せるようにするため。
   D を最後に置くのは、複数のディレクトリを動かす唯一の単位で、記録の版を上げる判断を含むから。
2. **仕様は先に 5 行を足し、備考に「未実装」と単位を書く**（#171）。実装した単位が自分の行の「未実装」を消す。未実装の行を実装済みに見せない（ADR 0001）。
   FR-010 と「決め打ちしない項目」の「ノート行の右クリック: 無し」は単位 M が書き換える。

### 共通の原則

3. **ファイルが真実で、台帳は追随する（ADR 0008 と同じ）。** どの操作も「ディスクの上の実体（ディレクトリ・md・履歴）を先に動かし → 台帳（`categories.json` / `index.json`）を書き →
   メモリの状態を差し替える」。実体を動かす前の失敗は何も変えない。**確保（新しい台帳・`notes[]` の伸長・空の本文）は実体を動かす前に済ませる**
   （動かした後で確保に失敗して数が食い違う状態を作らない）。実体を動かした後で台帳を書けなかったときは、表示はファイルに従う:
   - `index.json` は既存の「未同期の再試行」（`index_pending`・初回保存と同じ経路）に載せる。
   - `categories.json` はメモリの台帳を採用して `FOLIO_STATE_LEDGER_STALE` を返す。次に台帳を書く操作（開閉・色・並べ替え）が同じ内容を書く。
   起動時の照合（FR-008）が、台帳にだけ残った名前を落とし、ディスクにだけある名前を足すので、**巻き戻しは書かない**。
4. **対象は行で名指しする。** application の意図は対象を引数で受ける（ノートは既存の `struct note_ref`、カテゴリは添字）。「いま選んでいるもの」を application が推測しない。
   UI が対象を決める規則:
   - **右クリックメニュー**: 押した行（カテゴリ行ならそのカテゴリ、ノート行ならそのノート）。
   - **「操作 ▾」・パレット・Ex のノートの操作**: **開いている名前付きの文書**。無題・未選択なら UI が既存の `NOTHING_SELECTED` を出す（`begin_replace` と同じ形）。
   - **「操作 ▾」・パレット・Ex のカテゴリの改名・削除**: **カーソルの行のカテゴリ、無ければ開いている文書のカテゴリ**。どちらも無ければ `NOTHING_SELECTED`。
     `folio_state_current_category` の「最初のカテゴリ」への落ち方は使わない（見えていないカテゴリを名前や存在ごと変える既定を作らない）。作成は対象を取らない。
   UI の実行は「対象を受ける関数 `…_at(self, target)`」を 1 つ持ち、表（`command_runs[]`）の行は既定の対象を解いてそれを呼び、メニューの通知は押した行でそれを呼ぶ。
   表の形（窓と引数）は変えない。
   既存の「名前を変更」（FR-031）は開いている文書だけを対象にする契約を変えない。ノート行のメニューの「名前を変更…」は、**押した行が開いている文書ならそのまま**、
   違えばその行を選んで（左クリックと同じ経路）から同じ `FOLIO_COMMAND_RENAME` を実行する。選べなければ（読めない md）その失敗を出して止まる。
   同じノートを選び直すと本文を読み直して Undo を失うので、開いている文書は選び直さない。
5. **断る判定が先、同期が次。** 絞り込み中の拒否（決定 6）と対象の範囲の確認は、既存の開閉・並べ替えと同じく同期より前に行う。
   その後で既存の同期入口（未同期の台帳の再試行と未完了の改名の再開）を通し、失敗したら進まない（ADR 0022 決定 7 の準用）。
6. **絞り込み中は、カテゴリの構造を変える操作を断る。** カテゴリの作成・削除・改名は `FOLIO_STATE_FILTERED`（並び替え・折畳と同じ・ADR 0024）。
   **ノートをごみ箱へ移す操作は絞り込み中でもできる**（探して消すのが自然な流れ。新規・改名が可であるのと同じ側）。終わったら一致集合を作り直す。
7. **確認の箱は作らない（ADR 0038・ADR 0016 の補正 4 の流儀）。** 取り返しは「ごみ箱から元に戻す」（ノート）と「失うものが無い」（空のカテゴリ）で担保する。
   代わりに**項目の名前が行き先を言う**: ノートの項目は「削除」ではなく **「ごみ箱へ移す」**。操作の後の知らせは出さない（行が消えることが結果。成功を知らせる面は今も無く、足さない）。
   裁定の問いには「1 行で知らせる」と書いたが、成功の 1 行を出す面が存在しないので、押す前に読める項目名へ情報を移した（hide へ申し送り済み。違えば変える）。
8. **鍵は割り当てない。** `Delete` や `dd` で消せるようにしない（誤操作 1 打で実体が動く操作に単独の鍵を付けない）。入口はメニュー・パレット・Ex の 3 つ。
   Ex の名前は Vim の `:delete`（行の削除）と紛れない綴りにする（決定 9）。

### コマンド

9. **コマンドは 4 つ足す。** 列挙の末尾にこの順で足す（「操作 ▾」とパレットは登録表の順で平たく並ぶので、壊す 2 つが末尾に来る。区切りは足さない）。

   | 列挙 | ラベル（ja） | Ex | 引数 | 一覧に出す |
   | --- | --- | --- | --- | --- |
   | `FOLIO_COMMAND_NEW_CATEGORY` | 新しいカテゴリ | `:newcategory 名前` / `:newcat` | 名前（無ければ名前入力面） | 出す |
   | `FOLIO_COMMAND_RENAME_CATEGORY` | カテゴリ名を変更 | `:renamecategory 名前` / `:rencat` | 名前（無ければ名前入力面） | 出す |
   | `FOLIO_COMMAND_TRASH_NOTE` | ノートをごみ箱へ移す | `:trashnote` / `:trash` | なし | 出す |
   | `FOLIO_COMMAND_DELETE_CATEGORY` | カテゴリを削除 | `:deletecategory` / `:delcat` | なし | 出す |

   名前を取る 2 つは既存の `FOLIO_ARGUMENT_NAME`（`:rename` と同じ形。ヘッダの注記「ノート名」は「名前」に直す）。各コマンドは自分の単位で足す。
   パレットは 16 行から最大 20 行になるが、既存のスクロールで最小寸法でも出る。色の変更はコマンドにしない（決定 12）。

### 単位 A — カテゴリの作成（FR-034）

10. - **カテゴリ名は core の専用の型 `category_name`**（不完全型と関数・結果は専用の列挙）。規則は `name_list` の規則に次を足したもの:
      (a) 先頭が `.` でない（`.` で始まるディレクトリは走査しないので、作れても見えない）、
      (b) `data/` の直下でアプリが使う名前でない（`categories.json`・`settings.json`。ASCII の大小は無視。同名のディレクトリは次の起動で台帳や設定の読み書きを壊す）。
      末尾の `.md` は剥がさない。`name_list` そのものは変えない（ADR 0012 決定 4。既存の `data/` を読む側の規則は動かさない）。
      UI と Ex は入力からこの型を作り、作れなければ既存の `INVALID_NAME` / `NAME_REQUIRED`。単位 D の改名も同じ型を通る。
    - **重複は application が先に断る**（既存のカテゴリ名と ASCII の大小を畳んで一致すれば `NAME_TAKEN`。ノートの改名と同じ規則）。
      それをすり抜けた衝突は**ファイルシステムに拒ませる**（`CreateDirectoryW` の `ERROR_ALREADY_EXISTS` → `NAME_TAKEN`）。
    - **port に `create_category(adapter, 名前)` を足す。** adapter は `data/` が無ければ作り、**錠を持っていなければ `data/.nenefolio.lock` を取り**
      （ADR 0022 決定 3 の予告の履行）、**取った直後に `data/.rename.json` が無いことを確かめて**から、カテゴリのディレクトリを作る。
      錠を取れない・記録が在る（起動の後で他のプロセスが `data/` を作って使っている）ときは、カテゴリを作らずに既存の値で断る（新しい値は足さない。値と文言は A1 が選び、補正に記録する）。
      このとき作った空の `data/` は残ってよい。`index.json` は作らない（無ければ空の台帳として読む既存の経路）。
      偽ポート（単体・確保失敗・probe）にも同じ行を足す（書き忘れは `nullptr` のまま通るので、A1 の完了条件に入れる）。
    - **application `folio_state_create_category(state, 名前)`**: 絞り込み中なら `FILTERED` → 同期 → 重複の判定 → **新しい台帳（`category_ledger_inserted`・末尾・既定の色・展開）と
      伸ばした `notes[]` を確保** → `create_category` → `write_category_ledger` → 差し替え → カーソルを新しいカテゴリ行へ（空のカテゴリ行は止まる行・ADR 0015）。
      選択・開いている文書・モードは変えない。ディレクトリを作った後で台帳を書けなければ決定 3。
    - **UI（A2）**: 名前入力面に種別 `NAME_PROMPT_NEW_CATEGORY` を足す。名前の EDIT と失敗の 1 行と OK / Cancel だけで、**カテゴリの一覧を持たない配置**にする
      （今の面は一覧を前提にした固定座標）。確定は種別ごとに名前の型を分け、**未完了の改名の保留経路（`hold_pending` 以降）は種別 RENAME だけ**が通る
      （同期が `RENAME_PENDING` を返しても、カテゴリの面がノートの改名の再試行に化けない。失敗の 1 行を出して面は残る）。
      `:newcategory 名前` は面を開かず直接作る。作ったらドロワーを描き直し、新しい行が見える位置へ寄せる。
    - これで「カテゴリ 0 件 → 新しいカテゴリ → 新しいノート」がアプリの中だけで通る。

### 単位 M — 右クリックメニュー（FR-038）

11. - `drawer_window` の `WM_RBUTTONUP` が、押した位置の行の種別で OS のポップアップメニュー（`TrackPopupMenuEx`・「操作 ▾」と同じ部品）を出す。
      左ボタンを押している間は今までどおり無視する。

      | 押した所 | 項目（上から） |
      | --- | --- |
      | カテゴリ行 | 色を変える… / カテゴリ名を変更…（D）/ カテゴリを削除（C）/ ―― / 新しいカテゴリ…（A） |
      | ノート行 | 名前を変更… / ごみ箱へ移す（B） |
      | 行の無い所 | 新しいカテゴリ…（A） |

      括弧はその項目を足す単位。単位 M の時点では A と既存の操作だけが並ぶ。頭の帯（絞り込みの欄のある帯）では出さない。
    - **右クリックは選択もカーソルも動かさない。** 項目を選んだ後で、その項目が必要とするときだけ選ぶ（決定 4 の「名前を変更…」）。
    - メニューで選ばれた項目は、ドロワーが主窓へ**対象付きのコマンド**として同期で送る（`folio_message` に 1 つ足す: `WPARAM` = コマンド、`LPARAM` = 送る側のスタックにある
      `const struct note_ref *`。カテゴリ行ではノート番号を使わない）。実行は主窓の `…_at` を通り（決定 4）、ドロワーが application のカテゴリ操作を直接呼ぶ第 2 の経路を作らない（ARC-001）。
      例外は色だけ（決定 12）。
    - 項目を灰色にする判断を UI はしない（ARC-011）。断る理由（絞り込み中・空でない）は application が返し、失敗の箱が 1 行で言う。
    - 文言は `ui_text`（3 言語）。メニューの項目名はコマンドのラベルと別の ID にしてよい（行の上では「ごみ箱へ移す」で足りる）。
12. **色はメニューの 1 項目になるが、コマンドにはしない。** 「色を変える…」は今の `choose_color` をそのまま呼ぶ。色の選択は OS の箱で引数を取れず、
    鍵とパレットからの入口は今も無い。入口を増やすのは別の要望が出てからにする（この ADR の範囲を増やさない）。色の選択が 1 クリック増えることは hide の裁定 3 に含まれる。

### 単位 B — ノートをごみ箱へ移す（FR-035）

13. **ADR 0040 で決める。** ここで固定するのは 3 つだけ: 編集中なら先に保存する・履歴も一緒に送る・**ごみ箱へ送れると確かめられない場所では消さない**
    （黙って完全に削除される経路を作らない。hide の裁定 1 は「ごみ箱へ」であって「消す」ではない）。
    ADR 0038 決定 16（履歴の削除はしない）は「履歴は、その持ち主のノートまたはカテゴリと一緒にごみ箱へ送るときだけ動かす」へ補正する。

### 単位 C — 空のカテゴリの削除（FR-036）

14. - **「空」は、application の台帳でノートが 0 件で、そのカテゴリに無題の文書が無いこと。** ノートがあれば新しい値で断る（「ノートが残っているカテゴリは削除できません。…」）。
      保存していない無題の文書がそのカテゴリを宛先にしているあいだも同じ値で断る（パンくずと初回保存が宛先を失う）。
    - adapter（port に `remove_category(adapter, 名前)`）は、カテゴリのディレクトリの中身が **`index.json` だけ（または空）** であることを確かめる。
      それ以外が 1 つでもあれば（外で増えた md・サブディレクトリ・`desktop.ini` や `Thumbs.db` を含む利用者や OS のファイル）**何も消さずに**新しい値で断る
      （「フォルダにほかのファイルが残っているので削除していません。」特別扱いの一覧は持たない）。
      通ったら、残った履歴のディレクトリ `data/.history/<カテゴリ>/`（移動で孤立した履歴・ADR 0012）を ADR 0040 の同じ関数でごみ箱へ送り、`index.json` を消し、
      ディレクトリを `RemoveDirectoryW` で消す。**履歴をごみ箱へ送れない（ADR 0040 の `UNAVAILABLE`）ときは、何も消さずにその値で断る。** 履歴のディレクトリが無ければごみ箱は使わない。
    - application `folio_state_delete_category(state, category)`: `FILTERED` → 範囲 → 同期 → 空の確認 → 新しい台帳（`category_ledger_removed`）と詰めた `notes[]` を確保 →
      `remove_category` → `write_category_ledger` → 差し替え。選択・無題の文書の宛先・カーソル・保留の添字を付け替える（並べ替えが既にやっている付け替えと同じ）。
      カーソルが消えた行にあれば、次に止まれる行へ。最後の 1 つを消して 0 件になってよい（単位 A が戻る道を持つ）。

### 単位 D — カテゴリの改名（FR-037）

15. 骨格だけをここで決める。
    - 動かすのは `data/<旧>` → `data/<新>`、`data/.history/<旧>` → `data/.history/<新>`、`categories.json` の名前の 3 つ。添字は変わらない。
    - **記録は `data/.rename.json` を広げて使い、別の記録ファイルを作らない**（復旧の入口を 1 つに保つ・ARC-001）。版を上げる形・識別子の取り方・再開の判定は専用の ADR。
      **記録は完成後のカテゴリの台帳を持つ**（ノートの改名の記録が完成後の `index.json` を持つのと同じ。台帳を書けずに止まったとき、照合に任せると色・順・展開を失うので、
      この単位だけは決定 3 の「照合が揃える」に頼らない）。ADR 0022 の事前拒否（ローカル NTFS・name surrogate・錠）はそのまま準用する。
    - 開いている文書がそのカテゴリにあれば先に保存し、パンくず・`note_corpus` の宛先・置換の下見・履歴の面を新しい名前へ揃える（本文・モード・Undo は変えない）。
    - UI は名前入力面の種別 `NAME_PROMPT_RENAME_CATEGORY`（一覧なしの配置・元の名前を選択状態で出す）。

### 結果の値と文言

16. 足す結果の値は単位ごとに最小にする。既存で言えるものは既存を使う: 名前の不正 `INVALID_NAME`・空 `NAME_REQUIRED`・衝突 `NAME_TAKEN`・絞り込み `FILTERED`・
    台帳の遅れ `LEDGER_STALE`・書けない `STORE_FAILED`・対象なし `NOTHING_SELECTED` / `NO_SUCH_CATEGORY` / `NO_SUCH_NOTE`。
    新しく要る見込み: A = 0、B = 3（ADR 0040）、C = 2（ノートが残っている・ほかのファイルが残っている）、D = 専用の ADR。
    **値を 1 つ足す単位は 4 か所を同じ PR で埋める**: application の `failure_lines[]`・`tests/unit/state_tests.c` の同じ形の表・ui の `inline_outcomes[]`・`ui_text` の 3 列
    （CNF-009 / CNF-011 が落とす）。コマンドを 1 つ足す単位は core の登録表・`argument_kind`・`folio_command_listed`・ui の `command_runs[]`。

## 強制

- 新しい操作が ui から adapters を直接呼ばないこと・shell32 が adapters 以外に結ばれないことは ARC-002 / ARC-003 が **active**（OS ライブラリの強制は CMake の
  `nenefolio_system_link` と `eng/architecture.json`。リンカのシンボル検査は core と application を見る）
- コマンドと結果の値の網羅は CNF-009 の `lineTables`（core の登録表・ui の実行の表・ui の分類の表・application の文言の表・単体の表）が **active**
- 文言の置き場所と 3 言語の列は CNF-010 / CNF-011 が **active**
- 意図の意味（何も変えない失敗・確保が先・`LEDGER_STALE`・添字の付け替え・カーソルの行き先）は `tests/unit/state_tests.c` の偽アダプタ、確保失敗は `allocation_tests.c`（QLT-009）。
  `category_name` の規則（先頭の `.`・予約名・`.md` を剥がさない）は core の単体
- 「錠と記録を確かめてから作る」「空でないカテゴリを消さない」「ごみ箱へ送れない場所では消さない」は adapter の実物を動かす probe で確かめ、確認記録に残す（A1 / B1 / C1）
- メニューの見た目と実機の操作は統合チェックリストの行（hide の目視）

## 結果

得る: アプリの中だけで始められる（カテゴリ 0 件からの道）。消す操作が取り返せる形で入る。右クリックが「その行に効く操作」の入口になり、ADR 0010 の先送りが片付く。
対象を引数で受けるので、開いていないノート（読めない md を含む）もごみ箱へ移せる。カテゴリ名に型が付き、見えないカテゴリや起動を壊す名前を作れない。

失う・残る:

- 色の選択が 1 クリック増える
- 中身のあるカテゴリを 1 回で消せない（ノートを 1 つずつごみ箱へ送るか、エクスプローラでフォルダごと消して再起動する）
- ごみ箱へ送った履歴は、md を「元に戻す」で戻しても、履歴のフォルダを別に戻さないと付いて来ない（ごみ箱の中では別の項目）
- 成功の知らせは無い。ごみ箱に入ったことは項目名とヘルプで伝える
- OS のポップアップメニューはアプリのテーマに従わない（「操作 ▾」と同じ・既知）
- 鍵だけでは右クリックメニューを開けない（Shift+F10 / アプリケーションキーは対象外）。同じ操作はパレットと Ex にある
- カテゴリ間の移動が履歴を連れて行かないこと（ADR 0012 決定 5）はこの ADR では変えない。空のカテゴリの削除が、孤立した履歴をごみ箱へ送る最初の掃除になる
- 外でエクスプローラから作った `.` 始まりや `categories.json` という名のディレクトリは、この ADR の型を通らない（既存の害で、この ADR は増やしも減らしもしない）
- 大小文字の重複の判定は ASCII だけを畳む（ノートの改名と同じ）。それ以外の文字の大小だけが違う名前は、ファイルシステムが拒んだときに `NAME_TAKEN` になる
- カテゴリの台帳を書けずに `LEDGER_STALE` になったカテゴリの作成は、次に台帳を書く操作まで `categories.json` に入らない。その前に終了すると、次の起動の照合が末尾・既定の色・展開で足す（作成の結果と同じ）
- 「このカテゴリに新しいノート」をカテゴリ行のメニューに置く案は入れていない（裁定の範囲の外）
- 简体中文の訳は母語話者の確認を得ていない（ADR 0032 と同じ注意）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| `data/.trash/` へ移す（アプリ独自のごみ箱） | 空にする操作・戻す UI・同名の衝突の規則が要り、単位が増える。hide の裁定 1 |
| 確認の箱を出して完全に消す | 分岐する箱をこの製品は持たない（ADR 0038）。取り返せない。hide の裁定 1 |
| 中身ごとカテゴリを消す | 誤操作の影響が大きく、確認の手段が要る。hide の裁定 2。不便なら後で広げられる |
| 右クリックは色のまま・新しい操作は「操作 ▾」だけ | 対象が「カーソルの行」でしか決まらず、展開中でノートを持つカテゴリ行（カーソルが止まらない）を名指しできない。hide の裁定 3 |
| 対象を「選んでいるもの」に固定し、右クリックで先に選ぶ | 読めない md を選べないので、消したいノートほど消せない。右クリックが保存や切替の副作用を持つ |
| カテゴリの改名・削除の既定の対象に「最初のカテゴリ」を使う | `:delcat` だけで、見えていない先頭の空のカテゴリが消える |
| カテゴリ名を `note_name` や台帳の `MALFORMED` で検証する | `.md` が剥がれ、不正な名前が「台帳が壊れている」と表示される |
| `Delete` / `dd` の鍵 | 1 打で実体が動く。入口は 3 つで足りる |
| ノートの削除で履歴を残す | 同じ名前のノートを作り直すと他人の履歴が付く（FR-033 の一覧に出る）。改名の事前拒否（移動先に残った履歴）にも掛かる |
| カテゴリの改名に別の記録ファイル | 復旧の入口が 2 つになる（ARC-001）。起動時の順序の判断が増える |
| 作成の失敗でディレクトリを巻き戻す | 巻き戻しの失敗という新しい状態を作る。照合が次回の起動で揃える（ADR 0008 と同じ） |
| 空のカテゴリの削除で `desktop.ini` などを黙って消す | 何を「無視してよいファイル」とするかの一覧を持つことになる。利用者が置いたものと区別できない |

## 2026-10-07 の補正 1（#176）

決定 16 の「既存で言えるものは既存を使う」「新しく要る見込み: A = 0」を改める。

1. **理由。** 既存の文言はノートや特定の操作を名指ししており、カテゴリの操作にそのまま使うと起きていないことを言う:
   `NAME_TAKEN`「同じ名前の**ノート**があります。…既存ファイルは変更していません。」・
   `INVALID_NAME`「…**.md を含め** 255 バイト以内で指定してください。」・
   `LEDGER_STALE`「**md は**反映しましたが、台帳（**index.json**）を書き戻せませんでした。保存を再試行するか、…」・
   `FILTERED`「絞り込み中は**並び替えと開閉**ができません。」。
2. **カテゴリ用に 4 値を足す**（`enum folio_state_outcome` の末尾）:
   - `FOLIO_STATE_CATEGORY_NAME_INVALID`: カテゴリ名が `category_name` の規則に合わない。**空の名前もこの値**で、`NAME_REQUIRED`（無題のノートの文言）は使わない
   - `FOLIO_STATE_CATEGORY_NAME_TAKEN`: 同じ名前のカテゴリがある（大小文字だけ違う名前を含む）。何も変えていない
   - `FOLIO_STATE_CATEGORY_NOT_CREATED`: カテゴリのフォルダを作れなかった。台帳も索引も変えていない
   - `FOLIO_STATE_CATEGORY_LEDGER_STALE`: フォルダには反映したが `categories.json` を書けなかった。表示はフォルダに従い、次に台帳を書く操作で揃う
3. **`FILTERED` は値を足さずに文言を一般化する**: 「絞り込み中はこの操作ができません。絞り込みを解いてからやり直してください。」
   （3 言語とも同じ意味へ）。ADR 0024 の決定 4 が引用している旧い字面は、この補正で置き換わる。
4. **決定 3 の読み替え。** 「`categories.json` を書けなかったときは `FOLIO_STATE_LEDGER_STALE` を返す」は `FOLIO_STATE_CATEGORY_LEDGER_STALE` と読む。
   決定 16 の一覧のうち、カテゴリの名前・衝突・台帳の遅れは上の 3 値に置き換わる（ノートの操作は既存の値のまま）。
5. **単位 C / D の対象なし。** カテゴリの対象が無いときの文言も `NOTHING_SELECTED`（「ノートを選んでから編集してください。」）では言えないので、
   その単位で値を足す。決定 16 の C / D の見込みはその分だけ増える。
6. **この補正では値を返すコードを書かない。** 値・文言・4 か所の表（`failure_lines[]`・`tests/unit/state_tests.c` の表・`inline_outcomes[]` は 4 つとも箱・`ui_text` の 3 列）だけを足し、
   網羅は CNF-009 / CNF-011 が守る。返すのは単位 A の実装（application の意図 #177 と A2 の UI。#174 は port と adapter だけ）。
7. **文言の決め方。** 何が起きたか・いまどうなっているか（何も変えていない／フォルダに従う）・次にすること（別の名前・`data/` を確かめる・絞り込みを解く）の
   3 点で書いた（`design:ux-copy` の観点）。English の 2 本（`CATEGORY_NAME_INVALID`・`CATEGORY_LEDGER_STALE`）は最初の案が既存の最長（`INVALID_NAME` の 131 字）を
   大きく超えた（148 字・171 字）ので、意味を保って 133 字・116 字へ縮めた。失敗の箱（幅 480）で 2 行に収まることは既存の最長でしか測っていないので、実機の目視に残す。
   简体中文は母語話者の確認を得ていない（ADR 0032 と同じ注意）。

## 2026-10-08 の補正 4（#197）— ごみ箱操作の入口と完了の 1 行

B3 の実装前に設計サナが受理。決定 7 の「成功の知らせは出さない」を撤回し、hide の元の希望「確認の箱は出さず、1 行で知らせる」を満たす。
ClaudeCode の NeNe Folioリナが `design:design-critique` / `design:ux-copy` で案を検討し、設計サナとの往復で下端の既存余白を選んだ
（`D:\NeNeFolio\design\2026-10-08\trash-notice\`）。他の操作へ通知基盤を広げない。

1. **入口と対象。** `FOLIO_COMMAND_TRASH_NOTE`（`:trashnote` / `:trash`・引数なし）のラベルは「ノートをごみ箱へ移す」。
   「操作 ▾」・パレット・Ex は開いている名前付きの文書だけを対象にし、無題・未選択は `NOTHING_SELECTED`。
   ノート行のメニュー項目「ごみ箱へ移す」は押した行を対象にする。両方が `trash_note_at(self, target)` を通る。
   先にその行を選ばない。対象が現在の文書かつ編集中のときだけ RichEdit の本文を取り出し、保存の判断と実行は application の意図が行う。
2. **完了した後の UI。** `READY` と `LEDGER_STALE` は実体の処理後なので、どちらも一覧を描き直す。

   `LEDGER_STALE` は後始末の後で既存の失敗の箱を出し、成功の 1 行は出さない。それ以外の失敗では完了の後始末を行わない。
3. **空の状態からの次の操作。** B2 で `NONE` の保存を `NOTHING_SELECTED` とするが、「新規・切替・終了の前の保存」がこれを理由に止まってはならない。
   UI の `store_body` は application の保存を呼んで未同期の台帳を再試行したうえで、`NONE` の `NOTHING_SELECTED` だけを前処理の完了へ読み替える。
   明示の保存コマンドの `NOTHING_SELECTED` と、同期に失敗した結果は読み替えない。
4. **完了の文言は事実だけを言う。** `READY` のときだけ「一覧から除きました。」（English: `Removed from the list.`、简体中文: `已从列表移除。`）。
   `TRASHED` と `ABSENT` は application では同じ完了なので、「ごみ箱へ移した」「元に戻せる」とは断言しない。
   行き先は実行前の項目名とヘルプで伝える。通知のためだけに application の結果型や port を増やさない。
5. **描く場所は 1 か所。** 右ペインの既存の下余白 32 DIP のうち下端 24 DIP（既存の `base_command_status_height`）に 1 行を描く。
   左端は本文の左端、右端は窓の右端から既存の閉じるボタンの余白。既存の `mono_font` と `palette.header_text` を使い、
   1 行・縦中央・長ければ末尾省略とする。本文の HWND・大きさ・選択・スクロールを通知のために変えない。
   通知中の下端の面（Ex・検索・置換）は同じ 24 DIP だけ上げる。上寄せの面（パレット・設定・履歴）は下限だけ同じ高さぶん確保し、
   小さい窓でも通知を覆わせない。縮んだ一覧では既存の選択行が見えるように既存の送り位置を調整する。
   検索件数・置換の下見・履歴の行を成功通知で置き換えない。位置調整だけで、入力欄の内容・キャレット・Undo・フォーカスは変えない。
6. **寿命。** UI に完了の印を 1 つだけ持つ。立て下げと配置更新を 1 関数に集める。
   次のコマンド・文書選択・モード切替・面の開閉で消す。既存の `clear_command_status` と選択・モードの経路へ接続する。
   本文の打鍵やマウス移動で消すためのフック、時刻・タイマー、通知の蓄積、復元ボタンを足さない。
7. **同期呼び出し中。** 実 adapter の 21 場面では試験用の `WM_APP` / `WM_TIMER` 配送が 0 回だったが、Shell の全条件で再入しない保証にはしない。
   主窓は処理中の印を持ち、処理中のコマンド・対象選択・終了を重ねて実行しない。
   呼び出し中は所有する主窓への入力を `EnableWindow` で止め、戻ると元の有効状態へ戻す（子窓も暗黙に入力停止する Windows の契約）。
   一時的なフォーカス変化で既存の入力面を閉じず、他文書の操作では元の有効なフォーカスへ戻す。OS 境界と COM は B1 の adapter に閉じたまま。
8. **検証と限界。** コマンドの解釈・引数拒否・表の網羅・3 言語を対象単体で固定する。
   隔離したデータで現在／別文書／未選択／無題、失敗、`NONE` 後の新規と終了、通知と検索／置換／履歴の同居を確認する。
   最小窓・light/dark・DPI は実際に測った条件だけ記録する。親窓の描画文字には UIA を追加せず、読み上げ通知は未対応。
   简体中文は母語話者の確認を得ていない。

参照: [EnableWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enablewindow)。

## 2026-10-08 の補正 5（#202・C1）

空カテゴリの削除を実装する前に、決定 14 の API・結果・失敗境界を次のとおり受理する。
補正 4 は単位 B3 として統合済みで、統合順は B3 → C1 とする。

1. **検査した実体のハンドルで削除を求める。** カテゴリと既存の `index.json` は `DELETE | FILE_READ_ATTRIBUTES`、
   `FILE_SHARE_READ`、`FILE_FLAG_OPEN_REPARSE_POINT`（ディレクトリには `FILE_FLAG_BACKUP_SEMANTICS` も）で開き、
   既存の `open_entry` / `not_link` を使って種類と name surrogate を検査する。カテゴリは列挙から最後の処理まで保持し、
   index は履歴の処理前に開いて保持する。index の readonly は履歴を動かす前に拒否する。
   カテゴリの共有を 0 にすると、保持中の `FindFirstFileW` が共有違反になるため採用しない。
2. **削除の API は `SetFileInformationByHandle(FileDispositionInfo)` だけ。** 履歴の処理が成功した後、
   index の `DeleteFile=TRUE` を受理させて閉じ、空カテゴリにも同じ要求をして閉じる。
   `DeleteFileW` / `RemoveDirectoryW` で名前を開き直す経路も、再帰削除も、完全削除への fallback も作らない。
   disposition の対象は検査済みのアプリの index と空カテゴリに限る。ノート・履歴には使わない。
3. **列挙と履歴の順。** adapter は錠と改名記録の不在を呼ぶたびに確認し、`data/` は作らない。
   カテゴリ内に `index.json` 以外の項目があれば、履歴も動かさず拒否する。index は通常のファイルだけを受け入れ、
   同名ディレクトリや name surrogate は拒否する。孤立履歴は B1 の `recycle_entry` だけに渡し、
   `TRASH_TRASHED` / `TRASH_ABSENT` 以外なら index とカテゴリに disposition を求めない。
   カテゴリが既に無い場合も孤立履歴を同じ経路で処理してから不在を返す。
4. **port に専用結果 `enum category_remove_outcome` を置く。** `CATEGORY_REMOVE_REMOVED`（カテゴリ削除を OS が受理）、
   `CATEGORY_REMOVE_ABSENT`（カテゴリは既に不在）、`CATEGORY_REMOVE_HAS_FILES`（事前列挙でほかの項目）、
   `CATEGORY_REMOVE_HISTORY_NOT_RECYCLED`（履歴の移動を確認できない）、`CATEGORY_REMOVE_FAILED`（その他）の 5 値。
   初めの 2 値だけが application の台帳採用へ進む。ごみ箱とカテゴリ削除を同じ結果型にはしない。
5. **成功と即時の物理不在は同義ではない。** 削除共有を許す既存 reader があれば、disposition 受理後も最後の reader が閉じるまで削除待ちになる。
   index が削除待ちだとカテゴリの disposition は `ERROR_DIR_NOT_EMPTY` で失敗し得る。このとき index だけが既に削除を受理され、
   履歴も移っている可能性がある。列挙後に子が増えた場合もカテゴリ削除は失敗し、増えた子は保持される。
   後段の失敗を事前の `HAS_FILES` に読み替えず、`FAILED` として返す。巻き戻し・再帰処理はしない。
   `REMOVED` は OS の削除受理を表し、全 reader の終了や実体の即時不在を保証しない。
6. **application の追加値は 4 つ。** 台帳にノートがある／無題の宛先なら `FOLIO_STATE_CATEGORY_NOT_EMPTY`、
   port の後半 3 値は `FOLIO_STATE_CATEGORY_HAS_FILES` / `FOLIO_STATE_CATEGORY_HISTORY_NOT_RECYCLED` /
   `FOLIO_STATE_CATEGORY_REMOVE_FAILED` に写す。決定 16 の値の見積りを置き換える。
   文言はカテゴリ用に 3 言語で持ち、履歴失敗では「フォルダを削除していない」、後段失敗では
   「フォルダの削除を確認できない。フォルダとごみ箱を確認。履歴や索引だけ処理済みの可能性」を伝える。
   ノートの残存や操作全体の無変更は断言しない。`categories.json` 失敗は既存の `CATEGORY_LEDGER_STALE`。
   対象なしの UI 結果は C2 で足す。
7. **確保と状態採用。** `FILTERED` → 範囲 → 既存同期 → 空の確認 → `category_ledger_removed` と
   null 番兵を持つ縮小 `notes[]` の確保 → port → 台帳書出し → 採用を守る。
   失敗前の配列は既存の note ledger を借り、成功時だけ除いた空 ledger と旧配列を捨てる。
   現在の別文書・無題・モード・本文・Undo・履歴・preview は保存も再読込もせず、カテゴリ添字だけ詰める。
   対象のカーソルは同じ添字の次カテゴリ見出し（残りが無ければ既存の `settle_cursor` による先頭見出し、0 件なら無し）へ移す。
   「次に止まれる行」はこの見出しへの移動とし、削除後に別ノートを読んだり本文を確保したりする経路は足さない。
8. **根拠と限界。** Windows 11 / 固定 NTFS の隔離 probe で 18 場面・108 checks、保持確認 20/20 が成功した。
   記録は `D:/NeNeFolio/agents/202-remove/probe-report.md`、証跡は
   `D:/NeNeFolio/design/2026-10-08/category-remove-probe/`。
   別 OS・媒体・ACL・祖先ディレクトリの差替え・全競合・クラッシュを測定済みとはしない。
   製品 adapter の結線は C1 が別に検証する。保存 schema・依存・ゲートは変えない。Waivers: none。
