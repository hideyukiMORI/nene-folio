# ADR 0043 — 単体実行を既定とし、現在の指示・状態と過去の記録を分ける

- 状態: 受理（2026-10-12のhide指示を正本へ反映。NeNe Folioサナ）
- 日付: 2026-10-12
- Issue: #274
- 置換: [ADR 0034](0034-agent-seats-by-job.md)（運用全体。製品アーキテクチャは不変）
- 影響する規則: GIT-001 / GIT-002 / GIT-003 / GIT-004 / ARC-001 / QLT-010 / QLT-012 / QLT-013

## 文脈

hideは2026-09-07に単体実行を既定とし、2026-10-12に適用範囲を明確にした。
対象プロジェクト・現在の作業で明示された分担はその範囲で優先するが、他案件や次の作業へ広げない。
古いメモリ・日報・引き継ぎは時点付きの参考情報であり、現在のhide指示・正本・実際のIssue/PRと照合する。
過去の一時的な許可や手順を、新しい実行の許可として扱わない。

ADR0034は2026-09-22のClaude Code利用実績をもとに、特定モデルの固定分担と工程ごとの新規Agentを求めていた。
現在の対話席がAstraでも、この記述を無条件に適用すると最新指示と衝突する。
さらにCLAUDE.mdは500行、todo/current.mdは595行あり、古い停止・再開指示、closed済みIssue、
実装済みの履歴復元を未実装とする説明が「現在」の入口に残っていた（調査基点 `2b0e376`）。
ローカルのNeNe Folio用メモリにも、旧停止点・固定分担・ブランチ削除付きの旧merge手順が残っていた。

[OpenAIのAstra向け公式記事](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)も、
古いモデル向けの細かい手順を見直し、必要な文書を必要な場面で読む構成と明確な完了条件を勧めている。
これは整理の参考であり、hideの指示・本プロジェクトの品質基準を置き換える根拠にはしない。

## 決定

**現在の対話席が調査・設計・実装・検証を直接進めることを既定にし、現在の指示と状態だけを短い入口に置く。**

1. 必要な独立レビューだけ、読み取り専用のサブエージェントを使う。軽微な変更に一律のレビューは足さない。
   hideが対象プロジェクトまたは現在の作業に明示した役割分担があれば、その対象・期間・仕事の範囲で適用する。
   Opus/Sonnet/HaikuやAstra/SOL/LUNAへの固定分担、工程ごとの新規席、席の再利用・forkの一律禁止を既定にしない。
   実際のモデルや委任方法は現在の指示と利用可能な道具に従う。
2. 委任する場合は、目的・完了条件・根拠となる指示・読み取り/編集の範囲・成果物・対象検証・置き場を伝える。
   [指示書テンプレート](../IMPL_SEAT_BRIEF_TEMPLATE.md)は必要項目の確認に使い、固定文言や機械的な工程分割を要求しない。
   対話席が結果と実出力を確認して受理する。委任そのものを目的にしない。
3. `AGENTS.md`と`CLAUDE.md`は入口と安定した注意点、[todo/current.md](../todo/current.md)は現在状態の要約とする。
   タスクの実状態はIssue/PRとcheckoutを確認する。製品仕様はSPECIFICATION、判断は受理ADR、実測は品質記録、
   日付付きの経緯は日報・引き継ぎに置く。入口へ過去の状態を追記し続けず、完了した項目を置き換える。
4. 再開時は現在の依頼・作業範囲を確認し、最新main、未コミット差分、該当Issue/PRを照合する。
   古い「停止」「自走」「全権委譲」や過去のmerge許可だけで現在の指示を決めない。
   現在の依頼に含まれる作業は必要な検証・反映・整理まで完了させ、工程ごとの不要な再確認を挟まない。
5. production変更前の必読・正典経路・品質基準は維持する。既読かつ変更の無い規約は作業継続時に読み直さず、
   対象に関係する差分・ADR・waiverを確認する。文書の修正のために全履歴や製品全体を読み直さない。
   検証は変更と直接影響する境界に絞る。実装が不変なら成功済みの対象検証を再利用し、受け渡しだけで繰り返さない。
   フルゲート・必須CIの条件はQLT-012のまま。閾値・除外・重大度を変えたり、未実行を成功として扱ったりしない。
6. 追加worktreeは `D:/NeNeFolio/worktrees/<issue>-<名前>`、報告・ログは `D:/NeNeFolio/agents/<issue>-<仕事>/`。
   測定/設計の絵は既存の `D:/NeNeFolio/design/`、実機の絵は `D:/NeNeFolio/check/` を使う。
   編集先を絶対パスで確定し、本体main・他の作業木を誤って書き換えない。統合・必要反映・成果物収載後は、
   [ワークフロー](../DEVELOPMENT_WORKFLOW.md) §2の確認をして追加作業木と不要な一時物を整理し、ブランチとcommitを保持する。
   旧C側41作業木とD側`210-rename-state`の従来の判断待ちは、このADRだけで解除しない。
7. 編集可能な当プロジェクト用メモリも正本への短い参照にする。変更前を復元可能に保存し、古い状態・許可を複製しない。
   グローバル設定、他プロジェクト、アプリ管理のメモリ、モデルそのものへこの変更を広げない。
   重複や矛盾が再発したら既存の正本を直す。新しいルールやスクリプトは、具体的に防ぐ問題と対象を説明できるときだけ足す。

## 強制

- 機械強制: **不能**（指示の適用範囲、委任の要否、履歴を現在指示として読まない判断）。変更した入口と旧版・参照先を自己レビューする。
- 既存のゲート、Issue/PRの経路、`tools/merge-pr.ps1`、完了後の整理は引き続き使う。
  今回は運用文書とローカルメモリだけの移行であり、製品コード・ゲート・schemaの移行は無い。
- CI成功は文章の意味の適切さやメモリの参照方法を証明しない。`active`な機械強制を新たに主張しない。

## 結果

現在の状態を読む入口が短くなり、モデル固有の古い手順と現在のhide指示の衝突を減らせる。
旧ADR本文、日報、引き継ぎ、品質記録は時点付きの証拠として保持する。削った現在欄の原文は固定commit `2b0e376`で参照できる。
過去の全記録の事実監査はしていない。利用時の照合は必要であり、メモリが再び古くなることを機械で防ぐものでもない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| モデル名だけをAstra/SOL/LUNAへ置換する | 固定分担と過剰な工程分割が残り、単体実行の既定に合わない |
| 新しい優先規則だけを古い現在欄の先頭へ追記する | 過去の指示と実装状態が同じ入口に蓄積し続ける |
| 過去の記録や判断を消す | 根拠と復元性を失う。現在の入口から分ければ足りる |
| 読取・検証・品質ゲートを一律に省く | 今回の問題は古い運用と重複した状態であり、製品の保証を弱める理由がない |
