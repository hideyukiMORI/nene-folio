# ADR 0046 — 設定は既存の採用経路を保ち、独立した中央の面として描く

- 状態: 受理（hideが中央ダイアログ案を承認。2026-10-12の完成候補で対象確認）
- 日付: 2026-10-12
- Issue: #286
- 規則: FR-013/014/016/021/022/024、ARC-001/002/004/011、C-002/018、QLT-008/012/013
- 関連: [ADR0031](0031-theme-and-settings-surface.md)、[ADR0032](0032-languages.md)、[ADR0033](0033-vector-icons.md)、[ADR0044](0044-tests-at-completion-and-integration.md)

## 文脈

hideの実画面では、設定と背後のメニューに同じ暗い面が使われ、設定の見出しと輪郭が無いため、表示崩れのように見える。
中央ダイアログ案を承認し、カテゴリ追加の常設入口、3表示モードと順に実装する指示を受けた。本Issueは設定だけを扱う。
現行は`COMMAND_SURFACE_SETTINGS`がパレットの矩形を共用し、11行を縦に並べる。値の採用・失敗表示・元のフォーカスへ戻る経路は既にある。

## 決定

1. 設定の状態・入力・採用は既存`command_layer`と`settings_rows`に置く。別の設定モデルや保存処理は作らない。
   ADR0031/0032の縦の一覧という見せ方を、この中央ダイアログへ置き換える。設定schemaは版3のまま。
2. 設定だけに中央の矩形を与え、タイトル「設定」と右上の閉じるアイコン、背景より明るい不透明な面、細い輪郭を持たせる。
   文字は`ui_text`の3言語表、色と暗幕の濃さは`folio_palette`、閉じる/選択の形は`icon_paint`を正本にする。
3. 背後を暗くする装飾用のchild windowを、設定面より下・他の子より上に置く。`WS_EX_LAYERED`と`SetLayeredWindowAttributes`の定数alphaを使用し、
   設定中だけclient全体から同じ設定矩形を除いた領域を`SetWindowRgn`で覆う。背後クリック/ホイールは渡さず、設定へフォーカスを戻す。
   Z順が正しくてもlayered childの合成がカードまで暗くなる実測があり、カード範囲を暗幕のregionから物理的に除く。
   成功したregionはOS所有とし、失敗時だけ破棄する。背景のcaptureやRichEdit本文の再描画経路は追加しない。
   HWND/brushと生成失敗・破棄は`folio_window`が所有し、設定を閉じた後や別の入力面では暗幕を残さない。
4. テーマ3候補と言語3候補をそれぞれ横並びにする。言語は承認案のコンボと異なり、既存の3候補を常に見せる。
   項目数が少なく、現在値と選択肢を一目で比較でき、追加のpopup/controlによる入力経路の二重化も避けられる。
   内容幅が約360 logical px未満なら同じ表と矩形計算から1列へ折り返す。文字を省略せず、後続の細い一覧窓でも内容を辿れる。
   行番号は1つのチェック操作にまとめ、採用は現在値の反転を既存`apply_number`へ渡す。
5. 設定項目の矩形を描画とhit判定で共用し、方向キー/Tabも同じ選択状態を使う。Enter/クリックの採用は既存の設定適用へ合流する。
   キーボードの注目と採用済みの値は別に示す。Escと右上の×は既存のclose/return-focus経路に結ぶ。
   開くときは現在値から選択を決めてから配置する。設定保存の失敗・読込不良は面内で読めるように残す。
6. 見出し・閉じる入口・版と案内のfooterは固定し、窓/DPIに合わせて内容の領域を決める。小さい窓でも選択と採用に到達できる。
   文言を短縮して意味を失わせず、必要なら内容だけスクロールする。失敗理由と版が互いに重ならないことを確認する。
7. 設定の開閉だけで本文・Undo・変更印・キャレット・読んでいる論理行を変えない。テーマ/言語/行番号を実際に変えるときは、
   既存の退避・設定保存・採用・復元の経路を維持する。OSテーマ変更への追随も維持する。

## 確認と強制

既存のenum網羅、文言表の列網羅、source所有、コンパイラ/静的解析の規約を維持する。閾値・除外・waiverは追加しない。
見た目の識別と実OS操作は機械での一般保証ではなく、完成候補で3言語・明暗・最小窓・125%の実画面を確認する。
キーボード/クリック、背後操作の遮断、閉じた後の操作復帰、編集中の保持、保存失敗表示を変更境界としてまとめて確認する。
成功済みの無関係な製品回帰を繰り返さず、最終PR headのフルゲートは必須CIに集約する。
実測の範囲・環境・画像・初回の診断は[品質記録](../quality/2026-10-12-settings-dialog-checks.md)に残す。

## 結果と範囲

設定であることを面・見出し・操作のまとまりで示せる。追加のwindowは暗幕の表示と背後入力の遮断だけを担当し、設定の意味を所有しない。
カテゴリ追加入口と表示モードは後続Issue。窓サイズの永続化、配布版の変更、既存Releaseの差替え、他の入力面の外観変更は含めない。

## 却下した選択肢

- 色だけを変える: 設定の見出しと範囲、背後との操作上の区別が不足する。
- 右端の設定パネル: 比較案として提示したが、hideが承認した中央案に統一する。狭い一覧窓では本文と競合しやすい。
- 独立した設定windowと保存model: 既存の設定採用・エラー・フォーカス復帰を二重化するため採らない。
- 背後の画像を取得して暗く描く: RichEditとDPIを含む再描画・キャッシュの同期が増えるため採らない。
- 設定ごとの新しいテスト経路: 保存契約は既存の対象テストを利用し、今回の実OS確認は表示と入力の変更境界に限定する。
