# ADR 0049 — 125種類の配色を既存のテーマ採用へ結び、設定から検索して選ぶ

- 状態: 受理
- 日付: 2026-10-12
- Issue: #294
- 規則: ARC-001 / ARC-003 / ARC-004 / ARC-008 / ARC-009 / ARC-011、C-002 / C-003 / C-012 / C-014 / C-016 / C-018、CNF-009 / CNF-010 / CNF-011、QLT-008 / QLT-009 / QLT-012 / QLT-013
- 置換範囲: ADR0031の3値という上限、ADR0046のテーマ3択の表示。設定採用の原子性、編集中の再着色、言語・行番号・中央ダイアログの既存契約は維持する。

## 根拠

hideはNeNeNibと同じ125種類をFolioでも選べることを指定した。参照するNibはcommit
`5b7dbb2791785e508384fd3a7e82cb01f40c8ebb`の`src/core/BuiltinThemes.hpp`。
現在のFolioは`folio_settings` → `folio_state_set_theme` → 再着色という1本の経路を既に持つ。
125項目を現在の3択の横列へ足すだけでは探しにくいため、設定に検索できる候補一覧を設ける。

## 決定

1. 既存light/darkにNibの125種類を追加して、固定配色は127種類とする。選択肢はOS追従のsystemを加えた128種類。
   既存のFolio light/darkのRGB値と、systemがこれらを選ぶ通常時の規則を保持する。
   OSポートのlight/dark限定は#320の[ADR0057](0057-system-contrast-snapshot.md)で置換する。
   高コントラストではOS色から解決した一時的な実効paletteが優先し、保存した固定選択は保持する。
2. `folio_theme`は固定配色ID、`folio_theme_choice`はsystemを含む利用者の選択という既存の区別を維持する。
   固定配色の名前と全色はcoreの1表が所有する。選択enumの固定値は固定配色enumから明示的に導出し、独立した名前表を作らない。
   systemの解決と名前の解析は`folio_theme_choice`へ集約する。旧`folio_theme_resolve`は同時に移行・削除する。
   表の網羅はCNF-009の既存検査対象を新しい正本表へ移す。新しい抑制・例外・閾値変更は不要。
3. coreの`theme_palette`はRGB値とRTF色の束を持つ。UIの`folio_palette`はそこからCOLORREFへ写す境界にする。
   UI/RTFの別々の固定RGB表は撤去する。Nibの本文背景・本文前景を保持し、一覧・選択・見出し・コード背景・ダイアログに
   必要なFolioの役割へ配色を割り当てる。本文/一覧/選択/番号/見出し/リンク/コード/ダイアログの可読文字は、
   実際に載る各背景とのコントラスト比4.5:1以上を求める。元色で不足すれば本文前景へ整数1%刻みで寄せ、
   それでも不足すれば黒、白の順で同じ補間を行って最初に条件を満たす値を採る。選択文字は初めからその背景に対して
   比の高い黒/白を補間の行先にする。これは取り込み時の値決定で、runtimeに別の色生成経路を持たない。
   変更は色だけで、Markdown構文解析・フォント・レイアウトの変更を含めない。
4. Nibの配色を固定commitから一度取り込み、名前・出典・RGBの対応を記録する。
   Nibの配色notice/ライセンス全文はTHIRD_PARTY_NOTICES.txtへ保持し、配布layoutの正典へ加える。実行時のNib参照、外部ファイル読込、
   ビルド時コード生成、C++依存は追加しない。採用後の製品色の正本はFolioのC表1つ。
   テーマIDは保存/Exにも使う翻訳しない識別子で、ノート名と同じく表示するデータである。案内・ラベル・失敗説明は従来のui_text三言語表へ置く。
5. settings.jsonを版4へ上げる。キーと順序は`version/number/theme/language`のまま、themeの有効値だけを広げる。
   版1〜3を既存の契約で読み、次の明示的な設定変更で版4を書く。起動だけでは書き換えない。
   旧版2/3のthemeは従来の3語に限り、版4は128候補を受ける。未知のテーマ・破損・未来版を既定値で上書きしない。
   `folio_state_set_theme`の「必要な値を作る→設定を書く→成功時だけ採用」を維持する。
6. 設定のテーマ部分は現在値を示す1つの選択入口へ変える。開くと同じcommand_layerのテーマ選択面へ移り、
   EDITで名前を部分検索できる。候補は名前・色見本・採用印を持つ。候補カーソルと採用済み値を区別する。
   一覧は128項目を持ち、検索はASCII英字の大小を無視する。0件、スクロール、最小幅320、3言語を扱う。
7. テーマ選択面も中央の設定矩形と暗幕・背後入力抑止を共有する。新しい保存モデルや別のモーダルループは作らない。
   クリック/Enterで既存apply_themeへ渡し、採用後も一覧を保って配色を比較できる。矢印/PgUp/PgDnで候補を移動する。
   Esc/戻るは設定へ戻り、閉じるは設定を閉じて元の可視領域へフォーカスを戻す。検索欄のIME変換中に候補を採用しない。
8. Exの`:set theme=<ID>`も同じ名前解析とapply_themeへ合流する。旧3語の特別な実行分岐は撤去し、
   新しいテーマも同じ構文で選べる。未知語を別テーマへ黙って落とさない。
9. 色の反映は既存recolor_window/recolor_pane/TOM Undo停止を使う。未保存本文・Undo・変更印・選択・表示論理行を保つ。
   一覧・設定・入力欄・tooltip・後から開く名前入力面/失敗箱にも同じ配色を渡す。設定以外のファイルをテーマ選択で書き換えない。

## 確認

対象検証・独立レビュー・実画像の結果は[品質記録](../quality/2026-10-12-theme-catalog-checks.md)を参照する。

名前と件数・Nibからの基礎色の一致、旧配色の不変、可読文字のコントラスト、設定移行/拒否/往復、設定採用の失敗不変、
Ex解析、三言語文言を変更境界のunitで確認する。nativeの候補操作・再着色・編集中保持は隔離fixtureで実際のWin32経路を通す。
代表的な明暗と狭幅・3言語を実画像で確認する。最終headの必須CIで正典フルゲートを要求する。
実物の全125配色の目視、別OS/DPI、物理IMEとスクリーンリーダーの一般保証には広げない。Waivers: none。

## 採らない案

- 125個の選択肢を一般設定へ直接並べる: 言語・行番号へ辿りにくい。
- runtime JSON/C++ライブラリをNibから共有する: Folioの純C・単独配布・設定境界に不要な依存を足す。
- 選択中の仮配色を保存状態とは別に持つ: 当初は採らなかった。#366の[ADR0061](0061-theme-live-preview.md)で、保存値を複製せず既存設定へ戻すプレビューへ置換する。

利用者のテーマファイル読込と公開Release更新は別の依頼範囲で扱う。
