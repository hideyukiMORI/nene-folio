# ADR 0050 — 無題から離れるときだけ保存しない選択を受ける

- 状態: 受理（2026-10-13のhide指摘を具体化。設計: AstraのNeNeFolioサナ）
- 日付: 2026-10-13
- Issue: #298
- 規則: FR-006/018/019/029、ARC-001/003/004/010/011、C-002/005/008/012/018、QLT-008/009/012/013
- 関連: [ADR0020](0020-untitled-note-and-first-save.md)決定5/8の離脱契約を補正する。
  [ADR0016](0016-command-catalog-and-shared-execution.md)決定2/7/10の通常終了と明示保存終了の同一視も補正する。
  [ADR0021](0021-save-as-preserves-original.md)の明示保存、[ADR0035](0035-dialog-theme.md)の同期モーダルと塗りを維持する。

## 問題

新規の無題から別ノートを開くと、名前と保存先を入力する初回保存面が開く。
保存とキャンセルしかないため、不要な作りかけを保存せずに移動できない。
一方、同じ保存経路はCtrl+S、本文Esc、保存して閲覧、明示的な保存終了も使う。
共通保存へ無条件に破棄を足すと、それらの操作で意図せず本文を失う。

## 決定

1. 無題を別ノートまたは次の新規ノートで置き換える操作と、通常の閉じる操作（上部の×・Alt+F4・WM_CLOSE）に、
   **保存 / 保存しない / キャンセル**を用意する。空の無題も現行どおり未保存として扱い、自動では破棄しない。
   保存は初回保存の成功後だけ元の操作を続ける。保存しないは現在の無題を保存せず元の操作を続ける。
   キャンセル・Esc・ダイアログの×は元の操作を止め、無題・本文・Undoを保つ。
2. `name_prompt`の退出用の閉じた種別で、既存の名前欄・カテゴリ一覧・エラー・テーマを再利用する。
   前段の確認面を追加しない。見出しは「保存しますか」、説明は保存しないと内容を失うことと既存の拡張子説明。
   ボタンは左に「保存しない」、右に従来の「保存」「キャンセル」。保存を既定とし、破棄に初期focusを置かない。
   日本語・English・简体中文は`ui_text`の一表へ置く。
3. Enterは名前欄・カテゴリ一覧では保存。各ボタンに明示的にfocusを移した後のEnter/Spaceはそのボタンの操作。
   owner-drawのEnterがIDOKとして届く既存のOS挙動を、focusから解決する同じ経路で扱う。
   IME変換中の確定抑止、親の無効化、同期呼出し、キャンセル時のfocus復帰を維持する。
   Tabは名前・カテゴリ・保存・キャンセル・保存しないの順。文言の幅と折返しは実画像で確認する。
4. Ctrl+S・`:w`・別名保存・`:wq`/`:x`・「保存して終了」は明示保存なので破棄を出さない。
   本文Escによる索引へのfocus移動と「保存して閲覧」も、同じ文書を残す保存操作として維持する。
   `:q`は未保存なら拒否、`:q!`は明示破棄終了のまま。名前付きノートの既存自動保存を変更しない。
5. 保存面の成功/取消/失敗と、無題を置き換えてよいかの閉じた許可を分けて返す。
   許可は同期呼出し元のローカル値だけに置く。`folio_state`へ破棄済みフラグや継続操作を保存しない。
   保存しないを選んだ時点では文書状態もRichEditも変えない。単なる保存成功への読み替えもしない。
6. 既存の`folio_state_select_note` / `folio_state_new_note`等の一つの採用経路に、無題保護/明示破棄の型付き許可を渡す。
   通常の呼出しは無題保護。明示破棄を受けた一回の遷移だけ無題からの置換を許す。
   対象の妥当性・本文の読取・閲覧RTF・必要な編集RTFを先に準備し、成功後だけ文書と表示値を採用する。
   読取/確保失敗で無題を先にNONEへ落とさず、本文・Undo・現在文書を保つ。
   選択後のUIは準備済みRTFを反映し、編集RTFを再確保して失敗し得る第2段階を作らない。
7. ノート行のクリックと索引キーは既存の`switch_note`へ集約する。
   カテゴリの展開キーが中のノートを開く場合も同じ許可を渡す。
   文書を置き換えないカテゴリ移動・端・並替へ、新しい破棄確認を増やさない。
   通常終了と明示的な保存終了は入口の意味を区別し、最後の終了処理は共有する。
8. 保存先不正・同名・md公開前の保存失敗は既存どおり面内に理由を示し、入力を保持する。
   md公開後の台帳失敗や検索写しの確保失敗は、名前付きになった文書を未保存へ戻さない。
   退出面を閉じて表示を更新し、理由を通知して後続遷移を止める。保存済み文書へ「保存しない」を適用しない。
   保存しない経路は無題のmd・履歴・索引を作らない。既存の復旧/台帳同期を迂回する許可にも使わない。

## 検証と範囲

対象unitで許可なしの保護、破棄許可付きselect/new、無効対象・読取失敗・閲覧/編集RTF確保失敗時の保持、
create/write/archiveの非実行を確認する。既存の確保失敗測定経路を使い、製品にテスト専用窓口を作らない。
実Win32の隔離fixtureでは3選択・Enter/Esc/×・IME抑止・保存成功/失敗・本文/Undo・通常終了を確認する。
明示保存に破棄が出ないこと、名前付きノートの自動保存も直接影響する境界として確認する。
3言語・狭い配置の実画像を視認する。物理IMEや別OS等の未測定条件は区別して残す。
対象検証は完成候補でまとめ、最終headの必須CIへ統合フルゲートを集約する（QLT-012）。

保存schema・公開Release・実行時依存・品質ゲートは変更しない。Waivers: none。

## 採用しなかった案

- 先に無題を消してから別ノートを読む: 読取や確保の失敗で作りかけを失う。
- 共通保存へ無条件に破棄を追加: Ctrl+Sや本文Escの意味を変えてしまう。
- 前段の3択確認と後段の名前入力: 保存に必要な面と操作数が増える。
- 非同期の継続キュー: 既存の同期モーダルと呼出しローカルだけで解決できる。
