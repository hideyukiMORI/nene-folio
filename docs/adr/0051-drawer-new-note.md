# ADR 0051 — ドロワーの新規入口は対象カテゴリを共通作成処理へ渡す

- 状態: 受理（実装前に判断を固定）
- 日付: 2026-10-14
- Issue: #302
- 規則: FR-029/034/038/039、ARC-001/004/011、C-002/012/017/018、QLT-008/012/013
- 関連: [ADR0020](0020-untitled-note-and-first-save.md)、[ADR0039](0039-note-trash-and-category-operations.md)、[ADR0047](0047-three-layout-modes.md)、[ADR0050](0050-unsaved-note-departure.md)

## 文脈

一覧のみ表示にはCtrl+Nがあるが、マウスで新しいノートへ進む常設入口がない。
10月13日のGUIレビューの最優先項目として、hideの継続依頼を受けて実装する。
既存の新規コマンドは現在カテゴリを解決するため、カテゴリ右クリックからそのまま呼ぶと別のカテゴリを使ってしまう。
また、新規コマンドは無題の離脱確認より前に一覧から両方へ広げるため、キャンセルしても表示が変わる。

## 決定

1. ドロワーの検索欄の上に高さ40 logical pxの固定帯を足し、文字付きの「＋ 新しいノート」を常設する。
   検索欄とカテゴリ見出し・カテゴリ作成の＋はその下に置く。新規ノートとカテゴリ作成は別の段で意味を区別する。
   描画・hit・capture解除は同じ矩形を使い、固定帯全体の高さは既存の行配置/clip/hit/scrollへ一度だけ渡す。
   押した固定ボタンはNONE / NEW_NOTE / NEW_CATEGORYの閉じた型で一つだけ保持し、外で離す・captureを失う場合は実行しない。
2. カテゴリ右クリックの先頭へ「このカテゴリに新しいノート」を加える。右クリックだけでは選択・カーソル・focusを動かさない。
   既存の型付きdrawer menu通知にNEW_NOTEを足し、押した行のカテゴリ番号を同期で主窓へ渡す。
   常設ボタンは既存のfolio_state_current_categoryで解決したカテゴリを同じ通知へ渡す。
3. 主窓はnew_note_at(self, category)を一つ持ち、Ctrl+N・本文側GUI・Ex・パレットとドロワー通知がここへ合流する。
   カテゴリは無題の保存面を開く前に値で確定する。保存面で旧無題の保存先を変えても、新規の作成先は変わらない。
   depart_document → folio_state_new_note → 準備済みRTFの反映という既存経路を保ち、初回保存を複製しない。
4. 新しい無題の採用成功後にだけ一覧から両方へ広げ、本文を表示して編集focusへ移る。
   保存のキャンセル・作成前の失敗ではlayout/窓幅/検索語を変えない。本文とUndoの保持、保存しない許可、公開後の部分失敗はADR0050に従う。
   名前付きの自動保存と明示保存の意味も維持する。
5. 空カテゴリと絞り込み中も既存の新規・初回保存を使う。検索語を消さず、無題のカテゴリと初回保存の既定カテゴリを一致させる。
   一致しない保存済みノートは既存の絞り込み規則に従って一覧に出ない。検索欄の既存クリア入口を維持する。
   カテゴリ0件では既存の理由表示を使い、既存のカテゴリ＋から作成できる。
6. 常設ボタンの文言は既存UI_TEXT_COMMAND_NEW、右クリックの文言はui_textの新しいIDにja/en/zh-Hansを揃える。
   自前描画ドロワー・既存Ctrl+Nとパレットのキー入口を使い、別の標準ボタンや新しいfocus所有者は追加しない。
   保存schema・applicationの作成API・依存・ゲートは変えない。Waivers: none。

## 検証と限界

完成候補でDebug/tidy・関係する文言/コマンドunit、実Win32の固定ボタンとカテゴリ右クリック、空カテゴリ、
絞り込み、320幅の3言語、保存/保存しない/キャンセルと失敗、押して外へ離す/capture解除を確認する。
変更していない保存処理の確保失敗・初回公開等は入力が同じ過去の結果を再利用する。
UIAの公開・実読み上げ・物理IMEの一般保証はこの確認から主張しない。最終headの必須CIは維持する。
