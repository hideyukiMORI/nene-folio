# ADR 0052 — ノート内検索は本文上部に置き、閉じる操作を既存の入力面へ揃える

- 状態: 受理（hideの2026-10-15の継続・全権委譲に基づき、設計サナが実装前に決定）
- 日付: 2026-10-15
- Issue: #306
- 規則: FR-011、ARC-001/004/011、C-002/012/017/018、QLT-008/012/013
- 関連: [ADR0023](0023-in-note-search.md)、[ADR0016](0016-command-catalog-and-shared-execution.md)、[ADR0047](0047-three-layout-modes.md)、[ADR0048](0048-layout-controls-and-native-tooltips.md)

## 文脈

ノート内検索の入口は本文の操作行にあるが、入力は窓の左下、前後ボタンは右下にあり、検索対象の本文から離れている。
マウスで明示的に閉じる入口がない。10月13日のGUIレビューの次項目として、既存検索の意味を保って入口をまとめる。
語と向きはapplication、表示本文・選択・UndoはRichEdit、入力面のHWNDと戻り先はfolio_windowが既に所有している。

## 決定

1. `COMMAND_SURFACE_SEARCH`の同じnative EDITとcommand layerを、本文側の操作行の下へ配置する。
   検索帯は本文ペイン領域内に収め、ドロワーを覆わない。本文の上端を帯の高さだけ下げ、一致箇所を帯で隠さない。
   ADR0016の「入力面の開閉では本文の矩形を変えない」は検索面に限って本決定で置き換える。
   Ex・置換・パレット等の配置は変更しない。
2. 対象とEnterの方向は、入力後も残る文字で示す。空欄のcueや配色だけに意味を依存させない。
   広幅は「対象・Enter方向／結果／閉じる」と「入力／前へ／次へ」の2行、狭幅は結果を独立させる3行とする。
   幅による固定の切替を使い、検索結果の変化だけでは本文の高さを変えない。
   最小BOTH窓560 DIPの本文ペイン320 DIPで、入力・前後・閉じる・結果が欠けず、本文の可視領域も残るようにする。
   NOTEの正規最小幅は560 DIP、DRAWERだけが320 DIPであり、最小幅の契約を変更しない。
3. 前後ボタンと閉じるは、それぞれ描画とhitで同じ矩形を使う。前後は既存の`step_search`、
   閉じるはEscと同じ`close_command_surface`へ渡し、可視の戻り先へフォーカスを返す。
   本文等へのフォーカス移動による既存dismissは維持し、新しいフォーカスを奪わない。
   検索入力のIME変換中は前後・閉じるのmouse hitを消費して無操作とし、変換終了後の再操作だけを実行する。
4. 検索面の開閉・他の入力面との切替・resize/DPI・表示切替の配置は、既存の`arrange`と
   `rearrange_keeping_line`の経路へ集める。本文を流し直さず、選択・Undo・未保存本文と読んでいる論理行を保つ。
   検索による一致選択・可視化だけは従来どおり行う。行番号帯は実際の本文矩形へ追従する。
5. 検索の判断・巡回・ASCIIの大小無視、語と方向の所有者、Enter/Shift+Enter・F3・n/N、
   検索中Ctrl+Sの保存と欄維持、標準の青選択、全ノート絞り込みとの分離はADR0023/0016のまま。
   一覧表示からは既存の本文表示経路を使う。配置変更のために保存・本文の再投入・新しい検索状態を足さない。
6. 表示文言は3言語のui_text、形と配色は既存のvector icon/paletteを使う。
   長いエラー文は意味を保って短くできるが、結果表示の省略で失敗理由を隠さない。
   保存schema・ポート・依存・ゲート・公開版は変更しない。Waivers: none。

## 確認

完成候補の対象build/tidy・文言unit・規約検査と、実Win32の合成fixtureで確認する。
対象はmouseでの開く/入力/前後/閉じる、0件/不正語、×/Escの戻り先、IMEメッセージ中の無操作、
Ctrl+SとUndo/選択/dirty/表示論理行、全ノート絞り込みとの独立、他surfaceへ移った後の本文矩形、
最小BOTH・NOTE・DRAWERからの検索、3言語と明暗の重要配置である。
成功済み結果は関係入力が不変なら再利用し、最終PR headの必須CIを通す（QLT-012）。
物理IME・実打鍵・UIA/実読み上げ・別OS/DPI・全テーマとhide実機受理は合成検証から推定しない。

## 却下した案

- 本文上に浮かせるだけ: RichEditが可視と判断した一致を検索帯が覆い得る。
- cueだけで対象を示す、方向を色だけで示す: 入力後や配色によって操作の意味を読み取れない。
- 件数と全エラーを狭い固定セルへ入れる: 3言語の失敗理由を欠落させる。
- 別の検索EDITや検索エンジンを作る: 語・フォーカス・保存・IMEに第二の経路ができる。

## 設計相談

Claude Codeのデザインリナが`design:design-critique`で既存画像と実装を読み、本文を覆わない配置を支持した。
同CLIの`/design`はアクセス管理用であり、設計用としては利用できなかった。
入力後も残る対象表示・文字によるEnter方向・結果の十分な幅は設計サナが採用条件として補正した。
今回のモデル分担はhideの現在指示に限る。恒久証跡は`D:/NeNeFolio/agents/search-ui-20261015/`。

## 2026-10-24 の補正（#351 / I-D）

[ADR0060 決定25](0060-ui-part-styles-and-state-rule.md)で、決定1の「置換の配置は変更しない」を置き換える。
SEARCH/REPLACEは同じCommandLayerの上部帯のmode差とし、置換は正規表現のパターンと置換後の2入力を置く。
SEARCHのliteral/ASCII大小無視とREPLACEの正規表現・編集中だけという意味は不変。語を自動コピーしない。

- ラベルとEnter方向は入力後も残す。対象は帯より上に常に見えるpane breadcrumbとそのUIA全文を共用し、帯へ長い名前を複製しない。
  置換面の件数はSTATUS_REPLACE_COUNT_ONLY、直接Exの:%sでは既存の対象名/件数表示を維持する。
- 狭幅ではラベルと結果を独立した固定高の行へ。最小pane320では置換欄144、1件/すべて各64を許す。
  結果領域は実font/spacing/DPIの最長関連理由から予約し、表示結果で本文高を変えず、最小560×360でも本文の可視行を残す。
- 1件のanchorは現選択の開始位置以降の最初の一致。選択範囲内に制限する意味へ変えない。Enter=1件、Ctrl+Enter=すべて、Tab=2入力、Esc/×=閉鎖。
  Ctrl+Hのcaretと:%sの直接置換は既存経路を保つ。保存/Undo/dirty/IMEと閉鎖後の矩形復帰も同じ所有者のまま。
- 決定5の標準RichEdit選択を維持する。Issue下書きのselected_background強制は、文字書式・Undo・dirty・高コントラストへ別経路を作るため採用しない。

完成候補の対象確認でgeometryと最長文言を記録する。3言語/3DPIの範囲や物理IME/実reader等の未測定を区別し、既に成功した無関係な検証は繰り返さない。
