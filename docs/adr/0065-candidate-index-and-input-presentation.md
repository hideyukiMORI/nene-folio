# ADR 0065 — 候補の対応を所有者で共有し、入力後の描画を通知待ちにしない

- 状態: 受理（#375の実装前判断）
- 日付: 2026-10-25
- Issue: [#375](https://github.com/hideyukiMORI/nene-folio/issues/375)
- 規則: ARC-001/004/005/008/011/012、C-008/012/013/016/017、QLT-008/012/013
- 関連: ADR0016/0056/0058/0060/0061/0062/0063/0064

## 根拠

main 3ab9d44の隔離desktopで操作一覧へ60回のキー/ホイールを送ると、最大描画間隔が2.94秒/1.20秒になった。
選択移動は60回合計約12msだが、入力後のUIA snapshot更新は合計3.02秒/1.23秒だった。
通常の選択移動だけでもUIA nodeが保持され、各nodeの有効性確認が子一覧・候補・群・登録表の先頭走査を重ねていた。
テーマの128候補にも、名前/件数/有効性の照会ごとに同じqueryを照合する処理がある。
前件の単発計測では、この保持項目と連続入力の関係を確認できていなかった。

Windowsの通常のGetMessageではposted通知と入力がWM_PAINTより先に処理される。
InvalidateRectだけでは、重い通知と連続入力が残る間に描画機会が来ない。
根拠は[GetMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessage)と
[WM_PAINT](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-paint)。
測定はPostMessageによる合成入力とGDI処理完了であり、物理入力からdisplay呈示までの保証ではない。

## 決定

1. 操作一覧の候補対応は`command_candidates`、テーマ一覧の候補対応は`theme_candidates`に集約する。
   どちらも`folio_window`が生成/破棄するUIの派生資源とし、選択・scroll・設定・focusの正本を複製しない。
   実件数の上限は既存のcommand/theme登録表から導き、生成時に必要な領域を確保する。
   操作の群順・群見出しと候補の対応は`command_candidates`に移し、旧来の群別走査と同義の表を残さない。
2. 候補を準備する入力は、既存EDITから変換したquery、言語、補助面の改訂番号とする。
   開閉・mode/キー面切替・EN_CHANGEによる既存の世代更新と、言語の変更を照合する。
   queryの変更は既存EN_CHANGEの世代で表し、同じ言語/世代ならEDITも読み直さない。必要になった最初の照会だけで同じ候補列を作る。
   初期WM_SETTEXT中は同期再入からの準備を拒否し、初期化完了時にも対応を失効させる。抑止したEN_CHANGEの代わりに旧語を採用しない。
   `UINT64_MAX`では再利用せず、旧参照を拒否する既存契約を維持する。変換/資源失敗時に古い候補を新しい語の結果として返さない。
3. 操作の各候補は、群と、群見出しを含む子一覧での位置を保持する。
   候補添字→操作/子位置、群→最初の候補/見出し位置を直接参照し、子位置→項目は同じ列から導く。
   有効性確認・列挙・名前・描画・hit・鍵・UIA操作の全てがこの対応を使う。
   候補矩形は同じ子位置の差と現在の先頭/領域/DPI/行高から計算し、選択を動かすために全候補を探し直さない。
   スクロール先頭に群見出しを再掲する既存の幾何、完全な行だけを表示する規則、空候補を維持する。
4. テーマの候補は同じ登録表の順序を保ち、UIAの確認を含めて候補添字から直接引く。
   検索中のIME、候補変更時のpreview、0件の保存色復元、確定/取消/失敗はADR0061の既存経路を通す。
   テーマのcomposition中はEN_CHANGEで世代を進めず、共通の候補入口も未確定語を読まない。
   直前の成功対応を保ち、未準備/失効済みなら候補を公開しない。nativeのcomposition終了処理後に一度失効し、既存query処理へ渡す。
5. 入力後の既存合流点で保存状態を確定し、無効化済みの可視の自前面を`UpdateWindow`で描いてからUIA差分通知へ進む。
   対象は主窓・drawer・設定暗幕・CommandLayerの既存描画であり、別のbitmap正本や描画実装を作らない。
   一つにまとまった通知につき現在の状態を反映し、キューの全入力を一つずつ強制描画するloopやtimerを追加しない。
   更新領域がない窓や非表示窓を再描画せず、native入力の描画/IME処理は標準部品に委ねる。
   同期描画中も既存のdispatch寿命と通常終了の合流を維持する。
6. UIAの通知・有効性確認・再入拒否・STA・非同期Invoke・切断を無効化しない。
   public参照の同一性は従来のkind/slot/revisionで決まり、派生候補のアドレスを外へ渡さない。
   worker thread、UIA通知専用timer、入力の間引き、保存schema、依存、ゲートの弱化は追加しない。

## 横断確認と受理

設定/テーマ、操作/キー、メニュー、履歴、検索/置換、索引、本文、名前入力/失敗箱について、同じ入力後経路と独自の同期処理を棚卸しする。
修正前の隔離条件では設定/履歴/検索/置換/メニューは60入力に対して60回描画し、1,000ノートの索引も同じだった。
キー説明には再折返し計測、本文/テーマには本文量に比例するnative処理、全ノート初回検索には#369のI/Oが残る。
これらを今回の秒単位停止と混同せず、同根の修正範囲と残る境界を品質記録へ書く。

対象検証は候補の全件/絞込/空/3言語、子と候補の相互対応、改訂失効、描画/hit/UIA一致、DPI/幅/最小窓、IME、focus、previewと取消、閉鎖/破棄/再入。
連続入力は全操作を横断し、通常移動とUIA列挙後の双方で入力処理と描画間隔を分けて記録する。
他部品は共通描画合流の直接影響を確認する。計装・時計・回数検査は外部fixtureに置き、製品の試験口を増やさない。
入力と判定を恒久証跡へ残して同じ回帰を再実行可能にし、最終PR headの必須CIで`eng/check.ps1`を通す。
Waivers: none。

実装・対象検証と残る境界は[#375品質記録](../quality/2026-10-25-continuous-ui-response.md)を参照。
