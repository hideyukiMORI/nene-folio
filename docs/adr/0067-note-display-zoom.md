# ADR 0067 — 本文の倍率を一つのRichEdit表示状態として扱う

- 状態: 受理
- 日付: 2026-10-25
- Issue: #383（hideの閲覧/編集エリアの拡大縮小依頼）
- 規則: ARC-001/002/004/005/008/011/012、C-002/005/008/012/013/016/017/018、QLT-008/012/013

## 文脈

本文の閲覧/編集は一つのRichEdit HWNDとRTF投入経路を共有する。標準のCtrl+ホイールは表示を拡大するが、
`EM_STREAMIN`で倍率が0/0（100%）へ戻ることを実測した。選択文字の書式変更では、本文/Undoや閲覧RTFの階層を壊す。
行番号は主窓の別描画なので、本文の倍率だけを変えると番号の字と折り返し後の位置が揃わない。

## 決定

1. 本文の表示倍率は`note_pane`が一つだけ所有するUI一時状態。初期100%、50～300%を10%刻みとする。
   閲覧/編集/ノート間で共有し、テーマ/言語/DPI/本文再投入でも維持する。終了時に破棄し、保存schemaは増やさない。
   RichEditの倍率はその投影であり、標準のCtrl+ホイールに独立して変更させない。
2. 表示変更は`EM_SETZOOM`の一経路。文字列・RTFの文字サイズ・選択・dirty・Undo/Redoを変更しない。
   本文投入後も同じ経路で倍率を再適用し、その成功までREADYにしない。失敗は既存の投入失敗として扱う。
   入力による変更はAPI成功後だけ所有値を更新する。API拒否は警告音とし、元のキーを文字入力として再実行しない。
3. 本文上のCtrl+ホイールは上で拡大、下で縮小。WHEEL_DELTA未満はnote_paneで累積し、1刻みにつき10%。
   通常のホイールはnativeへ渡す。本文外へのホイールは主窓の既存の座標による振分けへ戻し、本文を拡大しない。
   本文にfocusが無くてもポインタが本文上なら適用できる。操作領域や別の入力欄は拡大しない。
4. 本文focusのCtrl++/Ctrl+-とテンキーのCtrl+Add/Subtract、Ctrl+0（テンキー0含む）を用意する。
   OEM_PLUSはCtrlとCtrl+Shiftの両方を受け、US配列のCtrl+=も同じ拡大とする。
   キーは既存`TranslateAcceleratorW`を使い、OSの修飾状態を自己追跡しない。Alt併用は割り当てない。
   zoom表は両モード、既存Ctrl+hjkl表は編集だけで使う。ADR0019の翻訳対象をこの範囲で広げる。
5. IME変換中・入力停止/モーダル・本文未準備の間はzoomを適用しない。他の入力欄やdrawerのキーを奪わない。
   無効状態へ移るときと通常ホイール/キーzoomでは細かいwheelの残りを破棄し、後の操作へ持ち越さない。
6. 変更前の先頭論理行を取り、主窓への一つの倍率変更通知で行番号の派生font/幅と本文配置を更新した後、その行へ戻す。
   折り返しの途中はその論理行の先頭へ寄せる。末尾はnativeのscroll上限に従う。選択/キャレットは移動しない。
   行番号のbaselineは従来どおりTOMの実位置から取り、論理行表をzoomだけで作り直さない。
7. 行番号のfontは主窓が既存mono_fontのLOGFONTと本文倍率から生成・所有する派生資源。
   描画と数字幅計測は同じfontを使い、倍率/DPIの変更時だけ更新する。操作文字用mono_fontは変更しない。
   新しいfontの確保に失敗したときは有効な既存font（初期はmono_font）を保ち警告音で知らせる。幅もその実fontで測る。
   fontは破棄経路で解放する。ADR0026のfont所有と幅計測をこの範囲で補正する。
8. ヘルプ「キー」の共通説明へ3言語で追加する。新しい操作メニューや保存設定、文書ごとの倍率は設けない。

## 検証

専用desktopの合成データで両モード/3言語/通常と最小幅/境界倍率、各キーと高分解能wheel、IME/モーダル/他領域を確認する。
本文・選択・dirty・Undo/Redo、各再投入後の倍率、先頭行、行番号baseline/幅を実値と画像で照合する。
物理入力・物理DPI移動と合成メッセージ/描画倍率の検証は区別する。全件ゲートは最終headの必須CIに集約する。

## 2026-10-26 の補正（#392 — 通常ホイールの配送）

閲覧へ切り替えた直後はfocusが主窓へ戻る。主窓で受けた本文上のホイールは、Ctrlの有無によらず
既存の座標による振分けから同じ`note_pane`へ渡す。通常ホイールのスクロールはnative、
Ctrl+ホイールの倍率は既存の`note_pane`が処理し、focusを移動しない。
nativeの未処理ホイールが親へ伝播して戻っても二度nativeへ入らないよう、`note_pane`が同期呼出し中だけ
再入を拒否する。主窓からの転送と本文へ直接届く入力の両方に同じ拒否を適用し、同期呼出し後の独自行番号通知は一度だけ出す。
本文の生成時にnativeのスクロール能力を残してバーだけを隠す判断と、非同期の`EN_VSCROLL`による追随は
[ADR0026の同日補正](0026-line-numbers.md)に揃える。公開API・スクロール位置の所有・保存schemaを変更しない。対象検証と合成入力の限界は
[品質記録](../quality/2026-10-26-view-wheel.md)に残す。

## 根拠

2026-10-31補正（#473）: 通常wheelのnative配送は[ADR0026の同日補正](0026-line-numbers.md)の
短い減速経路へ置き換える。Ctrl+wheelは従来の倍率所有とdelta蓄積を維持し、倍率変更前に通常wheelの残りを取り消す。
本文外の座標振分けと実focusを動かさない契約は維持する。通常wheelをnativeへ送らなくなるため、
native親伝播だけの再入guardは削除する。

- [EM_SETZOOM](https://learn.microsoft.com/en-us/windows/win32/controls/em-setzoom)：表示倍率を適用し、受理を返す。
- [EM_GETZOOM](https://learn.microsoft.com/en-us/windows/win32/controls/em-getzoom)：nativeへ適用された倍率の検証に使う。
- [WM_MOUSEWHEEL](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mousewheel)：focus窓への入力と、未処理時の親への伝播。
- `D:/NeNeFolio/agents/note-zoom-20261025/native-zoom-probe.log`：倍率変更で文字/選択/dirty/Undoを保ち、RTF投入で倍率が戻る実測。
