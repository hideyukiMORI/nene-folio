# ADR 0090 — お気に入りは台帳に保存し、表示順と手動順を分ける

- 状態: 受理（2026-11-14のhideの実装開始指示に基づく。製品編集前）
- 日付: 2026-11-14
- Issue: #813
- 規則: ARC-001〜012、C-001〜018、FR-003/006/008/009/015/018/032、QLT-008/009/012/013
- 関連: [仕様案](../plans/2026-11-14-note-discovery.md)、ADR0007/0008/0022/0024/0025/0041/0073

## 根拠

hideが#811の計画に「対応を始めて」と指示した。最初の単位はお気に入りの付け外し、優先表示、星だけの絞り込み。
現行の索引は名前と手動順だけを持つ。表示順をそのまま書き換えると優先表示を解除した際に元の順へ戻せない。
また、md移動後に移動先の台帳を書くADR0008の手順では、台帳保存失敗後の再起動で星を復元できない。
台帳の順序は走査から補えるが星は補えないため、保存順を同じ一つの移動経路で改める。

## 台帳と設定

1. `note_ledger`がノート名・手動順・星の唯一の所有者。`index.json`の版2は
   `{"version":2,"notes":["A","B"],"favorites":["B"]}`。キー順を含めて固定する。
   版1も読んで全て星なしとし、次の台帳保存で版2を書く。起動だけでは書き直さない。
   favorites内の重複、notesに無い名前、未知版、不正型は拒否し、黙って星なしへ落とさない。
2. 内部では名前の番号に対応する星と、星あり/なしをそれぞれ手動順で並べた番号列を所有する。
   番号列はfactoryで完成させる派生値であり、外へ可変配列を返さない。表示時に並べ替えや名前検索を反復しない。
   名前・星を渡す短命の`note_entry`を挿入にも用い、カテゴリ移動では同じentryを渡す。
   新規・取り込み・別名保存は星なし。照合・並べ替え・改名・削除は同じfactory経路で星を保持/除去する。
3. 優先順は`note_order`のMANUAL / FAVORITES_FIRST。設定の既定はFAVORITES_FIRST。
   `folio_settings`の版6へ`note_order`（`"manual"` / `"favorites_first"`）を追加し、版1〜5は既定を補う。
   保存成功後だけ採用し、同値なら書かない。設定面と共通コマンドは同じ操作を呼ぶ。
4. 星だけの条件は`note_scope`のALL / FAVORITES。`folio_state`が実行中だけ所有し、起動時はALL。
   星はMarkdownや本文履歴に入れず、単票/ZIP書き出しでは運ばない。新版の台帳/設定は旧アプリの対応外になる。

## 表示と操作

`drawer_source`へ順序とscopeを加え、可視条件・展開条件・表示位置と台帳番号の対応を同じcoreのqueryへ集約する。
配置、applicationの鍵移動、件数とUIAが同じ意味を使う。選択・cursor・操作対象は元の台帳番号で保持する。
カテゴリ順は変えず、カテゴリ内で星ありを先に並べ、各群の手動順を保つ。
星だけの表示と全文検索はAND。星だけではcorpusの読込を始めない。条件に合うカテゴリは展開して見せる。
星を外して行が消えても開いている本文は保ち、cursorだけを既存の着地経路で補正する。

ノート行の星、共通コマンド/メニュー、UIAは同じ`folio_state`操作へ渡す。
クリックは押下/解放の一致と取消を確認し、星だけの操作でノートを開き直さない。
未保存の本文・Undo/Redo・変更印・履歴は保持し、星を保存できなければ表示値も採用しない。
星だけの表示と優先順の切替も共通コマンドから操作でき、適用中の条件を画面/アクセシビリティへ出す。
新しい表示文言は日本語・英語・簡体字のui_text表へ置き、星の図形は既存icon_paintで描く。

ノートの並べ替えは絞り込み中に拒否する。お気に入り優先が有効で星がある場合も拒否し、手動順へ戻す案内を出す。
星が一つも無ければ表示順と手動順は一致するため、従来どおり並べ替えられる。
カテゴリの並べ替えは優先表示だけでは禁止しない。星/語の絞り込み中は従来同様禁止する。
表示順が変わるため、UIAの行探索などの「台帳番号が表示上も昇順」という仮定を残さない。

## カテゴリ間移動の保存順（ADR0008の決定3を置換）

1. 同名・対象・未同期状態を既存経路で検査し、移動後の両台帳を確保する。
2. 星を含む移動先の台帳を先に原子的に保存する。失敗ならmdと表示状態を変えず終了する。
3. 既存の`move_note`でmdを置換なしに移動する。成功後は同じentryを持つ新台帳と参照を採用する。
4. md移動失敗時は、移動先の元台帳を書き戻し、表示は元のまま保つ。
   戻しも失敗した場合は既存`index_pending`にそのカテゴリを記録し、次の意図/終了前に同じ台帳同期を試す。
   mdが移ったという成功/台帳通知を出さず、移動失敗と未同期の状態を区別する。
5. md移動成功後は移動元台帳を書き戻す。失敗時は既存`index_pending`で移動元を再同期する。
   表示は移動先を指し、移動先の星はすでに永続化されている。mdを戻す補償や別の移動APIは作らない。

途中でプロセスが終了しても、mdが元にあれば元台帳の星が残り、移動後なら先に保存した移動先台帳の星が残る。
実在しない名前が残った側はFR-008の走査照合で除く。外部ツールによる同時のファイル/台帳改変までは保証しない。
本体は従来どおり一回のrenameであり、コピー/削除の二段にはしない。
ADR0008で却下した「両台帳を先に確定して表示も先へ進める」方法とは異なり、移動元と表示の採用はmdの結果まで保つ。

## 改名・復旧と検証

ノート改名は位置と星を保った台帳を既存rename_plan/journalへ渡す。
外側journalの版2は維持し、内側台帳の同じcodecで旧/新版を読む。カテゴリ改名はその台帳を同じフォルダーとともに運ぶ。

対象検証は旧/新版・不正/未知版・確保失敗、順序と星/語の組合せ、鍵/クリック/UIA、保存失敗、
移動の先行台帳失敗・md失敗・戻し失敗・移動元保存失敗、改名/復旧、本文とUndo保持。
新規の広い回帰をローカルで反復せず、直接境界の対象試験と最終head必須CIを使う。
実ノート・通常appは診断に使わず、専用data/desktopへ閉じる。追加waiverなし。
