# ADR 0093 — タグ全体管理は対象確認と一件ずつの保存・部分成功を分ける

- 状態: 受理（2026-11-15のhideの継続目標に基づく。製品編集前）
- 日付: 2026-11-15
- Issue: #821
- 規則: ARC-001/003/004/005/008/009/010/011/012、C-002/003/005/007/008/012/013/014/016/017/018、QLT-008/009/010/012/013
- 関連: ADR0006/0012/0024/0038/0042/0050/0057/0068/0073/0092

## 根拠と対象

#819 / PR820のタグ付与・絞り込みに続く、ロードマップ段階2b。一つのタグの全体改名と全体解除を扱う。
現在rootの台帳にある全カテゴリ・保存済みノートを対象とし、星・検索語・タグ条件で範囲を狭めない。
無題、外部フォルダー、台帳に未採用の外部追加ファイルは対象に含めない。
解除するのはタグであり、ノートではない。新しいタグ台帳、一般YAML、外部監視、batch journal、
全体Undo、版上げ・配布・Store操作は加えない。

背景Claudeの`design:design-critique`へ読取専用で相談し、独立レビューで保存契約を確認した。
原本はD:/NeNeFolio/agents/tag-management-20261115/claude-advice.mdとcontract-review.md。
プレビューを確認画面そのものにする案、再試行を再走査へ統一する案を採る。付与面からの入口は
未保存staged集合と先行保存の契約が異なるため採らず、共通メニュー/パレットを入口とする。

## 1. 値と唯一の原文更新

名前はADR0092の`note_tag`、集合は`note_tags`のfactoryを使う。大小文字・Unicodeを勝手に同一視しない。
旧名と新名が同じなら変更しない。新名が既にある場合は集合へ統合し、同じノートを二回更新しない。
解除は旧名を集合から除く。旧名を持たないノートは対象外で、履歴・本文・日時を変更しない。

`note_metadata_edit`の内部にあるbyte patch生成と完成原文の再検証を一つの共通処理へまとめる。
単票GUIは同じpatchのnative `replace_edit`投影、全体管理は同じpatchの完成`note_text`投影を使う。
parser/writerや保存経路を複製しない。未知フィールド・本文・タグ外コメント・既存改行はそのまま写す。
取り除いた要素に付いたinline comment、flow区切りの表記はADR0092の既存契約に従う。
全体処理はRichEditを通さないため、本文全体の混在改行を正規化しない。
入力署名と本文U+FEFFの区別、保存表現の16 MiB上限はADR0042を維持し、本文を再びファイル入力として
解釈して文字を落とさない。単なるBOMの有無だけを新たな本文の相違とは数えない。

一件の準備結果は不変値として宛先名を複製し、変更対象なら元本文と完成本文を所有する。
対象外、読取不能、未対応/壊れたmetadata、更新上限は区別する。確保失敗は準備全体を停止し、
部分的に作れた対象一覧を完成プレビューとして適用可能にしない。
可変なphase・位置・件別結果は既存`folio_state`だけが所有する。新しい可変core builderを設けない。

## 2. 管理入口と新しい対象確認

名前付きEDITからの入口は、現在の保存済み本文を期待値にした共通保存を先に通す。
外部変更・読取失敗・保存失敗では面を開かず、native本文・Undo/Redoを保持する。
変更のないEDITも期待値照合を行い、照合のためだけに履歴や本文を書かない。
VIEWと無題には保存を要求しない。無題の内容は全体操作の対象にも混ぜない。
通常の単票保存に外部変更拒否を一括導入する変更ではなく、同じ保存入口に期待値を任意で渡せるようにする。

選択段の候補と件数は既存catalogを使う。旧名・新名の意図が決まった時点で、既存corpusの読込を
先頭から新しく要求する。準備は既存の一本文ずつのidle読込へ結び、別のファイル走査や読込workerを作らない。
各読込済み本文から一件の準備結果を作る。同じidleで読む本文は最大一件で、全件の準備後だけプレビューへ進む。
台帳の行同一性を開始時と照合し、内部の改名・移動・削除等で変われば準備/適用を失効させる。
この台帳世代は、絞り込み結果の再構築でも進む既存のUI行参照世代とは区別する。
既存条件の再構築が自身の対象確認を失効させないよう、台帳変更だけで進める。
対象確認時のファイル変更は後述の保存前照合で再確認する。

プレビューには変更できるノートと、読めず/解釈できず対象か判断できないノートを示す。
候補catalogの古い使用数ではなく、この走査で得た件数を確認と実行ボタンに使う。
0件では実行できない。取得不能が残る場合に「全件完了」と表示しない。

## 3. 履歴と本文保存の一つの入口

従来の`persistence_port.archive_note`と`write_note`の二段呼出しを、既存ノート保存の一つの入口へ移す。
要求は宛先・新本文・省略可能な期待元本文を持つ。adapterが同じpathを一度読み、期待値があれば
既存`note_text`として照合し、その読取で得たraw bytesを既存`store_history`へ渡す。
期待値があるときの不在・相違・不正/読取不能は履歴回転や本文公開より前に拒否する。
期待値がなく元ファイルが不在の通常保存は、従来どおり履歴無しで再作成できる。

期待値照合後の本文が変更なしなら、履歴/本文を変更しない結果を返す。
履歴が保存できた後だけ、既存`file_bytes_store`の一時ファイル・flush・原子的置き換えを行う。
既存の`create_note`による初回公開/取り込み、外部単票/ZIP書出しは異なる意味の入口として維持する。
古い二段ポートを製品の別経路として残さない。試験fixtureも新入口か新規公開を使う。

型付き結果で、未変更、公開成功、照合不一致、読取不能、履歴失敗、本文公開失敗、確保失敗を区別する。
履歴回転後に本文公開が失敗すると履歴だけが進む場合がある。ADR0012の既存の部分失敗を維持し、
exactly-once履歴やbatch全体の原子性を約束しない。

**外部変更の保証は、最後の照合で読んだ本文までである。** 照合・履歴・公開はファイルシステムの
compare-and-swapではない。照合後から公開までの外部同時更新/renameを排除するとは主張しない。
読み取りhandleのdelete共有を拒むと自分の置換も妨げ、許せば外部renameの余地がある。
単に`ReplaceFileW`へ変更しても期待値照合と公開が一体にはならないため、今回それを導入しない。
根拠は[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)と
[ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)の公式仕様。
この限界を、プレビュー後に判明した変更の無条件上書きを許す根拠にはしない。

## 4. 逐次適用と公開後の採用

明示した実行意図の後、同じUIスレッドのidleごとに最大一件を保存する。入れ子message pumpや新threadを作らない。
各要求に準備元本文を渡し、競合・読取不能は見送り、履歴/公開失敗は失敗として対象名とともに残す。
通常のファイル失敗後も他の独立した対象へ進められ、中止は現在の同期一件が返った後の残りを止める。
適用中に通常保存・文書変更を受け付けず、面や窓の終了は未処理分を中止してから既存の終了経路へ戻す。

**公開済みと後処理失敗を分離する。** mdを公開した時点で変更済み件数とstore revisionへ算入し、
索引更新やnative投入が失敗しても「未保存の失敗」に戻さない。
保存済みcorpusは共通の無効化と再読込へ戻し、複数対象を選択中一件の`copy_pending`へ押し込まない。
現在の検索語・タグ集合/AND/OR・星scopeは保持し、同じengineで再構築する。非同期再構築失敗はADR0092の
既存契約に従い通知する。旧タグ条件を新名へ自動改変しない。

選択中の対象は本文コピー・閲覧/編集RTF等を公開前に準備し、失敗ならその一件を保存しない。
公開成功直後にapplicationの本文と表示値を採用し、通常操作を再開する前にnativeへ投入する。
投入で旧Undoを切り、新しい保存済み本文を基準にする。プレビュー/取消ではこの投入をしない。
native投入失敗は既存`NOTE_PANE_READINESS_UNAVAILABLE`へ渡し、新しい採用済み本文から再描画できるまで
保存を止める。残りのbatchも止めて結果へ進む。結果面を閉じる処理は本文採用を遅延実行せずfocusを戻すだけにする。

## 5. 結果・再試行・画面

共通command surfaceへ管理モードを加える。選択、新名入力、準備、プレビュー、実行、結果を閉じたphaseで表す。
選択は単一選択で、付与/絞り込みのcheckboxと区別する。削除は専用ボタンだけから対象確認へ進む。
改名先が既存名なら統合を表示し、元の二つの名前への単純な逆変換では戻せないことを確認できるようにする。
入力段では候補catalog、プレビュー段では新しい走査で判明した改名先の存在を使う。
旧タグを持たないノートにだけ改名先がある場合も集計し、候補取得後の外部変更を説明へ反映する。
プレビュー自体が確認であり、別の確認dialogを重ねない。行上のEnterを実行にせず、実行ボタンへ明示的に移動する。

結果は変更済み・見送り・失敗、途中中止時だけ未処理を示し、各ノートの名前と短い理由を読めるようにする。
「取消」と「中止」を区別し、中止しても変更済みを巻き戻したとは表示しない。全体Undoを設けない。
残りがある場合の操作は「残りを確認し直す」とし、同じ意図で新しい準備へ戻る。
成功済みノートには旧タグが無いため、同じ原文を再度書かない。外部操作で旧タグが戻れば、新しい確認対象となる。
再起動後も同じ再走査を使い、記録していない「前回の続き」を表示しない。

既存native入力のIMEを尊重する。Tabは入力/一覧/操作/閉じるを巡り、phase変更でsurface世代を更新する。
準備/実行中のEscは停止、書込前のEscは閉じる。結果/プレビューは読取専用行、選択はSelectionItemとして公開する。
進捗を1ファイルごとに読み上げ通知せず、準備完了と停止/完了時の要約を通知する。
3言語・最小560×360 DIP・高コントラストでは説明より入力/一覧1行/操作を優先し、実fontの折返し高を
paint/hit/UIAで共用する。長い名前は視覚上省略できるがUIA名で全文を読めるようにする。

## 6. 検証と限界

固定期待bytesで改名/解除/統合/重複/未対応構文/未知フィールド/混在改行/FEFF/上限を確認する。
対象の確保失敗、各read/history/writeと公開後の表示失敗、中止、再走査、外部変更/削除を注入する。
管理入口の外部変更拒否、native本文/Undo、選択対象の即時採用、無題保護、条件保持を確認する。
合成dataと専用desktopで3言語/最小寸法/テーマ/鍵/合成IME/UIAを確認し、準備と一件処理の費用を計測する。
時計はadapter外の試験fixtureへ加えず、既存の外側計測を使う。測定値を全環境の時間上限と呼ばない。
最後の照合と公開の間の同時外部更新、物理IME/全screen-reader/全OS・DPIは保証したものと扱わない。
全試行は[品質記録](../quality/2026-11-15-tag-management.md)へ残し、最終head必須CIと正典merge、通常exe/data不変確認、
恒久保全、今回追加したD作業領域の監査と整理まで行う。
