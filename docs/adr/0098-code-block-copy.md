# ADR 0098 — コードブロックのコピーは見出し行のリンクから、描画時に集めた原文を渡す

- 状態: 受理（production変更前。見た目の最終受理は実画面の確認後）
- 日付: 2026-11-16
- Issue: #839
- 関連: ADR0057/0069/0079/0085/0086/0089、ロードマップ「コードの色分け — コピー操作は別候補」
- 規則: ARC-001/002/003/004/005/008/010/011/012、C-002/003/005/007/012/014/016/017/018、CNF-002/009/010/011、QLT-008/009/010/012/013、GIT-001〜004

## 背景と置き換える決定

hideが11月16日に「Mdプレビューモード時に、コードブロックにコピーボタン」を依頼した。
ADR0069の決定5は当時の表示調整へコピーボタンを含めず、ADR0086は言語ラベルを通常の閲覧テキストとし「位置の別索引やoverlayを作らない」と決めた。
本ADRはADR0069決定5の「コピーボタンを追加しない」だけを置き換える。**overlayと位置の別索引を作らない決定は維持する。**
RichEditの上へ別の窓や自前描画を重ねると、スクロール・倍率・折返し・再配置のたびに位置を追う第二の所有者が要り、
nativeの読み上げ・鍵操作からも外れるためである。

## 表示

閲覧（VIEW）で描くすべての通常のコードブロックに見出し行を置き、言語ラベル（あれば）の後ろにコピーの操作を一つ置く。
言語指定が無いブロックにも見出し行を置く（従来より1行分高くなる）。未指定の空fenceは従来どおり何も足さない。Mermaidの図は対象外。
操作はRTFのリンク（field）として出し、nativeのリンクとして同じ文書の中でスクロール・倍率・折返しに従う。
文言は `ui_text` の三言語（コピー / Copy / 复制）。書体・大きさ・色は既存の言語ラベルと同じ役割（本文書体9pt・code_comment色・code背景）を使い、
新しい色・テーマ項目・保存設定を足さない。高コントラストでは既存のwindowText/window対に従い、リンクであることは下線で残す。
編集（EDIT）の表示とMarkdown原文には何も足さない。保存・書出し・編集への再投入は原文のまま。

## 原文の所有

coreの既存renderer（`markdown_blocks`）が、fenceの本文行を描くのと同じ箇所でブロックごとのコード文字列を集める。
集める内容は描画するコードと同じ（fenceの字下げと引用/リストの接頭辞を除いた各行を `\n` で結ぶ。最終行の後ろに改行を付けない）。
Mermaidの原文収集と同じ媒体slotの所有者（`markdown_media`）へ新しい種別として置き、既存の上限（slot数・総byte）を共有する。
上限を超えたブロックには操作を出さない（コードの表示は従来どおり）。本文の第二の写しやASTは作らない。
リンクの宛先は内部の識別子だけで、利用者が書いたMarkdownのリンクからは生成できない（利用者のリンクは従来どおり `web_uri` の検証を通ったhttp/httpsだけがfieldになる）。
UIは宛先の文字列を解釈して検証済みのslot番号へ変換する処理を一箇所だけ持ち、範囲外・古い世代は拒否する。

## 操作と結果

クリック（既存のリンクと同じ押下/解放の一致）と、キャレットを置いた状態の既存 Ctrl+Enter が同じ意図 `folio_state_copy_code` へ入る。
applicationが現在の描画に属するslotのコードを新しい `clipboard_port` へ渡し、`adapters/win32` だけがクリップボードを書き込む（CF_UNICODETEXT、改行はCRLF）。
結果は閉じた結果型で返す。成功は本文下の通知行と読み上げ通知で「コードをコピーしました」と知らせ、失敗（他のアプリがクリップボードを保持・確保失敗）は同じ行で理由を知らせる。モーダルの箱は出さない。
コピーは本文・選択・スクロール位置・Undo/Redo・未保存印を変えない。閲覧準備中やコマンド面が開いている間は既存のリンクと同じ条件で受け付けない。

## 検索・選択

コピーの文言は操作であって本文ではないので、ノート内検索の対象から除く（既存の非表示区間と同じ派生索引で除外し、別の検索経路を作らない）。
範囲選択に操作の文字が入った場合のnativeコピーにはその文字も含まれる（言語ラベルと同じ扱い）。コード本文だけを選択したコピーは従来どおり。

## 採らなかった案

- RichEditの上へ重ねるボタン（hoverで出る右上のボタン）: 位置の第二の所有者と描画の追従が要り、スクロール中のちらつきとUIAからの欠落を招く。ADR0086の決定を維持する。
- アイコンだけの表示: nativeの読み上げ名が無くなる。絵文字/私用領域の字形は書体の有無に依存する。
- 右端への寄せ: 幅の変化ごとにtab位置の再計算かRTF再生成が要る（ADR0069決定5の「resizeで再生成しない」を保つ）。
- 選択中の範囲をコピーする専用キーの追加: 既存のCtrl+Cと重複する。

## 検証

unit（見出し行のRTF、収集した文字列とcontainer/EOF/空行/上限、利用者リンクからの偽造不可）、applicationの成功/範囲外/ポート失敗/確保失敗、
adapterの実クリップボード（試験専用window stationのみ）、nativeのクリック/Ctrl+Enter/通知/検索除外/本文とUndo不変、三言語×明/暗/高コントラストの実画面。
最終headの必須CIを完了条件とする。読み上げの実聴取、物理IME、全OS/DPIは確認外。

## 実装時の補足（2026-11-16・#839）

決定は変えていない。実装で確定した細部と、文面の読み方を一つに定めた箇所を記録する。

- **slotの数え方**: コードの原文は`markdown_media`が所有するが、番号は画像/図の表示slotとは別に数える。
  表示slotは本文中の目印とnativeの画像投入・ミニマップが1対1で使っており、コードを同じ並びへ入れると
  画像の遅延表示がコードの番号を画像として探すうえ、コードブロックの多いノートで画像の表示枠（256）を減らす。
  個数の上限値（256）・1ブロックの上限（256KiB）・総byteの上限（Mermaid原文と合計4MiB）は既存の定数を共有する。
  コードの超過は画像/図の「多すぎる」案内を立てない。
- **見出し行の要否は先読みで決める**: fenceの開始行で、描画と同じ述語（containerの一致・閉じfence・字下げの除去）だけを
  使って結合後の長さを数え、コード行を書く前に上限と空を判定する。何も書かない読み取りで、ASTや本文の写しは作らない。
  コピーする文字が無いブロック（行が無い・空行1行だけ）には操作を出さず、従来の表示のままにする。
- **宛先の形**: `nenefolio-code:<番号>`（先頭ゼロの無い10進・256未満）。書くのは`markdown_blocks`だけで、読むのは
  coreの`code_copy_target`のparse一つ。UIは`folio_window`のリンク宛先の分岐一箇所でslot番号へ変える。
- **言語の渡し方**: 閲覧RTFの入口は書体名に加えて文言の言語を`markdown_rtf_locale`で受ける（coreは現在の言語を持たない）。
- **ラベルと操作の間**: U+2003を1つ、リンクの外に置く。検索の対象になる本文側の文字である。
- **結果の通知**: 成功の文言は他の通知行に合わせて句点を付けた（「コードをコピーしました。」）。通知行は既存の結果行と同じ寿命で、
  次の操作の結果で置き換わる。確保失敗もこの経路では箱を出さず同じ行に出す。
- **クリックと選択**: クリックではnativeのキャレットが操作の位置へ移る（既存のWebリンクと同じ）。Ctrl+Enterは選択を変えない。
  編集中のCtrl+Enterは従来どおりeditorのキーで、コピーにはならない。
- **クリップボードの所有者**: adapterが表示しない窓を最初の書き込みで作り、所有者にする。他のプログラムが開いている間は
  10msおきに5回まで開き直し、それでも開けなければ「使用中」とする。
- **検索からの除外**: 内部宛先を持つリンクの見える区間を、非表示区間と同じ`note_pane_links`の索引へ入れる。
  範囲選択のnativeコピーには見える文字（ラベル・「コピー」・コード）だけが入り、fieldの指示文字列は入らない（実測）。

## 第2版（配置と見た目）（2026-11-16・#839）

hideが第1版の実画面を見て「ブロックの右上」「ボタンかタグのような見た目」を求めた。
確定案は作業記録 `D:/NeNeFolio/design/code-copy-20261116/decision.md`（批評は同じ場所の `critique.md`）で、ここへ要点を写す。
overlayを作らない・位置の別索引を作らない・新しい色やテーマ項目を足さない、は変えていない。

- **右上への配置**: 操作のある見出し行の段落を右寄せ（`\qr`）にする。並びは「言語ラベル・間隔・操作」のままなので、
  操作が常にブロックの右端に来る。右の余白はコード行と同じ（9pt）。
  「採らなかった案」の「右端への寄せ」は**tab位置の再計算かRTF再生成が要る方法**への却下で、段落の右寄せには当たらない。
  右寄せは幅・倍率・折返しをnativeに任せたままで、resizeで再生成しない決定（ADR0069決定5）も保つ。
  操作の無い見出し行（指定付きの空fence）は従来どおり左寄せ。
- **チップ**: リンクの区間を「改行しない空白2つ・文言・改行しない空白2つ」とし、余白ごと塗りと押せる範囲にする。
  ラベルとの間のU+2003はリンクの外で、塗らない。言語ラベルは文字のまま（塗らない・切り詰めない）。
- **色**: 操作はラベルの色役割（code_comment）ではなく、**主操作と同じ `chip_background` / `chip_text` の対**を使う。
  `theme_palette` の既存の役割で、閲覧RTFの色表の11（文字）と12（地）へ足した。編集用と空の文書の色表は10色のまま。
  このため閲覧RTFの入口は `rtf_palette` ではなく実効の `theme_palette` を受ける。
  高コントラストでは塗らず、本文の文字色（windowText）と下線にする。
- **下線**: 通常の配色では下線の書式を付けないが、RichEditはfriendly nameのリンクへ自前の下線を引くので、
  表示には下線が残る（`\ul0`・`\ulnone`・下線色の指定のいずれでも消えないことを実画面で確認した。書式上のCFE_UNDERLINEは立っていない）。
  確定案の「外せない場合は下線付きのチップで受理」に当たる。
- **塗りの高さ**: RichEditは文字の背景を段落の前後の間隔まで塗るので、チップは見出し行の高さいっぱい（上端はブロックの上端）になる。
  上に地を残すには空の段落を1つ足す必要があり、文書の文字列と行数が変わるので採っていない。
- **検索・選択・鍵・通知**: 第1版のまま。検索から除く区間はチップ全体（余白の空白を含む）。同じ操作を続けて押しても毎回知らせる。
- **コントラスト**: 127配色の計算では、チップの文字と地は最小4.63:1（4.5:1未満なし）。チップの地とコード面は15配色で3:1未満、
  うち3配色（tokyo-night-light・cobalt2・synthwave-84）は1.5:1未満で、塗りがコード面とほぼ同じに見える（文字色と下線は残る）。
  テーマ別の例外形は作っていない。値は品質記録に残す。
