# ADR 0101: 参照形式のリンクは描画の前に定義の表を作り、ただの括弧の対から引く

Status: accepted / 2026-11-17 / Issue #861

## 背景

閲覧表示は表示名の後に丸括弧で行先を書く形のリンクだけを解釈し、参照形式（`[表示名][ref]`と`[ref]: URL`の定義）は原文の文字のまま、定義の行も本文に出していた。
CommonMark/GFMと主要なMarkdown環境は参照形式をリンクにし、定義の行を出さない。長いURLを本文の外へ置けるので、メモでもよく使う。
[Markdown対応の整理](../quality/2026-10-31-markdown-scope.md)の「参照形式のlink/imageと定義」（中規模）にあたる。
定義は文書のどこにあってもよく、前の方のリンクが後ろの定義を参照する（前方参照）ので、描画の途中では決められない。

## 決定

- coreの`markdown_references`が、描画（`markdown_blocks_render`）の始めに文書を1回だけ走査して定義の表を作り、同じ描画の間だけ持つ。
  表は正規化したラベルと、`markdown_destination`で読んだ行先（`<...>`・escape・文字参照を展開したbytes）を所有する。
- 定義として読む行（CommonMarkの部分集合）:
  - 行頭の空白3つまで、`[ラベル]:`、空白、行先、任意で同じ行のtitle（`"..."` `'...'` `(...)`）、他に何も無い1行。
  - 段落の途中に置けない: 文書の始め・front matterの後・空行・見出し・水平線・閉じたフェンス・別の定義の直後だけ。フェンスの中は読まない。
  - ラベルはASCIIの大小を区別せず、空白の並びを1つにまとめ、両端を除いて比べる。999 bytesまで。入れ子の角括弧は不可。
  - 同じラベルが複数あれば最初の定義。1ノート1024個まで（超えた分は定義として扱わない）。
- ブロックの描画は、走査が記録した行の開始位置と一致し、段落が開いていない行だけを出さない（`markdown_references_defines`）。判定の位置は行の開始byte。
- 行内では、既存の丸括弧の行先のリンクと画像の対応付けの後に残った括弧の対を、完全（`[文字][ラベル]`）・省略（`[ラベル][]`）・短縮（`[ラベル]`）の順の形で表から引く。
  見つかれば既存の`MARKDOWN_INLINE_LINK`の対にし、2つ目の括弧の中は名前として扱う（強調にしない）。見つからなければ原文のまま。
  行先は既存の`web_uri`の検証→RTF HYPERLINK field（ADR0100のschemeの書き方を含む）→既存の起動経路。`web_uri`が拒むもの（mailto等）は丸括弧の形と同じく装飾だけ。
- 画像の参照形式（`![説明][ラベル]`）は解かず、2つの括弧を含めて原文のまま（画像の読込経路は見ているviewの範囲を前提にしているため、別Issue）。

## CommonMark/GFMとの差

- 定義は1行に収まるものだけ（複数行にまたがる行先・titleは読まない）。
- 引用（`>`）の中の定義は読まない。リストの中は、空行の後で行頭の空白3つまでなら読む。
- ラベルの比較はUnicodeの大小の畳み込みをせず、ASCIIだけ。
- titleはtooltipにしない（[ADR0079](0079-view-web-link-activation.md)と同じ）。

## 却下した案

- 描画を2回（1回目で定義だけ集める）: 同じブロックの解釈を通せるが、コードの色分け・コピー用の原文の収集・画像の登録まで2回走り、大きいノートで遅い。出力を捨てる経路を製品に増やす。
- ブロックの解釈と別に定義を読み、描画は表を見ずに独自に判定: 読む所と隠す所が食い違う。隠す判定は「表が記録した行」に限り、記録と表示を1か所に結ぶ。
- 定義の行を残して表示する: 主要な環境と違い、本文に長いURLの行が並ぶ。

## 検証

定義の読み取り（行先・title・空白・大小・前方参照・重複・段落の途中・フェンス・字下げ・余計な文字）、3つの形、見つからないラベル、画像の参照形式、
表のセル・見出しの中、強調の名前、行先が`web_uri`で拒まれる場合を単体で、閲覧での起動先・定義の非表示・編集表示の原文をnativeで確かめる。
最終headの必須CIで正典`eng/check.ps1`を要求する。Waivers none。
