# ADR 0103: 脚注は定義の表へ記録し、初めて参照された順の番号で文書の最後にまとめる

Status: accepted / 2026-11-17 / Issue #869

## 背景

閲覧表示は脚注（`本文[^1]`と`[^1]: 脚注の文`）を解釈せず、原文のまま本文の途中に出していた。GFM・Obsidian等は参照を上付きの番号にし、脚注を文書の最後へまとめる。
[Markdown対応の整理](../quality/2026-10-31-markdown-scope.md)の「脚注・定義リスト」（中規模）にあたる。
#861の定義の表（[ADR0101](0101-reference-links.md)）が、文書全体の1行の定義を描画の前に集め、定義の行を隠す仕組みをすでに持っている。

## 決定

- 定義の表`markdown_references`が、ラベルが`^`で始まる1行の定義`[^ラベル]: 文`を脚注として記録する（`:`の後の空白と行末の空白を除いた残りの範囲）。
  ラベルの比べ方・置ける場所・定義の行を隠す仕組みはリンクの参照形式と同じ。脚注のラベルはリンクの参照形式の名前にならない（GFMと同じ優先）。
- 行内では、他の括弧に続かない`[^ラベル]`だけを脚注の参照にし（新しい種類`MARKDOWN_INLINE_FOOTNOTE`）、上付きの番号をリンクの色で出す（`{\super\cf4 n}`）。
  番号は、その描画の中で初めて出力された順に1から振る（同じ脚注は同じ番号）。定義が無ければ原文のまま。
- 本文の後に、水平線と同じ細い区切りと、番号の付いた脚注を並べる。文字は本文より一回り小さく（9pt）、引用と同じ控えめな色。脚注の文は既存の行内の描画を通す（強調・リンク・コード・画像等）。
  脚注の中の参照も番号を振り、並びの後ろへ足す。参照されない定義は出さない。

## CommonMark/GFMとの差

- 定義は1行だけ（GFMの、字下げで続く複数行・複数段落の脚注は読まない）。
- 参照から脚注への飛び先、脚注から本文へ戻るリンクは作らない（RichEditの中の位置へ飛ぶ仕組みが別に要る）。
- 脚注の区切りに見出し（GitHubの「Footnotes」）を付けない。

## 却下した案

- 脚注を定義の位置で表示する: 本文の途中に注が挟まり、主要な環境と違う。
- 番号を定義の順に振る: 本文の中で番号が飛ぶ。GFMは参照の順。
- 脚注の表を別に作る: 定義の行の読み取り・隠し方・ラベルの比べ方が2か所になる（ARC-001）。

## 検証

番号の順・同じ脚注の再参照・未定義・参照されない定義・大小・リンクの参照形式との区別・コードと画像の中・表と見出しの中・脚注の中の参照・空の脚注を単体で、
上付きの書式・脚注の文字の大きさ・検索用の本文の並びをnativeで、明・暗・高コントラストの実画面で確かめる。Waivers none。
