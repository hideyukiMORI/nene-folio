# ADR 0106: 本文の右クリックメニューはアプリのメニュー面で出し、編集は本文のキーと同じ経路で行う

Status: accepted / 2026-11-17 / Issue #883

## 背景

閲覧・編集のどちらでも、本文（RichEdit）で右クリックしてもメニューが出なかった。hideの依頼（2026-11-17）は、少なくとも切り取り・コピー・貼り付けを右クリックからできるようにすること。
Shift+F10とアプリケーションキーは、本文にフォーカスがあっても索引のメニューを開いていた。
アプリには、操作▾と索引の右クリックが使う自前のメニュー面（`folio_message_open_menu` / `COMMAND_SURFACE_MENU`）と、その読み上げ（UIAのMenu / MenuItem）がある。

## 決定

- 見た目と面: 既存のメニュー面で出す（OSのメニューや別の面を足さない・ARC-001）。メニューの文脈に`FOLIO_MENU_TEXT_EDIT` / `FOLIO_MENU_TEXT_VIEW`を、項目の種類に`FOLIO_MENU_ACTION_TEXT`を足す。
  項目が行う本文の編集は閉じた`enum folio_text_edit`（元に戻す・切り取り・コピー・貼り付け・すべて選択）。
- 項目: 編集は「元に戻す (U)」｜「切り取り (T)／コピー (C)／貼り付け (P)」｜「すべて選択 (A)」。閲覧は読み取り専用なので「コピー (C)」｜「すべて選択 (A)」だけを出す（切り取り・貼り付け・元に戻すは隠す）。
  一時的に使えない項目（選択が無いときの切り取り・コピー、クリップボードに文字が無いときの貼り付け、戻すものが無いときの元に戻す）は淡色で残す。キーの表示は本文が既に応えるCtrl+Z/X/C/V/A。
- 実行: `note_pane_text_edit`が本文へ、キーと同じメッセージを送る（`EM_UNDO`・`WM_CUT`・`WM_COPY`・`WM_PASTE`・`EM_SETSEL`）。貼り付けは既存の`paste_text`（書式を持ち込まない`CF_UNICODETEXT`だけ）を通る。
  使えるかどうかは`note_pane_text_edit_available`の一か所で決め、メニューの淡色と実行の両方が使う。
- 開き方: 右クリックは押した位置に開く。選択の外を押したときは先にキャレットをそこへ移し、選択の中なら選択を保つ。
  Shift+F10・アプリケーションキーは、本文にフォーカスがあれば選択の終わり（無ければキャレット）の行の下に開き、それ以外は従来どおり索引のメニューを開く。
  実行・Esc・外側のクリックで閉じた後、フォーカスは本文に戻り選択を保つ（既存のメニュー面の戻り先）。
- メニュー面の縁: 本文の文字の上に開くと、設定カードと同じ輪郭の色では面の端が見分けにくい（本文の地との差が3:1未満）。全メニューの外枠を、読める濃さの副次の文字色（`dialog_secondary`）にする。区切り線は変えない。

## 見た目の決め方

制約を先に固定せず、アプリの色で描いた7案（OSのメニュー、アプリの面、アイコン付き、小さな道具帯、選択で出る道具帯、アプリの面・改、小さく締めた面＋アイコン）を押せる模式図にし、
/design の観点（第一印象・使い勝手・階層・一貫性・アクセシビリティ）で専門家3席（Windowsの使い勝手・アクセシビリティ・視覚デザイン）に独立に見てもらった。
2席がアプリの面を1位、視覚デザインの席が小さく締めた面＋アイコンを1位にした。hideは推奨の「アプリの面・改」を選んだ（2026-11-17）。
専門家が挙げた直しのうち、選んだ行の左端の帯と、選んだ行のキー表示を明るくすることは既存の面が既に行っていた（専門家に見せた画像は選んだ行の無い状態だった）。残る「縁を明るく」を今回入れた。

## 却下した案・今回やらないこと

- OSのメニュー（`TrackPopupMenu`）: 読み上げとキー操作はOS任せで確実だが、紫の面に灰色の角丸が浮き、アプリのメニューが2種類になる。
- 小さな道具帯・選択で出る道具帯: 右クリックで縦のメニューという期待とずれ、書いている途中に邪魔になる（3席とも下位）。
- 小さく締めた寸法とアイコン: 操作▾と寸法が分かれる。入れるなら全メニューで揃える別件。
- メニューの影: メニュー面は主窓の中の子の窓で、OSの影（`CS_DROPSHADOW`）は付かない。影は別に検討する。
- 閲覧での「Markdownとしてコピー」「ここを編集」、リンクの上での「リンクをコピー」: 表示と原文の位置の対応が要る。次の段階。
- 無効の文字色を明るくする: 主題の色の表（coreの対比の検査）を変える別件。

## 検証

本文の窓の単体（`minimap_structure_tests`）で、使える項目（編集・閲覧・選択の有無・戻すものの有無）、右クリックでのキャレットの移動と選択の保持、開く依頼の文脈と位置（マウス・キー）、
元に戻す・すべて選択の実行を確かめる。実窓（`image_status_tests --text-menu`）で、項目の並び・名前・キー・淡色、すべて選択の実行と本文へのフォーカスの戻り、明暗の画像を確かめる。
試験はクリップボードへ書かない（切り取り・コピーの実行は試験しない。利用者のクリップボードを壊さないため）。Waivers none。
