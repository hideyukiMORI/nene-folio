# ADR 0107: クラス図はフローチャートの模型へ読み、UMLの印を矢印の種類として足す

Status: accepted / 2026-11-17 / Issue #890

## 背景

閲覧表示のMermaidはフローチャート・シーケンス図・状態遷移図（[ADR0104](0104-mermaid-state-diagram.md)）・ER図（[ADR0105](0105-mermaid-er-diagram.md)）を図にし、クラス図（`classDiagram`）は「未対応の種類」の案内だった。
クラス図は、クラス（名前とメンバーの箱）と関係（線と両端の印）からなる。箱は#888の実体の形（名前の帯・区切りの線・左揃えの行）で、線はフローチャートの辺で表せる。足りないのはUMLの印（白抜きの三角・ひし形）だけ。

## 決定

- coreの新しい`mermaid_class`が、クラス図を種類`DIAGRAM_FLOWCHART`の`diagram_model`へ読む。配置・描画・上限・遅延描画・通知・書出しでの原文の保持は既存のまま（ARC-001）。
  文は行ごとに読み、向きは`mermaid_flow_direction`を共有する。既定の向きは上から下。
- クラス: `class A`・名前だけの行・関係に現れた名前は四角。`class A { ... }`の段と`A : メンバー`の行でメンバーを足すと、#888の形（`DIAGRAM_ENTITY`。名前はid、表示の文字はメンバーだけ）になる。
  段の中の`<<interface>>`は「«interface»」の行として読む。
- 関係`A <左><線><右> B : ラベル`: 線は`--`（実線）か`..`（破線）。印は左が`<|` `*` `o` `<`、右が`|>` `*` `o` `>`。辺はAからBで、左の印が始点、右の印が終点。
  `o`と`*`を右の印として読むのは、直後に空白があるときだけ（線の直後に`order`のような名前を書いた場合と区別する）。
- 矢印の種類に、白抜きの三角（`DIAGRAM_ARROW_HOLLOW`、継承・実現）、白抜きのひし形（`DIAGRAM_ARROW_DIAMOND`、集約）、塗りのひし形（`DIAGRAM_ARROW_DIAMOND_FILLED`、コンポジション）を足す。
  描画はadapters/win32の矢印の一か所。白抜きは図の地の色で塗り、線が透けないようにする。関連・依存の`>`は既存の開いた矢印。
- 同じクラスの同じ辺（下端・上端）にUMLの印が複数付くとき、配置は印を横に並べる（`marker_shift`）。印は意味が違う（コンポジションと集約）ので、重ねると片方が隠れて読み違える。
  フローチャートの既存の矢印（閉じた矢印・丸・×）は従来どおり1点に集める（見え方を変えない）。
- 未対応（図全体を未対応の案内にし、部分的な図を作らない）: ジェネリクス`~T~`の付いたクラス名、`class A["表示名"]`、`note`、`namespace`、
  `style` / `classDef` / `cssClass` / `click` / `link` / `callback`、単独の`<<annotation>> A`、`accTitle` / `accDescr`。

## 補足（#916・2026-11-17）: 関係の両端の多重度

- `A "1" *-- "0..*" B : ラベル` の引用符の中を、線の両端の文字として読む。片方だけでもよい。閉じない引用符・空の引用符・同じ側に2つは不正。
- 模型の辺（`diagram_link`）に両端の文字（`start_text` / `end_text`）を足した。フローチャート・状態遷移図・ER図は空の文字を入れる。
- 配置: 文字は線が箱を出る（入る）所のすぐ横に、小さい文字（線のラベルと同じ役割）で、地を塗らずに置く。
  端に文字のある線は、UMLの印と同じく同じ辺で横に並べる。並べる間隔には、その辺でいちばん幅の広い文字の幅を足す（隣の線に文字が掛からない）。
  図の左右の余白は、文字の幅のぶん広げる。段の間隔は変えない（両端の文字が段の間に収まることを試験で確かめる）。
- 却下: 多重度を線のラベルに混ぜる（どちらの端の数か読めない）。段の間隔を文字2行ぶん広げる（多重度の無い線まで図が縦に間延びした・実測の画像で確認して外した）。

## 補足（#918・2026-11-17）: 多重度の配置の直し（#916の独立レビュー）

- 箱の同じ辺（流れの向きで上の辺・下の辺）に文字のある端が1つでもあれば、その辺の端はすべて自分の場所を持つ。文字の無い矢印も、迂回する線（上へ戻る・同じ2クラス間の2本目・段を飛ばす）も含める。
  中央に残った線が隣の文字を貫くことと、同じ点から出た2本の文字が重なることを防ぐ。UMLの印だけの辺は#890のまま（迂回する線の印も並ぶようになった）。
- 文字のある辺を持つ箱は、端を並べられる幅まで広げる（1文字の名前のクラスでも重ならない）。印だけの辺は広げない。
- 流れの向きの場所: 文字のある図では、段の間隔を「文字の長さ＋12」の3倍以上にする（迂回する線が曲がる所と図の端まで文字が届かない）。線の通り道の単位は「文字の長さの2倍−16」以上（上下向きのふつうの文字では変わらない）。
- 文字の有無は、向きで縦横を入れ替える前の幅で判定する。空の文字にも1行ぶんの高さがあり、左右向きでは入れ替えた後の「幅」が0でなくなる。#916はここを誤り、左右向きのフローチャートの余白が広がっていた（公開前に直した）。
- 多重度の無い図（フローチャート・状態遷移図・ER図・多重度を書かないクラス図）の配置は#916の前と同じ。

## 却下した案

- UMLの印を既存の矢印（閉じた三角・丸）で代用する: 継承と関連、集約とコンポジションの区別が付かない。
- すべての矢印を横に並べる: フローチャートの見え方が全体に変わる。
- クラス図の専用の模型・配置: 同じ箱と線の配置を2つ持つことになる。
- 属性と操作の間の区切り線: メンバーの種類の判定（`()`の有無）と、区切りの位置を配置へ渡す仕組みが要る。最初はメンバーを書いた順の行で示す。

## 検証

模型（クラス・メンバー・注釈・関係の13通りの線と印・ラベル・向き）、印を横に並べる配置、未対応・不正・上限の入力を単体で、
既存の描画の試験（`diagram_render_tests`）にクラス図を加え、解析・配置・描画の3段階と明暗の画像（新しい印を含む）を確かめる。Waivers none。
