# ADR 0108: 起動時の窓の位置と大きさは、PCごとの別ファイルに持ち、使えない値は初期値へ戻す

Status: accepted / 2026-11-17 / Issue #891

## 背景

主窓は毎回、主画面の左上に960×640（倍率に合わせて拡大）で作られ（枠なしの窓では既定の位置の指定が左上になる）、位置と大きさをどこにも保存していない。
hideの依頼（2026-11-17）: 初期値で開くか前回を引き継ぐかを選べるようにする。窓が画面から離れた・ヘッダーが見えない等、操作に支障のある位置や大きさのときは初期値に戻す。

保存の場所は2つある。ノート側の`data/settings.json`（`folio_settings`、利用者の表示の選択。保存先フォルダーと一緒に動く・ADR0025）と、
PCごとの起動設定`nenefolio-startup.json`（`startup_settings`、保存先の指定。`storage_adapter`が配布形式に応じた場所へ置く・ADR0077）。

## 決定

1. 窓の状態はPCごとの別ファイル`nenefolio-window.json`（版1）に持つ。場所は起動設定と同じフォルダー。
   画面の構成・倍率はPCごとに違い、保存先フォルダーを複数のPCで共有しても他のPCの位置を持ち込まないため。ノート側の`settings.json`と起動設定の形は変えない。
   形（キーの順序も固定）: `{"version":1,"restore":<bool>,"placed":<bool>,"x":<n>,"y":<n>,"width":<n>,"height":<n>,"dpi":<n>,"maximized":<bool>}`。
   `restore`は利用者の選択（前回を引き継ぐか）、`placed`は位置を記録済みか。`x`・`y`は画面座標に1000000を足した非負の整数（左や上の画面は負の座標になり、既存のJSONの読み書きは非負の整数だけを扱うため）。
   `width`・`height`は物理ピクセル、`dpi`は記録したときの窓の倍率。未知の版・欠落・順序違い・範囲外の値は読まない（不正として扱う）。
2. 既定は「前回を引き継ぐ」（ファイルが無いとき`restore`は真、`placed`は偽）。設定の面に「前回の窓の位置と大きさで開く」の行を足し、切り替えるとその場でファイルへ書く。
   書けなかったときは選択を変えず、警告音で知らせる。
   オフにすると次の起動から初期値で開き、終了時の記録もしない（記録済みの位置は残すが使わない）。
3. 記録: 主窓を閉じるとき、`restore`が真なら、通常時（最大化・最小化でないとき）の位置と大きさ・その時の倍率・最大化かどうかを書く。
   最小化のまま閉じたときも、通常時の位置を書く（最小化では開かない）。書けなくても終了は妨げず、知らせない（次回は前の記録か初期値で開く）。
   複数の窓を開いていた場合は、最後に閉じた窓の記録が残る。
4. 復元の前の検査はcoreの純関数`window_fit`の一か所で行う。入力は記録・全画面の作業領域（タスクバーを除いた範囲）とその倍率・窓の最小の大きさ・ヘッダーの高さ。出力は「復元する位置と大きさ」か「初期値」。
   次のどれかなら初期値:
   - `placed`が偽、または`restore`が偽。
   - 記録の値が壊れている（大きさが0以下・座標が範囲外）。
   - ヘッダーの帯（窓の上端から、つかんで動かせる高さの帯）が、どの作業領域にも十分に入っていない: 帯の上下が1つの作業領域の中に収まり、かつその中に横160px（96dpi基準。倍率に合わせる）以上が見えていること。
     これで「画面から離れた」「ヘッダーが上や横にはみ出してつかめない」「モニターを外した・解像度や配置を変えた」をまとめて扱う。
   - 大きさ（倍率の差を合わせた後）が、窓の最小の大きさより小さい、またはヘッダーが入っている作業領域より大きい。
   ヘッダーをつかめる範囲のはみ出し（窓の下や横が画面の外に出ている）は、そのまま復元する。わざと一部を画面の外へ置く使い方を壊さない。寄せ直しはしない（初期値か、記録どおりかの2つだけ）。
5. 倍率: 判定（`window_fit`）は、記録したときの倍率と作業領域の倍率が違えば、幅と高さを比で合わせてから検査する。位置は物理座標のまま。
   ただし画面ごとの倍率をOSに尋ねる関数は、UIが結んでいないライブラリ（shcore）にある（ARC-002）。そこでui/win32は、各作業領域に「記録したときの倍率」を入れて判定に渡し（大きさは記録どおりに検査する）、
   窓を作った後に窓自身の倍率が記録と違えば、大きさを比で合わせ直す（その画面の作業領域より大きくはしない・`window_restore_settle`）。
6. 最大化: 通常時の位置を上の検査に通し、通れば通常時の位置を設定してから最大化で表示する（最大化を解いたときに戻る位置になる）。通らなければ初期値の位置で最大化する。
7. 責務: 形の検証と読み書きはcoreの`window_placement`、判定は`window_fit`。画面の一覧の取得・窓の位置の取得と設定はui/win32（`EnumDisplayMonitors`・`GetWindowPlacement`）。
   ファイルの読み書きは`storage_adapter`、保持と選択の切り替えは`storage_state`（`storage_port`に読み書きを足す）。`folio_state`と`folio_settings`には足さない。
8. 読めない・不正なファイルは、起動を止めず初期値で開く（保存先の起動設定と違い、失っても困らない状態のため）。そのファイルは、次に設定を切り替えるか窓を閉じたときに正しい形で書き直す。

## 補足（#904、独立レビューの後）

- 一覧だけの表示は窓の幅を縮め、表示の種類は起動をまたいで保存しない。その表示で閉じるときは、通常の表示へ戻したときの幅（最大化から入った場合は、その通常時の位置と最大化）を記録する。細い幅を記録すると、次の起動で最小の幅より小さいと判定され、毎回初期値に戻る。
- 最小化・最大化でない窓は、画面上の位置（`GetWindowRect`）をそのまま記録する。換算が要らず、スナップした窓も見えているとおりに記録される。最小化・最大化のときだけ通常時の位置を換算する。
- 判定は、ヘッダーが届いても大きさが合わない画面を飛ばして次の画面を見る（決定4の「その作業領域より大きい → 初期値」を、「ヘッダーが入り大きさも合う画面が1つも無い → 初期値」へ改める）。大きい画面に収まる窓のヘッダーが、小さい画面に少し掛かっているだけで初期値に戻らないようにする。
- 変えていない点: 倍率を変えた直後の合わせ直しは大きさだけで、位置は動かさない（ヘッダーはつかめるまま）。

## 却下した案

- ノート側の`settings.json`に入れる（版8）: 保存先を共有すると、別のPCの画面の位置を持ち込む。位置は利用者の選択ではなく実行のたびに変わる状態で、「起動だけでは設定を書き換えない」（ADR0025）とも合わない。
- 起動設定`nenefolio-startup.json`に足す: そのファイルは保存先の指定だけの契約で、競合時は上書きしない厳しい扱い（ADR0077）。窓を閉じるたびに書く状態とは扱いが違う。
- はみ出した窓を画面の中へ寄せ直す: 「どこまでなら寄せ、どこから初期値か」の規則が増える。わざと外へ置く使い方も壊す。依頼は「支障があれば初期値」。
- レジストリに書く: portable版はexeの隣で完結する契約（ADR0077）。
- 既定を「初期値で開く」にする: 依頼の主旨は再起動で位置が戻ることへの不満。安全策があるので、引き継ぐ側を既定にする（hideが変えたければ既定は1か所）。

## 検証

coreの単体: 形（読み書きの往復・未知の版・欠落・順序・範囲外）、判定（画面内・画面外・ヘッダーが上/横にはみ出す・160px未満・画面をまたぐ・小さすぎる・大きすぎる・倍率の違い・負の座標の画面・`placed`/`restore`が偽）。
applicationの単体: 読めないファイルで初期値、切り替えで書く、オフでは記録しない。
実窓: 引き継いだ位置と大きさで開く、最大化の復元、画面外の記録で初期値、オフで記録を使わない。Waivers none。
