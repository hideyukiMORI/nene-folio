# ADR 0109: 「ノートを探す」は入力欄のまま候補を選び、原文previewは折り返す

Status: accepted / 2026-11-18 / Issue #933（#928の一部）

## 背景

hideの実機確認（2026-11-18、#928）。「ノートを探す」で入力欄から↑↓を押すと候補は動くが、フォーカスが候補の列へ移り、続けて文字を打てない。
PageUp/PageDownは入力欄にいても候補のページ送りで、原文previewを読み進めるにはTabでpreviewへ移る必要があった。
原文previewは折り返さず（`ES_AUTOHSCROLL`と横スクロールバー）、長い行の後ろの一致は横の外に隠れていた。
previewの横の操作は、hideが案A（折り返して横スクロールを無くし、一致箇所が見える位置へ寄せる）を選んだ（#928のコメント）。

## 決定

1. 入力欄にフォーカスがあるときの↑↓は、候補を1つ動かし、フォーカスを入力欄に残す。候補の列にフォーカスがあるとき・クリック・UIAの選択は従来どおり候補の列へフォーカスを移す。
   経路は既存の`discovery_navigate`の1つで、フォーカスの行き先だけを引数で分ける（`discovery_pick`）。
2. 入力欄にフォーカスがあるときのPageUp/PageDownは、原文previewを1画面ぶん縦に送る（`EM_SCROLL`）。候補の選択は変えない。
   previewが出ていない（狭い窓で結果を表示中・候補0件）ときは従来どおり候補のページ送り。候補の列にフォーカスがあるときのPageUp/PageDownも従来どおり候補のページ送り。
3. 原文previewは折り返して表示する（`ES_AUTOHSCROLL`と`WS_HSCROLL`を外す）。一致の選択と`EM_SCROLLCARET`で、一致箇所が可視範囲に入る（ADR0095の寄せ方は不変）。
4. 行番号は論理行（原文の行）の1行目の高さにだけ付け、折り返した続きの行には付けない。読み込み時にpreviewの文字列から各論理行の開始位置（UTF-16の位置、最大80行）を記録し、描画時に`EM_LINEFROMCHAR`で表示行へ写す。
5. 日本語入力の変換中は、従来どおり↑↓・PageUp/PageDownを変換へ渡す（`command_composing`）。

## 影響

- ADR0094「単クリック/上下/Page移動は候補選択とpreviewだけ」は、入力欄のPageUp/PageDownがpreviewの送りになる点だけ補う。確定（Enter/開く）・取消・本文を変えないことは不変。
- 原文の内容・範囲・選択・コピーは変えない。折り返しは表示だけで、コピーした文字列に改行は入らない（EDITの表示の折り返し）。
- 未決: 左右キーで名前/本文を切り替える、Ctrl+Enterで一致箇所を開く（入力欄の文字のカーソル移動・既存のEnterとの関係をhideが選ぶ。#928に残す）。探し方の説明文は別Issue。

## 検証

native試験`body_discovery_native`に、入力欄の↓で選択が進みフォーカスが残り、続けて文字を打てること、previewに横スクロールが無く長い行が折り返されること（論理23行が表示40行）、
入力欄のPageUp/PageDownでpreviewの最初の可視行が動き（19→1→19）選択とフォーカスが変わらないことを足した。行番号の対応は実描画の採取で確かめた（品質記録）。
