# ADR 0114: 見出しの階層は段落のスタイルで渡し、閲覧欄が段落を読んで索引にする

Status: accepted / 2026-11-18 / Issue #975

## 背景

長いノートで見出しへ移る手段が無い。出し方は見本を並べ（D:/NeNeFolio/design/928-finder-choices/ の9番）、
hideが案B（原文には書かず、閲覧表示の横に「見出し」の欄を開く。いま読んでいる見出しに印）を選んだ（2026-11-18「C,b, a で」の2つ目）。

調べたこと（読み取り専用の調査、#975に記録）:

- 見出しの一覧はどこにも無い。原文の位置から閲覧表示の文字位置への対応も無い（検索は表示の文字の上で動く）。
- 縮小表示（ADR0084）はMarkdownを解析し直さず、RichEditの各行の先頭の文字の大きさと行の文字数で見出しを描く。h5・h6は本文と同じ大きさなので、大きさだけでは階層が分からない。

## 決定

この決定は段階に分けて実装した。1〜4はすべて実装済み（3・4は#975の第3・第4段階、同じPR）。

1. スタイルと索引（実装済み・#975の第1段階）
   - RTFの頭にスタイル表を書く: `\s1`〜`\s6`を`heading 1`〜`heading 6`と名付ける。閲覧・編集・空の文書で同じ頭（既存の決まり）。
   - coreの描画は、見出しの段落に`\sN`（Nは階層）を付ける。普通の段落は`\pard`でスタイルが外れる。**文書の文字は1つも増えない。**
   - RichEditは`heading N`という名前のスタイルを組み込みの見出しスタイルとして覚え、段落ごとに読み戻せる（`ITextPara::GetStyle`が-2〜-7を返す）。
     非表示のRichEditで確かめた（D:/NeNeFolio/agents/975-headings/probe.c と probe-output.txt）。`\s-2`のような負の番号や`\outlinelevel`は読み戻せなかった。
   - 閲覧欄の`note_pane_headings`が段落を順に読み、見出しの段落の先頭のnative位置と階層を持つ。
     文書の最後にRichEditが自分で置く段落記号は、直前の段落の書式を引き継ぐので数えない（ノートが見出しで終わると、空の見出しがもう1つあるように読める）。
   - 索引は、読み込みのあと最初に尋ねられたときに作る（読み込みのたびに全段落を読まない）。読み込み直したら捨てる。
   - `note_pane`は見出しの件数・階層・位置を公開し、`note_pane_show_heading`で見出しへキャレットを置いて、その行を表示の先頭へ寄せる。動いている途中のスクロールは止める。
   - 見出しの文字の一覧をcoreやapplicationに別に持たない。欄に出す文字は、表示されている段落から読む（表示が正本。ARC-004）。
   - 欄の1行の文字（実装済み・#980）: `note_pane_heading_text`が、見出しの段落の表示されている文字を読む。リンクの宛先などの非表示の文字、
     画像や表の構造を表す文字は入れない。1行・最大127単位で、長い見出しは切る（省略の印は欄が描く）。文字は覚えておかず、要るときに読む。
     リストの項目の中の見出しは、段落に表示されている項目の記号（•など）も一緒に出る（表示どおり）。
   - いま読んでいる見出し（実装済み・#980）: `note_pane_heading_current`が、表示の先頭の行か、それより上にある最後の見出しを返す。
     最初の見出しより上を見ているときは「無い」。見出しへ移る動きが行を表示の先頭へ寄せるので、移った見出しがそのまま「読んでいる見出し」になる。
     ノートの最後の方の見出しは先頭まで上がれないので、押した直後に1つ前の見出しが返ることがある（最初の版はそのまま）。
2. 「見出し」の欄（部品は#982、主窓への接続は#975の第3段階で実装済み）
   - 欄の部品`note_outline`が、行の配置・当たり判定・欄の中の送り・描画を持つ。1つの配置の値（`note_outline_paint`）を描画・当たり判定・読み上げで共有する。
   - 持つ状態は欄だけのもの（欄の中の送り位置、キーボードの位置、ポインタの乗っている行、押している行）と、観測した「いま読んでいる見出し」。
     見出しの文字と位置は持たず、描くたびに`note_pane`へ尋ねる。文書を読み込み直したら初めへ戻し、版を進める。
   - 見た目: 本文の側に細い線、上に欄の名前、行は階層ごとに字下げ。いま読んでいる見出しは選択の面と本文の側の棒。見出しの無いノートでは「見出しはありません」。長い見出しは省略の印。
3. 主窓への接続（実装済み・#975の第3段階）
   - 開閉: コマンド「見出しの欄の表示を切り替える」（操作メニュー・パレット）と`Ctrl+Shift+O`。開閉の状態は`folio_state`が実行中だけ持ち、初めは閉じている。設定には残さない（hideの了承・2026-11-19）。
   - 置き場所: 本文と縮小表示の間。幅184 logical px、本文との間12 logical px。`body_content_rect`だけが本文から切り出す。縮小表示の矩形は欄の有無で変わらない。
     本文の最小幅（320 logical px）を欄の横に取れない窓では、欄を先に隠す（縮小表示は従来の規則のまま）。開いた状態は変えず、窓を広げると戻る。
   - 閲覧表示だけに出す。編集表示でコマンドを押すと状態だけを切り替え、閲覧へ戻ったときに出す。閲覧と編集の切り替えで本文の幅を戻す（`outline_carved`で前回の切り出しを覚え、違えば並べ直す）。
   - 押して移る: 行を押して同じ行の上で離すと、その見出しを本文の先頭へ寄せる（`note_pane_show_heading`）。行の外で離すと何もしない。
     マウス・読み上げのInvoke/Select（とキーボード）は、同じ`folio_window_accessible_action`の経路を通る（ADR0060の決定4）。押している行は選択の面、ポインタの乗っている行は細い線。
   - いま読んでいる見出しの印は、本文が送られたとき（`refresh_gutter`）と読み込みのあとに尋ね直す。印が変わったときだけ、その行が見えるように欄を送る（ホイールで送った欄を、本文が動くまで戻さない）。
   - ホイール: 欄の上のホイールは欄を1刻み3行送り、本文は動かさない。1刻みに満たない量は次へ持ち越す。本文にフォーカスがあるときの入口（`translate_minimap_wheel`）も欄を受け付ける。
   - 本文を読み込み直すたび（ノートの切り替え・閲覧と編集の切り替えのほか、色の変更や検索の強調の描き直しも）、欄の送り位置・キーボードの位置・ホイールの余りは初めへ戻り、行の版が進む。
     押している途中に読み込み直されたら、押した時点の版で要求するので移らない（独立レビューの指摘）。
   - 読み上げ: 欄はList（名前「見出し」、Selection＝いま読んでいる見出し）、行はListItem（名前＝見出しの文字、Level＝階層、PositionInSet/SizeOfSet、Invoke、SelectionItem）。
     行は読み込みごとの版（`note_outline_revision`）を持ち、前の読み込みの行や、隠れた欄の行は答えない。hostが版の変化で古い行を捨て、構造の変化を知らせる。
   - 欄全体のtooltipは出さない（行が文字を出している）。欄の題と空きの上ではポインタを矢印のままにする。
4. キーボード（実装済み・#975の第4段階）
   - 欄は本文の操作列と同じ区画のTabの止まり先の1つ（操作列の後、縮小表示の前）。入ると、いま読んでいる見出しの行（無ければ先頭）にキーボードの位置を置く。
   - ↑↓で1行、PageUp/Downで欄に見える行の数、Home/Endで端へ。位置だけを動かし、本文は動かさない。Enterと（離したときの）Spaceで、その見出しへ移る。移った後も位置は欄に残る。
   - 読み上げのフォーカスは位置の行（ListItem）。読み上げから行にフォーカスを置くと、その行が位置になる。
   - 欄が隠れたら（狭い窓・編集表示・閉じる）、キーボードの到達先を閲覧/編集の札へ戻す（縮小表示と同じ作り）。
   - 第3段階と第4段階は同じPRにした。マウスだけで操作できる途中の状態をmainへ置かない（ADR0060の決定4）。

## 影響

- 閲覧のRTFの頭が、スタイル表のぶん長くなる。見出しの段落の書式に`\sN`が付く。見える文字・検索・コピー・生の文字列は変わらない。
- 編集表示には見出しのスタイルが無く、見出しは0件。
- RichEditが見出しのスタイルを持つので、読み上げ（UI Automation）が段落を見出しとして扱える可能性がある（確かめていない）。
- 閲覧表示からコピーしたときのRTFに見出しのスタイル名が入り、Word等へ貼ると貼り先の見出しスタイルになる可能性がある（確かめていない。文字としてのコピーは変わらない）。
- 索引を作れなかったとき（メモリ不足など）は、次に読み込むまで見出し0件として扱う。

## 却下した案

- 見出しの前に非表示の印（`<nenefolio:heading:L>`、画像の印と同じ形）を書く: 最初に実装し、全試験も通したが、独立レビューと既存の試験が次を見つけた。
  - 縮小表示が行の文字数に非表示の21字を数え、見出しの棒が長くなる（h1は19字以上で幅いっぱいになる）。
  - 印を段落の書式の前に置くと、縮小表示が印の大きさを読んで見出しと見分けられなくなる。
  - 生の文字列に印が入る。コピーと読み上げに印が出ないことを確かめられていなかった。
  - 見出しがリンクで始まるとき、段落の先頭でCtrl+Enterが効かなくなる見込みだった。
  文字を足す方式は、文字と位置を使う処理すべてに影響が及ぶ。スタイルはどれにも影響しない。
- 見出しをリンク（内部の宛先）にする: 見出しの上で手の形のポインタになり、リンクの操作が見出しに付く。
- 文字の大きさと色から見出しを見分ける: h5・h6が本文と同じ大きさで、色もテーマしだいで本文と同じになりうる。
- coreで見出しの一覧を作ってapplicationが公開する: 文字と位置の正本が表示と別に増え、対応を取り直す仕組みが要る。
- 読み込みのたびに索引を作る: 欄を開いていないときにも全段落を読むことになる。
- 原文に`[TOC]`と書く（案A）: hideが案Bを選んだ。

## 検証

単体: スタイル表、見出しの段落の`\sN`（ATX・setext・リスト・引用の中）、普通の段落と表に付かないこと、文字が増えないこと。
native（`minimap_structure_tests`）: 7つの見出し（ATX、setext、リストと引用の中、リンクを含むもの）の階層と段落の先頭の位置と順、
生の文字列が見出しの文字だけであること、見出しへ移ると行が先頭に来てキャレットが置かれること、範囲外の番号、
見出しの無いノート、読み込み直しへの追従、ノートが見出しで終わるときに1回だけ数えること、編集表示では0件。
縮小表示の見出しの大きさの試験（既存）が通ること。
native（`outline_native`・`outline_96_native`。後者はCIと同じ96 DPIの窓）: 欄を開くと本文が幅＋間だけ狭くなり縮小表示は動かない、編集では本文の幅が戻る、
9行の名前・階層・位置と前後の移動、行の外で離すと移らない、押すと移っていま読んでいる見出しになる、Invokeで戻る、
低い窓で本文にフォーカスがあるままホイールが欄を送って本文を動かさない、狭い窓で欄と行が隠れて広げると同じ行が戻る、読み込み直すと古い行は答えない。Light・Dark・高コントラストで流す。
本文にフォーカスがあるときのホイールの入口を外す変異で、試験が落ちることを確かめた。Waivers none。
