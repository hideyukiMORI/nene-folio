# ADR 0114: 見出しの位置は閲覧RTFの非表示の印で渡し、閲覧欄が索引にする

Status: accepted / 2026-11-18 / Issue #975

## 背景

長いノートで見出しへ移る手段が無い。出し方は見本を並べ（D:/NeNeFolio/design/928-finder-choices/ の9番）、
hideが案B（原文には書かず、閲覧表示の横に「見出し」の欄を開く。いま読んでいる見出しに印）を選んだ（2026-11-18「C,b, a で」の2つ目）。

調べたこと（読み取り専用の調査、#975に記録）:

- 見出しの一覧はどこにも無い。原文の位置から閲覧表示の文字位置への対応も無い（検索は表示の文字の上で動く）。
- 縮小表示（ADR0084）はMarkdownを解析し直さず、RichEditの各行の先頭の文字の大きさで見出しを見分けている。h5・h6は本文と同じ大きさなので、大きさだけでは階層が分からない。
- 閲覧表示の中の位置を覚える前例は、脚注の番号とコードのコピー（内部の宛先を持つリンク）と、画像（非表示の印`<nenefolio:image:N>`）。

## 決定

この決定は段階に分けて実装する。**いま実装済みなのは「1. 印と索引」だけ**で、2と3は#975の後続（未実装）。

1. 印と索引（実装済み・#975の第1段階）
   - coreの描画は、見出しの段落に非表示の印`<nenefolio:heading:L>`（Lは階層1〜6）を書く。書式と読み取りは`heading_target`の一か所。
   - 印は見出しの書式（大きさ・色）の内側、項目の記号の後に置く。段落の書式より前に置くと、縮小表示が印の大きさ（本文と同じ）を読んで見出しと見分けられなくなる（既存の試験が検出した）。
   - 閲覧欄の`note_pane_links`は、書式の区間を歩くときに、非表示の区間が印で始まっていれば見出しの位置と階層を覚える。
     非表示であることを条件にするので、本文に同じ文字を書いても印にはならない。
   - `note_pane`は見出しの件数・階層・位置を公開し、`note_pane_show_heading`で見出しへキャレットを置いて、その行を表示の先頭へ寄せる。
   - 見出しの文字の一覧をcoreやapplicationに別に持たない。欄に出す文字は、表示されている段落から読む（表示が正本。ARC-004）。
2. 「見出し」の欄（未実装）: 主窓に描く部品として本文の右を切り出す（縮小表示と同じ作り）。行を押すと移る。
3. 開閉のコマンド・設定・いま読んでいる見出しの印（未実装）。

## 影響

- 閲覧のRTFの見出しの段落に、非表示の文字が21字増える。見える文字・検索・コピーには現れない（非表示の区間は既存の索引が検索から外す）。
- 見出しの文字がリンクで始まるとき、印とリンクの非表示の部分が1つの区間になることがある。索引は区間の先頭の21字だけを読むので影響しない。
- 編集表示には印が無く、見出しは0件。

## 却下した案

- 見出しをリンク（内部の宛先）にする: 見出しの上で手の形のポインタになり、リンクの操作（Ctrl+Enter、右クリック）が見出しに付く。
- 文字の大きさと色から見出しを見分ける: h5・h6が本文と同じ大きさで、色もテーマしだいで本文と同じになりうる。
- coreで見出しの一覧を作ってapplicationが公開する: 文字と位置の正本が表示と別に増え、対応を取り直す仕組みが要る。
- 印を段落の書式の前に置く: 縮小表示が見出しを見分けられなくなる。
- 原文に`[TOC]`と書く（案A）: hideが案Bを選んだ。

## 検証

単体: 印の書式と読み取り（階層1〜6、形の違うもの）、見出しのRTF（ATX・setext・リスト・引用の中）。
native（`minimap_structure_tests`）: 7つの見出し（ATX、setext、リストと引用の中、リンクを含むもの）の階層と位置と順、
検索用の文字に印が出ないこと（本文にコードとして書いた同じ文字だけが出る）、見出しへ移ると行が先頭に来ること、範囲外の番号、編集表示では0件。
縮小表示の見出しの大きさの試験（既存）が通ること。Waivers none。
