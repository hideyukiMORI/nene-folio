# ADR 0115: ガントは作業を節点、区分を群、目盛りを模型の欄として持ち、日付は整数の暦で解いて今日を読まない

Status: accepted / 2026-11-19 / Issue #992

## 背景

閲覧表示のMermaidはフローチャート・シーケンス図・状態遷移図・ER図・クラス図・円グラフを図にし、ガント（`gantt`）は「未対応の種類」の案内だった。
見た目は3案の見本を並べ（D:/NeNeFolio/design/928-finder-choices/ の10番）、hideが案A（区分ごとにアクセント色の濃淡、済んだ作業は淡く、「今日」の線は引かない）を選んだ（2026-11-18「C,b, a で」の3つ目）。
計画は読み取り専用の計画席が作った（D:/NeNeFolio/agents/gantt-20261119/plan-20261119.md）。

ガントは日付を扱う。Mermaidは開始日の無い最初の作業や、知らない名前を`after`で指したときに「今日」を使う。
このアプリは中核で現在時刻を読まない（ARC-007）。今日を読めば、同じノートが日によって違う図になる。

## 決定

- 図の種類に`DIAGRAM_GANTT`を足す。coreの`mermaid_gantt`が読み、`diagram_gantt_layout`が配置する。振り分けは従来の最初の語の表。
- 模型: 作業1つが節点1つ（labelは名前、idは書かれたidか名前）。節点に`start`（図の最初の日からの日数）・`length`（日数。長さ0のマイルストーンは0）・`state`（予定/進行中/済み）・`critical`を足す。
  マイルストーンは形を菱形にする。区分1つが群1つ。目盛りは新しい欄（`diagram_tick`: 日と、ラベルの模型の文字）として模型に持つ。
  配置は文字を足せない（測った文字の数と模型の文字の数が一致することを確かめている）ので、目盛りのラベルは読み取りの最後に模型の文字として作る。
- 暦: `diagram_calendar`が年月日と通日を整数だけで相互に変える（0000-03-01を0日とする、H. Hinnantのcivil-from-days）。曜日は月曜を0とする。1〜9999年。OSの暦・時刻・ロケールを読まない。
- 構文（受ける）: `gantt`、`title`（1つ）、`dateFormat YYYY-MM-DD`（無いときもこれ）、`axisFormat`（`%Y %y %m %d %e %-m %-d`と文字）、`tickInterval N(day|week|month)`（Nは1〜999、先頭に0を書かない）、
  `excludes weekends`と`excludes YYYY-MM-DD`（空白かカンマで区切る）、`excludes monday`などの英語の曜日名（大文字小文字を区別しない。#1022）、`todayMarker`（読み飛ばす。何も描かない）、`section 名前`、`%%`のコメント。
  作業の行は`名前 : [done|active|crit|milestone,]… [id,] [開始,] 終わり`。項目は1つなら終わり、2つなら開始と終わり、3つならidと開始と終わり（Mermaidと同じ）。
  開始は`YYYY-MM-DD`か`after id id…`（そのうち最も遅い終わり）。書かなければ1つ上の作業の終わり。終わりは`YYYY-MM-DD`（その日を含まない。Mermaidと同じ）か`Nd`・`Nw`、または`until id id…`（#1022）。
  `until`は名前を挙げた作業のうち最も早い始まりで終わる。下に書いた作業を挙げてもよい（始まりは終わりより先に決まるので、互いの始まりを待つ2つの作業も解ける）。
  除外日があるときは、Mermaidが期間と同じ手順で終わりを延ばすのに合わせ、始まりからの日数として期間と同じに数える。挙げた作業が自分より前に始まるなら不正。1つでも知らないidがあれば未対応（Mermaidは知っているidだけを使い、どれも知らなければ今日を使う）。循環は不正。
  Mermaidとの違い: idに使える文字を絞らない（Mermaidは英数字・`_`・`-`の後で切る。`after`と同じ扱い）。挙げた作業の始まりがすべて決まるまで待つ（Mermaidは、その回で決まっていたものだけで終わりを決めることがある）。
  #1022のレビューで、#992の期間の数え方の違いを2つ直した: 作業が始まる日は除外日でも1日に数える（Mermaidは始まりの翌日から歩く）。0日の作業は除外日の上でも始まった所で終わる。
  `done`と`active`が両方あれば`done`（Mermaidの描き方と同じ）。`after`は下に書いた作業も指せる（解けるまで繰り返す。作業の数を超えたら循環として不正）。
- 除外: 日数で書いた作業は、除外した日を数えずに延ばす。書いた終わりの日は動かさない（Mermaidの`checkTaskDates`と同じ）。除外した日の塗りは描かない。
  作業が除外した日の直前で終わるとき、棒は最後の数えた日までで、次の作業は除外した日の後から始まる（Mermaidの`fixTaskDates`の`renderEndTime`と`endTime`。独立レビューの指摘で合わせた）。
- `%%`はMermaidと同じく行のどこでも注釈の始まりなので、`axisFormat`の`%%`は届かない（受けるのは`%`1つの書式だけ）。
- 目盛り: `tickInterval`が無ければ、1日・1週・2週・1か月・3か月の順に、目盛りが10以下になる最も細かいものを使い、どれも多ければ1年。週は月曜、3か月は1・4・7・10月、1年は1月1日。
  2以上の間隔（`tickInterval`で書いたものも、自動の2週も）は、Mermaidが使うd3の`every(k)`と同じ位置に置く（#1036）: 日は「月の日付−1がkの倍数の日」（2日なら1・3・5…31日、次の月はまた1日から）、週は「1970-01-01を含む週から数えてkの倍数の週」、月は「1月を0としてkの倍数の月」。図がどこから始まっても同じ日に立つ。
  ラベルは既定で`M/D`、最初の目盛りと年が変わった目盛りだけ`YYYY/M/D`。図が間隔より短くても目盛りは1つ出す。
- 配置: 上に題（中央）、その下に目盛りのラベル（小さい字・薄い色）、左に区分の名前、行ごとに作業の棒と、その右に名前（小さい字）。区分の間は少し空ける。
  目盛りの縦線は地に近い色で全行を通す。横の縮尺は1日を1/16画素で持ち、図の幅560を目安に1日40画素まで。目盛りのラベルが重なるなら広げる。棒は最低2画素。
- 色（案A）: 棒はアクセント色の段（区分の順に12/16・9/16・6/16を繰り返す。区分の前の作業は12/16）。輪郭は描かない。
  済んだ作業は淡い面（図の節点の色）と灰色の縁。進行中はアクセント色の細い縁。critはアクセント色の太い縁（見本の赤ではなく、案Aの色だけで示す）。マイルストーンはアクセント色の菱形を、その日の位置に置く。
  新しい色は足さない。高コントラストではアクセント色が文字色になり、段は灰色の段になる（既存の`diagram_palette_for`）。

### 後から足した指示語（#1030・#1032）

- `weekday monday`〜`sunday`で週の目盛りを置く曜日を選べる。`weekend friday`は`excludes weekends`の週末を金・土にする（`weekend saturday`は既定の土・日）。どちらも大文字小文字を区別せず、ほかの語は不正。
  行が`weekday`・`weekend`で始まっても、後ろがこの形でなければ作業の行として読む（Mermaidの字句と同じ。例: `Weekend deploy :2026-11-07, 2d`）。同じ指示語を2回書けば後のものが効く。
- `inclusiveEndDates`を書くと、日付で書いた終わりがその日を含む（終わりを1日後ろへ。図のどこに書いても全体に効く。期間と`until`の終わりは変わらない）。
  書いた終わりは除外日があっても動かない（指定の有無によらない）。指示語の後ろに文字があれば未対応（Mermaidはそれを別の作業として読む。ここでは描かず、黙って捨てもしない）。

## 未対応（図全体を案内にし、部分的な図を作らない）

`dateFormat`の`YYYY-MM-DD`以外、時刻を含む開始、`h`・`m`・`s`・`ms`・`M`・`y`や小数の長さ、`axisFormat`の`%b` `%a` `%B`など（月や曜日の名前はロケールのもの）、
1日より短い`tickInterval`、`includes`・`topAxis`・`displayMode`・`click`・`call`・`vert`・`accTitle`・`accDescr`、`%%{init}%%`。
**開始日の無い最初の作業と、知らないidを指す`after`・`until`**（Mermaidは今日を使う）。

不正: 存在しない日付、開始より前の終わり、`after`・`until`の循環、自分より前に始まる作業を指す`until`、同じid、名前の無い作業、`:`の無い行、題が2つ。
大きすぎる: 作業129以上、区分65以上、図の長さが3660日（約10年）を超える、9999年12月31日より後まで続く、目盛り65以上（`tickInterval`を細かくしすぎたとき）、目盛りのラベルが64バイトを超える。

Mermaidとの違い（受けるが描き方が違う、または断る）: `weekday`は、`tickInterval`を書かずに自動で週の目盛りが選ばれたときにも効く（Mermaidは`tickInterval`が週のときだけ）。k週ごとの目盛りの数え始めは1970-01-01（定数）を含む週で、d3は見ている人の時間帯の日付でそれを決める。協定世界時より西の時間帯で`weekday thursday`のときだけ、d3と1週ずれる（このアプリは時間帯を読まない）。週の目盛りは、`weekday`を書かなければ月曜（Mermaidの既定は日曜）。
指示語（`title`・`section`・`dateFormat`・`excludes`の`weekends`等）は、Mermaidの字句解析と同じく大文字小文字を区別しない（#1002。1.5.0の候補では区別していた）。作業の印（`done`等）はMermaidと同じく書いたとおりに読む。
`%e`は空白で詰めない。自動のid（`after task1`）は知らないidとして未対応。作業の`vert`の印は未対応。

## 影響

- 節点の構造体が大きくなる（他の図では0のまま）。模型に目盛りの配列（64）が増える。
- 狭い閲覧欄では、他の図と同じく図全体の画像を縮めて出す（折り返さない）。
- 区分の名前が長く折り返して、その区分の行より高くなるときは、その区分の後の間を広げ、次の区分の名前と棒をその下から始める（#1006。1.5.0の候補では重なることがあった）。
- critの縁は、最も弱いテーマでアクセント色と1段目の比が1.38。見本の2画素より太い3画素で見分ける。弱すぎるならhideの判断で文字色の縁にする（下の試験の下限を変える）。
- Storeの掲載文と1.4.0の変更一覧は「ガントは未対応」と書いている。リリースのときに直す。

## 却下した案

- 今日を読んで、開始日の無い最初の作業を今日から始める: 同じノートが日によって違う図になり、中核で時刻を読むことになる（ARC-007）。
- 目盛りを配置で作る: 配置は文字を足せない。足せるように測り直す仕組みを作るより、読み取りで作る方が既存の流れのまま。
- 作業をフローチャートの節点として描く: 日付の軸が無い。
- 案B・案C: hideが案Aを選んだ。
- 済んだ作業の縁をアクセント色の段で描く: GDIのペンは段を持たない（`create_pen`）。段のあるペンを足すと円グラフにも及ぶ。灰色の縁は節点の色と3:1以上が保証されている。
