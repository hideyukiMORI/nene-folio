# ADR 0116: 閲覧の段落と原文の行の対応は、描画と同じ一巡で記録し、閲覧欄の段落の記号の数で照らす

Status: accepted / 2026-11-19 / Issue #1008

## 背景

[ADR0106](0106-note-body-context-menu.md)は、閲覧の右クリックの「ここを編集」「Markdownとしてコピー」を次の段階とした。表示と原文の位置の対応が無いからである。
閲覧欄はcoreの描画が作ったRTFを読み込んだRichEditで、どの段落がどの原文の行から来たかを持っていない。
計画は読み取り専用の計画席が作った（D:/NeNeFolio/agents/source-map-20261119/plan-20261119.md）。

## 決定

この決定は段階に分けて実装した。1は#1008、2と3は#1012。

1. 対応表（実装済み・#1008）
   - coreの描画（`markdown_blocks`）が、ブロックを出す直前にそのブロックの原文の範囲を記録する。範囲は行の始まり（リストや引用の印を含む）から最後の行の終わり（改行は含まない）まで、加えて内容の始まり（キャレットを置く所）と種類。
     種類は段落・見出し・コードの柵の開き・コードの1行・柵の閉じ・図・区切り線・表の行（見出しの行は区切りの行を含む）・記法のままの表の行・定義リストの用語と説明・脚注の前の線・脚注。
     コードの柵（図の柵も）と表は群を作り、同じ群の番号を持つ（どの種類が群に入るかは閉じたswitchの1か所）。前付け（タグ）と参照の定義は閲覧に出ないので記録しない。
     setextの見出しは下線の行まで、空のリスト項目（印だけの行）はその行を1つのブロックとして記録する。説明の直後の表は、表を先に記録してから間の段落を出すので、その段落は表のもの。
     脚注の前の線は自分の原文を持たないので、最初の脚注の定義を指す。図の柵の中の行は記録しない（図は1つの段落。群の範囲は開きと閉じの行で柵全体になる）。
   - 描き終えたRTFを数えて、各ブロックが閲覧欄に残す段落の記号（RichEditの生の文字のCRとU+0007）の数を求める。
     数え方は隠したRichEditで確かめた（D:/NeNeFolio/agents/source-map-20261119/probe.c と probe-output.txt）: `\par`がCR1つ、表の1行は`\trowd`の始まりの印・`\cell`ごとのU+0007・`\row`の終わりの印。
     文書の最後の`\par`はRichEditの最後の段落記号に吸収されて生の文字に出ないので、総数から1つ引く。`\pard` `\cellx`などの似た語と、`\\par`のような文字は数えない。
   - 表は`markdown_rtf`が持つ。読み込み直し（色の変更・検索の強調の描き直し）はRTFと一緒に作り直す。編集用と空の文書には表が無い。
   - 表示が正本（ARC-004）のまま: どこを読んでいるかは閲覧欄が段落の番号で答え、表は行を答えるだけ。閲覧欄の記号の数が表の総数と違うときは表を使わない（推測しない）。
     表はコードのコピーの原文（ADR0098）と同じく、同じ描画の一巡の副産物で、別の解析器ではない。
2. 原文の位置への変換（実装済み・#1012）: coreの`markdown_source_lookup`が、段落の番号から編集を始めるバイト位置（ブロックの内容の始まり。表の行では、何番目のセルかを記号の数から求め、そのセルの`|`の後の文字の始まり）と、
   選択の範囲のMarkdown（本文の最初から最後のブロックまでの行をひと続きに。柵・表・図は群の全体へ広げる。脚注は空行の後に定義を1つずつ。改行はLFにそろえる）を求める。
   applicationの`folio_state_source_mapped` / `folio_state_source_caret` / `folio_state_copy_markdown`が窓口。閲覧欄の記号の数が表の総数と違うとき、表に項目が1つも無いとき（前付けだけ）、および「ここを編集」では編集で原文が変わる保護された文書でも`FOLIO_STATE_SOURCE_UNMAPPED`を返し、何も変えない。
   保護された文書の原文を写すのは害が無いので、「Markdownとしてコピー」は保護された文書でも使える。
   見つからないことを`markdown_source_none`（キャレット）と`bool`（コピー）で返すのは#1008の`markdown_source_map_find`にそろえた中核の内側の形で、窓口のapplicationでは閉じた結果`FOLIO_STATE_SOURCE_UNMAPPED`にする（C-005は窓口で守る）。
   編集表示のキャレットは既存の`note_source_units`（ADR0095の本文検索と同じ）で求める。
3. 右クリックの項目（実装済み・#1012）: 閲覧のメニューは「コピー／Markdownとしてコピー」｜「ここを編集」｜「すべて選択」、リンクの上は「リンクを開く／リンクをコピー」｜「コピー／Markdownとしてコピー／ここを編集」｜「すべて選択」。
   アクセスキーはM・E。自前のキーは持たない。閲覧欄は選択（右クリックの位置）の前の段落の記号の数を生の文字（隠れた文字を含む）で数えて番号にする。
   「ここを編集」は検索から編集で開くときと同じ順（状態からキャレットを受け取る→編集表示へ→そこを選ぶ）。「Markdownとしてコピー」はクリップボードのポートへ1回渡す。
   使えないとき（表と数が合わない、読み込み中、「ここを編集」では保護された文書）は淡色。全文を写す判定はメニューを開いたときに1回だけ行い、描画やポインタの移動のたびには読まない。実行のときは今の文で確かめ直す。既定の振る舞いは計画席の推したもので、hideが2026-11-19に確定した: 表のセルはそのセル、脚注はその定義、段落の途中の選択でもその段落の全行。

## 影響

- 閲覧の描画のたびに、ブロックの数だけ小さな記録（約60バイト）が増え、描き終えたRTFを1回読む。RTFの文字は変わらない。
- 関数`markdown_blocks_render`の引数を、言語・コントラスト・対応表の1つの値（`markdown_blocks_options`）にまとめた。
- 表は`markdown_rtf_create`のたびに作る。閲覧のほか、画像を含む書き出し（`image_export`）も同じ関数を通るので、そこでも作られて使われない。費用はブロックの数の小さな配列で、確保に失敗すると書き出しもメモリ不足になる（従来の確保の失敗と同じ扱い）。

## 却下した案

- 段落の書式（スタイル・タブ・間隔）に番号を入れる: 読み戻せるのは「heading N」という名前のスタイルだけだった（ADR0114）。ほかの書式は見た目を変えるか、Wordへのコピーに漏れる。
- 見えない印の文字を足す: ADR0114で却下した。文字の位置・縮小表示・コピーが変わる。
- いちばん近い見出しだけで答える: 「ここを編集」には粗く、コピーには使えない。
- coreでRichEditの文字の位置を数える: 隠した文字・フィールド・後から入る画像を真似ることになり、壊れやすい。

## 検証

#1012: 単体（`source_map_tests`）でキャレット（段落・コードの行・表の各セルと行末・説明の後の表の空き段落を含む行・記法のままの表・脚注）とコピー（柵の中→柵の全体、段落からリスト、表のセル→表の全体、本文から脚注、脚注だけ、CRLF→LF）。
`code_copy_tests`の`verify_source_state`で状態の窓口（編集表示では表が無い、キャレットの値、数が違うときは何もしない、コピーの1回、クリップボードが使用中）。
native（`minimap_structure`の`source_places`）で、見出し・段落・表の各セル・コードの行・脚注の上に生の位置を置くと、番号から引いたキャレットがその原文を指すこと。
実窓（`text_menu_native`）でメニューの並びと名前、「ここを編集」で編集表示に移りキャレットが選んだ文字の行にあること。試験はクリップボードへ書かない。

単体（`source_map_tests`、`code_copy_tests`から呼ぶ）: 手書きのRTFで数え方（`\par`、表の行、`\pard`・`\cellx`・`\\par`・`\uN`、最後の`\par`の吸収、文字が後にあるとき、最初の項目より前の記号）、
実際の描画ですべての種類の範囲・キャレット・記号の数・群（前付けと参照の定義は無い）、CRLF、確保の失敗。
native（`minimap_structure`）: 6つの文書（既存の見本、すべての種類、表・コード・見出しで終わる文書、作業と番号のリスト）で、閲覧欄の生の文字の記号の数が表の総数と一致すること、
ASCIIのコードの行はその番号の段落がその行を表示していること。`\trowd`を数えない変異で落ちることを確かめた。Waivers none。
