# ADR 0118: 指定したノートを開いて箇所を選ぶ入口（`nenefolio://`のリンク）

Status: proposed / 2026-11-20 / Issue #1071（決定のうち「hideの確認待ち」と書いたものは、確認の後にacceptedへ改める。確認してもらう5点は[判断のページ](https://claude.ai/artifact/MKr49ZHc4sRPPLAifGd1xA)にまとめた）

## 背景

LLM（WSLのClaude Codeなど）がノートを探して説明するとき、該当のノートを開いて、読んでほしい箇所を選んだ状態で見せたい（#1071、2026-11-13の検討の3）。
hideは2026-11-19に、SPECIFICATIONの「やらないこと」を改めて、これを取り入れると決めた。進める順は #1069 → このリンク → #1070と依頼のファイル → #1062。

前提と縛り:
- WSL側のLLMは、Windows側の実行ファイルを起動しない。LLMが答えにリンクを書き、利用者がクリックする。
- 読み取りだけ。書き込みの口は開けない。ローカルのポートで受けるHTTPのAPIは採らない（#1071の「採らないもの」）。
- いまのアプリは引数を読まない（`wWinMain`が`arguments`を捨てている）。同じ`data/`を使う2つ目の起動は、`data/.nenefolio.lock`で断られ、箱を出して終わる（ADR0022の決定3）。
- 外から来た値は、最初の自前の境界で検証して型へ変える（ARC-008）。プロセスの状態を読んでよいのは`adapters/win32`と入口だけ（ARC-007）。

この文書はリンクを決める。依頼のファイル（`data/.requests/`）は#1070のフォルダの見張りと一緒に、次のADRで決める。箇所の探し方と開く経路は、依頼のファイルでも同じものを使う。

## 決定

1. **リンクの形**: `nenefolio://open?category=<カテゴリ名>&note=<ノート名>&lines=<始>-<終>&text=<探す文>`。
   - `category`と`note`は必須。`lines`と`text`は任意。`lines`は原文（Markdownのファイル）の1始まりの行で、`3-8`または`3`。
   - 値は%で符号化したUTF-8。知らないキーは無視する（後で足せるように）。同じキーが2回あれば不正。
   - `open`以外の動作は不正として断る。書き込み・作成・削除の動作は作らない。
   - 全体の長さの上限は2,000 UTF-16単位（コマンドラインとShellの上限より内側）。`text`は復号後1,024byteまで、改行と制御文字は不可。
2. **検証は中核の1か所**: 新しい中核の型`open_request`（`src/core/open_request.h`）が、文字列から作られる唯一の入口を持つ。
   - スキームと動作の確かめ、queryの分解、%の復号、UTF-8の確かめ、`category_name`・`note_name`への変換（既存の名前の規則＝区切り文字・予約名・長さをそのまま使う）、`lines`の範囲の確かめを行う。
   - 結果は閉じた`enum`（受理／形が不正／名前が不正／長すぎる／記憶不足）。受理した値だけがapplicationへ渡る。
   - ノート名に`.md`が付いていれば落とす（既存の`note_name`の振る舞い）。
3. **開く経路は既存の1本**: 窓の`switch_note`（ノートを切り替える唯一の経路、ADR0013の決定4）を通す。新しい経路は作らない（ARC-001）。
   - 編集中の名前のあるノートは、ドロワーのクリックと同じく黙って保存してから移る。保存に失敗したら移らない。
   - 無題の下書きがあれば、ドロワーのクリックと同じく名前の入力を出す。取り消したら開かない。
   - 流し込み中・削除中・面（設定・名前の入力など）を開いている間は、開かずに1行で知らせる。**（hideの確認待ち: 面を閉じて開く、ではなく断る）**
   - カテゴリ名とノート名は、applicationがいまの一覧から位置を引く（大文字小文字は区別しない＝Windowsのファイル名と同じ）。見つからなければ開かずに知らせる。一覧に無いノートを作らない。
     引く前に、カテゴリの台帳と、そのカテゴリのノートの台帳を読み直す（[ADR0117](0117-refresh-ledgers-before-write.md)の部品。読み直しても書かない）。依頼を書いた側（LLMなど）が、直前にノートを外で作っていることがあるため。
   - 絞り込み中・「お気に入りだけ」の表示でも開く（一覧の見え方は変えない。開いたノートは右の窓に出る）。カテゴリが閉じていれば開く。**（hideの確認待ち）**
4. **箇所の探し方**（#1071のとおり。依頼のファイルと共通）: `lines`のあたりで`text`を探す → 無ければノート全体から探す → 無ければ`lines`を選ぶ → どれも無ければ開くだけ。
   - 「あたり」は`lines`の範囲の前後5行まで。**（hideの確認待ち: 幅）**
   - `text`は原文の上で、大文字小文字を区別して探す（LLMは原文を読んで引用するため）。最初の一致を選ぶ。
   - 探すのは保存済みの原文。中核の純粋な関数（原文・行の範囲・探す文 → 原文の範囲または「無い」）にして、単体の試験で固める。
5. **見せ方**: 閲覧表示のまま、該当の箇所を選んで見える所へ送る。編集表示にはしない（読み取りの入口。利用者が編集中だった場合も、保存の後は閲覧で見せる）。**（hideの確認待ち: 編集中だったら編集表示のまま選ぶ、という案もある）**
   - 原文の範囲から閲覧の範囲へは、ADR0116の対応表（`markdown_source_map`）を逆に引く（原文の範囲に重なる段落の、最初から最後まで）。段落より細かくは選ばない（閲覧表示は原文と文字が1対1でないため）。
   - 対応表が引けない段落（図・表の一部など）は、その段落全体を選ぶ。
   - 見つからなかったとき・`lines`へ落ちたときは、1行で知らせる（「指定の文は見つかりませんでした。行を選んでいます」など。文はUX copyで決める）。
6. **動いているアプリへ渡す**: 2つ目の起動は、リンクの引数があり、かつ`data/`が使用中なら、箱を出さずに、動いている窓へリンクの文字列を渡して終わる。
   - 相手は、主窓のclass（`NeNeFolioWindow`）の窓のうち、同じ`data/`を持つもの。`WM_COPYDATA`で「dataの場所＋リンクの文字列」を送り、受け手は場所が自分のものと同じときだけ受ける（ZIP版を2か所に置いて同時に使っている場合に取り違えない）。
   - 受け手は、送り手を信用しない。受けた文字列を、起動の引数と同じ`open_request`の入口でもう一度検証する（ARC-008。同じ利用者のどのプロセスも`WM_COPYDATA`を送れる）。
   - 送る前に、送り手が`AllowSetForegroundWindow`で受け手に前面へ出る権利を渡す。受け手は最小化を戻して前面へ出る。
   - 動いているアプリが無ければ、ふつうに起動してから開く（窓ができて最初の描画の後）。
   - 渡せなかった（窓が見つからない・応えない）ときは、いままでどおり「使用中」の箱を出す。
7. **登録**
   - MSIX版（Store）: マニフェストに`uap:Protocol Name="nenefolio"`を足す（`eng/release.py`の`msix_manifest()`と`eng/test-release.py`）。
     起動したプロセスへURIがどう届くか（コマンドラインか、WinRTの`GetActivatedEventArgs`だけか）は、Microsoftの文書からは確かめられなかった（調べた記録: D:/NeNeFolio/agents/open-link-1071/research-20261120.md）。
     **実機で確かめるまで、マニフェストは変えない。** 確かめるにはパッケージの登録が要り、hideの端末のStore版と同じ身元なので、hideの了解と手順の合意を取ってから行う。**（hideの確認待ち）**
   - ZIP版: アプリはレジストリに書かない（置くだけで動き、消すだけで消える、を保つ）。**（hideの確認待ち: 設定に「このPCでリンクを開けるようにする」を足して`HKCU\Software\Classes\nenefolio`へ書く案もある。採るなら別のADR）**
     ZIP版でも、引数にリンクを渡せば開く（`NeNeFolio.exe "nenefolio://open?…"`）。LLMからは、#1070の依頼のファイルが主な道になる。
8. **層**
   - `core`: `open_request`（検証と型）、箇所を探す純粋な関数、対応表の逆引き。
   - `application`: 名前から位置を引く、保存済みの原文から箇所を決める、結果の閉じた値（開いた／カテゴリが無い／ノートが無い／文が見つからず行を選んだ／開いただけ）。
   - `ui/win32`: `switch_note`を通して開き、選んで送り、1行を出す。`WM_COPYDATA`の受け口。
   - `app`（入口）: 引数を読む、`data/`が使用中のときに渡す。引数を読むのはここだけ。
9. **やらないこと**: 書き込みの動作、HTTPのAPI、開いたことの外への通知（既読の報告など）、リンクからの新しいノートの作成、複数の箇所の同時の強調。

## 理由

- リンクは利用者のクリックを通るので、LLMが勝手に画面を動かさない。開くだけ・選ぶだけなので、悪意のあるリンクでできることは「一覧にあるノートを開く」に限られる（名前の規則でdataの外は指せない）。
- 既存の「ノートを切り替える唯一の経路」を通すことで、未保存の編集と無題の下書きの扱いが、クリックと同じになる（新しい失い方を作らない）。
- 2つ目の起動から1つ目へ渡す道が無いと、アプリを開いたままリンクをクリックするたびに「使用中」の箱が出る。これがこの機能の主な使い方なので、渡す道は最初から要る。
