# ADR 0120: 画像をドラッグ＆ドロップで取り込み、画像のMarkdownを書く

Status: accepted / 2026-11-20 / Issue #1062（hideの判断: 2026-11-20、[判断のページ](https://claude.ai/artifact/VfoGXcQVTKB8SpVGrAgrKW)の5点は「全部推し」。実装した段階は「実装の状態」に書き足す。窓へつなぐ段はまだで、利用者から見える変化はまだ無い）

## 背景

hideの要望（2026-11-19）: 画像をドラッグ＆ドロップすると、画像フォルダへコピーされて、画像を表示するMarkdownが書かれるようにしてほしい。
[ADR0085](0085-lazy-markdown-images.md)は「Markdown原文・入力中のパスを自動変更せず、画像も自動移動/取り込みしない」と決めていた。SPECIFICATIONの「やらないこと」にも「画像の自動取り込み」があった。hideは2026-11-19に、これを改めると決めた。

いまのコード（2026-11-20に確認。記録: D:/NeNeFolio/agents/image-drop-1062/research-20261120.md）:
- 画像の置き場は`data/<カテゴリ>/images/`（ADR0085の推奨）。参照はmdのあるフォルダ（＝カテゴリのフォルダ）からの相対パス。PNG/JPEG、1枚16MiB・64M画素まで。空白を含むパスは`<images/my photo.jpg>`と山括弧で囲む。
- 「ファイルを`images/`へ写す」部品は、どのポートにも無い（書き出しは読むだけ。取り込みは`.md`だけ）。
- 本文は1つのRichEdit（閲覧と編集で共用）。ドラッグ＆ドロップも、画像やファイルの貼り付けも、扱っていない（貼り付けは文字だけ）。
- 文字をUndoつきで入れる道はある（`note_pane_replace`。置換と履歴が使っている）。入れると変更の印が付く。
- 無題のノートは保存先のカテゴリを持つが、初回保存の名前の入力でカテゴリを変えられる。画像の表示は、名前のあるノートの閲覧表示だけ。

## 決定

1. **受けるのは編集表示の本文だけ。** 閲覧表示へ落としたら、取り込まずに1行で「編集表示で落としてください」と知らせる。（hideの判断1。閲覧表示でも受けて編集表示へ移る案は採らない）
   - 理由: 閲覧表示の位置は原文の位置と1対1でない。落とした場所に入った、と言える所へだけ入れる。
2. **書く位置は、落とした位置。** ポインタの下の文字の位置に入れる（落とした点から`EM_CHARFROMPOS`で引く。2026-11-20の実験で、編集表示では投下の知らせ`EN_DROPFILES`の位置と一致することを確かめた）。（hideの判断2。キャレットの位置に入れる案は採らない）
   - 行の途中に落としても、そこへそのまま入れる（改行を足さない。原文を勝手に整形しない）。複数の画像は、1つずつ改行で区切って並べる。
3. **コピー先とファイル名**
   - コピー先は、そのノートのカテゴリの`images/`（無ければ作る）。
   - ファイル名は元の名前のまま。書くMarkdownは、`![名前]`に続けて丸括弧の中へ`images/名前.png`（代替の文は、拡張子を除いたファイル名）。空白や丸括弧を含む名前は、既存の記法どおり山括弧で囲む。
   - 同じ名前のファイルがもうあるとき（hideの判断3）: 中身が同じなら、コピーせずにそのファイルを指す。中身が違えば、`名前-2.png`、`名前-3.png`…と空いている番号を付ける。**上書きはしない。**
   - `images/`の中にあるファイルを落としたときは、コピーせずにそのまま指す。
4. **受ける画像と、受けないもの**
   - PNGとJPEG（中身で確かめる。拡張子は信じない）。1枚16MiBまで（表示の上限と同じ）。
   - それ以外（ほかの形式、大きすぎる、フォルダ、読めない）は取り込まず、最後に1行で数を知らせる（「3件を取り込みました。1件は画像として読めないため取り込んでいません」）。
   - 1回に取り込むのは64件まで。
   - リンクの先は辿らない: 落とされたファイルそのものがシンボリックリンクやジャンクションなら、取り込まない（ショートカットの`.lnk`は、中身が画像でないので取り込まれない）。親のフォルダがリンクであることは構わない（移したドキュメントのフォルダなど。利用者がそこを通って選んだ）。2026-11-22の補正: 最初は「既存の画像の読みと同じ守り」と書いていたが、表示の読みは親のフォルダも全部確かめる。落とす元はdataの外の好きな場所なので、同じにはしない。
5. **無題のノートでは取り込まない。** 1行で「名前を付けて保存してから、画像を落としてください」と知らせる。（hideの判断4。無題でも取り込む案は採らない）
   - 理由: 無題のノートは、初回保存のときにカテゴリを変えられる。先に`images/`へ写すと、別のカテゴリへ保存したときに画像のパスが切れる。下書きを捨てたときに画像だけが残る。
6. **貼り付け（Ctrl+V）は、今回は変えない。** クリップボードの画像やファイルの貼り付けは、要望が出たら同じ取り込みの道に足す。（hideの判断5）
7. **Undo**: 入れた文字はUndoで戻る。写した画像のファイルは、Undoしても消さない（上書きしていないので、残っても何も壊さない。消すのは利用者が決める）。
8. **既存の決まりを変えない所**
   - 画像を別のカテゴリへ動かす処理は足さない（ノートを別のカテゴリへ移しても画像は付いていかない、は今のまま。別のIssueで扱う）。
   - 入力中のパスを書き換えない・`images/`の外の画像を自動で動かさない、はそのまま。取り込むのは、利用者が落としたファイルだけ。
9. **層**
   - `ui/win32`: 本文の欄のサブクラス（`pane_procedure`）で`WM_DROPFILES`を直接受ける（`WS_EX_ACCEPTFILES`を付ける）。閲覧表示では`EN_DROPFILES`が来ないことを実験で確かめたので、知らせではなくメッセージを受け、編集表示と閲覧表示を同じ受け方に揃える。表示モードと無題の判定、文字の挿入、1行。
     エクスプローラからの本物のドラッグがこの道を通るかは、合成したメッセージでは確かめられない（RichEditは自分でOLEのドロップ先を登録している）。実装の後にhideに手で落としてもらい、来なければCOMのドロップ先（`RegisterDragDrop`、`OleInitialize`が要る）を実装する。
   - `application`: 取り込みの意図（落とされたファイルの一覧 → 写した結果と、入れるMarkdown）。結果は閉じた値。
   - `core`: 入れるMarkdownを作る純粋な関数（名前から代替の文とパス。山括弧が要るかの判定）、番号を付けた名前。
   - `adapters/win32`: ファイルを読む・`images/`へ写す新しいポートの関数（中身の確かめ、大きさの上限、同じ名前の照合、リンクを辿らない、作りかけを残さない＝一時ファイルから名前を付け替える）。ファイルに触るのはここだけ（ARC-007）。
10. **文書**: ADR0085の「自動移動/取り込みしない」に、この取り込みを例外として書き足す。SPECIFICATIONの「やらないこと」と`docs/MARKDOWN.md`の画像の節を直す。

## 理由

- 落としたファイルを写すだけで、原文や既存の画像には触れない。上書きしないので、取り込みで失うものが無い。
- `EN_DROPFILES`が使えれば、COMのドロップ先を自前で実装するより小さく、RichEditの文字のドラッグ（既存の動き）を変えない。使えるかどうかは未確認なので、段取りの最初に確かめる（どちらの受け方になっても、この文書のほかの決定は変わらない）。
- 無題と閲覧表示を断るのは、「どこに入ったか」「画像がどこにあるか」が後でずれる場合を作らないため。断るときは、次に何をすればよいかを1行で言う。

- **どのスレッドで走らせるか（2026-11-22、席の仮決め。hideには未確認）**: UIのスレッドで、入力待ちの回ごとに1件ずつ進める。workerは増やさず（C-013）、画像の読みのworkerとの受け渡しも足さない。
  - 引き継ぎに書いた3案（(a) そのまま同期・(b) 画像の読みのworker・(c) 1件ずつ）のうち、席の推しの(c)。hideが不在のあいだに進めるために席が決めた。hideが別の案を選んだら、段取りの4の「進める」の呼び方（窓の側）を替える。applicationの一連（始める・1件進める・結果・閉じる）は(a)でもそのまま使える。
  - 残ること: 1件のあいだは窓が止まる（1件は16MiBまで）。クラウドの置き場の未取得のファイルやネットワークの先では、その1件が長くなりうる。
