# ADR 0122: 左の欄の上の部分を、検索の枠1つと重ねて効く絞り込みの札に作り直す（段に分ける）

Status: accepted（1段目と、2段目の見出しの数の単位を実装。数の説明と読み上げ・札・解除・検索の範囲は未実装） / 2026-11-23 / Issue #1199（hideの判断: 2026-11-23「デザイン、今の案でいい」「並べるかな」「うん、それがいいかもね。」「左の欄の上の部分は、26で２行。よい。たりる。」）

## 背景

左の欄の上の部分（検索・すべて／お気に入り・タグで絞り込み・カテゴリの見出し）を、デザインとして詰める（#1199）。
14の配色の実物の絵を、ビジュアルの設計者とデスクトップGUIの操作の設計者の2つの席に見せて、いまの形を前提にせずに案を出してもらった。2人がそろって挙げた弱い所:

- 同じ形の箱が積まれていて、作る・探す・切り替える・絞るの違いが形に出ていない。
- いちばん目立つのが「すべて」の塗りで、強い色が「何も絞っていない」ことに使われている。
- 絞り込みが2つの別々の形（2択と釦）に分かれている。
- 畳む印（右の−）が、足す＋と対に見える。字の左端が2pxずれている（カテゴリ名は42、ノートの題は40）。

hideは、押して見比べる模式図（原本 D:/NeNeFolio/design/sidebar-header/index.html）から「詰めた案」を選び、実物の寸法で描いた絵（原本 D:/NeNeFolio/design/sidebar-header/real.html）を見て、残りを決めた。
絵は125%の拡大の画面の寸法で描いたので、絵の上の値は、ここでは96 DPIの論理pxへ直して書く（÷1.25）。

## 決定

### 目指す形（hideが決めたこと）

1. 枠を持つのは検索の欄だけ。その右に「新しいノート」の印を置く（名前とCtrl+Nは、マウスを載せたときの説明とメニューで伝える）。
2. 絞り込みは、重ねて効く同じ形の札（☆ お気に入り、# タグ ▾）。点いた札は、字の色・太さ・塗った星・✓で示し、強い色の塗りは使わない。
3. タグが複数のときは、タグごとに札を並べ、×で1つずつ外す。札の高さは21（絵の上の26）。2行を超えた分は「+N」の札にまとめる。
4. タグが2つ以上のときだけ「すべて含む／いずれか」を出し、「× 解除」と同じ1行に置く。絞り込みが効いていないときは、その行を出さない。
5. 高コントラストでは、点いた札を2pxの枠と太字で示す。
6. 検索の既定は全体。絞り込み中に検索しているあいだだけ「探す範囲 すべてのノート／絞り込みの中」を出す。
7. カテゴリの行の畳む印は、行の左の▾／▸にする。右の列は星だけに使う。

### 段の分け方

2段目で2択とタグの釦は札に置き換わるので、1段目では、2段目の後も残る所だけを直す。段ごとに、実窓の試験・変異・独立レビュー・必須CIを通す。

| 段 | 中身 | 改める決まり |
| --- | --- | --- |
| 1（このADRと同じ変更） | 決定7（畳む印を左へ）。ノートの題の左端を、カテゴリ名と同じ42にそろえる | ADR0033の決定3・6、ADR0015の決定7、ADR0091の決定1 |
| 2 | 決定1〜5（札・解除・「+N」・新しいノートの印の移動） | ADR0047、ADR0060、ADR0091の決定4・5 |
| 3 | 決定6（検索の範囲） | ADR0092（検索語と絞り込みはAND、の決まり） |

2段目・3段目の細かい決定（寸法・Tabの順・読み上げの木）は、その段の変更で、このADRに足す。

### 1段目で決めること

1. **畳む印の形**: `ICON_PAINT_FOLD_COLLAPSE`（開いている）は下向きの三角、`ICON_PAINT_FOLD_EXPAND`（畳んでいる）は右向きの三角。同じ三角を90°回した形で、24のviewBoxの中心のまわりに置く。「−」「＋」の板はやめる（ADR0033の決定3の、この2つの形を置き換える）。「新しいカテゴリ」の＋（`ICON_PAINT_ADD`）は変えない。
2. **畳む印の場所**: 箱は16の正方形で、カテゴリ行の左の余白（字下げ16）に置き、番号の左端で終わる（x = 0〜16。三角の見える幅は8）。行の縦の中央。色は`header_text`のまま（ADR0033の決定6の、折畳の箱 `[幅−16−24, 幅−16]` を置き換える）。
3. **右の列**: カテゴリ行の右の列には何も描かない。カーソルの角のxは、ノートの行と同じ 幅−52〜幅−46 のまま（ADR0015の決定7。式は変えない）。星の中心（幅−28）も変えない。
4. **ノートの題の左端**: 40から42へ（カテゴリの字下げ16＋番号から名前まで26）。カテゴリ名の左端と同じ式（別々に丸めた2つの和）で決めるので、どのDPIでも1pxもずれない。題の右端（幅−58）は変えない（ADR0091の決定1の、題の範囲の左端だけを改める）。
5. **カテゴリ名の右端**: 幅−32から、ノートの題と同じ幅−58へ。右の列が空いても、カーソルの角（幅−52〜幅−46）は残るので、長い名前が角の下へ入らないようにする（前は、長い名前の行にカーソルがあると、字の上に角が載った）。
6. **畳む・開くの操作は変えない**: カテゴリ行のどこを押しても畳む・開く（印だけの当たりは作らない）。キーボード・読み上げ（Expand/Collapse）も同じ。

### 2段目で決めること（決まった順に足す）

1. **見出しの行の数**（#1215）: 見出しの「カテゴリ」の右の数は、ノートの総数（絞り込み中は「該当 / 全体」）で、カテゴリの数ではない。模式図と絵は「カテゴリ 17」と見出しのすぐ隣に描いたが、隣に置くとカテゴリの数に読める。4つの案を、どれが席の案かを伏せて、ビジュアルの設計者とデスクトップGUIの操作の設計者の2つの席に見せた。ビジュアルの設計者は下の形を推し、GUIの操作の設計者は別の案（該当の数を解除の行に出す）を推したうえで、下の形も「それでよい。見過ごせない欠点は無い」と答えた。hideの指示（「専門家ペルソナに聞いてそれでいいならそれで。」）のとおり、下の形に決めた。
   - 数は「＋」の左（8空ける）に右寄せで、その左（6空ける）に単位を置く: ふだんは「ノート 17」、絞り込み中は「ノート 2 / 17」（英語 Notes、中国語 笔记。単位の文言は`UI_TEXT_STATUS_NOTE_UNIT`）。準備中の「準備中」は変えない。
   - 数は、細い等幅（Consolas 11。前のまま）。単位は、言語ごとのUIの書体の細字11。等幅の書体には仮名・漢字が無く、1つの書体で描くと、単位だけがOSの選ぶ代わりの書体になる（独立レビューが見つけた）ので、2つに分けて描く。見出しと同じ太字・字間にはしない。
   - 数に使える幅は、見出しの字の右（8空ける）から「＋」の左（8空ける）まで（下限は前と同じ64）。単位＋間＋数がその幅に入らないときは、単位を描かず、数だけ（前の形）を描く。
   - カテゴリの数は、見出しにマウスを載せたときの説明に出す（「カテゴリ 5 ・ ノート 17」。hide: 説明に出すだけで足りる）。読み上げでも、数は見出しと別の要素にする。この2つは、絞り込みの札で読み上げの木を作り直す変更に入れる（**未実装**）。

2. **札の並べ方**（#1220。中核の`chip_flow_arrange`。まだ左の欄からは呼んでいない）: 0番の札（お気に入り）、タグの札、「開く札」の順に、左から詰めて並べる。札の間と行の間を空け、入らなければ次の行の左端へ送る。使ってよい行の数（2）に入らないときは、後ろのタグの札から畳んで「+N」の札に置き換え、「+N」と「開く札」まで入る所で止める。0番の札と「開く札」は、行の数を超えても必ず置く。行より広い札は、行の幅に切る（描く側が省略する）。字の幅はWin32の側で測り、幅の配列で渡す。描画・当たり判定・読み上げは、この1つの結果を使う。

3. **解除の意図と、タグの条件の改訂の番号**（#1236。application。まだ左の欄からは呼んでいない）: 札の「× 解除」は、application の1つの意図`folio_state_clear_conditions`で行う。タグの条件を空にして「すべて含む」へ戻し、表示の範囲を「すべて」へ戻す。検索語は残す（タグの面の「すべての条件を解除」は検索語も消すので、別の意図）。タグの条件を外せなかったときは、範囲も変えずに、その結果を返す（UIで2つの意図を続けて呼ぶと、1つ目が失敗したときの半端な状態をUIが扱うことになる）。タグごとの札は、何番目の札がどのタグかを、`folio_state_tag_filter_revision`（タグの条件を持ち替える・捨てるたびに進む。非同期の失敗で application が自分で外したときも進む）で確かめる。見出しの列（#975）と同じ「種類1つ＋番号＋改訂」の方式。

4. **見出しの行の説明と、読み上げの数の要素**（#1238）: 見出しの行（「カテゴリ」の字の左端から、数の右端まで）に、説明（tooltip）「カテゴリ {k} ・ ノート {n}」を出す。同じ文を名前に持つ読み上げの要素（UIA の Text、`ACCESSIBLE_INDEX_COUNT`。フォーカスは取らない）を、左の欄の、タグの釦と「＋」の間に置く。数は application から取り、絞り込み中も全体の数。説明の文は、左の欄のほかの説明と同じ道（配置し直すときに写し直す）で新しくなる。別の写し直しは足さない（ノートを増やす実窓の試験で、足さなくても新しい数になることを確かめた）。

## 分かっていて残すこと

- 検索の欄の中の「Ctrl+Shift+F」は、1段目では残す。2段目で欄が狭くなると、いまの決まり（案内と並べて入るときだけ出す）で出なくなる幅が増えるので、そのときに扱いを決める。

## 検証

- 実窓の試験（`favorites_ui_native`の`fold_mark_pixels`・`note_title_edge`）: 開いたカテゴリ行の左の余白に横長の印があり、右の列（幅−40〜幅）は地の色だけ。畳むと同じ場所の印が縦長になり、開くと元に戻る。ノートの行は、x 41より左に何も描かず、41〜48に題の字がある。
- 絵（診断用の`--favorites-visual`）で、三角の向きと、題とカテゴリ名の左端がそろうことを席が見た。
