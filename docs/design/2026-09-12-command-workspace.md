## 配置

以下の px はすべて96 DPIの論理値。実フォントの高さ、最小窓、DPIの確認で調整し、その実測を採用ADRに残す。

| 部位 | 初期値と振る舞い |
| --- | --- |
| 窓 | 初期960×640、最小560×360。ドロワー240、既存の見出し帯44を維持 |
| 設定・閉じる | 右ペインの見出し帯で「閲覧・編集・設定・閉じる」の順。当たり24×24、線画16×16、間8、右余白16。絵文字を使わない |
| 幅の確保 | 閉じる・設定・札を確保し、残りを既存のパンくず計算へ渡す。描画・当たり判定・caption除外は同じ矩形 |
| Ex入力 | 窓の下端全幅、高さ26。本文と索引の矩形は動かさず重ねる。候補を出す場合は入力の上に積み、高さに収める |
| パレット | 幅 min(460, 窓幅−64)、水平方向中央、上から76。窓高480未満は上から40。入力40、候補行32、補助表示28を初期値とする |
| 検索 | 見出し帯の下に常設28pxの行を置く。INDEXの `/` でそこへ移る。機能を追加する #40 と同時に表示 |
| 原文行番号 | 編集時の本文左。論理行の先頭だけ番号を置き、桁数に応じて幅を計算する。#39で実測 |
| 置換 | 現在のノート名と一致件数、パターン・置換入力、行番号／前／後のプレビューを表示。本文をプレビュー用に装飾しない |

設定アイコンは #38、閉じるは #37で機能と同時に置く。`:help` は共通パレットで一覧を見せ、別のヘルプ窓を作らない。
パレットの行数は実際に使える領域から求める。「7行なら必ず収まる」などの未実測値を固定条件にしない。
設定画面には `settings.json` の版番号など実装情報を表示しない。表示言語は日本語・English・简体中文。

## 検索欄を常設する理由

デザインリナは、題字と検索欄を切り替える案Aと、常設行を足す案Bを比較した。設計サナは案Bを採用した。
入口が見えるため `/` を知らなくても使え、検索中も題字とノート件数が残る。索引の表示領域は28px減る。
レイアウトの `top_padding` を使って索引の座標・当たり判定・スクロール上限へ反映し、UIだけで行をずらさない。

## 相談で採用・不採用にしたこと

| 提案 | 設計サナの判断と理由 |
| --- | --- |
| 未保存 `:q` の拒否を入力面内へ表示 | 採用。モーダルを閉じる打鍵を挟まず次のコマンドを入力できる。理由文はapplicationの同じ結果から得る |
| ファイル・履歴・変換・確保の失敗をモーダルで示す | 既存 `failure_box` を維持する。入力面と本文を残し、保存失敗で終了しない |
| 取消・保存後に開く前のフォーカスへ戻す | 窓が残る操作で採用。終了成功後は戻さない。失敗時は入力面を保持する |
| `:q!` の前に既存 `archive_note` を呼ぶ | 不採用。既存処理が写すのはディスク本文であり、破棄する未保存本文は保護できない。下書き復旧を入れるなら別の契約が要る |
| `:q!` に追加確認を付ける | 初版では不採用。明示的な強制終了コマンドとし、パレットは「未保存変更を破棄して終了」と表示する |
| 置換プレビューを本文の色で示す | 不採用。RichEditの平文やUndoにプレビュー用の書式を混ぜず、前後の一覧を別に表示する |

ノート例は架空の内容で、hideの実際のmdは使用していない。

ChromeでローカルHTMLを開く操作はBrowser URL policy、ローカルHTTP previewの起動は自動承認に拒否された。

別surface、raw CDP、新しいproxy等で迂回していない。**Chromeの目視確認は未実施**であり、公開可否の回答後に扱う。

バイナリ6件とライセンス2件のサイズ・SHA-256一致を確認した。フォント合計27,028,564 bytes。
取得物は `out/fonts/2026-09-12/` にある。製品への登録・同梱・実フォントの表示検証は #42 の未完了事項。
