## 役割と運用

- 設計・判断・ADR・レビュー依頼・統合は設計リナ（Fable）。実装・調査・テスト・読み取り専用レビューはOpusの実装リナを背景で立ち上げ、報告で詰める。
  各PRは「実装 → 別のOpusの読み取り専用レビュー → 止める所見を同じPRで修正 → 最終SHAでフルゲート → Ready → CI → squash merge」の順。
- CIは`ready_for_review` / `synchronize` / `edited` / `reopened`でだけ走る。GitHubがイベントを落としたら`gh pr ready --undo`→`gh pr ready`で再発火する。
- mainを作業枝へ取り込むmergeの件名は`chore(sync): … (#N)`（GIT-003）。既定の`Merge branch`件名は`validate-git`で落ちる。
