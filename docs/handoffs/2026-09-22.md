### 役割と運用（本日の追加）

- 各PRは「実測probe → ADR草案 → 現行コードに照らした読み取り専用の批評 → 受理してコミット → 実装（層ごとにコミット）→ 別のOpusの読み取り専用レビュー → 止める所見を同じPRで修正 → 最終SHAでフルゲート → Ready → CI → squash merge」。
  批評は#41で実装不能な決定を2つ（`:%s`の解析・入力面の欄の数）見つけた。省かない。
- 関数の引数は4つまで（C-012・`.clang-tidy`の`ParameterThreshold: 4`）。ADRの署名を書く段階で束ねる型（`*_request` / `*_query`）を決める。
- `folio_state_outcome`に値を足すコミットでは、同じコミットで `src/application/folio_state.c` の `failure_lines[]` と `tests/unit/state_tests.c` の期待表にも足す（CNF-009が即落ちる）。
  「2つ目のswitchへ寄せる」という過去の注記は#65で無効になった。
- OS同梱のDLL（user32・gdi32・icu…）は `eng/architecture.json` の `platformLibraries` が正本で、`runtimeDependencies`（第三者の配布物）には書かない。
- 実装リナを区切りで止めるときは、同じagentへ「未コミットを事実の範囲でコミット → 狭い検査 → 最終HEADで1回だけゲート → push → どこまで済んだかをファイル名・関数名で報告」を送る。
- CIは`ready_for_review` / `synchronize` / `edited` / `reopened`でだけ走る。PR本文はGIT-004の字面どおりのフィールド行。mainを作業枝へ取り込むmergeの件名は`chore(sync): … (#N)`。
