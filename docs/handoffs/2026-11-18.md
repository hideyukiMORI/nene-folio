## 運用の知見（今回）

- 手元の確認に`eng/symbols.py --build-dir … --require core application`を入れる（coreへ新しいCの関数を足すと必須CIで落ちる。許可の一覧は`eng/symbol-allowlist.json`）。
- 窓の大きさに依る試験は、手元（120 DPI）とCI（96 DPI）で幾何が違う。`SetThreadDpiAwarenessContext(DPI_AWARENESS_CONTEXT_UNAWARE)`の変種を足して両方流す（#839・#933）。
- 96 DPIでは丸めが起きない欠陥（#936）はCIで検出できない。手元の試験と変異で確かめる。
- 端末のCPUが100%のときはnativeの試験が10倍以上遅くなり、CTestの30秒の上限に掛かる。変更前の構築と同じ負荷で比べる。`code_copy_scroll`の2件は普段でも7〜13秒で上限に近い。
- mainの取り込みのcommitの件名は`chore(scope): mainの#Nを取り込む (#M)`。
- 日本語・引用符・backslashを含む置き換えは、Writeで作ったPythonのscriptで行う（Bashのheredocは崩れる）。
- 統合の手順がReadyにした後で直すときは、先に`gh pr ready N --undo`でDraftへ戻してからpushする。
- 開く・選ぶのように複数の試験が使う入口を変えたら、名前で絞らず全CTestを流す（#940で`motion_native`を落とした）。全CTestは他の重い構築と同時に流さない。
- nativeの試験の見本（実行ファイルの隣の`data`）は、同じ実行ファイルの他の試験と共有で、回をまたいで残る。見本を足す試験は専用のカテゴリへ入れて最後に消し、同じフォルダーを使う他の試験を続けて流して確かめる（#928）。
- 独立レビューには「自分の試験が、言っているとおりのことを確かめているか」も見てもらう（#945で試験が欠陥を隠していた）。
- 必須CIが無関係の試験の打ち切りで落ちたときは、上限を変えず、調べたことを品質記録へ足したheadで流し直す（#928）。
