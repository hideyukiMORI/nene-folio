## 運用の知見（今回）

- `eng/coverage.py`は引数を受けず、`--help`でも測定が走る。測る作業木から、`. eng/toolchain.ps1`の後で実行する（メモリ`coverage-script-takes-no-args`）。
- 置き換えのスクリプトはclang-formatの後の文字列に当てる。途中で止まると前の置き換えは書き込み済みなので、`git diff --stat`で確かめてから続きを当てる。
- 試験が時間切れになったら、変更前の構築と交互に同じ時間帯で流して比べる（1回ずつでは負荷が変わって比較にならなかった）。
- 統合は本体のcheckout（main）から`tools/merge-pr.ps1`を流すと、統合後にmainもff-onlyで進む。`-Subject`（squashの件名）が要る。
- 必須CIで、試験の本体が走る前にAddressSanitizerの初期化のCHECK（`real_memcpy`）で落ちたことが1回ある（PR1053、run 44500351904、`first_save_native`、0.01秒）。同じheadの流し直し（`gh run rerun <id> --failed`の後に統合の道具をもう一度）で通った。原因は未調査。2回目が起きたら調べる。
- 位置や数え方を変える変更では、その値を使って決まるもの（図の幅など）も試験にし、描いた絵も見る（#1036→#1044の退行）。
- 指示語を足すときは、その語で始まる作業の行をMermaidがどう読むかを先に確かめる（#1030→#1032）。
- 小さい修正でも、統合の前に読み取り専用の独立レビューを通す。11月19日にレビューを省いて統合したもの（#1030・#1026・#1040）は、すべて後のレビューで欠陥が見つかった（#1032・#1056で修正）。
- 試験の出力を読む前に、構築が通ったことを確かめる。構築が落ちると古い実行ファイルがそのまま走る（#1056で2回）。
- 見出しの欄の「押した見出しを覚える」仕組み（#1040・#1056）は、最後の見出しが本文の先頭まで上がりきれないときだけ働く。試験では低い窓（本文の高さ200）で起き、高い窓では起きない。理由（RichEditの送りの上限）は未調査。
