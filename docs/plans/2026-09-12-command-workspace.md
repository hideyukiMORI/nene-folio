## 2. 共通の操作契約

Ex 入力・パレット・アイコン・既存ショートカットは同じ操作識別子に変換し、一つの実行経路へ渡す（ARC-001 / ARC-011）。
入力の解析は core の純関数、状態と可否の判断は application、編集本文の取得と Win32 の反映は UI。
登録した操作に翻訳可能な表示名・説明・入力別名を結び、パレット専用の保存実装を作らない。

| 操作 | 初版の意味 |
| --- | --- |
| INDEX の `:` | コマンド入力を開く。ノート本文への文字入力とは区別する |
| Ctrl+P | 索引・本文・検索・コマンド入力から共通パレット。設定モーダル内の扱いは設定 ADR で固定する |
| `:w` / `:write` | 現在の本文を既存の保存経路で保存。モードを維持。未選択なら理由を表示 |
| `:q` / `:quit` | 保存済みなら終了。未保存変更があれば終了せず理由を表示 |
| `:wq` / `:x` | 保存できた場合だけ終了。同じ本文なら履歴・md とも書かない |
| `:q!` | 現在の未保存変更を破棄して終了。既に自動保存された本文を過去へ戻す操作ではない |
| 閉じるアイコン / Alt+F4 | 既存どおり保存して終了。`:wq` の操作へ合流させる |
| `:help` | 現在実装されているコマンドと別名を登録表から表示 |
| `:set number` / `:set nu` | #39 で実装する原文行番号を表示。`nonumber` / `nonu` で非表示 |
| `/` | INDEX から全文検索の入力へ移る（#40） |

パレットの「終了」と「保存して終了」と「未保存変更を破棄して終了」は名前で区別する。
未知のコマンド・余計な引数・不正な入力は可視の失敗とし、成功したように入力を消さない。
コマンド文字列とユーザーの md / ファイル名は表示言語を変えても変更しない。

## 3. フォーカスと本文の保護

Win32 の実フォーカスを正本にする（ADR 0013）。application に HWND と競合するフォーカス状態を持たせない。
入力面には一時的な UI 状態として用途と戻り先を持てるが、ノート選択・モード・検索語・設定を二重に所有しない。

- コマンド／パレットを開くだけでは自動保存しない。編集中の RichEdit を再生成・再流し込みせず、本文・Undo・キャレット・モードを保つ。
- `j` / `k` / `:` / `/` は INDEX の操作。検索・コマンド・本文の入力へ紛れ込ませない。IME の未確定文字を確定済み文字として扱わない。
- Esc は入力面を閉じ、設計された戻り先へ移る。既存の本文 Esc の保存と INDEX 復帰は維持する。
- 保存の要否は正規化後の本文比較から求める。独立した dirty flag を application に足さない（ARC-004）。
- 保存・履歴・文字変換・確保に失敗したら終了も選択変更も進めず、本文を残す。保存に失敗した `:wq` が閉じる経路を作らない。
- `:q!` と通常の×を混同させない。通常終了の既存自動保存は勝手に破棄へ変えない。

## 4. 設定・テーマ・言語・フォント

設定の保存候補は `data/settings.json` の版 1。`theme`（system / light / dark）、`language`（ja / en / zh-Hans）、
`number`（初期値 false）を application が一つの値として所有する。最終スキーマと移行は #38 の ADR で固定する。
ファイル未存在だけを初期値として扱い、破損・未知版・不正値・書き込み失敗を黙って既定値へ落とさない（ARC-009）。
初期言語は日本語、初期テーマは OS に従う。OS のロケールを中核から読む処理は増やさない。

テーマは既存の `folio_palette` と `rtf_palette` の役割を維持し、OS 読取は `appearance_adapter` に閉じる。
切替時に編集中の本文へ RTF を流して変更を失わせない。設定・パレット・失敗表示まで全3言語で揃え、
翻訳キーの欠落・重複と未翻訳の自前 UI 文字列を検査する。OS の色選択など OS 所有のダイアログは OS の言語に従う。

Ubuntu の [公式配色](https://design.ubuntu.com/brand/colour-palette) の orange `#E95420` と aubergine を参考にする。
本文の地を強いオレンジにせず、選択やフォーカスの印に使う。ブランドロゴや Ubuntu の画面そのものを複製する計画ではない。

フォント候補は **Noto Sans JP / Noto Sans SC / Arimo**。[Arimo の公式説明](https://github.com/google/fonts/blob/main/ofl/arimo/DESCRIPTION.en_us.html) は
Arial とのメトリック互換を明記している。Google Fonts とそこから参照される公式上流から固定版を取得し、
元ファイル・revision・サイズ・SHA-256・ライセンスの一つの資産台帳を持つ。Google Fonts 掲載の可変版だけでなく
同じ公式上流の静的 Regular / Bold を比較し、GDI / RichEdit の実測で選ぶ。
JP / SC は同じ漢字でも字形が異なるので表示言語に応じた CJK フォントと欧文混植を確認する。
OS へのインストールはせず、プロセス内の private font 登録を使用する。登録・解除の所有者は一つにする。
同梱資産の欠損・破損・登録失敗を黙って代替フォントで隠さない。フォント単体の配布条件とライセンス本文も検査する。

## 5. 検索と置換の境界

全文検索は FR-011 の既定である大文字小文字を区別しない部分一致。検索方式を変える条件は速度の実測であり、
方式そのものを未定として扱わない。Unicode の比較規則と性能の受け入れ値は #40 の ADR に記録する。
起動時に保存済み本文をメモリへ載せ、保存が成功したノートだけを差分更新する。検索語の入力だけで md や台帳を書かない。
非一致になった選択中の本文を閉じず、入力中に保存やノート切替を発生させない。
フィルタ中の空カテゴリ・折り畳み・カーソル補正を明示し、初版は絞り込み中の並び替えとカテゴリ間移動を停止する。
空の検索語で元の台帳順へ戻す。絞り込んだ順番を本来の台帳番号として書き戻さない。

正規表現置換は**現在開いている md の現在の編集本文だけ**を対象にする。検索結果全部への一括置換はしない。
適用前に対象名と一致件数を示す。プレビュー後に本文や選択が変わったら、そのまま適用しない。
置換は一つの Undo 単位で編集本文へ反映し、ディスクへの保存は既存の履歴 → 原子的な書き戻しへ渡す。
正規表現エンジン、Unicode、捕捉参照、ゼロ幅一致、改行、実行・出力量の上限、基本 Ex 置換構文は #41 の実測と ADR で固定する。
背景スレッドを追加することや、検査対象を除外することで実装を通すことは前提にしない（C-013 / QLT-010）。

## 6. 検証と完了の境界

各実装 Issue で、純関数と状態遷移の単体・確保失敗・保存失敗を狭く検査する。閉じた操作集合の分岐は網羅し、
分岐 90% の下限を維持する（C-002 / QLT-009）。同じ操作を各入口から呼んだ結果が一致することも検証する。
設定は版と round-trip、翻訳は全キー、資産は hash / ライセンス / package 一覧を確認する。
Chrome のプロトタイプ確認は設計の証拠であり、Win32 製品が動くことの証拠にはしない（QLT-013）。

Win32 では 560×360（96 DPI 相当）・120 / 144 DPI 以上、英日中、ライト／ダーク、IME、本文編集中、
フォーカス復帰、長い翻訳、番号と本文のスクロール同期、×と `:q` の失敗時の動作を確認する。
hide の実機データ `out/hide/` は検証用に流用しない。

PR は Draft の間に狭い検査を行い、Ready の直前に次の唯一のフルゲートを実行する。

```powershell
pwsh -NoProfile -File ./eng/check.ps1
```
