## 1. hideが採用した方針

2026-09-13、hideは「`?`を後方検索へ揃え、ヘルプには画面上の『ヘルプ』とF1を用意する」案を明示採用した。
日本語のボタンとメニューを主入口とし、ショートカットは補助として見せる。VimやIDEの知識を操作の前提にしない。

- GUIだけで新規・開く・編集・閲覧・保存・別名保存・改名・検索・置換・設定・ヘルプへ辿り着く。
- 通常画面の入口を「＋」「…」や右クリックだけにしない。「新しいノート」「保存」「操作」「ヘルプ」など、読んで意味が分かるラベルを使う。
- メニュー・ヘルプ・パレット・Ex・キーは同じ操作定義と実行経路を使う。UIの入口が増えても意味を複製しない。
- ヘルプは画面の「ヘルプ」、F1、`:help`、`:h`から開く。現在の共通パレットを使い、別のヘルプ用コマンド集合を作らない。
- 未実装の操作は登録せず、未選択など一時的に使えない操作には理由を示す。

Vimの`?`は置換ではなく後方検索で、`n`は直前の方向、`N`はその逆である。
[Vim公式の検索ヘルプ](https://vimhelp.org/pattern.txt.html#%3F)と
[ヘルプの入口](https://vimhelp.org/helphelp.txt.html#%3Ahelp)を確認した。

## 2. 検索対象とキー

前日の#40は全ノート本文による索引の絞り込みであり、ノート内の一致箇所への移動とは別の操作である。
設計サナは、方向を持つ`/`と`?`を現在表示中のノート内検索に揃える。
**旧計画の「INDEXの`/`は全ノート検索」は、この計画で変更する。**

| 対象・操作 | 日本語GUI | キー |
| --- | --- | --- |
| 全ノート本文で索引を絞る（#40） | ドロワー「すべてのノートを検索」 | Ctrl+Shift+F |
| 現在表示中のノート内を検索 | 「このノート内を検索」 | Ctrl+F |
| 次方向の語を入力する | ノート内検索欄・「次へ」 | INDEX／閲覧本文の`/` |
| 前方向の語を入力する | 同じ欄・「前へ」 | INDEX／閲覧本文の`?` |
| 次の一致へ／前の一致へ | 「次へ」／「前へ」 | F3／Shift+F3 |
| 直前と同じ方向／逆方向に繰り返す | 上記の方向ボタンと同じ検索処理 | INDEX／閲覧本文の`n`／`N` |

INDEXの対象は現在表示中のノート。カーソルがカテゴリ行でも表示ノートを勝手に切り替えない。
ノート未選択なら選択を案内する。`?`を一覧の逆順表示、無反応、別のヘルプとして残す設計にはしない。
編集中の本文、検索・名前・コマンドの入力欄では`/`・`?`・`i`・`n`・`:`など通常の文字を奪わない。
ショートカットはIMEの未確定入力も保護する。

全ノート検索語とノート内検索語は別の目的を持ち、applicationがそれぞれ一つずつ所有する。
ノート内検索だけで左の一覧を絞り直さない。全ノート検索の語をノート内へ初期値として渡す場合も、
後の編集を強制同期しない。これは同じ値を二重所有する設計ではない。
SPECIFICATIONの旧「検索語一つ」は#40の絞り込みの所有者として範囲を明記し、新ADRでノート内検索を拡張する。

ノート内検索は現在表示中の内容を対象にする。編集中のCtrl+Fでは未保存本文も検索対象とし、
保存・本文の再生成・Undo破壊を起こさない。閲覧表示と原文の位置対応、一致範囲、折り返し、Unicodeの比較、
検索の巡回と端の通知は実装IssueのADRと試験で固定する。#41の置換は現在mdの編集本文だけという既存の境界を保つ。

### 移行順

GUI「ヘルプ」・F1・`:h`を先に用意する。旧`?`ヘルプを削る変更は、実際に動くノート内後方検索と同じ実装単位にする。
その単位で操作表・共通ヘルプ・旧計画の参照・テストを更新する。検索未実装の間に成功するふりの入口は置かない。
現時点のPR #44/#46はINDEXの`?`がヘルプで、この新計画が実装済みという意味ではない。

## 3. 閲覧からコマンドと編集へ

- INDEXと閲覧状態のプレビューペインで`:`を押すと同じコマンド入力を開く。Escは開く前のフォーカスと閲覧位置へ戻る。
- INDEXまたは閲覧本文の`i`、GUI「編集」、`:startinsert`は現在ノートを編集モードにし、本文へフォーカスする。
- Vimの`:e`／`:edit`はファイルを開く・読み直す操作なので、編集開始に流用しない。今回`:e`自体の実装は範囲外。
- 入力面を開閉するだけで本文を書き戻さず、Undo・キャレット・モードを保つ。既存の本文Escによる保存とINDEX復帰は維持する。

## 4. ノートの作成・保存・名前

| 操作 | GUI | キー・コマンド | 結果 |
| --- | --- | --- | --- |
| 新規 | 新しいノート | Ctrl+N／`:enew` | 現在カテゴリの無題を同じペインで編集。先に本文を書ける |
| 保存 | 保存 | Ctrl+S／`:w`／`:write` | 名前のあるノートは既存経路。無題は名前と保存先カテゴリを入力 |
| 初回の名前指定 | 名前をつけて保存 | `:w 名前` | 現在カテゴリに保存し、索引とパンくずに反映 |
| 別名保存 | 別名で保存 | Ctrl+Shift+S／`:saveas 名前` | 現在の編集内容を新しいノートへ保存し、そちらを開く |
| 改名 | 名前を変更 | F2／`:rename 名前` | 未保存なら保存成功後にmd・索引・パンくず・履歴を追随 |

`.md`は補完し、日本語と空白を許す。同名を上書きしない。保存先を表示し、名前の不正・同名・保存失敗でも入力を残す。
Windowsの予約名・区切り・制御文字・末尾の空白やピリオド・大小文字だけの衝突・長さは、既存の名前型とアダプタ境界を調べて定義する。
初版では名前のあるノートに対する`:w 別名`は拒否し、`:saveas`／`:rename`を案内する。

**別名保存は、元のノートに現在の編集内容を先に自動保存しない。** 元ファイルとその履歴は最後の保存状態を保つ。
新ノート作成後の保存で、そのノート自身の履歴を積む。改名と別名保存を同じ意味にしない。

無題のまま選択変更・新規作成・終了する場合も保存と取消で本文を守る。取消なら無題へ戻り、失敗なら切替・終了を進めない。
通常の×・Alt+F4は保存して終了。明示的な破棄は通常終了と分離する。GUIでも共通パレットを開く「すべての操作」から
保存済みなら終了する`:q`を含め全操作へ到達できるようにする。

無題の所有者と切替待ちの意図は新ADRで定義する。フォーカスをapplicationに複製せず、保存の要否は既存の本文比較を使う。
改名で履歴だけが追随しなかった場合を成功にしない。md・索引・履歴の部分失敗、永続的な復旧情報、再起動後の再開可能性を
設計してから実装する。ADR0012のカテゴリ移動時に履歴を追随しない旧決定は書き換えず、改名の契約を後継ADRで追加する。

## 5. 実装単位と検証

| 単位 | 主な成果 | 先に決めること |
| --- | --- | --- |
| GUI入口・閲覧操作 | 日本語の操作メニュー、ヘルプとF1・`:h`、閲覧本文の`:`、編集開始 | ADR0016の入口・表示契約の後継、最小窓と増加する候補の高さ・スクロール |

| 別名保存・改名 | 保存先の意味を分け、元本文と履歴を保護 | 履歴追随と復旧の後継ADR |
| ノート内検索とキー移行 | `/`・`?`・`n`・`N`とGUIの前後検索 | #40と区別した対象・状態・位置対応・IME・検索語の独立性 |

入口の違いで操作の結果が変わらないこと、取消・保存失敗・名前衝突で本文を失わないこと、IMEとUndo・フォーカス復帰を検証する。
最小560×360、長い名前・翻訳、高DPI、両テーマで日本語の入口が読めることを確認する。
