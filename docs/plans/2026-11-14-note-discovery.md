# お気に入り・タグ・検索プレビューの仕様案

2026-11-14 / [Issue #811](https://github.com/hideyukiMORI/nene-folio/issues/811)

状態: 段階1のお気に入りは#813で実装し、[ADR0090](../adr/0090-note-favorites-and-display-order.md)と正本仕様へ移した。タグ・検索プレビュー・演出は仕様案。本書は採用を示すADRではない。
優先順位と他の候補は[ロードマップ](../ROADMAP.md)、現在の動作は[仕様](../../SPECIFICATION.md)に従う。

## 1. hideの指定と今回の境界

hideが希望したのは、星によるお気に入り優先表示、タグの作成/付与/管理/フィルター、
fzf/Telescopeのようなlive grep・ファイル検索・プレビューにサイバーなアニメーションを組み合わせる機能。
追加の選択で、タグはMarkdown内のfront matterへ保存し、検索はまずFolio内の全ノートを対象とすることが決まった。
最初の依頼はロードマップと仕様の整理まで。その後hideが「対応を始めて」と指示し、先頭のお気に入りへ着手した。以下のタグ以降の操作・段階は推奨案で、実装順と公開日は未確定。

## 2. 利用の流れ

1. よく使うノートの星を付ける。通常の一覧で先に見え、「お気に入りだけ」でも探せる。
2. ノートへ「設計」「仕事」等のタグを付ける。カテゴリをまたいで同じ話題をまとめて探せる。
3. 「ノートを探す」を開き、名前をあいまい検索するか、本文を入力しながら検索する。
4. 候補を上下に動かすと、そのノートや一致行をプレビューする。Enterで開き、Escで元の文書へ戻る。
5. 星・タグ・カテゴリの条件を組み合わせ、結果の対象を狭める。

名前のあいまい検索と本文のlive grepは明示したモードとして分ける。
あいまい検索は文字が連続していなくても名前を見つける機能、live grepは入力のたびに本文の一致を更新する機能。
初期の本文検索は現在の全ノート検索と同じ部分一致を基準にし、正規表現や曖昧な本文一致を暗黙に加えない。

## 3. お気に入り

この節は計画時の案。実装#813の確定契約は[仕様 FR-044](../../SPECIFICATION.md)と[操作案内](../KEY_BINDINGS.md#お気に入り)に従う。
台帳版2・設定版6、星を失わないカテゴリ移動の保存順、星が無いカテゴリでは従来どおり移動できる条件をADR0090へ定めた。

| 項目 | 提案する動作 |
| --- | --- |
| 対象 | 保存済みノート。カテゴリへの星と無題への星は初期範囲に含めない |
| 操作 | 一覧行の星、ノート操作メニュー、共通コマンドから同じ付け外しへ渡す。状態はUIAでも読める |
| 通常の一覧 | 「お気に入りを優先」を既定ONとする案。カテゴリの順は維持し、各カテゴリ内で星ありを先へ、その中では元の手動順を保つ |
| 解除 | 優先表示をOFFにすると元の手動順へ戻る。表示の優先度を変えるために保存された順序を書き換えない |
| 星だけの一覧 | 全カテゴリを対象とする「お気に入りだけ」のフィルター。別のノート実体や複製した一覧台帳を作らない |
| 並べ替え | 優先表示中のドラッグは無効にし、手動順を変えるには優先表示をOFFにする。既存の検索中ドラッグ禁止とも整合させる |
| 保存 | 本文のfront matterには入れず、アプリのノート管理情報へ保存する案。既存index.jsonの拡張を第一候補とし、版・移行・失敗復旧は先行ADRで定める |
| 本文への影響 | 星の付け外しだけではMarkdown・本文のUndo・本文履歴・未保存印を変更しない。管理情報の保存成功後に表示へ確定する |

星ありを一覧上部へ二重掲載する方式は初期案に含めない。全カテゴリ横断で見る場合は星だけのフィルターを使う。
改名・カテゴリ移動後も星を同じノートへ引き継ぐ。削除時は管理情報も除き、失敗時は変更前を保持する。
別名保存した新ノートと新規取り込みノートは星なしとする案。既存ノートを開き直すことでは星を変えない。
Markdown単票や現在のZIP書き出しへ個人の星を混ぜない。星を含むバックアップが必要なら別の契約として決める。

## 4. タグとfront matter

タグの正本はノートのMarkdown。外へ持ち出しても残り、外部で編集して再読込した内容を採用できる。
一覧や検索用のタグ集合はそこから導出し、JSON側にも独立した正本を持たせない。

次は推奨する表現例で、採用する構文の正確な集合は先行ADRで決める。

```markdown
---
tags:
  - "設計"
  - "Mermaid"
---

# 図の描き方
```

| 項目 | 提案する動作 |
| --- | --- |
| 付与 | ノートのタグ欄へ入力し、既存タグの候補から選ぶか、その場で新しいタグを作って付ける |
| 複数タグ | 1ノートへ複数付与できる。タグの表示要素から解除する。日本語・空白を含むタグ名も扱う |
| 同一性 | 前後の空白を除き、空名・制御文字を拒否する案。大文字小文字、Unicode正規化、文字数/件数上限は保存契約で確定する |
| タグ一覧 | 現在の保存済みノートから名前と使用ノート数を導出する。使われていないタグだけを保存する別台帳は初期案に含めない |
| 管理 | タグを選ぶと該当ノートを表示。全体の改名・削除は対象件数を示す操作として段階2bへ分ける |
| フィルター | 初期値は選択した全タグを含むAND。複数タグのいずれかを含むORへ明示的に切り替えられる案 |
| 組合せ | タグ条件、カテゴリ条件、星条件、検索語はANDで組み合わせる。各条件を画面に表示し、個別解除と全解除を用意する |
| 表示 | 閲覧では対応front matterを本文の見出し/水平線として描かず、タグ欄へ投影する案。編集では元のMarkdownを編集できる |

GUIでのタグ変更もMarkdownの変更として、既存の編集・Undo/Redo・履歴・保存経路を使う。
編集中は現在の未保存バッファへ変更を適用し、保存済み本文を読み直して上書きしない。
閲覧時の変更は同じ編集操作と保存を通し、保存失敗を成功表示へ変えない。変更のない付与/解除では書かない。
全ノートの絞り込みは保存済みタグを使い、検索へ移る際の保存は既存の名前付きEDITの共通保存と整合させる。

既存front matterの未知のキー・値、本文、改行、引用の表現を勝手に整形しない。
未対応のYAML表現や壊れたfront matterはそのまま保持し、タグ編集を理由付きで断る。既存領域を消して作り直さない。
先頭の水平線やsetext見出しを誤ってメタデータにしないため、開始/終了位置・認識条件・対応外の扱いを先に定義する。
`tags`だけを書き換える位置対応、未知フィールドの保持、手入力とGUI入力の一致には一つの解析経路を用いる。
一般的なYAML parserの導入・全YAML互換はここでは決定しない。

タグの全体改名/削除は複数ファイルへ影響する。開いている未保存ノート、途中I/O失敗、外部変更、衝突を含む
処理単位と再開方法を先行ADRで定めてから段階2bを実装する。一部成功を全件成功として扱わない。
削除するのは指定タグであり、ノート本体ではない。

## 5. 検索・live grep・プレビュー

最初は現在の保存先rootにあるFolio管理の全カテゴリ・全ノートを対象とする。
任意フォルダーの追加、汎用ファイラーのコピー/削除/端末起動は初期範囲に含めない。

| 部分 | 提案する動作 |
| --- | --- |
| 入口 | 共通コマンド「ノートを探す」から開く。一覧の検索から同じ面へ展開する入口も検討する。既存のCtrl+P・Ctrl+Shift+F等は上書きせず、新規キーは実装前に操作表と照合する |
| 名前モード | ノート名とカテゴリ名を対象にあいまい検索。完全一致、前方一致、その他の一致度で順位を付け、同点は安定した既存順にする案 |
| 本文モード | 入力のたびに保存済み本文を部分一致検索。一致行・前後の文脈・ノート名・カテゴリを結果へ表示。ASCII大小無視という既存契約を継承する |
| 条件 | カテゴリ・タグ・星のフィルターを両モードで共有。お気に入り優先ONなら一致した星ありの群を先にし、群内で各モードの順位を使う |
| 空語 | 対象条件に合うノート一覧を表示する。本文のすべての空位置を一致結果として展開しない |
| 候補移動 | 上下キー・クリックでプレビュー対象を変更。移動だけで現在の編集ノートを開き直したり、本文を置き換えたりしない |
| プレビュー | 初期は読み取り専用のMarkdown原文。行番号、前後の文脈、一致箇所の強調を表示する。本文の一致行へ直接位置を合わせる |
| 確定 | Enterまたは明示した「開く」で既存のノート選択経路へ渡す。本文検索では編集モードの一致行を開く案とし、原文位置を閲覧後の座標へ流用しない |
| 戻る | Escで閉じ、元の文書・選択・スクロール・未保存内容へ戻る。検索画面の入口で成功した既存の保存は巻き戻さない |
| IME | 未確定文字列は検索語として採用せず、変換確定後に更新する。変換中のEnter/Escを候補確定/閉じるへ横取りしない |
| エラー | 0件、読めないノート、検索準備中、プレビュー読込失敗を区別する。読めないノートがある場合は不完全な結果であることを示す |

名前検索のあいまい一致を、既存の一覧部分一致へ黙って適用しない。既存モードと新モードの意味を明示する。
本文検索は保存されたMarkdown原文を対象とし、front matterやコード内の文字も含める案。
タグの一致だけを探す場合はタグフィルターを使い、本文一致とタグ一致を同じ意味にしない。
本文の一致判定は[ADR0073](../adr/0073-bounded-index-matching.md)の単一engineを拡張する経路から設計し、
検索面だけに独立した全文matcherや本文台帳を作らない。一致行情報の追加と既存filterへの投影は先行ADRで定める。

検索語、条件、対象の保存内容、候補選択が変わったら古い計算・プレビューを取り消す。
古い結果で新しい語の画面を上書きせず、部分結果は完了件数として表示しない。
保存済みの本文を使う既存契約を保ち、名前付きEDITからの移動時は共通保存が成功してから検索を始める。
無題は保存を強要せず対象外。新しいworkerや外部検索プロセスの採用をこの案だけで決めない。

読み取り専用のプレビューは選択中の保存済み内容から派生させ、編集本文の別の正本にしない。
大きいノートは範囲を制限したプレビューであることを示す。検索結果と表示原文の版が違えば再取得し、古い一致位置を使わない。
ファイルの再読込時点・外部変更の検出・結果件数とメモリの上限は実装前に決める。
Markdownとしての閲覧プレビューは後続段階。採用時は既存rendererを使い、画像/図・座標変換の契約を別途定める。
原文のプレビューだけで外部画像を取得したり、リンクやコードを実行したりしない。

画面は上に入力と条件、左に結果、右にプレビューを置く案。狭い幅では結果/プレビューの切替にする。
ノート名・カテゴリ・星・タグ・一致行を読める密度に保ち、選択状態を色だけで示さない。

## 6. サイバーなアニメーション

テーマのアクセント色による細い発光枠、選択位置の短い移動、開閉の短いフェードを基本案とする。
処理中は小さな走査光やパルスで更新中を示し、検索が終われば止める。架空の完了率を表示しない。
120〜180ms程度を演出の初期調整案とし、性能の達成値や入力待ち時間としては使わない。

キー入力・候補選択・結果更新は即時に処理し、演出の終了を待たせない。連打では古い演出を打ち切って最新状態へ追従する。
文字を一文字ずつ出す演出、結果の全文が動く演出、常時点滅する背景は初期案に含めない。
明暗のテーマに合わせ、OSの動きを減らす設定とアプリ内の演出OFFに対応する案。
高コントラスト時は装飾を減らし、静止状態だけでも処理中・選択・失敗を判断できるようにする。
時計やOS設定はadapterから取得し、coreの検索判断へ時間依存を入れない。

## 7. 保存と持ち出しの境界

| 操作 | お気に入りの案 | タグの案 |
| --- | --- | --- |
| 再起動 | 管理情報から復元 | 保存済みMarkdownから復元 |
| ノート改名・カテゴリ移動 | 同じノートに引き継ぐ | Markdownと一緒に移る |
| 別名保存 | 新しいノートは星なし | コピーしたMarkdownのタグを維持 |
| 単票/ZIP書き出し・取り込み | 現行のMarkdown中心の転送では星を運ばない | front matterを含む原文で運ぶ |
| タグ変更のUndo/履歴復元 | 星は変更しない | 本文とともにタグも戻り、検索用の派生情報を更新 |
| 外部編集 | 星の同一性は現行のノート識別契約を基準にする | 再読込後のMarkdownを正とする。外部監視の新設は未決 |

## 8. 実装前に確定する設計と受け入れ条件

実装は小さなIssueに分ける。保存形式・状態owner・公開API・並行性の変更には先行ADRと規範文書の更新が必要。
この計画だけで既存の仕様・ゲート・保存schemaを変更しない。

| 単位 | 先に決めること | その単位の対象検証 |
| --- | --- | --- |
| 1. 星 | 保存先/版/移行、安定した並び、改名/移動/失敗復旧 | 付け外し・再起動、元順復元、フィルター併用、改名/移動、本文不変、保存失敗 |
| 2a. タグ付与と絞り込み | front matter認識/更新、名前の同一性と上限、原文位置/Undo | 未知キーと本文の保持、手入力/GUIの一致、既存先頭構文、未保存編集、Undo/履歴、単票/ZIP、AND/OR |
| 2b. タグ全体管理 | 改名/削除の件数確認、衝突、途中失敗、外部変更と再開 | 複数ファイルの部分失敗、開いている未保存ノート、再試行での二重処理防止 |
| 3. 検索と原文プレビュー | あいまい順位、一致範囲、engine拡張、原文座標、取消と上限 | 名前/本文の区別、複合条件、連続入力/IME、古い結果拒否、プレビューだけの移動、開く/取消/保存失敗 |
| 4. 演出 | 配色、動きを減らす設定、描画資源と時間のowner | 入力を妨げないこと、連打/閉じる/テーマ切替、停止、OFF/高コントラスト、DPI/狭幅 |

大量ノートの初回準備・長い本文・多い一致は、既存の性能制限がある独立した検討点。
代表的な合成データでcold/warmと検索・描画を分けて測り、入力応答の目標は根拠とともに設定する。
新機能の計画段階で「一瞬」「遅延ゼロ」「無制限」等の保証を置かない。
成功済みで関係入力が変わらない試験は再利用し、変更境界の検証と最終headの必須CIに従う（QLT-008/012）。

検索対象を任意フォルダーへ広げること、Markdown閲覧プレビュー、追加Mermaid図種は初期範囲とは分けて扱う。
