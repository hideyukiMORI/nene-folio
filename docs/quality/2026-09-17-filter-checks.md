# 全ノートの絞り込みの確認記録（Issue #40 / ADR 0024）

2026-09-17。ゲート内の単体と、ゲート外の Windows 部品測定でそれぞれ何を守ったかを分ける。
「実機で見た」と「値として確かめた」を混ぜない。

## ゲート内（`pwsh -NoProfile -File ./eng/check.ps1` が守るもの）

### core `index_filter`（`tests/unit/filter_tests.c`）

- **ASCII の英字だけ大小を無視**する UTF-8 のバイト比較。`mixed` が `MIXED Case Body` に、
  `ALPHA` が名前 `Alpha` に一致する。
- 多バイト文字はバイト列として区別する。`カタカナ`（全角）は一致し、`アイウ` は半角の `ｱｲｳ` に一致しない。
- **名前か本文のどちらか**に部分一致すれば見える。
- **本文の写しが無いノートは、名前が一致しても見えない**（読めなかったノートの扱い・決定 1）。
- 空語は `INDEX_FILTER_NO_TERM`、整形式でない UTF-8 の語（`0xC3` 単独）は `INDEX_FILTER_MALFORMED`。
  どちらも集合を作らず、出力を触らない。
- 語が全ての本文より長い場合は 0 件の集合を作る（集合を作らないことと区別する）。
- `index_filter_category` は「そのカテゴリに見えるノートがあるか」だけを答える。
- 写しが空（0 バイト）でも名前では一致し、名前より長く本文より短い語は本文で一致する。
- **一致集合は台帳の順（カテゴリ番号・ノート番号の昇順）で作られる**。4 カテゴリ・11 ノートの
  一致と非一致を 1 件ずつ問い、カテゴリの端と間（一致を持たない中のカテゴリ）も見分けることで、
  二分探索が依る順序を固定する（レビュー対応・ADR 0024 の補正 6）。

### core `note_corpus`（`tests/unit/filter_tests.c`）

- 写しは本文を**複製して所有**し、元の `note_text` を破棄しても生き残る。
- 同じ宛先への `put` は写しを置き換える。
- `rename` は同じカテゴリの中で、`relocate` は同じ名前のまま別のカテゴリへ宛先を付け替える。
  写しを持たないノートへの `rename` / `relocate` は何もせず `ACCEPTED`。
- 付け替え先に古い写しが残っていれば捨てる（上の層が同名を断るので普段は起きない経路）。
- 並び替えは宛先を変えないので、写しには何も起きない。

### core `drawer_layout` / `drawer_source`（`tests/unit/filter_tests.c` / `layout_tests.c`）

- 配置の関数は 1 本のまま。入力を `struct drawer_source`（台帳の列と nullable の絞り込み）へ束ね、
  既存の呼び出しもテストもこの形に直した（第 2 の配置関数を作っていない）。
- 絞り込みがあれば、**一致を持つカテゴリだけ**を `expanded` に関わらず**展開して**並べ、
  一致しないノート行は置かない。一致を持たないカテゴリは行にならない。
- 行の `category` / `note` / `ordinal` / `color` は元の台帳の番号のまま。
  折り畳んだカテゴリの行も `expanded == true` で描かれる。
- 一致が 0 件なら行が 1 つも無い。最初に見える行は頭の帯の下に置かれる。

### application `folio_state`（`tests/unit/state_tests.c` / `allocation_tests.c`）

- **遅延読み込み**: 語が空のあいだ `read_note` は 1 回も呼ばれない。空でない語が初めて来たときに
  全ノート（8 本）を**ちょうど 1 回ずつ**読み、2 つ目以降の語では 1 回も読まない。
- 読めないノート（偽ポートが `ABSENT` を返す）は写しを持たず一致しない。
  **記憶不足（`OUT_OF_MEMORY`）は「読めない」ではなく、絞り込みごと失敗させる**。
- 壊れた UTF-16 の語は `FOLIO_STATE_SEARCH_MALFORMED` で、前の語と前の絞り込みを保つ。
- 空語で絞り込みが解け、索引が元に戻る。
- **絞り込み中の拒否 4 種**: `toggle_category` / `set_category_expanded` / `move_category` /
  `move_note` が `FOLIO_STATE_FILTERED` を返し、台帳の書き戻しが 1 回も起きない。
  色の変更・閲覧・編集は同じ状態で成功する。文言は
  「絞り込み中は並び替えと開閉ができません。」の 1 行。
- 絞り込み中の色の書き戻しは台帳の `expanded` をそのまま書く（絞り込みで全部が展開して
  見えることは、書き戻す値ではない）。
- **現在の文書**は一致しなくても選択・右ペイン・モードが変わらず、行が無いので面の印も付かない。
- カーソルの行が消えたら、その行のカテゴリ行が「見えていて止まれる行」ならそこへ、
  そうでなければ**最初に見える行**（＝最初に見えるカテゴリ行）へ移る
  （折り畳んだカテゴリの中のノートから索引の先頭へ飛ばさない・補正 4）。
  語を変えるたびにスクロール量が 0 に戻る。
- `j` / `k` / `gg` / `G` は**見える行だけ**を辿る（一致しないノートを飛ばし、
  一致を持たないカテゴリへ入らない）。
- 保存は写しを差し替えて一致集合を作り直し、絞り込みを保つ（保存した本文が語を含むようになれば現れる）。
  改名は名前も判定の対象なので、写しを新しい名前へ付け替えてから作り直す。
  新規公開したノートも写しと一致集合に入る。
- **改名を完了させたのが別の意図（`resume_rename`）でも同じ結果になる**。`RENAME_PENDING` で
  止めた改名を切替（`select_note`）が再開して完了させると、一致集合は新しい名前で作り直される
  （作り直しは `adopt_rename` の 1 か所・補正 3）。
- 絞り込みを解いてから別カテゴリへ移したノートは、次の絞り込みで新しいカテゴリの下に現れる
  （写しは移動で宛先だけが付け替わり、本文は読み直さない）。
- 語は 1 つだけで、ノート内検索の語（`set_search_term`）とは互いに影響しない。
- 絞り込みの確保失敗は `allocation_tests` の `state_scenario` が 1 回ずつ失敗させ、
  語・写し・一致集合・判定へ渡す列のどの確保が落ちても `OUT_OF_MEMORY` で片付くことを確かめる。
  絞り込んだまま保存する経路も同じシナリオに入っている。

### 副産物: 確保失敗の網羅が伸びた

`load_category_corpus` が `read_note` の記憶不足を「読めないノート」として飲み込んでいたあいだ、
`exhaust()` は最初の「飲み込まれた確保失敗」で完了してしまい、それ以降の確保を 1 度も失敗させていなかった。
記憶不足を伝播させる修正で、分岐網羅は **90.84% → 92.72%** になった（閾値 90%・QLT-009）。
レビュー対応の追加のあとは **92.85%（2299 / 2476 分岐）**で、`src/core/index_filter.c` は 100%。

## ゲート外の Windows 部品測定（`out/design/2026-09-17/filter_window_probe.c`）

タスク自身の主窓を画面外（-4000, -4000）に作り、自分の `data/` だけを使って測った。
結果は `out/design/2026-09-17/filter-window-probe.log`。**48 項目すべて成功、失敗 0、exit 0**
（レビュー対応で 33 → 48）。

- 欄はドロワーの頭の帯に**常設**されていて、起動直後から見えている。ドロワー自身はフォーカスを取らない。
- Ctrl+Shift+F がどの区画からでも欄へフォーカスを移す（主窓の HACCEL を通る）。
- 打つと `EN_CHANGE` で索引が減り、欄はフォーカスを保つ。
- **Esc と Enter は索引（主窓）へフォーカスを戻し、絞り込みを保つ。**
- 空にすると絞り込みが解け、索引が元の 3 本に戻る。
- IME の composition のあいだは語が動かず、`WM_IME_ENDCOMPOSITION` のあとで 1 回だけ絞り直す。
- 欄の中の Ctrl+S が共通の保存へ渡り、モードも絞り込みも変えない。
- 絞り込み中にドロワーの行を掴んで動かしても並び替えにならず、絞り込みも落ちない（挿入線を出さない）。
- `j` / `k` が見える行だけを辿る。一致を持つカテゴリの行は「見えるノート行を持つ」ので
  `k` の戻り先にはならない（ADR 0015 の決定 2 のまま。絞り込みを変えた直後の着地点であるだけ）。
- 現在の文書が一致しなくなっても選択・右ペインの本文・モードが変わらない。
- 絞り込みを変えた直後のカーソルは最初に見えるカテゴリ行にある。

### レビュー対応で足した測定（ADR 0024 の補正 1 / 2 / 5）

- 絞り込み中に**カテゴリ行をクリックしても何も変わらず、失敗箱も出ない**。
  失敗箱が出れば `MessageBox` が probe の `SendMessage` を止めるので、出たら probe は先へ進まない。
- 絞り込み中の索引の **`h` も同じ**（折り畳まれず、音も箱も出ない）。
- **絞り込み中のドラッグは押した行の選択にも落ちない**。同じ位置の「動かさないクリック」は
  今までどおりその行を選ぶので、位置の当たりも同時に確かめている。
- 欄の中の **F1 と Ctrl+P が共通のパレットを開き、Esc がその欄へフォーカスを返す**。
  **Ctrl+N** が新しい無題を開く（公開はしないのでノート数は変わらない）。
- **`WM_DPICHANGED` のあと、欄の `WM_GETFONT` が主窓の作り直した等幅書体**（パレットの欄と
  同じ `HFONT`）を返し、変更前の（破棄された）書体とは別物である。
- 絞り込みを解いたあと、絞り込み前に折り畳んでいたカテゴリが折り畳まれたままである。

### 性能（1000 ノート × 10KB ＝ 約 10MB の写し）

同じ probe が、1 カテゴリに 1000 本の 10KB の md を置いて測った（`QueryPerformanceCounter` は
probe の中だけで使う。製品は時刻を読まない・ARC-007）。ビルドは製品と同じ最適化なし。

| 測定 | 値 |
| --- | --- |
| 最初の語（写しの遅延読み込み 1000 本を含む） | **305.4 ms** |
| それ以降の 1 打鍵（最悪。1 文字の語 `n`） | **51.0 ms** |
| 1000 本すべてが一致する配置 1 枚（20 回の平均） | **0.22 ms**（線形走査のときは 2.24 ms） |

最初の 1 打鍵だけが読み込みを払い、以後は読み直さない。
判定は打鍵ごとに全文（10MB）を走るので、語の頭のバイトが合う位置だけを比べるようにしてある
（この最適化の前は 1 打鍵 117.5 ms だった）。
配置は描画・hit test・スクロールのたびに作り直されるので、所属の判定を二分探索にした
（レビュー対応・補正 6）。同じ probe を線形走査のままの `index_filter` で 1 度だけ作って測ると
1 枚 2.24 ms で、二分探索では 0.22 ms（約 1/10）。打鍵の数字はほぼ変わらない（そこは全文の走査が占める）。

## レビュー対応（2026-09-17・独立レビューの所見 → ADR 0024 の補正節）

読み取り専用の独立レビューの所見のうち、採った 6 つを同じ PR で直した。契約の正本は
[ADR 0024](../adr/0024-index-filter.md) の「2026-09-17 の補正」節で、ここは**何をどう確かめたか**だけを書く。

| 補正 | 直した所 | 確かめ方 |
| --- | --- | --- |
| 1 | 絞り込み中のカテゴリ行のクリック（`drawer_window` の `act_on_row`）と `h` / `l`（`folio_window` の `expand_cursor`）が静かに戻る | probe（クリックと `h` で索引が変わらず、失敗箱も出ない）。application の `FOLIO_STATE_FILTERED` の契約と単体は変えていない |
| 2 | 閾値を超えて動かしたドラッグは、絞り込みで拒まれてもクリックにしない（`moved` を 1 つ足した） | probe（同じ位置の静止クリックは選ぶ／ドラッグは選択を変えない） |
| 3 | 一致集合の作り直しを `adopt_rename` の 1 か所へ寄せ、`resume_rename` 経由の完了でも新しい名前で作り直す | 単体（`RENAME_PENDING` → `select_note` の再開 → 新名で一致） |
| 4 | カーソルの移し先を 1 つの規則にした（自分のカテゴリ行が止まれるならそこへ） | 単体（折り畳んだカテゴリの中のノート → 絞り込み → 解除でそのカテゴリ行。カテゴリごと消える従来の場合は最初に見える行） |
| 5 | `refresh_font` が絞り込みの欄にも書体を付け直す。欄でも F1 / Ctrl+P / Ctrl+N が効く | probe（`WM_DPICHANGED` 後の `WM_GETFONT` が主窓の新しい書体と同じ・3 つの操作） |
| 6 | 一致集合を台帳順の不変条件にし、所属の判定を二分探索にした | 単体（順序を固定する問い合わせ）・probe（配置 1 枚 2.24 ms → 0.22 ms） |

ノート内検索の欄と Ex / パレットの欄（`command_input`）では、F1 は `command_key_down`、
Ctrl+P と Ctrl+N は `command_character` が前から共通の操作へ渡している。**絞り込みの欄だけが
この 3 つを持っていなかった**ので、そこを揃えた（食い違いはこれだけ）。Ctrl+S は逆に
`command_input` では文字のままで、開いたまま作業する絞り込みの欄だけが共通の保存へ渡す
（ADR 0024 の決定 6 の「Ex とは違う」。これは意図した差で、変えていない）。

## 限界（この単位では測っていない・やっていない）

- **実機の目視**（欄の見た目・プレースホルダの色・高 DPI・ライト／ダーク）は未確認。probe は
  画面外の窓で値だけを測っている。
- **IME の候補窓と物理キーボード**での Ctrl+Shift+F は実機で別に見る必要がある。
- 外部で書き換わった md は検知しない（既存の限界のまま。次の保存で写しが入る）。
- **編集中でまだ保存していない本文は絞り込みの対象にならない**（写しは保存成功で差し替わる）。
- 実機の DPI 変更そのものは測っていない。probe は `WM_DPICHANGED` を送って
  書体の作り直しと付け直しだけを確かめている。
- 10MB を超える `data/` での打鍵の体感は測っていない。1 打鍵の判定は線形に伸びる。
