# 現在ノートの検索の確認記録（Issue #58 / ADR 0023）

2026-09-17。ゲート内の単体と、ゲート外の Windows 部品測定でそれぞれ何を守ったかを分ける。
「実機で見た」と「値として確かめた」を混ぜない。

## ゲート内（`pwsh -NoProfile -File ./eng/check.ps1` が守るもの）

### core `note_search`（`tests/unit/search_tests.c`）

- ASCII の英字だけ大小を無視する。語の側も本文の側も畳む。`İ`（U+0130）と `i` は一致しない。
- 全角／半角カタカナ・ひらがなは別の文字として扱う（`ハイク` / `ﾊｲｸ` / `はいく`）。
- **前方は anchor の開始の次**（anchor が空なら その位置）、後方は anchor の始まりより前から探し、
  端で反対の端へ巡回する。候補はちょうど 1 周ぶんだけ見るので、一致が 1 つでも同じ一致へ戻る。
- 重なった一致を飛ばさない。`aaaa` の中の `aa` を前方に辿れば 0 → 1 → 2 → 0、後方なら 2 → 1 → 0 → 2 で、
  どの一致も `note_search_count` の ordinal（1 / 2 / 3）と一致する（2026-09-17 の補正）。
- 反転した anchor（`start > end`）は `NOTE_SEARCH_BAD_SPAN` で拒み、出力を書かない。
- 折り畳むのは ASCII の A-Z だけで、その前後の記号（`[` `\` `]` `^` `_` `` ` `` `{` `|` `}` `~`）は畳まない。
- 語が本文と同じ長さ（候補が 1 つ）でも、1 単位の語でも、前後どちらからも巡回できる。
- `ordinal` は「`position` 以下から始まる一致の数」。一致の開始でない位置でも、そこまでの数を返す契約。
- 本文より後ろの anchor は端へ丸める。
- 総数と何番目かは重なりも数える（`aa` は `aaaa` の中に 3 つ）。一致が無ければ 0 / 0 で `NOT_FOUND`。
- 一致はサロゲート対を跨いで始まらず、補助文字そのものも語にできる（U+20BB7）。
- 空語は `NO_TERM`、孤立サロゲート（本文側・語側・末尾で切れた対）は `MALFORMED` で、
  どちらも出力を書かない。語が本文より長い場合と空の本文は `NOT_FOUND`。
- 確保をしない純関数なので、確保失敗の経路そのものが無い。

### application `folio_state`（`tests/unit/state_tests.c` / `allocation_tests.c`）

- 語（UTF-8 に写して所有）と直前の方向だけを持ち、本文・選択・フォーカスは持たない。
- 壊れた UTF-16 の語は `FOLIO_STATE_SEARCH_MALFORMED` で、前の語を保つ。空語は捨てる。
  UI はこれをモーダルにせず、0 件と同じ欄の中の 1 行で出す。表示中の平文を取り出せない事象は
  `FOLIO_STATE_PANE_UNAVAILABLE` として `OUT_OF_MEMORY` と区別する（どちらも 1 行の文言を持つ）。
- 語は 1 つだけで、ノートを選び直しても語も方向も変わらない（#40 の絞り込み語はここに無い）。
- 語の確保失敗は `allocation_tests` の `state_scenario` が 1 回ずつ失敗させて `OUT_OF_MEMORY` を確かめる。

### 登録表（`tests/unit/command_tests.c`）

- `FOLIO_COMMAND_FIND` が日本語の表示名「このノート内を検索」を持ち、Ex 別名は 0 個（GUI 専用操作）。
  「操作 ▾」のメニューとパレットはこの表から出るので、狭い窓でも同じ操作へ届く。

## ゲート外の Windows 部品測定（`out/design/2026-09-17/search_window_probe.c`）

タスク自身の主窓を画面外（-4000, -4000）に作り、自分の `data/` だけを使って測った。
結果は `out/design/2026-09-17/search-window-probe.log`。**30 項目すべて成功、失敗 0、exit 0。**

- `/`・`?`・Ctrl+F・操作行の「このノート内を検索」の 4 入口が同じ欄を開く。`/` は前方、`?` は後方。
- F3 は前方・Shift+F3 は後方へ 1 つ進み、**覚えている向きを変えない**（欄が閉じていても効く）。
- 欄は開く前のフォーカスを覚え、Esc で閉じて返す。閉じても一致の選択は残る。
- 打つたびに最初の一致が選ばれ、**選ばれた文字が語と一致する**。
  これは「表示中の平文（段落区切りは CR 1 つ）」と `EM_EXSETSEL` の位置が 1 対 1 であることの実測である。
  取り出しは `EM_GETTEXTEX` の `GT_DEFAULT`。保存用の `note_pane_text`（CRLF）とは別経路。
- Enter は欄を閉じずに次の一致へ進み、Shift+Enter は前の一致へ戻る。覚えている向きは変わらない。
- 一致しない語では選択が動かない。
- 欄を閉じた後の `n` / `N` が索引から効く。
- 閲覧本文の `/` は `EN_MSGFILTER` の経路で同じ欄を開き、composition 中は奪わない。
- 編集中の本文では `/` は普通の文字として入り、Ctrl+F の検索は未保存本文を対象にして
  本文も Undo も変えない。
- 幅 620px（96 DPI 換算）の窓では操作行の常設ボタンを描かず、同じ座標を押しても開かない
  （「操作 ▾」のメニューが持つ）。

## 限界（成功と扱わないもの）

- **件数「k / n 件」と「見つかりません」の表示そのものは目視していない。** 自前描画なので部品測定から
  文字を読み出せず、測ったのは元になる `note_search_count` の値（単体）と、0 件で選択が動かないことだけ。
- 物理キーボードの `/` `?` `n` `N`・Shift+Enter、HHKB、日本語 IME の候補窓と変換確定、
  高 DPI・両テーマでの見た目、最小寸法 560×360 での欄の折り返しは未確認。
- 部品測定の Shift+Enter と Ctrl+F は `SetKeyboardState` で修飾鍵の状態を作って加速表に読ませたもので、
  実際の打鍵ではない。
- 閲覧の RichEdit が描く文字は Markdown 原文と位置が違う（ADR 0023 の決定 1 のとおり）。
  原文の位置へ写す機能は無く、測ってもいない。
- 全ノート検索（FR-032 / #40）・置換（#41）・全一致の着色・検索語の永続化は対象外。
- 入力面（検索欄・Ex・パレット）にいるあいだ Ctrl+S が効かないのは #37 からの既存の振る舞いで、
  この単位では変えていない。検索欄は開いたまま作業する面なので、次の単位で扱う。
- 測定プログラムは計装なしの `clang-cl /clang:-std=c23 /MT /utf-8` で製品ソースを直接コンパイルしたもので、
  正規ゲートの ASan / UBSan 付きビルドとは別物である。
