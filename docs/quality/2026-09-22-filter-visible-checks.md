## 1. 原因（hide の実機の見え方を値で再現した）

Issue #86 の当たりは「ドロワーの `WM_PAINT` が欄の画素を上書きする」で、そこは合っていた。
**欠けていたのは `WS_CLIPSIBLINGS` ではなく z 順**である（ドロワーには元から付いている）。

| 測ったこと | 実測 | 意味 |
| --- | --- | --- |
| 主窓の子の z 順（0 が最前面） | **ドロワー 0 / 欄 1** | あとから作った子は**背面**に入る |
| ドロワーの `BeginPaint` の DC から見た欄の矩形 | **可視**（`RectVisible` が TRUE） | `BitBlt` が欄に届く |
| ドロワーだけ描き直したあとの欄の字の画素 | **232 → 0** | 語が消える（#86 の再現） |
| 欄にも `WS_CLIPSIBLINGS` を付けた場合 | **0 のまま** | 効かない（前の兄弟しか守らない） |
| 欄を z 順の前へ出した場合 | **232 → 232** | 直る |
| ドロワーから `WS_CLIPSIBLINGS` を外した場合（反例） | **232 → 0** | ドロワー側の型も要る |
| 主窓（`WS_CLIPCHILDREN`）を全域で無効化 | **232 → 232** | 主窓の描き直しは原因ではない |

`create_filter_input` のコメント「ドロワーより後に作るので前面に重なる」は事実と逆だった。
