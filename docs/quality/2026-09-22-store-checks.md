# 入力面の中の Ctrl+S の確認記録（Issue #67 / ADR 0016 の補正 2）

2026-09-22。ゲート内の単体と、ゲート外の測定でそれぞれ何を守ったかを分ける。
「実機で見た」と「値として確かめた」を混ぜない。**実機の目視はまだ 1 項目も行っていない。**

## ゲート内（`pwsh -NoProfile -File ./eng/check.ps1` が守るもの）

この単位は **ui/win32 だけの変更**で、core / application / adapters は 1 行も触っていない。
したがって**新しい単体テストは無い**（既存の CTest 2/2 がそのまま通ることだけを確かめた）。

守られているのは次の 2 つである。

- **保存の経路が 1 本のまま**であること。`store_from_surface()` は既存の `command_save()` を呼び、
  `command_save` → `store_body` → `folio_state_store_note`（履歴 → 原子的な書き戻し）という
  application の経路は変えていない。`eng/conformance.py`（ARC-002 の依存の向き）と
  `eng/symbols.py`（ARC-003 / ARC-007）は従来どおり通る。
- **`GetKeyState` を読んでいない**こと。Ctrl+S の判定は `WM_CHAR` の 0x13（既存の `store_character`）だけで、
  非決定名の字句検査（CNF-005）と `eng/symbols.py` にかかる新しい名前は増えていない。

分岐網羅は main と同じ 93.29%（中核を触っていないので数字は動かない）。

## ゲート外: Win32 部品 probe（`out/design/2026-09-22/store-probe/`）

製品コードは参照せず、画面外 (-4000,-4000) の窓で `EDIT` 4 つと `RICHEDIT50W` 1 つを作り、
製品の `store_from_surface` と同じ手順（保存 → 欄に触らない → フォーカスを押した欄へ返す）を模して測る。
**62 項目すべて成功**（`store-probe.log`）。ファイルも利用者の `data/` も触っていない。

### 1. Ctrl+S の届き方（6 項目）

| 欄 | 測った値 |
| --- | --- |
| Ex / パレット / 検索欄（`command_input`） | `WM_CHAR` **0x13** が 1 回 |
| 置換の欄（パターン） | `WM_CHAR` **0x13** が 1 回 |
| 置換の欄（置換文字列） | `WM_CHAR` **0x13** が 1 回 |
| ドロワーの絞り込みの欄 | `WM_CHAR` **0x13** が 1 回 |
| 本文（`RICHEDIT50W`） | `WM_CHAR` **0x13** が 1 回 |
| 素の `S` | `WM_CHAR` **0x73**（普通の文字入力のまま） |

**5 つの欄すべてで、鍵の状態を問い合わせずに Ctrl+S を見分けられる**（ARC-007）。

### 2〜4. 保存が成功する台本（5 欄 × 5 項目 ＋ 1）

各欄でテキストを入れ、**語の途中にキャレットを置いて一部を選んだ状態**で Ctrl+S を送り、前後を比べた。

| 確かめたこと | 結果 |
| --- | --- |
| 欄のテキストが変わらない | 5 欄すべてで不変（`foo` / `bar` / `baz` / `qux` / 本文） |
| 欄の選択とキャレットが変わらない | 5 欄すべてで `1..2` のまま |
| フォーカスの HWND が変わらない | 5 欄すべてで同じ HWND |
| 入力面の種類（`command_surface` を模した値）が変わらない | 5 欄すべてで不変 |
| 保存が 1 回だけ走る | 5 欄すべてで 1 回 |
| 書かれた本文 | 「本文の中身」がそのまま・**5 回**（5 欄すべてから同じ 1 本が走る） |

### 5. 保存に失敗する台本（5 欄 × 5 項目 ＋ 2）

失敗の箱（`MessageBox`）が**フォーカスを奪う**ところを模した（probe では自動で閉じられないので、
箱そのものは出さずに「フォーカスを別の窓へ移す」ところだけを作った）。

| 確かめたこと | 結果 |
| --- | --- |
| 欄のテキスト・選択・キャレット | 5 欄すべてで不変 |
| **フォーカスの HWND** | **奪われたあとで押した欄へ戻る**（5 欄すべて） |
| 入力面の種類 | 5 欄すべてで不変 |
| 本文 | 変わらない |
| 書き込みの回数 | **0 回**（失敗の台本では 1 度も書かれない） |

### 6. ヘルプ 18 行の幅（#69 の材料・1 項目）

この単位でヘルプの 1 行を長くした（「Ctrl+N 新規 …」→「**入力欄でも**  Ctrl+N 新規 …」）ので、
96 DPI・Consolas 11px・字間 1px で 18 行すべての描画幅を測った。

| 値 | 結果 |
| --- | --- |
| パレットの使える幅（460 − 16×2） | **428 px** |
| いちばん長い行 | **406 px（行 7 ＝ 今回長くした行）** |
| `DT_END_ELLIPSIS` で省略される行 | **0 / 18** |

**今回の変更で省略される行は増えていない**（長くした行が最長になったが、まだ 22 px の余裕がある）。
最小寸法 560×360 で操作の行が 0 行になる問題（**#69**）は箱の**高さ**の話で、この幅とは別である。

## 実機の目視に残すもの（hide）

probe は画面外の窓で値だけを測っており、**描いた絵も実際の打鍵も見ていない**。
[統合チェックリスト](2026-09-22-visual-checklist.md)へ次を足してほしい。

1. **物理キーボード**（HHKB）で、5 つの欄それぞれから Ctrl+S を押して保存されること。
2. **IME 変換中の Ctrl+S**（変換が優先され、保存が走らないこと）。確定後は保存されること。
3. 置換の欄で「すべて」を当てた直後に Ctrl+S（**置換してそのまま保存**が 1 度の操作で済むこと）。
4. 保存に失敗したとき（`data/` を読み取り専用にする等）の 1 行と、**箱を閉じたあとに欄へ戻る**こと。
5. **無題のノート**で入力面から Ctrl+S を押したときに名前入力の面が開き、閉じたあと欄へ戻ること。
6. ヘルプの「入力欄でも …」の行が最小寸法でも読めること（#69 と同時に見る）。

## 限界（この単位では測っていない・やっていない）

- **probe は製品の `folio_window.c` ではなく、同じメッセージ列を自分で並べた模型**である。
  「製品が実際にその順で送っている」ことは、コードの読みとゲート内のコンパイルでしか確かめていない。
- **失敗の箱（`MessageBox`）そのものは出していない。** 自動では閉じられないので、
  「フォーカスを奪われてから返す」ところだけを模した。実際のモーダルの出入りは実機の目視に残る。
- **無題の名前入力の面（`name_prompt`）も出していない。** `store_body` は無題では
  `command_save_as(self, "")` を通ってモーダルを開くが、probe はそこを模していない。
- **IME 変換中の Ctrl+S は測っていない**（`WM_IME_*` を probe で作っていない）。
  コード上は既存の `command_composing` / `filter_composing` の番人が先に返す。
- md への実際の書き込みは測っていない（probe は「書いた」ことを数えるだけで、
  履歴と原子的な書き戻しは application の既存の単体が守る）。
- 新しい単体テストは足していない（ui/win32 はゲート内の単体を持たない層である）。
