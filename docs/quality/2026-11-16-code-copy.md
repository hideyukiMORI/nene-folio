## 範囲と境界

- 閲覧（VIEW）の通常のコードブロックの見出し行へ、同じRTFのnativeリンクとして「コピー」を置く。
  クリックと、文字上にキャレットを置いたCtrl+Enterが`folio_state_copy_code`へ入り、描画と同じ走査で集めた
  そのブロックのコードを`clipboard_port`へ渡す。OSのクリップボードを書くのは`clipboard_adapter`だけ。
- 第1回は言語ラベルの直後・ラベルと同じ色の下線リンク。第2回はhideの所感を受け、見出し行を右寄せにして
  ブロックの右上へ移し、主操作と同じ色の対で塗った札（チップ）にした。
  第3回はその見た目だけを直し、ノートの地の色の小さな札をブロックの右上の角へ付けた（位置は第2回のまま）。
  第4回は第3回の形のまま、札の色だけを言語ラベルの対の反転へ変えた。
  第5回は第4回の色のまま、札の高さと行送りを仕上げた。
  第6回は、hideが第5回の見た目（下線と地の色だけの札）を不足と判断したのを受け、札はそのまま残して、
  その上へ描画のたびにアプリがボタンを重ねた。hideは比較画面（`D:/NeNeFolio/design/code-copy-20261116/options.html`）から
  2026-11-16に案C（静止は絵だけ・乗ると枠と文言・成功後はチェック）を選んだ。これが最終。
- overlay・子窓・自前描画・位置の別索引・新しい色やテーマ項目・保存schemaの変更は無い。Mermaidの図は対象外。
- 実クリップボードへ書く試験は、試験専用のwindow station（`fixture_clipboard_station`）だけで行った。
  それ以外のコピー試験と実画面の採取は、記録するだけの偽portへ差し替えてあり、対話用のクリップボードには一度も書いていない。

## 設計案の読み方を決めた点

| 項目 | 文面 | 実装と理由 |
| --- | --- | --- |
| slot数の共有 | 同じ媒体slotへ新しい種別として置き、slot数を共有 | 所有者は`markdown_media`のまま番号を別に数え、上限値（256個・256KiB・Mermaid原文と合計4MiB）を共有。表示slotは本文中の目印とnativeの画像投入が1対1で使うため、同じ並びへ入れると画像経路がコードの番号を画像として探し、画像枠も減る。hideの側で受理済み |
| 上限超過ブロック | 操作を出さない | 見出し行はコード行より先に書くので、fence開始行で描画と同じ述語だけを使って結合後の長さを先読みする |
| 成功の文言 | 「コードをコピーしました」 | 他の通知行に合わせて句点を付けた。受理済み |
| 言語の渡し方 | 記載なし | 閲覧RTFの入口が4引数で飽和していたので、書体名と文言の言語を`markdown_rtf_locale`へまとめた |
| 配色の渡し方（第2回） | 既存の役割だけを使う | 閲覧RTFの入口を`rtf_palette`から実効の`theme_palette`へ変え、`chip_text` / `chip_background`を色表の11・12へ足した。編集用と空の文書の色表は10色のまま。第3回で色表の追加は11（`pane`）だけになった |
| 札の地の色（第3回） | ノートの地の色 | `pane`そのままではRichEditが塗らないので、青を1/255ずらした。役割は増やしていない。第4回で対ごと外した |
| 札の色（第4回） | 言語ラベルの対の反転 | 地が`rtf.code_comment`（色表の9）、文字が`rtf.code_background`（色表の6）。色表の追加は無くなり、閲覧も10色。高コントラストかどうかを知るために、入口は`theme_palette`のまま |
| 下線（第2回） | 通常テーマは無し。外せなければ下線付きで受理 | 外せなかった（下記の試行）。下線付きの札で受理の扱い |
| 札の上の余白（第2回） | 上端に触れるなら既存の定数の範囲で調整 | RichEditは文字の背景を段落の前後の間隔まで塗るので、同じ段落の間隔では上に地を残せない。空の段落を足す方法は文書の文字列と行数を変えるので採っていない。札は見出し行の高さいっぱいで、上端はブロックの上端 |
