## 独立レビューで見つかった欠陥と対応

1. 扇が6・11・16…個のとき、最後の扇と最初の扇が同じ濃さで隣り合っていた。自分の試験は6個で「段＝番号を5で割った余り」を確かめていて、欠陥を固定していた。
   → 最後の扇が最初と同じ段になるときは中間の段にする。試験は2〜17個のすべてで、隣どうし（最後と最初を含む）の段が違うことを確かめる形にした。
2. 凡例が名前の原文をそのまま写していて、`"R&amp;D"`が`R&amp;D`と出ていた（他の図のラベルは実体を読む）。→ 凡例は読み取り後の名前から作る。
3. 名前の中の`;`と`%%`で文が切れ、図全体が不正になっていた。→ 扇の行の先頭の引用符の中は名前として読む。題は引用符を含められるまま。名前は行をまたげない。
4. 半径の区別が付かないとき、ほぼ全周の扇も描かれない書き方だった（いまの倍率2では起きないことをレビューが確かめた。倍率が1なら起きる）。→ 半周を超える扇は円として描く。

直さずに記録したもの（ADR0112の「影響」）: 36000分の1に満たない扇は描かれず凡例に0%で出る、最後の扇が丸めの残りを受ける、千分の一より下の桁、暗いテーマの5段目の淡さ。
描画の試験は3段階が走ることと画像の大きさだけを確かめる。向きや塗りは画像を目で見て確かめた（自動では確かめていない）。

## 追記: 描画を画素で確かめる試験（#961）

上の「描画の向き・塗りは自動の試験では確かめていない」を埋めた。`diagram_render_tests`が描いた画像（BMP）の画素を読み、扇の中と円の外の色を`diagram_palette_shade`の色と比べる（LightとDark、差は各色2まで）。

見本: 1/4・1/4・1/2（上から時計回りに書いた順）、扇1つ（円全体）、細すぎる扇が最後・最初にある場合、広い扇の間の1/100度の扇を5つの角度で、扇6つ（最後が最初の濃さを繰り返さない）。

試験が欠陥を捕まえることを、製品コードの一時的な変異で確かめた（`E:/NeNeFolio/temp/mutate961.py`。変異のたびに元へ戻し、最後に元の構築で成功を確認）。

| 変異 | 結果 |
| --- | --- |
| `Pie`の2本の半径を入れ替える（向きが逆） | 失敗（検出） |
| 半径の区別が付かない扇をそのまま描く（円全体を塗る） | 失敗（検出） |
| 描画で濃淡の段を無視する | 失敗（検出） |
| 配置で開始角を進めない | 失敗（検出） |
| 最後の扇が最初と同じ段になる | 失敗（検出） |
| 半径を上ではなく右から測る | 失敗（検出） |

1回目は2番目の変異を捕まえられなかった（「100と0.001」の見本では、倍率2で2本の半径が別の点になり、その分岐を通らない）。広い扇の間に1/100度の扇を置いた見本を5つの角度で足して、検出できるようにした。
製品コードは変えていない。あわせてROADMAPに残っていた「円グラフは未対応」の記述を直した。
