# 品質記録 — 2026-11-18 一覧だけの表示を往復すると窓の幅が1 pixel変わる（#936）

1.4.0候補のhideの実機確認（2026-11-18）で、一覧だけの表示で閉じたときの記録の幅が2026から2027へ増えた（[1.4.0の品質記録](2026-11-17-release-1.4.0.md)で未調査として残した件）。

## 原因

一覧だけへ切り替えるとき、広い窓の幅を`MulDiv(幅, 96, dpi)`で96 DPIの単位にして持ち、閉じるとき（#904の`closing_placement`）と広い表示へ戻すとき（`set_layout_width`）に`MulDiv(…, dpi, 96)`で戻していた。往復の丸めで幅が変わる。

計算で確かめたこと（PythonでMulDivと同じ四捨五入を再現）:

| DPI | 2026 pixelの往復を4回 | 800〜3000 pixelで1回の往復で変わる幅 |
| --- | --- | --- |
| 96 | 2026のまま | 0 |
| 120（125%） | 2026のまま | 440通り |
| 144（150%） | 2027になり以後2027 | 733通り |
| 168（175%） | 2027になり以後2027 | 943通り |

増え続けはしない（1回で止まる）。記録だけでなく、一覧だけから戻したときの実際の窓の幅も同じだけ変わっていた。
hideの今朝の記録（`nenefolio-window.json`、読み取りだけ）はdpi 120・幅1586で、この時点の記録からはどの画面だったかは分からない。2026→2027は150%か175%の画面と推測（未確認）。

## 直し

広い窓の幅を物理pixelとDPIで持ち（`wide_width`・`wide_dpi`）、同じDPIならそのまま、違うDPIのときだけ比で換算する（`wide_width_at`）。`set_layout_width`は物理pixelを受け取る。ADR0108に補足。

## 確かめていないこと

- 96 DPIでは丸めが起きないので、CI（96 DPI）はこの欠陥を検出できない。手元（120 DPI）の試験と変異で確かめた。
- 150%・175%の実画面、倍率の違う画面へ移してから一覧だけを往復する場合。
- 気づき: `code_copy_scroll`の2件は普段7〜13秒、負荷時に20〜30秒で、上限30秒に近い。別件として調べる候補。
