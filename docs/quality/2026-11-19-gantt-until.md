# 2026-11-19 ガントの`until`と、`excludes`の曜日名（#1022 / ADR0115）

## 何をしたか

ADR0115で未対応にしていた記法のうち、書くと図全体が「未対応」の案内になる2つを読めるようにした。次の版で、1.5.0の候補には入らない。

- 作業の終わりの`until id id…`: 名前を挙げた作業のうち最も早い始まりで終わる。
- `excludes monday`などの英語の曜日名（大文字小文字を区別しない）。

他の図の種類と扱いをそろえるため、`accTitle`・`accDescr`・`click`・`call`は未対応のままにした（フローチャート・シーケンス図・クラス図・ER図・円グラフも未対応にしている）。

## 判断

- `until`の終わりは、始まりからの日数に直して期間（`Nd`）と同じ道で数える。Mermaidは、書いた日付の終わりだけを動かさず、それ以外（期間と`until`）は同じ手順で除外日の分だけ延ばすため。
  例: `excludes weekends`で木曜に始まり、次の火曜に始まる作業まで → 終わりは次の木曜（7日の棒）。手で追ったMermaidの`fixTaskDates`の結果と同じ。
- 作業の始まりは終わりより先に決まる（`begun`）。`until`が待つのは相手の始まりだけなので、互いの始まりを待つ2つの作業も解ける（Mermaidも始まりを先に持つ）。解く回りの上限は作業の数の2倍にした（始まりで1回、終わりで1回）。
- 挙げた作業が自分より前に始まる場合は不正にした（Mermaidは負の長さの棒になる）。知らないidは未対応のまま（Mermaidは今日を使うが、このアプリは今日を読まない）。

## 試したことと結果

単体（`diagram_tests`の`gantt_until`）は1回目で通った。確かめたこと:
- 下に書いた作業までの`until`。
- 複数のidのうち最も早い始まり。
- 週末の除外で延びる終わり。
- 互いの始まりを待つ2つ（長さ0）と、その次の作業の続き。
- `excludes sunday`。
- 大文字の曜日名2つと、その後の作業の始まり。
- 断る形: idの無い`until`、自分より前に始まる相手、`after`と`until`の循環、知らない語の`excludes`。

試験の置き換えは1回当たらなかった（目印にした注釈が別の関数のものだった）。何も書き込まれていないことを確かめてから当て直した。

## 独立レビュー（読み取りだけの席）

| 指摘 | 対応 |
| --- | --- |
| 欠陥: 作業が除外日に始まると、終わりが1日分長い。Mermaidは始まりの翌日から終わりまでを歩くので、始まりの日は除外の検査に掛からない。#992の期間（`Nd`）の数え方にもあった違いで、`excludes monday`で踏みやすくなる | 始まりの日は除外日でも1日に数えるようにした。例: 週末を除外して土曜に始まる`1d`は1日の棒（前は3日）で、次の作業は月曜から |
| 欠陥: 0日の作業が除外日の上にあると、次の作業の始まりが除外日の後へ動く（Mermaidは動かさない） | 0日なら終わりを動かさない |
| 小: 知っているidと知らないidが混ざるとき、Mermaidは知っているものだけを使う | 1つでも知らなければ未対応のまま（`after`と同じ）。ADRの文を正確にした |
| 小: idの文字の範囲と、挙げた作業の始まりがそろうまで待つ点がMermaidと違う | 「Mermaidとの違い」としてADRに書いた |
| 小: ADRの未対応・不正の一覧に`until`が無い | 足した |
| 試験の不足 | 足した: 除外日に始まる`until`と`1d`、除外日の上の0日とその次の作業、挙げた作業の始まりが除外日、項目が`until`だけの行、自分を指す`until`、解けない待ち合い、7つの曜日すべての除外（大きすぎる）、`Until`（不正） |

レビューは曜日の番号（月曜が0）と、試験の期待値がMermaidの規則から出ることも1つずつ追って確かめた。0日の棒は既存の`0d`と同じ道で2pxの棒になる。
直した後の単体の試験は1回目で通った。

**1.5.0の候補への影響**: 上の2つの欠陥は、候補（`99adbab`）に入っているガントにもある。除外日（週末など）に始まる作業を書いたときだけ、棒がMermaidより長くなる。候補へ入れるかはhideが決める（引き継ぎに書いた）。
