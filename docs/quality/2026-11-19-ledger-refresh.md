# 2026-11-19 台帳を書く直前の読み直し — 第2・第3段（#1069 / ADR0117）

## 何をしたか

ADR0117の第2段（coreの補助）と第3段（ノートの台帳の読み直しと、星・同じカテゴリの並べ替えへの適用）を入れた。
ほかの台帳を書く道（初回保存・取り込み・ごみ箱・別カテゴリへの移動・カテゴリの操作・改名）は、まだ読み直さない。第4〜6段で入れる。次の版で、公開した1.5.0には入らない。

- core: `note_ledger_find` / `note_ledger_equals` / `category_ledger_find` / `category_ledger_equals`。見つからないことは`bool`で返し、位置は出力の引数に入れる。
- application（`folio_state.c`）:
  - `refresh_notes(state, category, first, second)`: そのカテゴリの`index.json`とフォルダを起動のときと同じ道で読み直す。メモリと違えば採用する。操作の相手（最大2つ）の位置を、名前で引き直す。
  - `adopt_notes`: 開いているノートとカーソルを名前で付け替え、一覧の作り直しを起こす。検索のための本文の読み込みを最初からやり直し、絞り込みとタグの一覧はその読み込みから作り直す（レビューの後）。
  - `load_notes`に「走査に無くても残す名前」を足した（開いているノート）。
  - 星（`folio_state_toggle_favorite`）と並べ替え（`reorder_note`）が、書く前に読み直す。
- 新しい結果: `FOLIO_STATE_LEDGER_CHANGED_OUTSIDE`（相手が消えていたので断った）と`FOLIO_STATE_LEDGER_REFRESHED`（読み直した一覧で操作が通った。知らせだけ）。3言語の文と、失敗の表の行を足した。
- 窓: 星と並べ替えの結果を`folio_state_ledger_outcome`に通し、読み直していたら下の行に1行出す。並べ替えの後は、結果によらず一覧を描き直す。

## 見つけたこと

| 見つけたこと | 対応 |
| --- | --- |
| 単体の偽の保存先は、書いた台帳を覚えず、読むたびに最初の固定の文字列を返していた。書く前に読み直すと、1回目に書いた並びが2回目の操作の前に元へ戻り、既存の試験が1つ落ちた | 偽の保存先を、書いた`index.json`を次の読みで返す形に直した（カテゴリごとに文字列を持つ。確保は足さない＝確保の失敗の掃引の数え方を変えない）。本物のファイルではもともとこうなる |
| 「お気に入りを先に」の設定で星のあるカテゴリは並べ替えない、という判定（`FOLIO_STATE_ORDERED`）が、読み直す前の古いメモリで行われていた | 同じカテゴリの並べ替えでは、読み直した後の台帳で判定するようにした。別カテゴリへの移動は第4段で直す |
| 設計席の試験の期待値の計算違いが3つ（読み直した並びの上で操作を当てた結果、`index.json`に載っている名前が戻る位置、開いているノートが残る位置） | 並びを手で追い直して直した。製品の誤りではなかった |
| ドロワーは、並べ替えを断られると一覧を描き直さなかった。読み直しで一覧が変わっていても古い表示のままになる | 読み直していれば、断られたときも描き直す |

## 試験

単体（`state_tests.c`）: 偽の保存先の「フォルダの走査」と「`index.json`の文字列」を、意図と意図の間で書き換えて、外からの変更を再現する。
- `verify_refresh_adds`: 何も変わっていなければ知らせない。外で足されたノートが、次の星の書き込みに入り、星も保たれる。知らせは1回だけ。書いたカテゴリだけが読み直される。並べ替えも読み直した台帳に当たる。
- `verify_refresh_follows_names`: 外で`index.json`の並びと星が書き換えられても、操作は名前で相手を引き直す。外の並びと星は残る。
- `verify_refresh_refuses`: 相手のノートが外で消えていたら断る。何も書かない。一覧は読み直した内容になる。動かすノートが消えた場合と、置く先のノートが消えた場合。
- `verify_refresh_unreadable`: 台帳が読めない・フォルダが読めない・台帳が壊れている、のどれでも断り、何も書かない（メモリの台帳で上書きしない）。
- `verify_refresh_keeps_open`: 開いているノートが外で消えても一覧に残り、開いたままになる。

core（`ledger_tests.c`）: 名前の位置、見つからない名前、等しさ（数・順・星・名前・色・開閉のどれかが違えば等しくない）。

## 独立レビュー（統合の前。読み取りだけの席）

| 指摘 | 対応 |
| --- | --- |
| 欠陥: 外で足されたノートの本文が、検索の対象に入らない。本文の読み込みが済んだ後は読み込みをやり直さないので、名前でしか一致しない。タグの一覧にも入らない | 一覧を採用したら、本文の読み込みを最初からやり直し、絞り込みとタグの一覧を作り直す（既存の`fresh_tag_corpus`）。試験を足し、直しを外すと落ちることを変異で確かめた |
| 欠陥: 知らせが、関係の無い後の操作で出る。読み上げの入口は知らせを読まず、カテゴリの並べ替えは知らせを消さないまま読む | 結果に直す場所を`folio_state_ledger_outcome`の1つにし、窓・ドロワー・読み上げの3つの入口が意図の直後に必ず通す。読み上げでは、通った操作をS_OKで返したうえで行を出す |
| 欠陥（確保の失敗のときだけ）: 一覧を採用した後で絞り込みの作り直しが失敗すると、絞り込みが古い位置を指したまま残る | 1つ目の直しで、採用の中の確保が無くなった |
| 欠陥: 絞り込み中に、カーソルが、まだ一致しているノートから外れる（古い絞り込みで確かめていた） | 1つ目の直しで、絞り込みを捨ててからカーソルを確かめる順になった。カーソルが名前で付いていく試験を足した |
| 欠陥: 「お気に入りを先に」で星のあるとき、置く先は表示の順の位置で、台帳の位置ではない。読み直しで星が外から消えていると、利用者が置いていないノートの場所へ動かしてしまう | 星があるときは、前と同じくメモリの台帳で先に断り、読み直さない |
| 振る舞いの変化: 同じ位置への並べ替え（何も書かない）でも読み直して、失敗を返しうる | 同じ位置なら読み直さずに返す |
| 試験の不足 | 足した: 本文の検索、カーソル、読み直しの途中の確保の失敗（開いているノートを残す道と、採用の道）。足していない: 保留中の台帳と読み直しの組み合わせ（第4段で道ごと変える）、開いているノートが`index.json`からも消えた場合、窓の知らせの配線 |
| 小: `note_ledger_find`が「見つからない」を`bool`で返す（C-005の文言） | 答えが2つしか無い問い（あるか無いか）で、位置は出力の引数に入れる。`name_list_contains`と同じ形。期待される失敗の種類が増える所（意図の結果）は閉じた列挙のまま |
| 小: 偽の保存先は名前の中の`"`や`\\`を書き分けない。名前が変わる操作では走査の結果も覚える必要がある | いまの試験はそういう名前を使わない。走査の結果は第4段で足す |

レビュー席が確かめて問題なしとした点: 位置で指す状態のうち、開いているノートとカーソルは名前で付け替え、索引の作りかけ・探す面・タグの編集は一覧の版で作り直しか拒否になる。新しい結果2つは、失敗の表すべてに行がある。読み直しの失敗は状態を変えない。
