# 2026-11-19 窓の高さが変わったときの見出しの欄（#1018）

## 何をしたか

#988で記録だけにした点を直した。点は「窓を縮めた後、いま読んでいる行が欄の外に出たままになる」。
`note_outline_fit`を足した。欄に見える行の数が前回と違うときだけ、2つのことをする。
- 送り位置を、最後の見出しで欄が終わる位置までに詰める。
- いま読んでいる見出しが欄の外にあれば、見える所まで送る。

`track_outline`（本文の送り・読み込み・並べ直しの後に呼ばれる）から呼ぶ。行の数が同じ並べ直しでは何もしないので、ホイールで送った欄は動かない（ADR0114の決定を保つ）。

## 試したことと結果

native（`outline_native`・`outline_96_native`）に`outline_shorten`を足した。手順は次のとおり。
1. 最後の見出しへ移る。
2. 窓の高さを620から260へ縮める。
3. いま読んでいる見出し（7番、全9）の行が見え、最初の行が見えないことを確かめる。（11月19日追記: #1040の後は、同じ試験で押した最後の見出し＝8番になる。）
4. 高さを620へ戻す。
5. 最初と最後の行が両方見えることを確かめる。

結果: 光・暗・高コントラスト、96 DPIと既定DPIのどちらでも通った。

変異（`note_outline_fit`が何もしない）で確かめた。高さを戻した後の確認は落ちた。縮めた直後の確認は落ちなかった。
縮める並べ直しでは本文も折り返し直され、その途中でいま読んでいる見出しの印が一度変わる。そのため、印の変化で欄を送る既存の経路（`note_outline_track`）が行を見せていた。
縮める側で印が変わらない場合の振る舞いは、この試験では確かめられていない。式は同じ`reveal`を使う。
