## 独立レビュー（読み取り専用・1回、第3段階に対して）

止める欠陥は無し。指摘と対応:

- 試験の注釈どおりになっていなかった2件: 「閉じると幅が戻る」は2回目のCtrl+Shift+Oを押していなかった → 閉じて幅が戻り、開き直すと狭くなることを確かめる形にした。狭い窓で縮小表示が残ることを表示だけしていた → requireにした。
- 押している途中に本文が読み込み直されると（色の変更・検索の強調の描き直しなど）、離したときに新しい文書の同じ番号へ移りうる → 押した時点の版を覚え、その版で要求する（古い版は行が答えないので移らない）。
- 欄の開閉とホイールの後に、ポインタの乗っている行の印が古い行に残る → 開閉で消し、ホイールで欄が動いたらポインタの下の行を付け直す。
- 開閉で状態を先に変えてから面を閉じていた → 面を閉じてから状態を変える順にした。
- ホイールの1刻みに満たない余りが次のノートへ持ち越される → 読み込みと開閉で0に戻す。
- 欄の説明文（`UI_TEXT_OUTLINE_HELP`）を使っていなかった → 欄の読み上げの説明に使う。
- 試験の窓の大きさが画素のままだった → 倍率に合わせた。
- 仕様のFR-055がFR-054の上にあった → 順を直した。
- 読み込み直しのたびに欄の送り位置が初めへ戻る（色の変更・検索の強調でも）→ 直さず、ADR0114に書いた。
- 記録だけにしたもの: 窓を縮めた後、いま読んでいる行が欄の外に出たままになる（印が変わるまで欄を送らない作り）。最後の方の見出しを選ぶと1つ前の見出しが選択として返る（ADR0114の既知の点）。`arrange`が毎回本文の区画全体を描き直す。
  自動の試験が無いもの: hostの古い行の破棄（readの失敗までは確かめた）、`folio_window_accessible_at`での行の当たり判定、見出しの無いノートの欄、ホイールの余りの符号、押している途中のcaptureの喪失、長い見出しの省略。
