# 2026-11-19 閲覧の右クリックの「ここを編集」「Markdownとしてコピー」（#1012 / ADR0116の第2・第3段階）

## 何をしたか

ADR0106が次の段階とした2つの項目を、#1008の対応表の上に作った。既定の振る舞いは計画席の推したもの（hideの確認は戻ってから）。
1.5.0の候補には入らず、通常exeへも反映しない（hideの実機確認の対象を変えないため）。

## 独立レビュー（読み取りだけの席）

| 指摘 | 対応 |
| --- | --- |

| 欠陥: メニューの淡色の判定が、描画とポインタの移動のたびに本文の全文を写していた | 開いたときに1回だけ測り、窓が値を持つ。実行のときは今の文でもう一度確かめる（数が違えば失敗の文を出す） |

## 見た目の確認（#1050で追記）

実窓の試験（`text_menu_native`）が撮る閲覧のメニューの画面の写しを、設計席が見た（D:/NeNeFolio/agents/source-map-20261119/menu/text-menu-view-light.png）。
「コピー (C) Ctrl+C」「Markdownとしてコピー (M)」｜「ここを編集 (E)」｜「すべて選択 (A) Ctrl+A」の順で3つの組に分かれている。自前のキーの無い2つの項目には、既存のリンクの項目と同じ「M（メニュー内）」「E（メニュー内）」が出る。いちばん長い「Markdownとしてコピー」も幅に収まり、文字の切れや重なりは無い。
見たのは日本語・光の配色だけ。英語と中国語の文言の幅は見ていない。

## 3言語の幅（#1052で追記）

メニューの幅は最も長い行を測って決まり、下限240・上限360（96 DPI）の間に収める。上限に張り付くと文字が切れうる。
実窓の試験（`text_menu_native`の`text_menu_languages`）で、英語と中国語の閲覧のメニューを開き、行の幅が上限より小さいことを確かめるようにした（日本語は既存の確認の言語）。

| 言語 | 行の幅（120 DPIの画面） | 上限 |
| --- | --- | --- |
| 日本語 | 300（下限） | 450 |
| 英語 | 312 | 450 |
| 中国語 | 300（下限） | 450 |

画面の写しも設計席が見た（D:/NeNeFolio/agents/source-map-20261119/menu/text-menu-view-en.png と -zh.png、暗い配色）。文字の切れや重なりは無い。英語の「Copy as Markdown (M)」と右の「M (menu)」の間は狭いが、離れている。

試した経過: 1回目は3言語分の窓を作り、試験の時間が0.75秒から7.4秒に伸びた（上限30秒）。日本語を外して2言語にし、5.3秒にした。呼び出しを足した関数が長さの上限に掛かったので、2つの呼び出しを1つの関数にまとめた。
