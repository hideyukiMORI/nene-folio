# 2026-11-19 閲覧の段落と原文の行の対応表（#1008 / ADR0116）

## 何をしたか

ADR0106が次の段階とした閲覧の右クリックの「ここを編集」「Markdownとしてコピー」の土台。coreの描画が、ブロックごとの原文の範囲と、閲覧欄に残す段落の記号の数を記録する。
画面には何も出ない（第2・第3段階は予定）。1.5.0の候補には入らず、通常exeへも反映しない（hideの実機確認の対象を変えないため）。

## 独立レビュー（読み取り専用・1回）の指摘と対応

止める欠陥は無し。欠陥5件をすべて直した。

- mermaidの図が群に入っていなかった（群の判定が三項演算の暗黙のelseだった）。→ 閉じたswitchの`grouped`にし、図を入れた。試験に図の群を足した。
- setextの見出しの範囲に下線の行が入っていなかった。→ 下線の終わりを覚えて範囲に入れた。
- 空のリスト項目（`-`だけの行）が記録されず、その印の段落が前のブロックの分になっていた。→ その行を1つのブロックとして記録した。記録を外す変異で単体試験が落ちることを確かめた。
- 説明の直後の表の間の段落が、説明の分になっていた。→ 表を先に記録してから間の段落を出す。途中で、元の表の記録を消し忘れて見出しの行を2回記録した（記号0の項目だったので総数は合っていた）。単体試験の項目の数で見つけて消した。
- 脚注の前の線の範囲が原文の1行目を指していた。→ 最初の脚注の定義を指す。
- 小さい指摘: 言語の判定（mermaidかどうか）を1か所にした、配列を広げるときのあふれを確かめた、`\\`と改行の組を探さない理由を注記した、書き出しでも表を作る費用をADRに書いた。
- 試験を足した: setext、空のリスト項目、説明の後の表、孤立したCR、図の群、実際の描画での番号の引き当て。native試験に2つの文書（setext・空の項目・引用の中の柵・リストの中の表・最後が説明、孤立したCR）を足し、コードの行だけでなく、見出しと地の段落（印や装飾の無いASCIIの文）も「その番号の段落がその文を表示している」ことを確かめる形にした。
- 記録だけ: 画像を差し込んだ後の記号の数は試験していない（第3段階の試験に入れる）。
