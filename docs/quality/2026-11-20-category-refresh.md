# 2026-11-20 台帳を書く直前の読み直し — 第5段 カテゴリの台帳（#1087 / #1069 / ADR0117）

## 何をしたか

ADR0117の第5段。カテゴリの台帳（`categories.json`）を書く意図（開閉・色・並べ替え・作成・削除）が、書く前に`categories.json`とdataフォルダの走査を読み直し、メモリと違えば採用する。次の版の変更で、公開した1.5.0には入らない。

- `load_category_ledger`: 起動のときの`load_categories`を、走査に無くても残す名前を受ける形に直した。起動では残す名前は無い。
- `refresh_categories(state, first, second)`: 読み直し → 同じなら何もしない → 新しい並びの`notes[]`を作る（もとからあるカテゴリのノートの台帳は名前で借り、外で足されたカテゴリはその`index.json`とフォルダを読む）→ 採用。採用の前の読み込み・確保が失敗したら何も変えない。
- 残す名前: 開いている文書（無題も含む）のカテゴリ、保留中のノートの台帳のカテゴリ。
- 採用で名前により付け替えるもの: 選択のカテゴリ、保留の台帳のカテゴリ、カーソルのカテゴリ（消えていたら近くのカテゴリへ落ち着かせる）、意図の相手（`first`・`second`）。相手が消えていたら`FOLIO_STATE_LEDGER_CHANGED_OUTSIDE`で断る。
- 開閉: 「いまと同じなら書かない」の判定を、読み直しの後へ移した（`prepare_expansion`と`toggle_fresh`に分けた）。
- 作成: 読み直した後に名前の衝突を確かめる。削除: 読み直した後に、そのカテゴリのノートも読み直してから空かを確かめる（`refresh_for_removal`）。
- ドロワー: 開閉と色の結果を`folio_state_ledger_outcome`へ通し（知らせの1行）、断られたときも描き直す。開閉では右の窓の頭（カテゴリの番号と色）も描き直す。

## 見つけたこと

| 見つけたこと | 対応 |

| tidyの認知的複雑さの上限（10）を2つの関数が超えた | 残す名前の収集（`kept_categories`）と削除の前の読み直し（`refresh_for_removal`）を分けた |

## 試験

単体（`state_tests.c`、`verify_category_refresh`の7つ。レビューの後に足したものを含む）:
- 外で作ったカテゴリのフォルダが、次の開閉で書く台帳に入り、一覧に出る。知らせは1回。
- 外で書き換えた`categories.json`の並び・色・開閉が残り、開閉と並べ替えは名前で相手を引き直す。
- 外で消えたカテゴリへの色は断り、何も書かない。次の色は新しい一覧の上で通る。読み直せないときはメモリで上書きしない。
- 外で開いたカテゴリを開く操作は何も書かない。
- 外で作られた名前のカテゴリは、フォルダを作る前に断り、一覧に出る。外でノートが入ったカテゴリは「空ではない」で断り、そのノートが一覧に出る。
- 開いているノートのカテゴリは、フォルダが外で消えても一覧に残り、選択はそのまま。

実ファイル（`ledger_refresh_native`に3段。全10段）:
- 外で作ったカテゴリのフォルダとノート → 開閉 → ディスクの`categories.json`に入り、ノートも一覧に出る。
- 外で書き換えた`categories.json` → 色 → 外の順・色・開閉が残り、色だけが変わる。
- 作ったカテゴリに外でノートを入れる → 削除 → 「空ではない」で断り、ノートは残り、一覧に出る。

## 独立レビュー（読み取り専用の席）と対応

メモリの安全（`gather_notes`・`release_gathered`・`adopt_categories`）と知らせの印の漏れは、欠陥なし。番号を持つ状態（検索の位置・絞り込み・タグの一覧・探す面）は`index_changed`と`fresh_tag_corpus`で作り直されることも確かめられた。
確定の欠陥1つと、リスク5つの指摘があり、次のように対応した。

| 指摘 | 対応 |
| --- | --- |
| **欠陥（窓の層）**: キーボードの開閉（`h`/`l`）は、開閉の前後で選択の番号を比べ、変わっていたら本文を流し込み直す。読み直しが選択のカテゴリの番号をずらすと、同じノートなのに「別のノートへ移った」と見なされ、**未保存の編集が保存済みの本文で上書きされる** | キーボードの開閉（`folio_state_set_category_expanded`）は、読み直しで一覧が入れ替わったら何も開閉せずに`FOLIO_STATE_LEDGER_CHANGED_OUTSIDE`で断る（一覧は新しくなり、もう一度押す）。呼び出し側の「先に保存するか」の判断と番号は古い一覧のものなので、それを使わない。番号でノートを指す意図の`synchronize_places`と同じ考え方 |
| リスク: 同じ入口の「先に保存するか」の判断も古いメモリで行われる（外で閉じられたカテゴリを`l`で開くと、保存せずに別のノートへ移る） | 上と同じ対応で無くなる（読み直しが入ったら断る） |
| リスク: 作成・削除が断られたとき、一覧は新しくなっているのにドロワーを描き直さない | 断られたときも描き直す（`finish_new_category`と削除の入口） |
| リスク（第4段からある穴）: 保留中のノートの台帳のカテゴリの番号を、カテゴリの並べ替えと削除が付け替えない。読み直せない`index.json`があるあいだにカテゴリを動かすと、後で別のカテゴリへ書く。末尾のカテゴリが保留のまま手前を削除すると、範囲の外を読む | 並べ替え（`move_places`）と削除（`adopt_category_removal`）で付け替える。保留のカテゴリ自体を削除したら、保留を消す（フォルダが無いので書くものが無い）。単体`verify_category_pending_follows` |
| リスク: マウスの開閉は、外で開閉が変わっていると、利用者が見ていた状態へ戻して書く（見た目が変わらない） | クリックは「一覧に見えていた状態の逆にする」と読む。外ですでにそうなっていたら何も書かない。単体に1つ足した |
| リスク: 開いている文書のカテゴリのフォルダを、外で大文字小文字だけ変えると、一覧に2つ出る（残す名前は古いつづり、走査は新しいつづり） | 記録のみ。重複した行が出るだけで、台帳の貸し借りは壊れない。再起動で1つに戻る |
| 試験の穴: 選択の番号がずれる場合を確かめていない（付け替えを外しても通る） | `verify_category_refresh_keeps_open`に、外で並びを書き換えて選択のカテゴリが名前で付いていくことを足した |
| 到達しないコード: 残す名前と付け替えの「保留中の改名」の枝（読み直しは必ず同期の後で、改名は終わっている） | 外した。ADR0117の決定4も書き直した |
