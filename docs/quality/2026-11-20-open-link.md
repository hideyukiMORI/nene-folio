# 2026-11-20 リンクでノートを開く — 窓と入口（#1097 / #1071 / ADR0118）

## 何をしたか

ADR0118の段取りの4と5。中核（#1095: リンクの検証`open_request`、箇所探し`open_place`、位置引き）の上に、窓と入口を足した。次の版の変更で、公開した1.5.0には入らない。
hideの判断（2026-11-20、判断のページの5点は「ぜんぶ推し」）のとおり: 閲覧表示で段落を選ぶ／面を開いている最中は断る／絞り込みは変えない／ZIP版は登録しない／Store版の登録はhideと実機で確かめてから。

- core: `markdown_source_lookup_paragraphs`（原文の範囲 → 閲覧の段落。ADR0116の対応表の逆引き）。
- application: `folio_state_open_paragraphs`、`storage_state_configured_directory`（この起動が使うはずのdataの場所だけを引く）。
- ui/win32: `folio_window_open_link`（共通の入口）、`WM_COPYDATA`の受け口、`note_pane_select_paragraphs`、知らせの1行（7つ、3言語）、`folio_launch_link`（引数を読む・動いている窓へ渡す）。
- app: 引数を読み、先に動いている窓へ渡してみる。渡せなければ起動して、窓ができたら開く。

## 見つけたこと

| 見つけたこと | 対応 |
| --- | --- |
| 同じdataの2つ目の起動が断られる所は2つある（起動設定があると場所の確かめで、無いと保存先のアダプタで）。「断られた後に渡す」だと両方に手を入れることになる | 起動のいちばん初めに渡してみる形にした（断られる所まで進まない。`storage_state_configured_directory`） |
| 本文の流し込みは同期（`switch_note`が戻った時点で閲覧欄は準備済み）。箇所を選ぶのを後へ回す仕組みは要らない | コードを読んで確かめ、作らなかった |
| 窓のメッセージの振り分けと、試験の実行関数が、tidyの行数の上限いっぱいだった（3か所） | 別の振り分けへ置く・判定を関数に分ける。閾値は触っていない |
| 設計席の試験の誤り1つ（設定の面を、メニューの操作としては開けない） | 読み上げの入口（`ACCESSIBLE_SETTINGS`）で開く既存の型に合わせた |
| 知らせの文 | designのUXコピーの手引きで3言語を決めた（記録: D:/NeNeFolio/agents/open-link-1071/ux-copy-20261120.md）。開いていないときは「開いていない」と言い、開いたときは「いま何が選ばれているか」を言う |

## 試験

実窓（`open_link_native`、`image_status_tests --open-link`）:
- 箇所: 行のあたりの文（知らせ無し）／文が無く行／文が別の場所／行の範囲（2つの段落）／どれも無い。
- 断る: カテゴリが無い、ノートが無い、名前が規則に合わない（`..%2Fsecret`）、動作が`open`でない。どれも選択は変わらない。設定の面が開いているあいだは開かない。
- 受け渡し: 別のdataの場所は受けない（`FALSE`、何も変わらない）。自分のdataは受けて開く。ほかの`WM_COPYDATA`は受けない。
- 起動の引数: 空・ファイルのパス・`--help`はリンクとして読まない。引用符と空白を落とす。日本語を含むリンク。別のdataでは渡せない・自分のdataでは動いている窓が受けて開く。
- 編集表示のノートへのリンクは、閲覧表示にして箇所を選ぶ。

単体: 対応表の逆引き（段落・続きの行・複数のブロック・空行・ブロックの中のキャレット・範囲の外・コードの柵・脚注）、dataの場所だけを引く窓口（既定・保存した場所・読めない設定）。

## 残ること（hideの実機確認）

- 実物のexeでの通し（自動の試験は、窓の入口と受け渡しの関数までを実窓で確かめている。`wWinMain`からの数行は自動の試験が無い）:
  1. `NeNeFolio.exe "nenefolio://open?category=<カテゴリ>&note=<ノート>&lines=3"`で起動して、そのノートが開き段落が選ばれること。
  2. アプリを開いたまま同じコマンドをもう一度流し、「使用中」の箱が出ずに、開いている窓が前へ出てノートが開くこと。
- Store版の登録（マニフェストの1行）と、クリックで起動したときにリンクがどう届くかの確認（ADR0118の決定7）。
- 留守中に実物のexeを起動しなかった理由: hideのデスクトップに窓が出て、前面を取るため。
