# 2026-11-20 台帳を書く直前の読み直し — 第6段 改名（#1091 / #1069 / ADR0117）

## 何をしたか

ADR0117の第6段。改名は、完成後の台帳を改名の記録（`.rename.json`）に入れ、アダプタがその台帳をそのまま書く（ADR0022 / ADR0041）。だから読み直しは、記録を作る前に置く（最初の案は採用の後にも置いたが、独立レビューで取りやめた。下の節）。次の版の変更で、公開した1.5.0には入らない。

- ノートの改名（`folio_state_rename_note`）: 同期の後、名前の確かめと計画の前に`refresh_notes`。開いているノートは残す名前で、選択は名前で付いていく。
- カテゴリの改名（`folio_state_rename_category`）: 計画の前に`refresh_categories`で相手を名前から引き直す。消えていたら`FOLIO_STATE_LEDGER_CHANGED_OUTSIDE`。読み直した後の処理は`rename_fresh_category`に分けた。
- カテゴリの改名の入力面は相手を名前で覚え、意図を呼ぶたびに`folio_state_find_category`で番号を引き直す。
- 保留中の改名があるあいだ、`retry_index`は読み直さずに待つ。

## 見つけたこと

| 見つけたこと | 対応 |
| --- | --- |
| **第4段からあった穴（コードを読んで気づいた）**: 同期は「保留の台帳の再試行 → 写し → 改名の再開」の順で、再試行は改名が保留でも読み直す。カテゴリの改名が途中で止まってフォルダがもう新しい名前のとき、古い名前で読むと`index.json`もフォルダも「無い」になり、そのカテゴリの一覧が空で採用される | 保留中の改名があるあいだは再試行を待たせる。改名が採用された次の意図で、新しい名前で読み直してから書く。単体`verify_rename_holds_pending_index` |
| 上の対応で、ADR0117決定4の「保留中の改名の前後の名前を残す」が要らなくなった | 決定4を書き直した（第5段のレビューで到達しない枝として外した所と同じ理由） |
| 設計席の試験の期待の誤り2つ: 既定の並べ方が「お気に入りを先に」で、星のあるノートが先に表示される。実ファイルの試験で、前の段が残した無題の下書きがあるとノートを選べない | 試験を直した。製品の誤りではない |

## 試験

単体（`state_tests.c`、`verify_rename_refresh`の4つ）:
- 外で`index.json`の並びと星を書き換え、ノートを足した後にノートを改名 → 並び・星・足したノートが残り、開いているノートは新しい名前。
- 改名を途中で止め、その間に外でノートを足し、次の意図で完了 → 番号は1つも動かない。次に台帳を書く意図（星）で、足したノートが一覧に出る（知らせは1回）。
- 外でカテゴリの並びを書き換えた後にカテゴリを改名 → 外の並びの上で、名前で引き直した相手が改名される。外で消えたカテゴリの改名は断り、何も呼ばない。名前から番号を引く窓口は、残っている名前の番号を返し、消えた名前には「無い」を返す。
- 保留中の台帳があるままカテゴリの改名を途中で止める → 次の意図は改名の保留で断られ、その間、台帳の読み直しも書き込みも起きない。改名を完了させた意図は通り（番号は動かない）、その次の意図で、台帳が新しい名前で書かれる。

実ファイル（`ledger_refresh_native`に2段。全12段）:
- 外で`index.json`を書き換え`.md`を足す → ノートの改名 → ディスクの`index.json`に外の並び・星・足したノートが残り、ファイルは新しい名前。
- 外でカテゴリのフォルダを作る → カテゴリの改名 → ディスクの`categories.json`に外のカテゴリが残り、フォルダは新しい名前。

## 独立レビュー（読み取り専用の席）と対応

確定の欠陥2つ。どちらも第6段の最初の案が入れたもので、統合の前に直した。

| 指摘 | 対応 |
| --- | --- |
| **欠陥**: 採用の後の読み直しは、再開で完了した改名でも走る。再開は同期の中なので、同期を通っただけの意図（色・並べ替え・開閉・新しいノート・取り込み・書き出し・カテゴリの改名と削除）が、古い番号で別のカテゴリに当たる。一覧が縮むと範囲の外を読む | 採用の後の読み直しを取りやめた。同期の中で完了した改名は番号を動かさない、という前からの約束を保つ。外で足されたものは次の書き込みの読み直しで出る（単体の試験をその形に直した） |
| **欠陥**: カテゴリの改名の入力面は相手を番号で持ち、断られても開いたまま。断った意図が一覧を読み直していると、2回目のOKで別のカテゴリを改名する。そのカテゴリが編集中のノートのカテゴリだと、空の本文で保存してしまう道もあった | 入力面は相手を名前で覚え、意図を呼ぶたびに番号を引き直す。消えていたら意図を呼ばない。applicationに`folio_state_find_category`を足した |
| リスク: 改名が同じ同期の中で完了すると、待たせた台帳はその回では書かれない。その次の意図が別のカテゴリを保留にすると、待っていた台帳は書かれないまま（フォルダの走査で一覧には戻る。並びだけが違いうる） | 記録のみ。第4段からある「読み直せない`index.json`」のときと同じ型の残り |
| リスク: ノートの改名は、`index.json`が読めない・壊れているときに断るようになった（名前が同じでも） | ADR0117の決定5のとおり（読めない台帳を既定値へ落として書かない） |
| 試験の穴: 採用の後の読み直しのうち、カテゴリの枝を確かめる試験が無かった | 枝ごと無くなった |
