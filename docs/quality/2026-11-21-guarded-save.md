# 2026-11-21 保存は、外で変わったファイルを上書きしない（#1107 / #1070 / ADR0119の決定4）

## 何をしたか

hideの判断（2026-11-20、案B）: ふつうの保存でも、読み込んだ（か最後に保存した）本文とファイルを照らし、外で変わっていたら保存を止める。
11月20日に作った枝は、独立レビューが「このままでは入れない」とした（外の版を読み直す出口が無い／閲覧中の読み直しより先に入れてはいけない）。その2つの条件を満たして入れた。次の版の変更で、公開した1.5.0には入らない。

- 条件1（閲覧中の読み直し）: #1112（[品質記録](2026-11-21-outside-refresh.md)）。
- 条件2（編集を破棄して、ファイルから読み直す）: このPR。`:e!`（表示名は前から「編集を破棄して読み直す」）が、`folio_state_reload_document`でファイルから読み直してから本文を流し込む。ファイルが無い・読めないときと無題は、これまでどおり最後に読んだか保存した本文へ戻す。
- 保存: 依頼に`recreate`を足し、ふつうの保存（`NOTE_SAVE_EDITS`）も期待する本文を渡す。編集が無ければ照らさない。外で消えたファイルは作り直す。11月20日の2つのコミットをそのまま載せた。
- 止まったときの1行を、次の一手を言う文にした（3言語）: 「外部で変更されたため、保存していません。別名で保存するか、編集を破棄して読み直せます。」。
- 外でテキストでなくなったファイル（不正なUTF-8・NUL）へのふつうの保存は、「ノートを読めません。表示は変わりません」ではなく、外の変更として止める（アダプタ）。
- 単体の偽の保存先を本物に合わせた（読めないファイルへのふつうの保存は「履歴を残せない」）。使われなくなった欄`remember_note_writes`を消した。

## 試験

単体（`folio_unit`）:
- 11月20日の分: 外で変わっていたら履歴にもファイルにも触らずに止まる／外で消えていたら作り直す／自分の保存の次は通る／編集が無ければ保存も照合もしない。
- 足した分: 改名・ごみ箱・カテゴリの改名は、保存が止まると、記録・台帳・ごみ箱に触る前に止まり、編集表示のまま。読めないファイルは、ふつうの保存が「履歴を残せない」、照らす保存が「読めない」。

実ファイル（`ledger_refresh_native`、本物のアダプタ）:
- 11月20日の分: 外の版がディスクに残る／消えたファイルを作り直す／自分の保存は外の変更ではない／編集が無ければ書かない。
- 足した分: BOMとCRLFのファイルを読んで2回保存できる／外でテキストでなくなったファイルは外の変更として止まり、そのまま残る／ほかのプログラムが握っているファイルは「履歴を残せない」で、上書きしない／ファイルから読み直してからの保存は通り、外の版に編集が乗る。

実窓（`outside_refresh_native`の後ろの2段）:
- 保存が止まる: Ctrl+Sで1行／別のノートへのリンクは開かず、選択はそのまま／窓を閉じても窓は残る／Windowsの終了は断る／そのあいだ本文（追記）とUndoは残り、ファイルは外の版のまま。
- 破棄: 外の版が編集表示に出て、追記は消え、1行「外部の変更を読み込みました。」。そこから追記して保存すると、ファイルは外の版＋追記になる。
- ファイルが外で消えた後の破棄: 最後に保存した本文へ戻り、1行「ファイルを読み直せなかったため、最後に読んだ本文に戻しました。」。
- #1112の2つの場面（「編集」の前に読み込んだ／「閲覧」へ戻って読み込んだ）で、1行が出ていること。

## 変異・検証

レビューの直しの前の版（`659e091`）で、変異7つ（`D:/NeNeFolio/temp/20261121-guard-mutate.py`、記録`D:/NeNeFolio/temp/20261121/mutations-1107.log`）をすべて試験が捕まえた: 期待する本文を渡さない／テキストでないファイルの結果／消えたファイルを作り直さない／破棄がファイルを読まない／破棄の1行／「編集」「閲覧」の1行／編集の無い保存も照らす。
同じ版で、全試験（`ctest -j 2`、73件）成功、測定（`eng/coverage.py`）成功で分岐の網羅率90.88%（下限90%）、適合0、シンボル0。
レビューの直しの後の結果はPRの本文に書く。フルゲートは必須CI。

全試験を並列2本で流したうち、`body_discovery_native`が3回落ちた（15回ほどのうち。どれも「本文の一致でEnter → 閲覧で開く」が編集表示のままになる。単独の3回と、調査の出力を足した後の6回は成功）。
- 分かったこと: 製品はこのEnterでCtrlの状態を読む（Ctrlがあると編集で開く。`folio_window.c`の`GetKeyState(VK_CONTROL)`）。落ちたときの出力は、編集で開く道の形（表示は編集、検索語は空）と合う。保存が止まった形（外の変更の1行）かどうかは、再現しなかったので確かめられていない。
- 対応: 試験が、素のEnterの前に自分のスレッドの修飾キーを中立にし、押されていたら出力に残す（#1101で`text_menu_native`に入れたものを関数に出して共用）。製品は変えていない。

## 残るリスク

- 照合と書き込みのあいだに外で書かれた場合は防げない（ファイルを握らない。ADR0093から同じ）。
- 編集のある保存のたびに、ファイル（最大16MiB）を読んで照らす。時間は測っていない。
- Windowsの終了を断るときの文は前のまま（「保存処理が未完了です。保存を再試行してください。」）。外の変更が理由のときは、再試行しても止まる（そのときに次の一手の1行が出る）。
- 「別名で保存」と`:q!`で出られることは、この場面の試験では確かめていない（それぞれの既存の試験はある）。
- 止まったときの1行が、狭い幅や一覧だけのレイアウトでどこまで見えるかは測っていない。
- 窓の試験で止まる場面を確かめたのは、Ctrl+S・リンク・窓を閉じる・Windowsの終了だけ（クリックでの切り替え・新規・改名の入力面・ごみ箱・絞り込み欄・検索・タグの適用は、単体の試験と、保存の入口が1つであることに頼る）。
- 改名の入力面の中にも同じ1行が出る（別の名前を入れても通らない。キャンセルで出る）。
- 破棄で本文を入れ替えた後、記憶域の不足で本文の欄へ流し込めないと、編集中の本文が残ったまま次の保存が通る（外の版は履歴に残る）。
- 本物のアダプタの試験は、止まったときに履歴のフォルダが変わらないことを直接は見ていない（偽の保存先の回数と、コードの順で確かめた）。
- 窓を前面にしたまま外で変わったノートを、「ここを編集」・タグの適用・検索・パレットやExの「編集」から編集し始めると、その保存は止まる（破棄して読み直せば続けられる。見張り＝段取りの4が入ると、編集の前に読み直される）。
