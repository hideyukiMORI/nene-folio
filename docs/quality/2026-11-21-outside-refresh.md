# 2026-11-21 窓が前面に戻ったときに、外で変わった一覧とノートを読み直す（#1112 / #1070 / ADR0119の段取り3）

## 何をしたか

ADR0119の段取りの3。#1106で入れた2つの意図（`folio_state_refresh_lists`・`folio_state_document_stale`）を、窓から呼ぶようにした。次の版の変更で、公開した1.5.0には入らない。
見張りのハンドル（段取りの4）はまだ無い。窓を前面にしたまま外で変わった分は、次にほかのアプリから戻ったときか、台帳を書く操作（FR-008）まで出ない。

- application: `folio_state_reload_document`（開いている名前のあるノートを、選択も表示モードも変えずにファイルから読み直す。読めなければ何も変えない）。
- ui/win32:
  - `WM_ACTIVATEAPP`（ほかのアプリから戻った）で印`outside_due`を立てるだけ。読むのは、メッセージの待ちの先頭（`folio_window_idle_work_ready` / `folio_window_continue_idle_work`）で、窓が静かなとき。待ちの形・スレッド・タイマーは足していない。
  - 静かの判定`outside_refresh_ready`: リンクで開くときの断る条件（`open_link_blocked`）＋面が1つも開いていない＋絞り込み欄の保存の途中でない。途中なら印が残り、終わった後の待ちで読む。
  - `refresh_outside`: 一覧を読み直し、変わっていたらドロワーを描き直す。開いているノートは`show_outside_change`で、閲覧なら読み直して位置を保ち1行、編集中なら1行だけ。
  - 「編集」の操作（`execute_mode_command`）は、閲覧から編集に入る前に同じ確かめをする。「閲覧」へ戻ったとき（`flush_edit`）にも印を立てる。
- core: 1行の文を2つ（3言語）。

## 見つけたこと

| 見つけたこと | 対応 |
| --- | --- |
| 最初の案は、編集に入る共通の関数（`enter_edit`）の中で読み直していた。自己レビューで呼び手を全部読んだら、タグの適用（置き換える範囲を古い本文で作った後に呼ぶ）と「ここを編集」（キャレットの位置を古い本文で作った後に呼ぶ）が、作った位置を持ったまま通ることが分かった。そこで本文を入れ替えると、位置がずれる | 利用者の「編集」の操作の入口（`execute_mode_command`）だけに置いた。タグの適用・「ここを編集」・検索から編集で開く、は読み直さない（ほかのアプリから戻ったときの読み直しが先に効く。窓を前面にしたままの変更は段取りの4の見張りが拾う） |
| リンクで開くときの断る条件は、ノート内検索の面を許している。読み直しは本文を入れ替えるので、検索が持つ本文の位置がずれる | 読み直しの「静か」は、面が1つも開いていないこと、とした（ADR0119の実装の状態に書いた） |
| 実窓の試験のfixtureのフォルダは、回をまたいで残る。外で作ったノートのファイルが前の回から残っていて、2回目の実行だけ落ちた（CTestの1回目は通り、直接起動した2回目で気づいた） | 試験が、数える前に自分のファイルを消して読み直す。最後にも消し、「外で消したノートが一覧から消える」も確かめる段にした。3回続けて成功 |
| 窓のメッセージの振り分けが、tidyの上限（1関数60行・認知的複雑さ10）いっぱいだった（2回当たった） | 別の振り分けへ置き、判定を関数に分けた。閾値は触っていない |
| 置き換えのスクリプトをbashのheredocで渡して、引用の解釈で落ちた（11月20日の引き継ぎにあった型をもう一度） | Writeでファイルに書いてから流す |

## 試験

単体（`folio_unit`）:
- `folio_state_reload_document`: 未選択と無題は`NOTHING_SELECTED`。読めないファイルは`NOTE_UNREADABLE`で本文はそのまま。読めたら本文が入れ替わり、名前と表示モードはそのまま、`document_stale`は偽、検索の写しも新しい本文、書き込みは0。
- 編集中: 表示モードは編集のまま、編集の元の本文が入れ替わる。編集で保てない本文になったら閲覧へ落として`NOTE_UNEDITABLE`を残し、次の読み直しで消える。

実窓（`outside_refresh_native`、`image_status_tests --outside-refresh`）:
- 外で何も変わっていなければ、戻っても何も起きない。
- 外で書いても、窓が離れているあいだは読まない。戻ったら読み、1行「外部の変更を読み込みました。」。
- 長いノートをスクロールした位置で、外で末尾に足す → 読み直した後も最初に見える行が同じ。
- 外で作ったノートは戻ったときに一覧に出る。外で消したノートは一覧から消える。
- 設定の面が開いているあいだは読まない。閉じたら（もう一度戻らなくても）読む。
- 外で変わった後に「編集」→ いまのファイルの本文から編集が始まる。
- 編集に入って何も打たずに外で変わり、「閲覧」へ戻る → 読み直す。
- 編集中（未保存の追記あり）に外で変わって戻る → 本文は追記を持ったまま、Undoも残り、1行「このノートは外部で変更されました。編集中の本文はそのままです。」。

## 残るリスク

- 窓を前面にしたまま外で変わった分は、まだ自動では出ない（段取りの4）。
- 戻るたびに、すべてのカテゴリのフォルダと台帳、開いているノートのファイルを1回読む。大量のノートでの時間は測っていない（読み直しの部品は#1069から台帳を書く操作のたびに使われている）。
- 起動のときも1回読み直す（窓が前面になるため）。1回きりで、繰り返す輪は無い（印は読む前に下げる。静かでなければ待ちに戻る）。実物のexeでの起動直後のCPU（入力なし20秒）は、段取りの4と一緒にhideがいるときに測る。
- 「ここを編集」・タグの適用・検索から編集で開く、は編集に入る前に確かめない（上の表）。
