# 2026-11-21 依頼のファイルでノートを開く（#1123 / #1070 / #1071 / ADR0119の段取り5）

## 何をしたか

`data/.requests/open-<何でも>.json`に依頼を置くと、Folioがそのノートを開いて箇所を選ぶようにした（FR-060）。WSL側のLLMなど、Windows側の実行ファイルを起動できない書き手のための道。次の版の変更で、公開した1.5.0には入らない。

- core: `open_request_create_json`。JSONの欄を、リンクと同じ受け取り手（名前の規則・制御文字・行の範囲・探す文の上限）へ渡す。規則は1か所（ARC-008）。
- application: 保存先のポートに`take_open_request`、意図`folio_state_take_open_request`。
- adapters/win32: `request_file`（一覧・読み・削除。5分より古い・64KiBを超えるものは読まずに消す。消せたものだけ渡す）。
- ui/win32: 読み直しの静かな回の最後に1つ取り出し、リンクと同じ`open_link_request`で開く。残りは次の静かな回。
- app: 起動のときに1回見る。入口の待ち（#1117）は変えていない。

## 設計の判断

| 判断 | 理由 |
| --- | --- |
| 依頼を取り出すのは、読み直しの静かな回の中 | 見張りの知らせ → まとめ → 静かなとき、という#1117の道に載せた。入口を足さない。窓が静かでないあいだは、ファイルを残して待つ |
| 保存先のポートに足した（新しいポートの束を作らない） | 置き場はdataの中で、保存先のアダプタが場所を知っている。試験の保存先の差し替えもそのまま使える |
| 消せたものだけ渡す | 消せないファイルを渡すと、見るたびに同じノートを開き続ける輪になる |
| 5分の規則は、起動のときに限らず常に当てる（ADR0119の決定6からの補正） | 規則を1つにする。動いている間は0.3秒ほどで処理するので、当たるのは、窓が5分のあいだ静かにならなかった依頼だけ |
| 正しくないファイルは黙って消す | 決定6のとおり。リンクと違い、利用者が押したものではないので、1行は出さない |

## 試験

単体（`folio_unit`）:
- JSON: 全部の欄・順不同・知らないキー（入れ子ごと読み飛ばす）・値はJSONの文字列そのまま（%を戻さない）。不正な形23通り（オブジェクトでない・閉じていない・後ろにごみ・versionやactionが無い／違う／重複・categoryやnoteが無い／重複・文字列でない値・行の範囲が逆・制御文字・壊れた入れ子）、名前の規則2通り、探す文の上限、ファイルの上限、確保の失敗の掃引。
- 意図: ファイルが無い／正しい依頼／読まずに消された／正しくない依頼を捨てる／無くなった／アダプタの記憶不足／確保の失敗の掃引。何も書かない。

実ファイル（`ledger_refresh_native`の`request files`の段、本物のアダプタ）:
- フォルダが無ければ無し。更新の古いほうから取り出し、取り出したファイルは消える。`other.json`と`open-c.txt`には触らない。
- `.requests`があっても、一覧の読み直しは「変わらない」で、カテゴリの数も同じ。
- 64KiBを超えるファイル・10分前のファイルは、読まずに消える。
- ほかのプログラムが握っていて消せないファイルは渡さず、次のファイルを渡す。握りが外れたら渡す。

実窓（`outside_refresh_native`の`request files`の段）:
- 依頼を置いて知らせると、まとめの後に、そのノートが閲覧表示で開き、指定の文が選ばれ、ファイルが消える。
- 依頼でないJSONは、消えるだけで何も開かない。
- 設定の面が開いているあいだは、依頼はファイルごと待つ。面を閉じると開き、ファイルが消え、窓は待ちに戻る。
- 正しくないファイル3つを一度に置くと、静かな回ごとに1つずつ消え、窓は待ちに戻る。

## 残るリスク

- 実物のexeで、WSLや別の端末からファイルを置いて開くことは、まだ確かめていない（hideの実機の通し）。起動のときの読み直しを足したので、起動直後のCPUは測り直す。
- 書いている途中のファイルを読むと、正しくないものとして消える恐れがある。確実な書き方（別名で書いてから名前を変える）は、段取りの6の文書に書く。
- 窓を前面へ出す動き（`SetForegroundWindow`）は、ほかのアプリが前面のとき、Windowsの決まりでタスクバーの点滅だけになることがある（リンクと同じ）。実機で見る。
- 依頼を開くときに無題の下書きがあると、名前の入力が出る（リンクと同じ）。保存が外の変更で止まると、依頼のノートは開かず、ファイルは消えている（リンクと同じく、依頼はやり直しになる）。
- 入口の関数（`main.c`の起動のときの1回）は自動の試験の外。
