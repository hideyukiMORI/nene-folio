## 独立レビュー（読み取り専用の席。コミット`5cd6f3b`を対象。外から来るファイルを扱う口として、安全の面からも）

| 指摘 | 対応 |
| --- | --- |
| **確定**: ファイル名に文字の参照（`&amp;`など。HTMLから保存した名前によくある）があると、書いたMarkdownを読み手が別の名前に読み替え、画像が出ない（か、別のファイルが出る） | パスの中の`&`を`%26`と書く（画像の読みは`%XX`を戻す） |
| **確定**: ファイル名に逆引用符があると、代替の文とパスの2つの逆引用符が組になって、画像の記法ごとコードになる | 代替の文からは除き、パスでは`%60`と書く。1行に2つ並べても2つの画像として読まれることを試験で確かめた |
| **確定**: あるのに開けないファイル（ほかのプログラムが握っている・権限が無い）を「画像でない」と返していた | フォルダだけを「画像でない」にし、開けないファイルは「読めない」にした |
| 同じ名前のファイルとの照合が、長さを比べる前に全部読む（同じ名前が多いと、1回の投下で最大999回×16MiB） | 先に大きさを比べ、違えば読まない |
| 試験の偽の画像のポート2つが、新しい`adopt`を空のままにしていた（次の段でつなぐと落ちる） | 「何も取り込まない」関数を入れた |

## 試験

単体（`folio_unit`の`image_links`）: 書いたMarkdownを本物の描画へ通し、集まった画像の参照が`images/<名前>`になることまで確かめる。名前は、ふつう・日本語・点が複数・空白・丸括弧・`%`・`%20`・角括弧・拡張子なし・`.png`だけ・`'`と`#`・下のフォルダ・**文字の参照（`&amp;`、`&#38;`）・逆引用符**。1行に2つ並べた場合。署名（PNG・JPEG・GIF・短すぎ）。番号を付けた名前。

## 残るリスク

- 落とされたファイルそのものがリンク（シンボリックリンク・ジャンクション）のときに断ることは、**試験していない**（リンクを作るには権限か開発者モードが要る）。その関数を消しても、どの試験も落ちない。
- リンクかどうかを確かめてから開くまでの間に差し替えられた場合は守っていない。
- 取り込みは同期（上の表）。窓へつなぐ前に、どのスレッドで走らせるか・途中で止められるかを決める。
- `images/`に予約の名前（`NUL`・`COM1`など）のファイルを写そうとした場合の動きは、読んで追っただけ（上書きは起きず、写せないか番号つきになるはず）。
- `images/`は、写せるかどうかが決まる前に作る。失敗すると、空の`images/`が残ることがある。
- 番号は1000まで。それを超える同じ名前があると「写せない」。
- 試験していない場面: 途中で同じ名前が現れる、1000個の名前が埋まっている、カテゴリのフォルダが無い・書けない、ちょうど16MiB、別のカテゴリの`images/`にあるファイル、中身と拡張子が食い違う画像。
