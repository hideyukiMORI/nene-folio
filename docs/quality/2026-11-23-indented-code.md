# 字下げのコードブロック（CommonMark 4.4）の品質記録 — 2026-11-23

Issue #1192。方針は[ADR0121](../adr/0121-markdown-follows-the-spec.md)（hideの判断 2026-11-22: 仕様に準拠が基本。「mdの規約に沿う形ならあわせるべき」「レンダリングが大きく変わっても支障はない」）。

## 何を変えたか

- 直す前: 字下げ4つ以上（またはタブ）の行のかたまりは、普通の段落として出ていた。
- 直した後: コードとして出す。見た目は、言語の名前の無い囲いのコードと同じ（等幅・面の色）。字下げ4つ分を除いた残りを、そのまま出す（強調・リンク・見出し・リスト・引用を解かない）。
- 付けないもの（決めたこと）: コードの見出しの行（言語の名前・コピーの操作。ADR0098）と色分け。コピーの通し番号は動かない。次のIssueにする。
- 変えた所: `src/core/markdown_blocks.c`だけ（始まり`indented_starts`・`start_indented`、空行の先読み`indented_resumes`、終わり`indented_ends`、囲いのコードと共用する左端の計算`place_code`）。出力は、囲いのコードの行の道（`code_line`・`close_code`）をそのまま使う。入れ物（リスト・引用）・表・行の読みは変えていない。

## 進め方

1. 実装は、新しい席（実装の席）が作業木で行った（コミット・pushなし）。CommonMark 4.4の例107〜118を全部、試験にした。
2. 席が、カバレッジの測定（確保の失敗の試験は、測定の構築でだけ走る）を流した: 成功。全体 91.76%（13671/14898）。
3. **独立レビュー（読み取り専用の席）を、mainへ入れる前に通した。** 落ちる・範囲外を読む・無限ループ・二次の時間になる欠陥の指摘は無し。囲いのコードの振る舞いは変わっていない。原文の対応表・コピーの通し番号・図・ミニマップ・目次への影響も無し。
4. レビューの指摘で、**変更を1つ取り下げた**（下）。
5. 席が、変異を流した。

## 取り下げた変更: リンクの定義の走査

実装の席は、「コードのすぐ下のリンクの定義を読めるようにする」ために、リンクの定義の走査（`src/core/markdown_references.c`）で、定義を始められる所の字下げ4つの行をコードと見る変更を入れていた（8行）。

独立レビューが、次の入力で表示が壊れることを見つけた（コードを追った結果）: リストの項目、空行、字下げ4つの行（項目の段落）、脚注の定義、空行、字下げ4つの行、と並ぶと、最後の行が本文から消えて脚注へ移る。空行が無い形では、同じ行が段落と脚注の両方に出る。走査はリストや引用を追わないので、字下げ4つの行が「コード」なのか「項目の段落」なのかを見分けられないのが原因。

取り下げて、走査は元のままにした（差分は D:/NeNeFolio/temp/20261122/indented/references-change-withdrawn.diff に保存）。その入力で行が動かないことを、試験で固定した。代わりに残るずれ（コードのすぐ下の、空行なしのリンクの定義が読まれない）は、ADR0121の「まだ合わせていない所」に理由と一緒に書いた。

## 確かめていないこと・残るリスク

- **RichEditでの実際の見た目は、まだ見ていない**（単体の試験はRTFの文字を比べる）。hideの実画面で、字下げのコードの面・左端・リストや引用の中の位置を見てもらう。
- 取り下げと試験の足し込みの後は、カバレッジの測定を手元で流し直していない（製品コードは、取り下げで元へ戻した分だけ減った）。必須CIが測る。
- 先読みの速さ（空行と字下げの行が何万回も交互に続く入力）は、独立レビューがコードを追って「原文の長さに比例する」と確かめたが、測ってはいない。
- 脚注の続きは64行まで。それを超えた字下げの行は、今までは段落、これからはコードになる。
- 既存のノートで、空行の後に字下げ4つで書いた文は、コードの見た目に変わる（hideの了承済み）。
- 仕様と違うまま残した所は、ADR0121の「まだ合わせていない所」。
