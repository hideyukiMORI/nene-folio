# 主窓の言葉を同梱の書体で描く（最初の段: 字の釦）の品質記録 — 2026-11-23

Issue #1228（#1222 の最初の段）。決定は [ADR 0036 の 2026-11-23 の補正（#1222）](../adr/0036-bundled-fonts.md)。

## 何を変えたか

- 主窓が「言葉の書体」（言語ごとの同梱の書体・大きさ11）を持つ。DPIと言語のどちらが変わっても作り直す（`src/ui/win32/folio_window.c`の`refresh_word_font`）。
- 字の釦の名前（新しいノート・表示の3択・閲覧／編集・保存・このノート内を検索・操作）と、上の帯の「表示」を、その書体で描く。釦の幅は、同じ書体で測る。
- 「NENE FOLIO」・番号・日時・キーの名前・パンくず・下の帯・面の中・入力欄は、変えていない。

## 確かめたこと

- 実測（GDI）: 同梱の書体の行の高さ・字の幅・持っている記号（ADR 0036 の補正の3）。
- 実窓の試験（`favorites_ui_native`の`word_font_parts`）: 「新しいノート」の釦の幅が、同梱の書体で測った名前の幅から決まる値と同じ（120 DPIで145。等幅で測ると125）。
- 実物の絵（見えない別のデスクトップ。125%・明るい配色・日本語の1場面）: 釦の名前が Noto Sans JP で出る。釦は少し広くなる（「新しいノート」が約15px）。「NENE FOLIO」とパンくずの番号は等幅のまま。
- 全試験・適合の検査・整形の結果は、PRの本文に書く。

## 残していること

- 実窓の試験は、釦の幅（測る側）だけを見る。描く側（`draw_part_label`・上の帯の「表示」）が言葉の書体を選ぶことと、言語を切り替えたときに作り直すことは、試験が見ていない（独立レビューの指摘。描いた字は、絵で席が見た。言語の切り替えは、日本語と英語が同じ書体で、中国語も全角の幅が同じなので、幅では見分けにくい）。
- 試験は、言葉の書体で測った幅と等幅で測った幅が同じ4の倍数へ丸まるDPIでは、「等幅で測る」変異を落とせない（120 DPIでは145と125で違う。ほかのDPIは未確認）。同梱の書体が登録されない機械では、試験も製品も同じ退避の書体で測るので通る。
- 上の帯の「表示」（言葉の書体）と「NENE FOLIO」（等幅）は、升の高さが違う。同じ帯の縦の中央に別々に置くので、字の下端が1pxほどずれうる（独立レビューの見立て。125%の絵では気にならなかった）。
- 英語・中国語、96／144／192 DPI、暗い配色・高コントラストの絵は、見ていない。狭い窓（釦の字を落とす幅）の境目は、幅を測り直すので動く（試験は既存のものだけ）。
- 表示の3択（幅56）と閲覧／編集（幅56）は、幅を決め打ちしている。同梱の書体で字が入ることは、日本語・125%の絵で見ただけ。
- 下の帯・面の中・入力欄・tooltipは、OSの代わりの書体のまま（次の段。パンくずは、下の節で替えた）。
- hideの実画面では、まだ見ていない。

## パンくず（#1230。2つ目の段）

- カテゴリ名とノート名（復旧待ちの言い換えを含む）を、言葉の書体で測って描く。番号は等幅のまま（`breadcrumb_cells`・`draw_breadcrumb`）。未保存の印の場所は、同じ書体で測ったノート名の幅から決まる。
- 実窓の試験（`favorites_ui_native`の`breadcrumb_word_font`）: 試験のdataの2つのノート「one」「two」は字の数が同じなので、等幅ではパンくずの幅が同じになる。言葉の書体では、2つの名前の幅の差（120 DPIで1px）だけ違う。その差が、同じ書体で測った差と同じことを見る。
- 変異（パンくずの名前の幅を等幅で測る）: 試験が落ちた（D:/NeNeFolio/temp/1222/mutations2.log）。
- 実物の絵（見えない別のデスクトップ。125%・明るい配色・日本語）: カテゴリ名とノート名が Noto Sans JP、番号は等幅。
- 残していること: 試験は測る側だけを見る（描く側は絵で席が見た）。2つの名前の幅の差は小さい（120 DPIで1px）。差が0になるDPIでは、試験は通るが、等幅で測る変異を落とせない（その場合は、試験の出力に「cannot tell the faces apart at this DPI」と出る。独立レビューの指摘で、最初は「差が0でない」を求めていて、必須CIで偽の失敗になりうる形だったのを直した）。96 DPIでどちらになるかは、まだ見ていない。
- 番号（等幅）と名前（Noto）は、升の高さが違う。同じ区画の縦の中央に別々に置くので、名前の字の下端が約2px下がりうる（独立レビューの見立て。125%の絵では気にならなかった）。
- 試験は、ノートの選択を state の関数で直に切り替える（窓の切り替えの道を通らない）。パンくずの矩形は state を直に読むので、幅は切り替えを反映する。終わりに選択を元へ戻す。
- 長い名前の省略・未保存の印・狭い窓・英語と中国語・ほかのDPIの絵は見ていない。

## 下の帯（#1234。3つ目の段）

- hideが、2通りの実物の絵（https://claude.ai/artifact/GAS6WaW8u9m6Fb3eSHJZ6G ）を見て、案2（言葉は Noto Sans、日時とキーの名前は等幅）に決めた（「案2で」）。
- 作り: 文に差し込む値（日時・キーの名前）の前後に印を付け、描く側が、印の中と空白を等幅、それ以外を言葉の書体で、左から順に測って描く（`src/ui/win32/folio_window.c`の`status_value`・`status_line`）。翻訳の文を記号で切り分けない。説明と読み上げの文には印を付けない。知らせと結果の1行は、言葉の書体。
- **絵と本番の作りの違いに、撮り直して気づいた**: hideに見せた案2の絵は、試しの簡単な作り（英数字の並びを等幅で描く）で、言葉と日時の間の空白が等幅の幅だった。本番の最初の作りでは、その空白を言葉の書体で描いていて、行が詰まって見えた。空白も等幅の幅で描く形に直して、hideが選んだ絵と同じ間隔にした。
- 実窓の試験（`favorites_ui_native`の`status_keys_fonts`）: 下の帯のキーの部分（右寄せ）の、描かれた字の幅が、「F1」「Ctrl+P」と空白を等幅、「ヘルプ」「·」「コマンド」を言葉の書体で測った幅と、3px以内で合う（120 DPIで、描かれた幅216、期待218）。
- 変異4本（値も言葉の書体で描く／言葉も等幅で描く／空白を言葉の書体で描く／描く側で値に印を付けない）: 全部、試験が落ちた（描かれた幅が期待と11px以上違う。D:/NeNeFolio/temp/1222/mutations4.log）。最初の試験は許す幅が広く（約5px）、空白を等幅にする前の作りで、4本のうち2本を落とせなかった。許す幅を3pxに詰めた。
- 実物の絵（見えない別のデスクトップ。125%・明るい配色・日本語）: 言葉が Noto Sans JP、日時とキーの名前が等幅で、間隔はhideが選んだ絵と同じ。
- 独立レビュー: 落ちる・あふれる・印が漏れる類の欠陥の指摘は無し。反映したもの: 英語で、言葉の中の空白（"Unsaved changes"）まで等幅の幅に広がっていた → 値の隣の空白と、2つ以上続く空白だけを等幅にした／試験が、言葉を等幅で描く退行を落とせないDPIがありうる → 2つの測り方の差が8pxより大きいことを試験が求める（足りないDPIでは、試験が自分で落ちる）／読み上げの名前に印が無いことの確かめを足した／ADRの言い方。
- 残していること: 試験は、キーの部分の幅と、読み上げの名前に印が無いことを見る（日時の側、知らせの1行、狭い窓で文を短くする落とし方は、試験が見ていない。落とし方の順は前のまま）。試験は、文言とキーの名前（「F1」「Ctrl+P」「ヘルプ」「コマンド」）を直に書いているので、文言やキーの割り当てを変えると、描画が正しくても落ちる。許す幅が3pxなので、ほかのDPIで字の端の空きが変わると、偽の失敗になりうる（96 DPIは必須CIが流す）。
- 幅が足りないときの省略の出方が、前と変わった: 前は行の全体を1本で描いて末尾に「…」。いまは、右端をまたぐ並び1つが、自分の場所の中で省略される。並びがちょうど右端で終わると「…」が出ない、日時の日付と時刻の間で切れると省略に見えない、という場合がありうる（更新だけ・ヘルプだけに落としても収まらない、ごく狭い窓。絵では見ていない）。
- 言葉と値は、升の高さが違う書体なので、字の下端が1pxほどずれうる（パンくずと同じ）。英語・中国語、ほかのDPI、暗い配色の絵は見ていない。
