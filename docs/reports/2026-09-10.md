## 実測で決めたこと（設計の根拠）

- RichEdit（`RICHEDIT50W`）は LF / CRLF / CR をすべて 1 つの段落区切りに潰し、取り出すと CR か CRLF しか出ない。よって改行の種類は core が覚えて付け直す（ADR 0006）
- `EM_GETTEXTEX` の `CP_UTF8` は孤立サロゲートを黙って U+FFFD にする。`EM_STREAMOUT` の UTF-16 → core の `utf8_text` なら型のある失敗にできるので、UI から application へは UTF-16 で渡す（C-014 の字面との衝突は ADR 0006 に記録）
- `EM_STREAMIN` は文字数上限を流し込んだ長さまでしか広げない。`EM_EXLIMITTEXT` を先に送れば縮まない
- `ENM_KEYEVENTS` の `EN_MSGFILTER` は `WM_CHAR` でも届き、親が非 0 を返せば既定処理が止まる。Ctrl+S は `WM_CHAR` の 0x13 で受け、`GetKeyState` を使わない
- `file_bytes_store` は読み取り専用・排他・無いディレクトリで `UNWRITABLE` を返し、元ファイルも `.tmp` も汚さない
- `MoveFileExW` に `MOVEFILE_REPLACE_EXISTING` を付けなければ同名（大文字小文字だけ違うものを含む）で失敗する。md の移動はこれ 1 回で原子的（ADR 0008）

## 規約が邪魔になった箇所（緩めずに通した）

- C-014「変換は ui / adapters の境界で」と ARC-011「判断を UI に置かない」が保存の意図で衝突 → application が UTF-16 を受ける例外を ADR 0006 に 1 本だけ記録
- C-012 の引数上限 4 と `move_note(state, from_category, from, to_category, to)` → `note_ref`（カテゴリ番号とノート番号の組）で 3 引数に（ADR 0008）
- 「書けなければ状態を変えない」と md の rename → rename の後は台帳が従う。`LEDGER_STALE` で正直に伝え、FR-008 の照合で自己修復（ADR 0008）
- `tests/unit/folio_tests.c` の `main` は早期 return の後ろに新しいテストを足さないと `coverage.py` の反例が落ちる（QLT-007）
- 撮影スクリプトが DPI 非対応だと `PrintWindow` が窓の左上だけを写し、右端の札が消える。1 度誤診した（gate-proofs 5-e に記録）
