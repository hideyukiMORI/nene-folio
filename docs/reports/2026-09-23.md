## #75 — テーマと設定画面と版 2（単位 B・ADR 0031）— PR #81

- **テーマの値を 2 つの型に分けた。** 利用者が選ぶ 3 値は core の `enum folio_theme_choice`（`system` / `light` / `dark`）、
  描画に渡す 2 値は既存の `enum folio_theme`。解決は core の純関数 `folio_theme_resolve(choice, os_theme)` 1 か所だけ。
- **`data/settings.json` を版 2**（`{"version":2,"number":<bool>,"theme":"…"}`）へ広げた。
  解析は「版を読む `parse_document`」「`parse_version_1`」「`parse_version_2`」の 3 本に割り、**版 1 は読めて `theme` に既定値 `system` を埋める**（移行）。
  書くのは常に版 2。**古い exe は版 2 を `UNSUPPORTED_VERSION` で拒み、既定値で起動して上書きしない**（ADR 0025 の決定 2 / 6 のまま）。
- application が値の所有者（ARC-004）。`folio_state` が `appearance_port` を**値で写して保持**し、`theme_choice`（設定）と `os_theme`（port）を別に持つ。
  `folio_state_set_theme` は**新しい設定と新しい閲覧文書を先に作り → `write_settings` が成功したら差し替える**（どちらの失敗でもファイルも状態も変えない）。
  `SETTINGS_UNREADABLE` のセッションは `set_number` と同じ値で断り、上書きしない。設定は md・台帳・`.rename.json` と独立なので `synchronize()` を通さない。
- **再着色は 1 本の経路**（`recolor_window`）。`note_pane_recolor` は `EM_SETBKGNDCOLOR` → 変更印を `EM_GETMODIFY` で退避 →
  `ITextDocument::Undo(tomSuspend)` → 書式 → `Undo(tomResume)` → `EM_SETMODIFY` で復元。
  **切り替えても本文・Undo の段数・未保存の印・キャレットと選択・モード・閲覧のスクロール位置を失わない。**
- OS の変更への追従は主窓の `WM_SETTINGCHANGE`（`ImmersiveColorSet`）→ `folio_state_refresh_theme` →
  解決値が変わったときだけ再着色（設定は書かない）。`WM_THEMECHANGED` / `WM_SYSCOLORCHANGE` は来ない（実測）。
- 設定画面は `command_layer` の自前描画で、**レイヤー自身がフォーカスと鍵を受ける**（鍵は既存の `command_key_down` / `command_character` を共有・第 2 の鍵の経路を書いていない）。
  IME は `ImmAssociateContext(layer, NULL)` で外す（`eng/architecture.json` の `platformLibraries.ui_win32` に `imm32` を足し、CMake で明示的に結んだ・ARC-002）。
- 入口は 3 つが同じ意図へ渡る: 頭の**歯車**・「操作」メニューとパレットの「設定」・Ex の `:set theme=system|light|dark`（`options[]` に 3 語）。
- 配色は Ubuntu 風の 2 組（ダークは aubergine 系の地 `#2C001E`・選択 `#772953`・札は orange `#E95420`）。**値は候補で、hide の実機目視で動かしてよい**（変える場所は `rtf_palette.c` と `folio_palette.c` の 2 ファイルだけ）。
  配色の画面案は <https://claude.ai/artifact/SHmNscVHWZjBmL3XLsqSXZ>。

## 運用の学び

- **1 つの実装 agent を複数の単位にまたいで使うと文脈が尽きる。Issue ごとに新しい agent を立てる。**
- **ADR が未定義の規則 ID を名指しすると CNF-006 で落ちる。** CNF-006 は「本文に定義があるのに強制マトリクスに行が無い」と「未定義の ID」の両方を拒むので、
  新しい ID（CNF-010 / C-018）は**それを定義する単位の同じコミットで planned として置き**、実装するコミットで active にする（ADR 0001）。
- **GitHub の `ready_for_review` で CI が起動しないことがある。** push（`synchronize`）で起動する。
  `gh pr ready --undo && gh pr ready` でも起きなければ、空でない push を足す。
- **使用制限で agent が止まっても、作業木の未コミットの編集から再開できた。** 区切りで止めるときは同じ agent へ
  「未コミットを事実の範囲でコミット → 狭い検査 → 最終 HEAD で 1 回だけゲート → push → どこまで済んだかをファイル名・関数名で報告」を送る運用のままでよい。
- 面ごとの行数を引数に取る式（#69）のように、**次の単位が使う形を先に 1 本にしておく**と、#75 の設定画面は行数を足すだけで済んだ。
