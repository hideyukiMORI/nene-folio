   **残るのはコンボの矢印の釦とドロップダウンのスクロールバー**（v5 の限界として明記し、目視の対象にする）。
4. **失敗の箱は `MessageBoxW` をやめ、同じ塗りの自前のモーダルにする**（案 (b)）。本文の幅は 480px（96 DPI）で

5. 開いている面のテーマ追随（**批評で撤回。下記 S4**）。
6. やらないこと: v6 / uxtheme / `SetWindowTheme`、`ChooseColorW`（ADR 0010 のまま）、コンボの矢印とスクロールバー、
   失敗の箱のアイコンと音、ハイコントラスト。

### 運用の学び（この期間の追加）

- **sync の merge コミットの件名も GIT-003**（`chore(sync): main を取り込む (#N)`）。`Merge remote-tracking branch …` は CI の `validate-git` で落ちる（#109 で 1 度落とした）。
- **`ready_for_review` の run は同じ PR への次の event に cancel される**（`concurrency.cancel-in-progress`）。Draft の push は job が skipped で、**skipped の必須 check を GitHub は満たしたと見なす**（#112）。
- **`gh pr merge` 直後の `gh issue view` は `OPEN` を返す**（閉じる処理の遅れ。`merge-pr.ps1` は最長 30 秒待つ）。
- **背景席は `out/agents/<issue>-<仕事>/report.md` を書けないことがある**（harness が「subagent は報告ファイルを書かない」と Write を拒む。14 席のうち 3 席）。拒まれたら最終メッセージに申し送りを入れる。テンプレートにその 1 行を足す。
- **Bash の素の pwsh から `validate-git.ps1` を呼ぶと文字化けで GIT-003 が誤って落ちる**。フルゲートの中の結果を正とする。
- **`TaskStop` は待ち手の task を止めるだけで、その task が待っていた背景の task は止まらない**。止めるべきは実体の方。
- 差し戻しは「変更 1 命題 = 新しい席」で 5 回（#102 × 2・#82 × 3）。1 席 7〜11 回の道具呼び出しで済み、**同じ席に SendMessage で足すより安い**ことが数字で見えた。
